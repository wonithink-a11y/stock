# 세션 마감

다음 세션의 Claude 는 이 대화를 기억하지 못한다. 인수인계 파일과 CLAUDE.md 상태 블록이 유일한 다리다.
그래서 쓰는 기준은 하나: **다음 세션이 이걸 읽고 같은 실수를 안 하고 바로 이어갈 수 있는가.**
CLAUDE.md 는 매 요청의 토큰 비용이라 길이를 늘리지 않는다 — 상세는 인수인계 파일에 두고, 상태 블록에는 포인터와 현재 트랙만 둔다.

## 0. 수시 기록 모드 (작업 중 계속)

마감 때 대화 전체를 되짚어 쓰면 컨텍스트가 가장 클 때 가장 많이 생성하게 되고, 한도 직전에 걸리면 못 쓴다.
그래서 **작업 중에 조금씩 쓰고 마감 때는 요약만 채운다.** 파일은 디스크에 있으니 한도가 차도 사라지지 않는다.

- 첫 의미 있는 작업(커밋·판정·운영 변경)이 끝나면 오늘 인수인계 파일을 만든다. 골격은 아래 2절.
- 커밋·판정·함정·미확인이 생길 때마다 **2~3줄만** 해당 절에 덧붙인다: `- 무엇 · 커밋 해시 · 확인함/미확인`.
  방금 일어난 일이라 짧아도 정확하다. 이때 CLAUDE.md 는 건드리지 않는다.
- `git commit` 뒤에는 훅이 상기시킨다 (`.claude/hooks/commit-note.js`). 알림만 오고 쓰는 것은 내가 한다.
- 작업 중에는 이 파일을 **커밋하지 않는다** (반쯤 쓴 문서가 push 되는 것을 막는다). 마감 때 한 번에 커밋한다.
  작업 폴더에 미커밋으로 남아 있으니 세션이 끊겨도 다음 세션이 `git status` 로 찾아 이어 쓴다.
- 새 세션이 시작될 때 오늘 날짜 미커밋 인수인계 파일이 있으면 이어서 쓴다.

### 한도 점검

체크포인트(커밋 직후, 큰 작업 사이)마다 `mcp__ccd_session_mgmt__get_usage` 를 부른다 (읽기 전용).
`plan.windows` 의 5-hour 가 **90% 이상**이면 하던 일을 멈추고 **최소 마감**만 한다:
`## 0. 한 장 요약`(한 일·push 여부) + `## 다음에 볼 것 (미확인)` + 미커밋 변경 목록, 그리고 파일을 커밋. 그 뒤 새 작업은 시작하지 않는다.
주간 한도가 90% 이상이어도 같다. 컨텍스트(`context.percentUsed`)가 80% 를 넘어도 마감을 제안한다.
한계: 나는 턴 사이에 스스로 깨어나 감시하지 못하고, 도구 호출 도중 끊을 수도 없다. 체크포인트에서 확인하는 것이 전부다.

## 1. 무엇이 일어났는지 모은다

- `git log --oneline` 으로 이 세션 커밋, `git status --short` 로 미커밋 변경.
- 이 세션에서 **확인한 것 / 못 한 것**을 가른다. "push·VM pull 완료, 새 방 실제 도착은 미확인" 처럼 미확인을 숨기지 않는다.
  통과로 보고하려면 실제로 본 증거가 있어야 한다 (로그·실행 결과). 코드 푸시는 검증이 아니다.

## 2. 인수인계 파일

`docs/control/세션인수인계-YYYY-MM-DD.md` (같은 날 두 번째부터 `-b`, `-c`). **저장소 루트에 쓰지 않는다.**
직전 파일(`ls docs/control/세션인수인계-* | tail -2`) 하나를 열어 형식을 맞춘다. 골격:

```
# 세션 인수인계 — YYYY-MM-DD (b) 한 줄 제목
## 0. 한 장 요약          무엇을 왜 했나, 지금 상태, push/배포 여부, 미확인 한 줄
## 1~N. 내용 절          표(무엇↔어디↔누가 실행)와 값, 파일 경로, 커밋 해시
## 커밋                   해시와 한 줄 요약
## 다음에 볼 것 (미확인)   언제·무엇을 보면 되는지 (날짜·명령까지)
## 함정                   이번에 물린 것, 조용히 틀릴 수 있는 것
```

- 비밀(키·토큰·`?key=` URL)은 넣지 않는다 (절대 규칙 2). 방 ID 같은 비시크릿 식별자는 가능.
- 시각은 KST. 상대 날짜("내일")는 절대 날짜로 바꾼다.
- 연구 판정이면 findings 경로와 "신호/경제성" 한 줄을 넣고 닫힌 길/남은 길을 쓴다.

## 3. CLAUDE.md 갱신 (길어지지 않게)

1. 해당 트랙의 "다음"/"안 한다" 항목 **한 곳**만 고친다. 새 항목이 필요하면 2~3줄로, 상세는 인수인계 링크.
2. 최신 인수인계 포인터를 그 항목에 건다. 예전 포인터가 쌓이는 긴 목록에 계속 덧붙이지 않는다 — 한 줄이 이미 너무 길면 옛 것을 줄인다.
3. 닫힌 연구는 "안 한다"에 신호/경제성 + 핵심 숫자 하나 + findings 경로. 끝난 운영 작업은 `docs/control/완료-이력.md` 로.
4. 월간 점검에 새 forward 가 생겼으면 `monthly-check` 스킬의 표와 상세 문서에 추가한다 (CLAUDE.md 에 쓰지 않는다).
5. 🔴 구조 변경(문서 구조·동결 목록)은 사용자 GO 후에만. 상태 문구 갱신은 🟡.

## 4. 낡음 점검

```bash
git log --oneline $(git log -1 --format=%H -- CLAUDE.md)..HEAD -- lib scripts config deploy .github
```

비어 있지 않으면 CLAUDE.md 갱신 이후 구현이 바뀐 것이다. 그 커밋을 읽고 상태 블록과 어긋나는 곳을 고친다.
구현과 문서를 같은 커밋에서 고치면 이 명령은 비게 된다 — 그게 원하는 규율이다.

## 5. 커밋과 push

- 인수인계 파일 + CLAUDE.md 만 **파일 명시 add** (`git commit -a` 금지 — 사용자 로컬 변경이 딸려 간 사고 2026-09-23).
- 메시지: `docs: 인수인계 YYYY-MM-DD — 한 줄 제목`, 상태 블록만이면 `docs(CLAUDE.md): …`.
- push 는 사용자 확인 후. `pull --rebase --autostash` 를 쓰고 `stash pop` 은 맹목 사용하지 않는다.
- `data/backfill/` 변경이 보이면 로컬 실행 부산물이니 `git checkout -- data/` 로 되돌린다 (절대 규칙 4).

## 6. 스킬 후보 점검

마감 때 `skill-candidates` 스킬(홈 폴더, 범용)을 따른다: 이 세션에서 반복됐거나 다음에도 올 절차를 최대 2개 제안하고, 승인되면 만든다.
이 프로젝트의 기존 스킬: monthly-check · monthly-forecast · preregistered-research · session-wrapup · vm-check · deploy-unit · run-regressions —
겹치면 새로 만들지 말고 보강한다.
