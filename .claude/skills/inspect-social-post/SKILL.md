# SNS 게시물 검증

내용은 매번 달라도 순서는 같다. 짧게 끝낸다 — 결과 한두 줄 + 위험·미확인만.

## 1. 주장을 쪼갠다
항목별로 나눈다: 출처 주장(공식/오픈소스), 설치 명령, 수치·규정, 기대 효과.

## 2. 출처를 분류한다

```
공식        저장소 소유자가 해당 회사 조직인지 직접 열어 확인 (이름만 믿지 않는다)
오픈소스    pip/npm 패키지·저장소 실재, 별·최근 커밋·라이선스
개인 제3자  가장 조심. 소스를 읽기 전 설치 금지
```

## 3. 원문을 직접 연다 (브라우저 패널)
- 저장소 README, 대상 디렉터리, `.mcp.json`(외부 커넥터 전제?), `hooks/hooks.json`(자동 실행?), `SKILL.md` 본문(스크립트 포함?)
- 못 읽은 것은 "미확인"으로 적는다. 읽은 척 금지.

## 4. 사실관계 대조
공시 기한·규정·수치는 공식 문서와 맞는지 본다. 틀린 건 짚는다.

## 5. 설치 명령 위험도
`--yes`(확인 생략) · `-g`(전역) · `curl | sh` · 서드파티 `npx`. 스킬은 Claude 가 따르는 지시문+스크립트다.

## 6. 이 프로젝트와의 관계 → 권고 하나
- 이미 있는 것과 겹치는가 (8-K 알림, 마감 리포트, yt-digest 등)
- 점수·매매에 쓰려는가 → 절대 규칙 1 위반, 맥락 전용. 신호로 쓰려면 사전등록 먼저.
- 추정치·목표가·뉴스류는 PIT 소스 없음(종결) 재확인.
- 결론은 "추가/보류/무시" 중 하나 + 이유.

## 안 하는 것
- **설치는 사용자 승인 후.** 이 스킬은 검증까지만 한다.
- 동영상은 직접 못 본다 — 자막·대본(`yt-digest` 요약 등)이나 핵심 장면 캡처를 요청한다.
- 시크릿·키를 요구하는 게시물이면 중단하고 알린다(규칙 2).
