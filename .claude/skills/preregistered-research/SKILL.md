# 사전등록 연구

이 프로젝트의 연구는 거의 다 REJECT 로 끝난다. 그건 실패가 아니라 정상 산출이다 — 싸게 접는 것이 값이다.
이 절차가 지키려는 것은 하나다: **결과를 보기 전에 판정 기준을 고정한다.** 결과를 보고 고르면 다중검정이고,
이 저장소의 "통과"가 쓸모를 잃는다(54축 전수 스윕도 난수 팩터로 t 3.21 이 나왔다).

## 1. 시작 전 — 이미 해봤는지

1. `research/strategy-lab/findings/INDEX.md` 와 `_registry.jsonl` 을 키워드로 검색한다 (`Grep`).
2. CLAUDE.md "안 한다" 항목과 대조한다. 같은 표본·같은 가설의 재판정은 금지다. 닫힌 라인을 다시 여는 길은
   **새 사전등록 + 새 표본(또는 forward)** 뿐이다.
3. 겹치면 멈추고 사용자에게 "이미 이렇게 닫혔다, 어느 점이 다른가"를 묻는다.

## 2. 사전등록 문서 (코드보다 먼저)

`research/strategy-lab/findings/<주제>-preregistration-YYYY-MM.md`. 형식은 최근 파일 하나(예: `us-target-change-forward-preregistration-2026-10.md`)를 복사해 시작한다.

- 머리말: `track` · `factor` · `date` · `verdict: PREREGISTERED` · `criteria_version: research-only` · `conditions`(고정 사항 요약) · `reason`("신호: (미측정) · 경제성: (미측정)" + 질문 한 문장).
- 본문에 **결과 전에** 고정할 것:
  - 질문, 배경(결과 아닌 것만), 현실적 기대(대개 INCONCLUSIVE/REJECT 라고 적는다).
  - 자료·사건 정의, 진입·청산, 대조군(매칭/등가중), 구간(TRAIN / VALID / TEST).
  - **비용과 시장**: 어느 시장·어느 비용을 볼지 여기서 정한다. 결과를 보고 손익분기가 낮은 곳을 찾아가면 사후 조건 변경이다.
    참고값 — KR 연속 시장 왕복 ≈33.5bp · 종가/시가 단일가 23.54bp · 선물 1.4bp · ETF ≈5bp · 크립토 10bp.
  - **바닥선**: 난수(부호반전 500회 등)로 잰 TRAIN |t| 문턱. 문턱 위에서만 "신호 있음".
  - 판정 규칙(REJECT → INFORMATION → ECONOMIC → ROBUST, 못 가리면 INCONCLUSIVE)과, forward 면 판정 시점(건수 ∧ 개월).
- 문서 끝에 "동결: 이 커밋 뒤 문턱·창·셀·비용을 바꾸지 않는다" 를 쓴다.

## 3. 코드 동결

1. 사전등록 문서를 **먼저 커밋**한다 (파일 명시 add, `git commit -a` 금지).
2. 코드 `research/strategy-lab/<이름>.py` 를 쓰고 커밋한다. 이 커밋 해시를 사전등록 `code:` 칸/결과 머리말에 적는다.
3. 판정 시점이 있는 forward 는 코드가 그 전 `--judge` 를 **거부**하도록 만든다 (건수만 출력). 기존 `run_*_forward.py` 를 본보기로 쓴다.

## 4. 실행과 결과 파일

클라우드 세션에서 `.cache`·크립토 시세·A4 가 없으면 다시 받지 말고 `python scripts/research-data.py get <묶음>`(목록은 `list`). 쓴 묶음의 sha256·builtAt 을 결과 파일에 적는다.

`findings/<주제>-results-YYYY-MM.md`. 머리말 `reason` 첫머리에 **"신호: 있음/없음 · 경제성: 통과/미달"** 을 쓴다
(UI 목록은 `verdict` 한 단어만 보여준다. 신호 실패와 비용 실패를 한 단어로 뭉개지 않는 규칙이다).

결과 표의 표준 열:
- gross 평균(부트스트랩 신뢰구간) · 비용 후 net · 손익분기 비용. 사전등록에서 고른 시장·비용 옆에 적는다.
- 시기 세 칸 **2016~23 / 2024 / 2025~**. 2025~ 는 다른 장이라 TEST 통과가 장세 특이일 수 있다.
- 반도체가 섞일 수 있는 결과(모멘텀·대형주·지수)는 **'반도체 제외' 한 줄** 추가 (진단 전용, 매매 규칙으로 쓰지 않는다).
- 사후 관찰은 "기록 전용, 판정 불사용" 으로 따로 표시한다. 뒤집어 쓰기(롱→숏)는 사후 가설이라 **새 사전등록으로만**.
- 마지막에 "같은 표본 재절단·창/문턱 변경 금지, 남은 길은 …" 을 적는다.

## 5. 데이터 함정 (조용히 틀리는 것들)

- **생존편향**: 현재 상장 종목만 쓰면 부푼다. 폐지 종목 포함 자료를 쓰고, 못 쓰면 한계에 적는다.
- A2a/A2b 가격은 수정주가인데 **거래량은 원값**(분할 시 가짜 급증). A4 `close` 와 a2a 는 수정 기준이 달라 갭 계산에 A4 close 를 쓰지 않는다.
- A2a 종가 2026-09-14~ 은 애프터마켓 혼입 구간이 있다 (PR-1.8, KIS 정규장으로 교체됨) — 그 구간을 쓰면 확인한다.
- 공시 `rcept_no` 는 최신 정정본이라 사건일이 어긋날 수 있다.
- 시각은 항상 KST. 성공 코드가 "내 질문에 답했다"는 뜻이 아니다 — 응답의 일자·종목을 대조한다.

## 6. 닫기

1. `python research/strategy-lab/build_findings_registry.py` 로 `_registry.jsonl`/INDEX 갱신. (INDEX.md 는 자동 생성이다. 손으로 쓰지 않는다.)
2. REJECT/종결이면 CLAUDE.md "안 한다" 에 **2~3줄**만 (신호/경제성, 핵심 숫자 하나, findings 경로). 상세는 findings 에 둔다 — CLAUDE.md 는 매 요청 토큰이다.
3. forward 로 넘기면 월간 점검 표(`.claude/skills/monthly-check/references/shadows.md`)에 한 행, 상세 문서에 원문을 추가한다.
4. 세션 인수인계 `docs/control/세션인수인계-YYYY-MM-DD[-b].md` 에 한 줄 (저장소 루트에 쓰지 않는다).
5. 보고는 한 줄: "판정 · 신호/경제성 · 핵심 숫자 · 닫힌 길/남은 길". 통과해도 점수·매매 반영은 🔴 별도 GO 다.

## 하지 말 것

- 결과를 본 뒤 문턱·구간·비용·셀 변경, 같은 표본 재판정.
- 소급해서 옛 findings 의 머리말 수정 (새 파일부터 적용).
- 위임 도구(OpenCode 등)의 결과를 판단과 동일시. 판정은 직접 하고, 위임은 기계적 전처리에만 쓴다.
