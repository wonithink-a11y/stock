# 조건 격자 연구 (condition-grid)

`preregistered-research` 의 확장판이다 — 같은 사전등록 → 코드 동결 → 실행 → 결과 규칙을 따르되, **사건 정의 × 조건 여러 개** 격자를 한 번에 본다.
조건을 넓힐수록 우연히 좋아 보이는 칸이 늘어난다(54축 스윕도 난수 팩터가 t 3.21). 그래서 이 스킬의 핵심은 두 가지다: **조건 목록을 결과 전에 전부 고정**하고, **격자 전체 크기 K 에 맞춰 보정**한다.

## 0. 시작할 때 (이 스킬을 부를 때마다)
`SKILL.md` 와 `references/catalog.md` 를 **먼저 읽는다**(대화마다 한 번). 그다음 조건을 **촘촘하게** 넣는다 — 기본 밀도 규칙:
- 축마다 문턱 하나가 아니라 **구간 3~5개**(예: VIX <15 / 15~20 / 20~25 / 25~30 / ≥30, RSI <20 / 20~30 / 30~40 / ≥40).
- 핵심 축끼리 **2축 조합**(AND, `{"all":[...]}`)을 사전에 정한 몇 개만 추가(VIX×거래량, VIX×RSI, 추세×직전 상승 등). 조합을 사후에 늘리지 않는다.
- 카탈로그에 있으나 엔진에 없는 축은 엔진에 먼저 더한다(`build_series`).
- 칸이 많아지면 K 가 커져 BH 가 엄격해진다 — 그 대가로 '촘촘함'을 사는 것이므로 K 를 사전등록에 적는다.

## 1. 순서
1. **이미 했는지**: `research/strategy-lab/findings/INDEX.md`·`_registry.jsonl` 과 CLAUDE.md "안 한다" 를 키워드로 확인(preregistered-research §1). 같은 사건·같은 표본 재판정 금지.
2. **사건 정의를 고른다**: `references/catalog.md` §A 에서(하루 급락 · 연속 하락 · 10일 −5% · 252일 낙폭 · 연속 상승 ...). 새 정의면 사전등록에 정확한 식을 적는다.
3. **조건 축을 고른다 — 기본값은 '전부'**: `catalog.md` §B 의 축(VIX 수준·VIX 변화·거래량·추세 위치·RSI·낙폭 깊이·하락 속도·원인·시기)을 모두 넣는다. 빼는 축은 이유를 한 줄 적는다("이 지수는 거래량 없음" 등). 기존 54개 차트 규칙(`catalog.md` §C)과 연구실 조건(§D) 중 이 사건과 맞는 것을 **사건 필터로** 가져올 수 있는지 먼저 본다.
4. **격자 크기 K 를 센다**: 사건 정의 수 × (조건 1개 + '조건 없음') × 시장 수. K 를 사전등록에 적는다.
5. **사전등록 문서를 먼저 커밋**한다(preregistered-research §2 형식). 다음을 반드시 포함:
   - 모든 조건의 정확한 식과 문턱(`condition_grid.py` 설정 JSON 그대로).
   - **보정**: 주 지표(보통 21거래일 초과수익) 전체 시험(K 칸)에 Benjamini–Hochberg FDR 5%. 칸 통과 = BH 통과 ∧ 같은 부호인 시장 ≥ 절반 ∧ VALID·TEST 합친 평균이 같은 부호.
   - 현실적 기대(대부분 INCONCLUSIVE), 절대 규칙: 결과를 보고 조건·문턱·시장을 바꾸지 않는다.
6. **엔진으로 실행**: `python research/strategy-lab/condition_grid.py --config <설정.json>`. 설정은 사전등록 커밋에 포함한다. 엔진은 순열 p(순환 이동)·BH·구간별 평균을 내고 **전 칸을 출력**한다(상위만 보지 않는다).
7. **결과 문서**: 전 칸 표 + 통과 칸 목록 + 통과 못 한 이유. 통과가 있어도 매매 근거가 아니다 — 새 사전등록 + forward(`run_*_forward.py` 형식, 월간 점검 표 한 행)로만 확인한다. CLAUDE.md "안 한다"/"다음" 에 2~3줄, 인수인계에 한 줄.

## 1-1. 국면 대조 (필수 — 2026-11-08 교훈)
VIX·낙폭·추세처럼 **국면을 가르는 조건**을 얹은 칸은 반드시 '같은 조건을 만족하는 모든 날'을 기준으로 한 대조(`"matched": true`)를 함께 낸다. `streak-conditions` 에서 A(≥3일·−5%) ∧ VIX≥30 칸이 전체 날 기준 +3.18%p 로 사전 기준을 통과했지만, VIX≥30 날 기준으로 다시 재니 +1.17%p·1개 시장으로 줄었다 — 반등 대부분이 사건이 아니라 국면이었다. 칸 통과를 보고할 때 이 대조 값을 같이 쓴다.

## 2. 하면 안 되는 것
- 결과 표에서 p 가 작은 칸만 골라 보고하기(다중검정). 반드시 전 칸과 K 를 함께 낸다.
- 칸이 통과 못 했는데 조건을 하나 더 얹어 다시 돌리기(같은 표본 재절단). 새 조건은 새 사전등록 + 새 표본.
- 사건이 같은 위기(2000~02·2008·2020)에 몰린 것을 독립으로 해석하기 — 결과 문서에 반드시 적는다.
- 원인 라벨(정책·금융·거시 등)을 기억으로 붙이고 확정처럼 쓰기 — 객관 기준(미국 동반 여부 등)을 우선하고, 사후 라벨은 '주관적'이라 명시.

## 3. 기존 도구
- 엔진: `research/strategy-lab/condition_grid.py` (설정 JSON → 칸별 통계). 지표 라이브러리: `tech_timing_3x.py`(SMA·RSI·MACD·볼린저·돈치안·피보나치 등 54규칙), `post_drop_asset_selection.py`(자산 33종 종가), `one_day_drop_5pct.py`·`streak_drop_events.py`(사건 정의 예시).
- 결과 예시: `findings/streak-drop-events-results-2026-11.md`, `findings/drop-cause-events-results-2026-11.md`.
- 조건 목록 확장: 새 축을 쓰면 `references/catalog.md` 에 한 줄 추가하고 엔진에 시리즈를 더한다.
