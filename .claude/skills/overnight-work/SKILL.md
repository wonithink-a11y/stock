# 밤샘 작업

사용자는 **자고 있다.** 질문해도 아무도 답하지 않는다 — 물으면 그 자리에서 밤새 멈춘다(2026-11-14 지적). 그래서 이 모드의 기본값은 "묻지 않고 안전한 쪽으로 진행"이다.
단 아래 '안전선'은 밤샘이라고 풀리지 않는다 — 안전선에 걸리는 항목은 **건너뛰고 아침 보고에 이유를 적는다**(묻지 않는다, 하지도 않는다).

## 1. 시작 — 큐를 만든다

1. 남은 작업을 `docs/control/밤샘작업-큐-YYYY-MM-DD.md` 한 장으로 적는다 (커밋하지 않는다 — 세션이 끊겨도 작업 폴더에 남아 다음 세션이 이어 쓴다).
   형식: `- [ ] 항목 · 규모(소/중/대) · 근거 문서 · 상태(대기/진행/완료/건너뜀: 이유)`.
2. 순서는 **소 → 중 → 대**. 작은 것을 먼저 끝내야 한도가 끊겨도 완료된 결과가 남는다.
3. 안전선에 걸리는 항목은 처음부터 "건너뜀"으로 표시한다.
4. 한도 상태를 한 번 읽는다: `mcp__ccd_session_mgmt__get_usage` (5-hour · Weekly · 컨텍스트).

## 2. 항목 하나를 처리하는 법

- 연구면 `preregistered-research` 절차 그대로(사전등록 커밋 → 코드 동결 커밋 → 실행 → 결과 → 등록소 빌드). 코드·설정 변경이면 `run-regressions`.
- 한 항목이 끝날 때마다: 파일 **명시 add**로 커밋(`git commit -a` 금지), 큐 파일에 상태 갱신, 오늘 인수인계 초안에 2~3줄(`session-wrapup` 0절 수시 기록).
- 로컬 실행 부산물(`data/backfill/` 등)은 `git checkout -- data/` 로 되돌린다. 사용자 소유 미커밋 파일은 건드리지 않는다.
- 긴 실행(5분 이상)은 백그라운드로 돌리고 완료 알림을 기다린다 — 폴링하지 않는다.
- 같은 오류가 **3번 연속**이면 그 항목을 "건너뜀: 막힘 + 증상"으로 적고 다음 항목으로 간다.
- `mcp__ccd_turn__wrap_up` 에 **ask·actions·blocked 를 쓰지 않는다**(recap 만). 버튼 질문은 밤새 대기를 만든다.

## 3. 한도 점검과 재개

**체크포인트(항목 끝, 큰 실행 직전)마다** `get_usage` 를 읽는다.

| 상태 | 행동 |
|---|---|
| 5-hour < 90% | 계속 |
| 5-hour 90~95% | 인수인계 초안을 최신으로 갱신(수시 기록 중이라 싸다)하고 **소 항목만** 계속한다. 중·대 항목과 엔진 실행·서브에이전트는 새로 시작하지 않는다. |
| 5-hour 95~98% | 새 항목을 시작하지 않는다. 진행 중인 것을 **커밋 가능한 지점까지만** 마치고 큐를 갱신한 뒤 아래 재개 예약. |
| 5-hour ≥ 98% | 도구 실행 없이 즉시 마감(큐·인수인계 파일이 이미 최신이어야 한다) 후 재개 예약. |

95% 에서 멈추는 한 단계 규칙은 빠듯하다 — 한도는 체크포인트에서만 읽는데 엔진 실행 한 번·긴 결과 정리 한 번이 몇 % 를 먹는다(2026-11-14 사용자 제안으로 90/95/98 3단계).
| Weekly(전체 또는 모델별) ≥ 95% | 재개 예약하지 않는다. 최소 마감(§5)으로 끝낸다 — 주간 리셋은 며칠 뒤다. |
| 컨텍스트 ≥ 80% | 마감 후 새 세션에서 큐 파일로 이어가도록 인수인계에 적는다. |

**재개 예약** — `CronCreate`(recurring: false)로 `resetsAt` + 3분(분 0·30 피함)에 한 번 발동:
- prompt: `밤샘작업 재개: docs/control/밤샘작업-큐-<날짜>.md 를 읽고 대기 항목부터 이어서 처리. overnight-work 스킬 규칙(질문 금지·안전선) 적용.`
- 예약이 성공했는지 결과의 다음 실행 시각을 큐 파일 맨 위에 적는다.
- 한계: 크론은 **이 Claude 세션이 열려 있는 동안만** 산다(디스크에 안 남는다). 세션이 닫히면 재개되지 않는다 — 아침 보고에 "재개가 끊겼는지"를 적는다.
- 리셋 시각이 1시간 이상 남았으면 그동안 한도를 안 쓰는 일(문서 정리, 큐 점검)만 하고 쉰다. 서브에이전트·백그라운드 작업 완료 알림은 크론과 별개로 나를 깨운다.

## 4. 안전선 — 밤샘이라도 풀리지 않는다

하지 않는 것(걸리면 "건너뜀"): 
- 유료 서비스 가입·결제·새 유료 도구(절대 규칙 9) · 실계좌 주문/실매매 코드 켜기 · 시크릿을 코드·로그·커밋에 넣기
- `config/policies`·`config/criteria` 수정(🔴), 정책 승격, 모의 슬리브 규칙 변경, `portfolio.v1.json` 반영
- force push, 푸시된 히스토리 재작성, 데이터 삭제, 남의 PR 병합
- 결과를 본 뒤 문턱·창·비용을 바꾸거나 같은 표본을 재판정하는 것 (닫힌 연구 80여 건 포함)
- 새 외부 데이터 소스 통합이나 대량 수집(DART·KIS 한도 소진). 무료 공개 자료의 소규모 수집은 이미 쓰던 소스에 한해 허용.
- 대량 토큰 서브에이전트 위임은 큐에 "위임 허용"이라고 적힌 항목만.

판단이 갈리면 **하지 않는 쪽**이다. 건너뛴 이유가 아침 보고의 가장 값진 줄이다.

## 5. 끝낼 때 (큐가 비었거나 한도·막힘으로 멈출 때)

1. 큐의 미완료 항목에 상태·이유를 확정한다.
2. `session-wrapup` 절차로 `docs/control/세션인수인계-YYYY-MM-DD[-b].md` 를 쓴다(0. 한 장 요약 · 항목별 결과 표 · 커밋 · 다음에 볼 것 · 함정). 연구면 findings 경로와 "신호/경제성" 한 줄, 닫힌 길/남은 길.
3. CLAUDE.md 는 최신 인수인계 포인터 한 줄만 고친다.
4. 파일 명시 add → 커밋 → **push**. 내가 만든 브랜치의 PR 은 병합까지 한다(`feedback-merge-prs-without-asking`; 🔴 변경이 섞였으면 병합하지 않고 보고). 병합 뒤 `gh pr view` 로 상태를 본다.
5. 예약해 둔 재개 크론이 남아 있으면 `CronDelete` 로 지운다.
6. 아침 보고(한 장): 완료 항목과 판정 한 줄씩 · **건너뛴 항목과 이유** · 미확인 · 사용자 몫(🔴 GO 가 필요한 것) · 재개가 끊겼는지. 점수나 매매에 반영된 것은 없다고 명시.

## 하지 말 것

- 밤새 사용자에게 질문하기(버튼 포함). 결과를 과장하기 — 통과가 아니라 "기록 전용"이면 그렇게 쓴다.
- 한도를 끝까지 태우고 인수인계 없이 끊기기. 90% 에서 마감 쪽으로 돈다.
