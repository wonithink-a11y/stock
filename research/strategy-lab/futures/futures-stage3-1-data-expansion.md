# KOSPI200 선물 과거 데이터 확장 가능성 조사 — Stage 3-1 (2026-09-13)

- 작성: OpenCode 실행 세션 (AGENTS.md §2 · §4 — 관측치 문서, 채택 판단은 Claude·사용자)
- 목적: 2018~2024 코스피200 선물 데이터를 **현재의 무료 경로**로 확보할 수 있는지 실측으로 판정.

  그 샘플을 7년으로 늘릴 수 있는지가 이 조사의 질문이다.
- 금지: 백테스트·대량 수집·production 코드 변경·데이터 삭제·commit/push — 전부 미실행.
  호출은 프로브용 소규모(날짜당 1콜)만 했다.

## 1. 실측 방법

기존 수집기 `build_futures_minute_panel.py` 를 모듈로 import 해 재사용했다.
프로브는 전부 Temp 디렉터리에 두고 저장소에 남기지 않았다.

```
KRX Open API drv/fut_bydd_trd?basDd=YYYYMMDD   (AUTH_KEY, 무료·로그인 불필요)
  -> 응답 OutBlock_1 = 그날 상장된 전 계약의 일별 정보
  -> pick_front = 코스피200 F / (주간) / max(ACC_TRDVOL)
  -> (분봉 테스트) krx_to_kis_code(ISU_CD) -> KIS FHKIF03020200 30초봉
```

- 표본 날짜: 2018~2024 연도별·분기별 60개 이상 + 경계·휴장일 세트 (총 ~90콜 내외)
- 분봉 긍정통제: 2026-05-04 · 2026-01-05 · 2025-09-16 · 2025-09-12 (전부 821봉 정상)
- 분봉 부정통제: 2025-09-01 · 2024-09-02 · 2018-01-02 · 2018-12-28 (전부 0봉)

## 2. KRX Open API 일별매매정보 — 전 계약 일봉

### 2.1 응답 구조 (한 콜에 그날 전 계약)

2026-08-26: 385행. 2018-01-02: 353행 · 2018-12-28: 360행 · 2024-12-30: 306행.
코스피200은 분기물 4개(3·6·9·12월)가 상장돼 있어 주간 7계약 + 야간 7계약 꼴.
(그날 상장돼 있는 분기물은 보통 7개 — 분기물 4 + 거래쌍? 이 아니라 근월~+7분기까지 표기상
13행이 되는 날도 있다. 계약 선택은 거래량 최대만 보면 되므로 계약 수 변동은 무해.)

핵심 필드 (실측 샘플로 확인):

```
BAS_DD, PROD_NM, MKT_NM, ISU_CD, ISU_NM
TDD_OPNPRC / TDD_HGPRC / TDD_LWPRC / TDD_CLSPRC   (시가/고가/저가/종가)
CMPPREVDD_PRC  (전일대비)
SPOT_PRC  (현물지수 가격) · SETL_PRC  (정산가 — 장 종료분)
ACC_TRDVOL / ACC_TRDVAL / ACC_OPNINT_QTY  (거래량/거래대금/미결제약정)
```

예) 2018-01-02 근월 `101N3000` 코스피200 F 201803(주간): O 326.60 H 327.50 L 325.45
C 327.00 · spot 326.00 · OI 254,524. 2020-03-19(COVID 급락) 근월 `101Q6000`: O 218.00
H 220.35 L 194.70 C 197.50 · spot 199.28 · OI 353,683.

### 2.2 계약코드 체계 변화 (실측)

```
101L3000 (2016-03) ... 101Q6000 (2020-06) 101R3000 (2021-03) ... 101W3000 (2025-03)
101W9000 (2025-09)  A0169000 (2026-09)   ← 2026년물부터 접두 101이 A016으로 변경
```

## 3. 1분봉(30초봉) — 2018~2024 확보 불가 (결정적 제약)

KIS 분봉 API `FHKIF03020200` / `FID_HOUR_CLS_CODE=30` 은 **보존창이 오늘부터
약 1년 롤링**이며 매일 앞이 잘린다. 실측(2026-09-13 기준):

| 요청일 | 근월 코드 | 30초봉 봉수 |
|---|---|---|
| 2026-05-04 | A0166000(202606) | 821 |
| 2026-01-05 | A0163000(202603) | 821 |
| 2025-09-16 | 101WC000(202512) | 821 |
| 2025-09-12 | 101WC000(202512) | 821 |
| 2025-09-01 | 101W9000(202509) | **0** |
| 2024-09-02 | 101V9000(202409) | **0** |
| 2018-01-02 | 101N3000(201803) | **0** |
| 2018-12-28 | 101P3000(201903) | **0** |

즉 **2025-09-12(약 1년 전)까지는 있고 그보다 오래된 날짜는 전부 0행**. Phase 0
(2026-09-04)의 "2025-08-29 O / 2025-08-25 X" 와 일관된, 하루씩 앞이 잘리는 롤링 보존창이다.

**주의(자기 수정)**: 이전 탐색 단계(krx_probe5)에서 "2026-05-04 콜이 0행"이라 관측한 것은
**엔드포인트 실패가 아니라 잘못된 근월 코드**였다 — 2026-05-04의 실제 근월은 A0169000
(202609)이 아니라 A0166000(202606)이다. 같은 날짜를 올바른 근월로 다시 콜하자 821봉이
왔다. 결론은 안 바뀐다(2018~2024 0행 확정)지만, "컨트롤이 0이었다"는 이전 기록은 폐기한다.

**시사점**: 1H EMA50/200 룰을 2018~2024에 그대로 재검증하는 것은 **이 무료 경로로는 불가능**.
1H 봉 자체를 받을 수 없다.

## 4. 야간 거래의 존재 구조 (2018~2024 일봉 구성에 대한 전제)

코스피200 야간선물은 자취가 바뀌었다(실측 행 존재 유무 + 공개 기사 교차):

| 구간 | 야간 시장 | KRX Open API 야간행 | 실측 |
|---|---|---|---|
| 2016-07 ~ 2020-12 | CME 연계 | 있음 | 2016-07-01~2020-12-15 kospi_night=7 |
| 2021-01 ~ 2025-06-05 | **Eurex 연계** (KRX 밖) | **없음** | 2020-12-30~2025-06-05 야간행 0 |
| 2025-06-09 ~ | KRX 자체 | 있음 | 2025-06-10~ kospi_night=13 (10개 상품) |

경위: CME 연계 코스피200 야간선물은 **삼성전자 시총 비중 30% 초과**로 CFTC/SEC 공동관할에
걸려 2020-04-07 거래 중단, CME 연계 잔여 야간 전반도 2020-12-18 종료(공식 공시). 이후
2021-03-22부터 **Eurex 연계**로 부활했으나 이 거래는 KRX 데이터가 아니라서
`drv/fut_bydd_trd` 에 기록되지 않는다. 2025-06-09 KRX 자체 야간거래 개시로 다시 들어온다.

**결론**: 2018~2024 일봉을 쓸 때 야간장은
①2018~2020.12는 KRX API에 야간행이 존재하고, ②2021~2025.06.05는 애초에 KRX에 야간
거래가 없다(그 구간의 야간 데이터를 얻으려면 Eurex 데이터가 따로 필요 — 현재 방법으론 불가).
따라서 EMA50/200 도 일봉 재검증은 **주간 세션 기준**이 자연스럽다(기존 1H 전략도 주간 기반).

## 5. API 호출량·기간 제한

- **콜량**: `basDd` 1개당 1콜. 2018~2024 = 7년 × ~250 영업일 ≈ **1,750콜**.
  수집기 관례 throttle 0.5초로 ~15분. 데이터 당 크기 수십 KB밖에 안 된다.
- **공식 제한**: 무료. 서비스 신청 시 **이용기간 1M/3M/6M/12M 선택**(재신청 가능),
  인증키 등급별 제한(일일/분당)은 개발 명세서에 수치로 노출돼 있지 않다.
- **멱종 관측**: 이 저장소에서 KRX 대량 호출 시 "조용히 빈 응답"으로 막힌 전례가 있다
  (docs/control/세션인수인계-2026-09-07.md — shares-snapshot 쪽, 실효 ~250~270콜 실질 상한,
  누적 소진·시간 경과로 회복). 이번 조사는 프로브 ~90콜(연속, throttle 있음)에서 막힘 없음.
  **백필 실제 실행 전에 1,750콜 규모의 혹은 분산 실행을 검증해야 한다.**
- 데이터 시작: 공식 2010-01-04 (실측과 일치). 그 이전 날짜는 응답이 텅 빈다(2010-01-01·2009-12-29·2009년 표본 전부 0행).

## 6. 대안 경로 확인 (어느 것도 불가/불필요로 결론)

- **KIS 일봉 차트 TR `FHKIF03020100`**: 비-JSON 응답(라인 1 컬럼 1 파싱 실패) —
  TR id나 경로가 안 맞음. 아예 안 써도 된다: **KRX 일봉이 같거나 위 필드를 더 준다**.
- **KRX Open API 다른 파생 엔드포인트**: 선물 일별매매정보가 유일한 선물 일봉 소스
  (주식선물·주식옵션·옵션 일별은 코스피200 선물과 무관). 분봉 엔드포인트 없음.
- **유료/외부 분봉**: 이번 범위 밖(현재 방법 = 무료 경로 기준으로 판정, §목적).

## 7. 결론과 후속 권고

1. **판정 B**: 2018~2024 코스피200 선물은 일봉(주간)으로 전 영업일 확보 가능.
2. **1H EMA50/200 의 장기 재검증은 불가**(1H 봉 자체가 없음). 대신 **일봉 EMA50/200** 규칙의
   2010~2024(또는 2018~2024) 장기 검증은 새 수집 없이 기존 `drv/fut_bydd_trd` 경로로 가능하다 —
   단 파라미터(일봉 EMA50/200 ≈ 10개월/장기추세)는 1H 룰과 다른 의미다. 이건 별도의
   "일봉 변형 후 검증"으로 취급해야지 1H 룰의 OOS 확장으로 취급하면 안 된다.
3. 백필 실행 단계에서의 과제(미실행, 판단은 Claude·사용자): ①콜량 1,750콜의 멱종 확인·분산
   재시도 설계, ②야간 구간(2021~2025.06) 데이터 부재가 결론에 미치는 영향 문서화,
   ③저장 위치·스키마(일봉 패널은 `data/` 계층 밖 — research 격리 원칙 유지).
