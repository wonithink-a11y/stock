# 파이프라인 반증 깃발의 변별력 — forward 사전등록 (2026-11-16)

> **동결.** 이 커밋 뒤 갈래·기준선·지표·문턱·비용·판정 시점을 바꾸지 않는다. 판정 코드 `pipeline/judge.py` 는 판정 조건 전에는 건수만 출력한다.
> 설계 원문은 `docs/VALIDATION.md` §3 이고, **숫자가 다르면 이 문서가 정본**이다(§7 에 달라진 곳을 적었다).

## 0. 배경 (결과 아닌 것만)

- 2026-11-15 부터 `pipeline.yml` 이 평일 저녁에 점수 상위 후보 20개를 뽑고(규칙 CR-1.0), **후보에 처음 오른 종목**(사건)에 Gemini 가 논리·반증을 쓴다. 인용은 코드가 근거 묶음과 대조해 통과분만 남긴다.
- 반증은 깃발 하나(`none`·`caution`·`thesis-weak`)와 무효 조건을 낸다. **깃발은 후보를 빼거나 순위를 바꾸지 못한다**(주석). 그래서 모든 사건에 반증이 달리고, 여기서 묻는 것은 깃발의 변별력이다.
- 이 등록 시점에 관측된 것은 첫 실행(기준일 2026-11-13)의 **깃발 분포뿐**이다: 반증 19건 중 `caution` 1건. 사후 수익은 한 건도 없다(만기 전). 이 분포는 §5 의 표본 조건을 정하는 데만 썼다.
- 기대: **INCONCLUSIVE 또는 REJECT.** 이 저장소의 연구는 대부분 REJECT 이고, 같은 모델이 논리와 반증을 쓰면 의견이 닮는다. 깃발 비율이 5% 수준이면 판정 조건을 채우는 데 2년 넘게 걸릴 수 있다.

## 1. 자료와 사건

- 기록: `data/pipeline/events/`(AE-1.0, 추가 전용) · 진단 `data/pipeline/diagnostics/{날짜}.json` · 기준선 사실 `data/pipeline/baseline/{기준일}.json`(§3).
- **사건** = `events.episode_starts` 가 고른 후보: 직전 5회 실행(기준일)에 그 종목이 후보가 아니었던 날의 `CANDIDATE_SELECTED`. 같은 종목이 계속 상위에 있어도 한 건이다.
- **사후 수익** = 그 사건의 `OUTCOME_MEASURED` h20: 진입 = 후보 기록일 **다음 거래일 종가**, 청산 = 그로부터 20거래일 뒤 종가, `excess` = 종목 수익 − 같은 기간 KR 관심종목 동일가중 평균 수익(`KR_WATCHLIST_EW`). 수정주가.
- `status != ok`(거래량 0 = 정지, 시세 없음)인 사건은 평균에서 빼고 **건수를 결과에 적는다**. 0 으로 채우지 않는다.
- 한계(미리 적는다): 기준 수익은 판정 시점이 아니라 각 측정 시점의 관심종목 목록 평균이다. 관심종목에서 빠진 종목은 그 뒤 평균에 없다. 가격 파일로는 상장폐지를 정지·시세 없음과 가릴 수 없다.

## 2. 표본 — 어느 지시문·어느 날부터인가 (코드가 정한다)

지시문이 아직 운영 품질을 통과했는지 모르므로, 표본의 시작을 사람이 고르지 않고 **진단 파일에서 기계적으로** 정한다.

1. 갈래 = (`promptVersion`, `model`) 조합. 진단의 `agents.promptVersion`·`agents.model`.
2. 갈래의 **G0 창** = 그 갈래로 `agents` 가 실제로 돈(건너뛰지 않은) 실행일 가운데 **처음 20일**. 20일이 안 찼으면 미정.
3. G0 통과 = 그 20일 합계로 아래 **전부**:
   - 논리 인용 통과율 `Σ claimsKept / Σ claimsTotal` ≥ **0.80**
   - 기록률: 논리 `Σ thesis.written / Σ candidates` ≥ **0.85** 그리고 반증 `Σ rebuttal.written / Σ candidates` ≥ **0.85** (`candidates` = 그날 주석 대상 사건 수)
   - 코드가 점검할 수 있는 무효 조건 비율 `1 − Σ manual / Σ invalidations` ≥ **0.50**
   - 창의 첫날부터 끝날까지 후보를 못 낸 실행일(`candidates.staleScoreSkip`) ≤ **2일**
4. **판정 갈래** = G0 창이 가장 먼저 끝난 갈래 가운데 통과한 첫 갈래. 통과 못 한 갈래는 영영 판정 대상이 아니다(같은 버전으로 창을 다시 잡지 않는다 — 지시문을 고치면 버전이 오른다).
5. **표본 시작일** = 판정 갈래의 G0 창 마지막 날의 **다음 날**. 표본 = 후보 기록일이 그 날 이후인 사건.
6. 어떤 갈래도 G0 를 통과하지 못한 채 2027-11-16 이 지나면 **INCONCLUSIVE(운영 품질 미달)** 로 닫는다.

스키마 위반은 기록 자체가 거부되고 워크플로가 실패해 커밋되지 않으므로 별도 조건으로 두지 않는다.

## 3. 갈래 (결과 전에 고정)

| 갈래 | 정의 |
|---|---|
| ALL | 표본 사건 가운데 h20 `status == ok` |
| LLM-KEEP | 판정 갈래의 `REBUTTAL_WRITTEN.flag == "none"` |
| LLM-DROP | `caution` 또는 `thesis-weak` |
| 미기록 | 판정 갈래의 반증 기록이 없는 사건 — **어느 쪽에도 넣지 않고 건수만** |
| CODE-DROP | 기준선 깃발: 후보 기준일에 **종가 < 60일 평균 종가** 또는 **직전 20거래일 수익률이 그날 후보 20개 중 하위 30%**(낮은 쪽부터 순위 ÷ 후보 수 ≤ 0.30, 동률은 종목코드 순) |
| CODE-KEEP | 그 나머지 |
| 기준선 모름 | 기준선 사실이 없는 사건(일봉 61일 미만 등) — `D_code` 에서 빼고 건수만 |

- 기준선 사실(종가·60일 평균·20일 수익률·순위)은 **후보를 뽑는 날 그날의 후보 20개 전부에 대해** `data/pipeline/baseline/{기준일}.json` 에 적는다. 가격 파일이 250거래일만 갖고 있어 판정 때 다시 계산할 수 없기 때문이다. 한 번 쓴 파일은 덮어쓰지 않는다.
- 기준선의 뜻: "LLM 없이 가격만 봐도 뺄 수 있는 후보". LLM 깃발이 이것을 다시 말하는 것뿐이면 값이 없다.
- 무작위 두 갈래(반증 있음/없음)는 쓰지 않는다 — 반증이 후보를 바꾸지 않으므로 표본을 반으로 나눌 이유가 없다.

## 4. 지표·바닥선·판정

- `D_llm = mean(excess | LLM-KEEP) − mean(excess | LLM-DROP)` · `D_code = mean(excess | CODE-KEEP) − mean(excess | CODE-DROP)` (h20, 비율 단위).
- **주(週)** = 진입일의 ISO 연-주. 같은 주의 사건은 같은 장세를 탄다.
- 신뢰구간: 주 단위 군집 부트스트랩 **2,000회**(주를 복원추출, 난수 씨 20261116), 5·95 백분위. `D_llm − D_code` 는 같은 추출에서 함께 계산한다. 한쪽 갈래가 빈 추출은 버리고 버린 수를 적는다.
- 바닥선: LLM 깃발을 **주 안에서 섞는** 순열 **500회**(씨 20261116)의 `D` 95 백분위 = 문턱. 한 주에 사건이 하나뿐이면 그 주는 섞이지 않는다.
- '반도체 제외' 한 줄: 판정 시점 `docs/data/sector-strength.json` 의 분류가 '반도체'인 종목을 뺀 `D_llm`(진단 — 분류가 판정 시점 기준이라는 한계를 적는다).
- 시기 세 칸(2016~23 / 2024 / 2025~)은 채울 수 없다. 결과 표에 "2025~ 한 칸뿐 — 장세 특이일 수 있다"를 적는다.

| 판정 | 조건 |
|---|---|
| REJECT | `D_llm` ≤ 바닥선 문턱 (신호 없음) |
| INFORMATION | `D_llm` > 문턱이나, `D_llm − D_code` 의 90% 구간 하한 ≤ 0 (코드로 되는 일) 또는 `D_llm` < 0.00335 |
| ECONOMIC | `D_llm` > 문턱 ∧ `D_llm − D_code` 구간 하한 > 0 ∧ `D_llm` ≥ **0.00335**(왕복 비용 33.5bp — 깃발을 보고 종목을 바꾸는 데 드는 한 번의 비용보다 커야 한다) |
| ROBUST | ECONOMIC ∧ 진입일 중앙값으로 나눈 전반·후반 둘 다 `D_llm` > 0 ∧ 반도체 제외 `D_llm` > 0 |
| INCONCLUSIVE | §5 의 조건을 마감까지 못 채움, 또는 §2-6 |

결과 머리말에는 "신호: 있음/없음 · 경제성: 통과/미달"을 가른다. 표준 열: gross `D_llm`(구간) · 비용 문턱 대비 · 손익분기(= `D_llm` 자체).

## 5. 판정 시점 (1회)

- 조건 **전부**: 표본 시작일부터 **365일 경과** ∧ **LLM-DROP 사건 60건 이상**(h20 `ok`) ∧ **사건이 있는 주 40주 이상**.
- 표본 시작일부터 **1,095일**이 지나도 못 채우면 INCONCLUSIVE 로 닫는다.
- 그 전의 `python -m pipeline judge` 는 **거부하고 건수만** 낸다(갈래별 평균을 계산하지 않는다). 월간 점검에도 건수와 운영 지표만 올린다 — 중간 성과를 보지 않는다.
- 판정은 한 번이다. 판정 뒤 같은 표본을 다시 자르거나 문턱·창을 바꿔 다시 보지 않는다.

## 6. 판정 뒤

- REJECT · INFORMATION · INCONCLUSIVE → 반증 단계(Gemini 호출)를 끈다. 논리 단계를 읽을거리로 남길지는 사용자가 정한다.
- ECONOMIC 이상이어도 깃발을 후보 규칙·점수에 넣는 것은 별도 🔴(정책 버전 승격). 이 forward 하나로 운용 근거가 되지 않는다.
- 지시문·모델을 바꾸면 새 갈래다. 판정 갈래는 §2 가 정한 하나뿐이고, 여러 갈래 중 좋은 쪽을 고르는 판정은 하지 않는다. **판정 갈래가 정해진 뒤에는 판정 때까지 그 지시문 파일과 모델을 계속 돌린다**(중단하면 표본이 끊긴다 — 중단 사실과 기간을 결과에 적는다).
- 사후 가설(예: `thesis-weak` 만 따로, 특정 근거 종류만)은 기록 전용이고 새 사전등록으로만 다시 묻는다.

## 7. 설계 문서(VALIDATION §3)에서 달라진 것

| 설계 | 이 등록 | 이유 |
|---|---|---|
| 깃발 사건 100건 · 24개월 마감 | **60건 · 1,095일 마감** | 첫 실행의 깃발 비율이 19건 중 1건이었다. 사건이 한 해 수백 건이어도 깃발은 수십 건이라 100건은 4년 안에 차지 않는다. 사후 수익을 보기 전의 조정이다 |
| ECONOMIC = KEEP 순초과수익 > ALL | `D_llm` ≥ 33.5bp | 원래 조건은 `D_llm > 0` 과 같은 말이었다(비용이 양쪽에서 상쇄). 실제 비용 문턱으로 바꿨다 |
| G0 는 사람이 20거래일 뒤 판정 | 코드가 진단 파일로 판정, 표본 시작일도 코드가 정함 | 등록을 G0 보다 먼저 하므로 사람이 고를 자리를 없앴다 |
| 무효 조건 닿음 뒤 20일(부 질문) | **등록하지 않는다** | 닿은 날 기준 사후 수익을 재는 기록이 아직 없다. 필요하면 새 사전등록으로 |
| 기준 수익 = 소속 지수 | KR 관심종목 동일가중 | 지수 일별 시세가 저장소에 없다 |
