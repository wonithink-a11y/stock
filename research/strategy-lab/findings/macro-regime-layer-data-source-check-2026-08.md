## 1. 미국 금리 — 레벨(level) 두 개 확정

기존 `fetch_macro.py`는 `T10Y2Y`(10Y-2Y 스프레드)만 쓴다 — **레벨 자체는 지금 프로젝트
어디에도 없다.** 라이브 조회로 확인:

| series | 설명 | 빈도 | 확인된 범위 | 최신값(2026-08-20) |
|---|---|---|---|---|
| **`DFF`** | Federal Funds Effective Rate | 일별 | 1954-07-01~2026-08-20 | 3.63 |
| **`DGS10`** | 10-Year Treasury Constant Maturity | 일별 | 1962-01-02~2026-08-20 | 4.69 |

둘 다 기존 `fred()` 함수를 그대로 호출하면 된다(신규 코드 불요) — USD/KRW·VIX와 완전히
같은 패턴.

## 3. 한국 시장(KOSPI) — 기존 함수 재사용, count만 확장

`scripts/collect.js:475 fetchKospiClose()`가 이미 `fetchDailyCandlesKR('KOSPI', 5)`
(네이버 차트 API, `fchart.stock.naver.com/sise.nhn`)로 KOSPI를 받고 있으나 **count=5(최근
5일 스냅샷)뿐**이라 이력 축적이 없다 — USD/KRW가 기존에 겪던 것과 같은 "롤링 스냅샷,
백필 아님" 문제.

라이브로 `count=3000`을 직접 넣어 확인: **2014-05-30~2026-08-21 전체 반환** — 프로젝트의
기존 데이터 시작점(2014-05-13)과 거의 일치한다. 신규 소스 불요, count 파라미터 확장만
필요.

## 4. 한국 금리 — 있으나 월간뿐

| series | 설명 | 빈도 | 확인된 범위 | 비고 |
|---|---|---|---|---|
| `IRSTCI01KRM156N` | 초단기(익일물) 금리, OECD 경유 | 월간 | 1991-01~2026-06 | 최신(2개월 지연) |
| `IR3TIB01KRM156N` | 3개월 은행간 금리 | 월간 | 1991-01~2026-06 | 최신, 값 계속 변동(활성) |
| `INTDSRKRM193N` | 재할인율 | 월간 | 1964-01~2026-05 | **값이 최근 여러 달 1.000000000로 고정 — 사실상 비활성 계열로 판단, 채택 안 함** |

두 후보(`IRSTCI01KRM156N`·`IR3TIB01KRM156N`)는 최신이지만 **월간**이다 — 기존 VIX·USD/KRW·
KOSPI가 전부 일별인 것과 결이 다르다. 월간 값으로 "20일 추세"류 feature를 만들 수 없어,
regime 축에 넣으려면 "레벨·전월 대비 변화" 정도로 설계를 다르게 잡아야 한다(별도 검토
필요 — 이 문서는 소스 확정까지만).

## 5. 한국 물가·경기 — FRED로 못 채운다 (실측)

아래 네 계열을 2026-08-23에 라이브로 직접 조회했다. **전부 특정 시점 이후 완전히
갱신이 멈춰 있다** — 최신값이 아니라 2~3년 전 값이 그대로 마지막 줄이다:

| series | 설명 | 마지막 관측치 |
|---|---|---|
| `KORCPIALLMINMEI` | 한국 CPI (OECD MEI) | **2023-11-01** |
| `BSCICP03KRM665S` | 기업경기실사지수 (OECD) | **2023-12-01** |
| `KORLOLITONOSTSAM` | 경기선행지수 (CLI, OECD) | **2024-01-01** |
| `KORPROINDMISMEI` | 산업생산지수 (OECD MEI) | **2024-03-01** |

원인은 조사 범위 밖이지만(OECD 쪽 시리즈ID 개편이나 한국 보고 방식 변경 등으로 추정),
**결과는 명확하다 — FRED가 제공하는 한국 물가·경기 계열은 지금 살아있지 않다.**
이걸 모르고 그대로 쓰면 "매일 갱신되는 것처럼 보이지만 실제로는 2년 넘게 고정된 값"이
regime 판정에 조용히 섞여 들어간다(교훈57 "모르는 것은 0이 아니다"와 같은 함정의 변형 —
여기서는 "낡은 값을 최신으로 오인"하는 함정).

**대안은 한국은행 ECOS API 또는 통계청 KOSIS API** — 둘 다 무료지만 **API 키 발급이
필요**하다(FRED는 키 불요였다는 점과 다름). 이 확인·연동은 이번 조사 범위를 넘는
별도 결정이다.

## 7. 한국은행 ECOS API — 사용자 키 발급 후 라이브 확인 (2026-08-23 추가)

사용자가 ECOS API 키를 발급받아 `.env`의 `ECOS_API_KEY`에 등록(커밋 안 함, `.gitignore`
확인됨). 엔드포인트: `https://ecos.bok.or.kr/api/StatisticSearch/{키}/json/kr/{시작행}/
{끝행}/{통계표코드}/{주기}/{시작일}/{종료일}/{항목코드...}` — 키 필요, 무료.

라이브 조회로 **금리·신용·물가·경기 네 축을 전부 확인**했다:

| 축 | 통계표코드/항목코드 | 주기 | 최신 확인치 |
|---|---|---|---|
| 한국 기준금리 | `722Y001`/`0101000` | 월별 | 2026-07 (2.75%) |
| 한국 콜금리(정책금리 근접 일별 대용) | `817Y002`/`010101000` | **일별** | 국고채·회사채와 같은 테이블에서 확인됨 |
| 한국 국고채(3년) | `817Y002`/`010200000` | **일별** | 2026-08-21 (3.854%), 2016-01 이력 존재 확인 |
| 한국 신용스프레드 | `817Y002`/`010300000`(회사채 AA-3년) − `010200000`(국고채3년) | **일별** | 2026-08-21 기준 약 0.69%p (4.542−3.854) |
| 한국 CPI(총지수) | `901Y009`/`0` | 월별 | **2026-07**(118.03→119.77, FRED보다 2년 이상 신선) |
| 한국 경기선행지수순환변동치 | `901Y067`/`I16E` | 월별 | **2026-06**(105.7) |
| 한국 경기동행지수순환변동치 | `901Y067`/`I16D` | 월별 | 확인됨(정상 갱신 중) |

**FRED 대비 결정적 차이**: FRED의 Korea 물가·경기 계열(§5)은 2023-11~2024-03에서
멈춰 있었지만, **같은 지표를 ECOS 원천으로 받으면 2026-07/06까지 정상 갱신 중이다** —
즉 문제는 "한국이 그 지표를 안 낸다"가 아니라 "FRED가 그 시점 이후 갱신을 안 받아온다"
였다. 원천(ECOS)으로 직접 가면 최신성 문제 자체가 사라진다.

**신용(credit) 축은 이 조사로 새로 추가됐다** — 애초 §0 요약엔 없었으나, 시장금리
테이블(`817Y002`)에 국고채·회사채(AA-/BBB-)가 같이 있어 스프레드 계산이 바로 된다.
이력도 일별로 2016년 이전부터 존재함을 확인(§7 표).

**보류 판단**: 사용자가 함께 보낸 ECOS "API개발명세서" xls 6종(서비스통계목록·
통계메타DB·100대·통계조회조건·통계세부항목목록·통계용어사전)은 **이번 조사에는
쓰지 않았다** — 라이브 조회(`StatisticItemList`)로 필요한 코드를 직접 찾는 쪽이 더
빨랐다. 이후 추가 지표가 필요해지면 이 xls들이 코드 검색의 1차 참고 자료가 된다.

## 8. 종합 — 이 조사가 하지 않은 것

- 실제 백필 스크립트 작성·실행 없음
- regime feature 정의(threshold·z-score 창 등) 설계 없음 — 이건 소스 확정 다음 단계
- ECOS 일별(콜금리·국고채·회사채)과 월별(CPI·경기종합지수) 두 빈도를 regime 축에
  어떻게 섞을지 설계하지 않음 — VIX·USD/KRW·KOSPI(전부 일별)와 CPI·경기(월별)가
  같은 파이프라인에 들어가려면 리샘플링 규칙이 필요하다(다음 단계 과제)
- 2016년 이전(2014-05~2015) 구간의 ECOS 커버리지는 표본 확인만 했다(2016-01
  10일 창) — 백필 실행 시 전체 구간 커버리지 재확인 필요
