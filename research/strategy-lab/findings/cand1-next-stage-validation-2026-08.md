## 6. Strategy Lab 엔진 연결 전제조건

`strategies/base.py` 계약과 기존 전략(`trend_breakout_v1/rule.py`) 실측 확인 결과:

| 항목 | 확인 내용 | CAND1과의 정합성 |
|---|---|---|
| `bars` 스키마 | `[open, high, low, close, volume]`, **일봉**만, date 인덱스 | CAND1의 `r_1400_close`(14:00가 필요)는 표준 일봉 컬럼이 아님 |
| feature 확장 | `compute_features()`가 bars에 파생 컬럼(ATR·Donchian 등)을 자유롭게 추가 가능 | **해결 가능** — `engine/data/minuteProvider.py`(이미 존재, 미커밋)로 종목·일자별 14:00가를 뽑아 `close1400` 같은 파생 컬럼으로 주입하면 나머지는 표준 계약과 동일하게 짤 수 있다 |
| 진입 시점 | `Signal(symbol, signal_date, direction)` → 익일 시가 진입(관례) | CAND1의 "익일 시가 진입"과 **정합** |
| 청산 시점 | `RiskSpec(stop_distance, reward_risk, max_holding_sessions)` — **전부 일봉 단위**(고저·종가 기준 stop/target, 세션수 단위 보유기간) | CAND1의 검증된 청산(**익일 09:35, 장중 특정 시각**)은 이 모델로 표현이 안 된다 — **구조적 공백**. PBR이 겪었던 "횡단면 랭킹 미지원"과 같은 급의 문제, 다만 이번엔 "일중 특정 시각 청산 미지원" |

**결론**: 신호 계산(14:00가)은 MinuteProvider로 해결 가능하지만, **09:35 청산은 현재 엔진 계약 밖이다.** 옵션은 두 가지뿐이다(둘 다 이번 문서 범위 밖 — 실행하지 않았다):

1. **근사**: 첫 SMOKE는 청산을 익일 09:35 대신 **익일 종가**로 근사해 돌린다. 검증된 결과(net 21.65bp)와 다른 숫자가 나올 게 확실하므로 "이식 검증"이 아니라 "다른 전략의 SMOKE"로 취급해야 한다 — 사용자 승인 후 별도 재검증 필요.
2. **엔진 확장**: PBR 때처럼 09:35 청산을 지원하도록 실행 계약을 확장한다. 모든 전략이 공유하는 핵심 루프를 건드리므로 범위가 크다(PBR 때도 이 이유로 중단됐다) — 사용자 승인 필요.

## 7. SMOKE 계획 (제안, 미실행)

```
1단계  MinuteProvider로 종목×일자별 c1400(14:00가) 파생 테이블 생성
       — 신규 스크립트, engine/ 무변경, research 전용 캐시에 저장
2단계  strategies/cand1_pmcrash_v1/ 신설(pbr_value_v1과 같은 패턴 —
       엔진 무변경으로 흡수 가능한지 먼저 시도)
         policy.json: thr=0.02·vthr=1.5·mthr=None·cost=20bp 그대로 박제
         rule.py: r_1400_close·rel_v_w1400_1500 조건 그대로 이식
3단계  청산 방식 결정(§6의 옵션 1 vs 2) — **여기서 사용자 승인 필요**,
       이번 문서는 결정하지 않는다
4단계  run_smoke() 1회 실행 — 계약 위반(거래일수·PIT·중복) 0건 확인
5단계  SMOKE 결과를 이번 연구 결과(21.65bp)와 대조 — 옵션 1(근사)이면
       불일치가 예상되고, 왜 다른지 설명 가능해야 통과
6단계  통과하면 그제서야 "production 후보" 승격 여부를 사용자가 판단
```

**왜 여기서 멈추는가**: 4~6단계는 전부 실행(코드 신설·엔진 접점)이라 사전 승인
대상이다(안전 규칙). 이번 문서는 "무엇이 필요한가"까지만 확정했다.
