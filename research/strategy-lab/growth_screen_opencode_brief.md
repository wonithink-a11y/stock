## 확정된 결정 (임의 변경 금지)

1. **음수 처리 정책**: growth rate 계산 시 base(t-3) <= 0이면 그 지표는
   "계산불가"로 처리하고 순위(TOP20) 대상에서 완전히 제외한다(0등도
   최하위도 아니라 아예 없음). 이건 절대 규칙이다.
2. **이상치 필터**: 매출액(revenue) 또는 영업이익(opProfit)의 절대값이
   4×10^14원(400조원, 삼성전자 실측 매출보다 넉넉한 상한)을 넘는 레코드는
   백테스트에서 제외하고 별도 로그에 남긴다. Claude가 소규모 슬라이스에서
   실제로 이 상한을 넘는 레코드 2건(032680/FY2022, 039230/FY2021)을
   발견했다 — A3 원본 파싱 버그로 보이며, 이런 레코드가 걸러지지 않으면
   "TOP20 by % growth"가 이 오염된 레코드 하나에 완전히 지배된다.

## 필요 데이터 위치 (전부 로컬, 새 API 호출 불필요)

- **재무 원자재**: `data/backfill/fundamentals/a3/{2015~2024}.jsonl.gz`
  (JSONL gzip, 연도별 파일, 종목당 연도당 1행). 필드: `ticker`, `corp`,
  `fiscalYear`, `availableFrom`(YYYY-MM-DD, PIT 공시일 - 이거보다 미래
  데이터는 그 asOf 시점에 절대 쓰면 안 됨), `revenue`, `opProfit`,
  `liabilities`, `equity`(전부 원 단위 정수, null 가능). **assets 필드는
  없다 — `liabilities + equity`로 직접 유도**(회계항등식, null 방어 필요).
  부채비율 = `liabilities / equity * 100`(equity<=0이면 계산불가 -> 부채
  필터 적용 시 자동 탈락 처리).
- **현재 상장 유니버스**: `data/backfill/universe/a1a/current.jsonl`
  (JSONL, 필드: `ticker`, `name`, `market`, `corp`, `listedAt`(YYYY-MM-DD),
  `sector`).
- **상장폐지 유니버스**: `data/backfill/universe/a1b/delisted.jsonl`
  (필드: `ticker`, `corp`, `corpName`, `exitReason`, `exitAt`(대부분
  null), `dartModifyDate`, `source`). **exitAt이 대부분 null이라 정확한
  폐지일을 모르는 종목이 많다** — 이 경우 그 종목을 해당 asOf 유니버스에
  포함시킬지 모호하다. 판단하지 말고 아래 "데이터 계약 확인 필요" 항목에
  보고해라(사용자 스펙 §5·§13이 "모호하면 임의로 정하지 말고 보고"를
  명시했다).
- **가격 데이터(수익률 계산용)**: `data/backfill/price/a2a/{연도}.jsonl.gz`
  (상장 종목, 필드 `ticker`,`date`,`open`,`high`,`low`,`close`,`volume`)
  + `data/backfill/price/a2b/{연도}.jsonl.gz`(상장폐지 종목, 같은 스키마 -
  존재하면 사용, 커버리지가 불완전할 수 있음 - 결측 종목/기간은 숨기지
  말고 집계해서 보고).

목적:

이미지에서 제시된 다음 성장주 스크리닝 규칙을 실제 PIT 금융 데이터로 백테스트한다.

조건:

1. 최근 3년 자산 증가율 TOP 20
2. 최근 3년 영업이익 증가율 TOP 20
3. 부채비율 120% 이하
4. 최근 3년 매출액 증가율 TOP 20

이번 연구에서는 조건 3번을 포함한 버전과 제거한 버전을 반드시 별도로 비교한다.

핵심 질문:

"자산·매출·영업이익이 모두 빠르게 증가하는 기업을 TOP20 교집합으로 선별했을 때 실제 초과수익이 존재하는가?"
그리고
"부채비율 120% 제한이 성과를 개선하는가, 아니면 오히려 좋은 기업을 제거하는가?"

==================================================
1. 전략 정의
==================================================

전략 A — Debt Filter 포함

A1. 각 리밸런싱 시점에서 최근 3년 자산 증가율을 계산한다.
A2. 전체 투자 가능 유니버스에서 TOP 20을 선정한다.

B1. 최근 3년 매출액 증가율 TOP 20을 선정한다.

C1. 최근 3년 영업이익 증가율 TOP 20을 선정한다.

D1. A ∩ B ∩ C 를 구한다.

E1. 그 중 부채비율 <= 120%인 기업만 최종 선정한다.

전략 B — Debt Filter 제거

A/B/C는 동일하다.

최종:
A ∩ B ∩ C

단, 부채비율 조건은 적용하지 않는다.

==================================================
2. TOP20의 정확한 정의
==================================================

중요:

"TOP20"은 매 리밸런싱 시점의 당시 투자 가능 유니버스 안에서 계산한다.

예:

as_of = 2021-06-25

당시 투자 가능한 종목만 사용한다.

각 종목에 대해:

asset_growth_3y
= assets(t) / assets(t-3) - 1

revenue_growth_3y
= revenue(t) / revenue(t-3) - 1

operating_profit_growth_3y
= operating_profit(t) / operating_profit(t-3) - 1

을 계산한다.

그 후 각각 내림차순 정렬하여 TOP20을 만든다.

절대 현재 시점의 재무정보를 과거 시점에 사용하는 일이 없어야 한다.

==================================================
3. PIT / Look-ahead bias
==================================================

가장 중요한 검증 항목이다.

재무제표의 fiscal year 자체가 아니라
"시장 참가자가 실제로 알 수 있었던 시점"을 기준으로 사용한다.

즉:

availableFrom <= as_of

인 데이터만 사용한다.

예를 들어 2020 사업연도 재무제표가 2021년에 공시됐다면
2020년 데이터라는 이유만으로 2020년 리밸런싱에 사용하면 안 된다.

반드시 실제 공시 가능 시점을 기준으로 한다.

PIT violation이 발견되면 결과를 PASS로 처리하지 말고 즉시 보고한다.

==================================================
4. Universe
==================================================

가능하면 현재 Research Dataset에서 사용하는 historical universe를 그대로 사용한다.

Survivorship bias를 피해야 한다.

현재 살아 있는 기업만 사용하여 과거 TOP20을 계산하면 안 된다.

상장폐지 기업, 신규상장 기업 등 historical universe 정보가 존재하면
각 as_of 시점의 투자 가능 여부를 적용한다.

Universe 정책을 임의로 변경하지 않는다.

==================================================
5. 리밸런싱
==================================================

우선 연 1회 리밸런싱을 기본 실험으로 한다.

기본 기준일:

각 연도 말 재무정보가 실제 시장에 공개된 이후 처음 가능한 리밸런싱 시점.

단, 현재 Dataset의 PIT 구조상 명확한 리밸런싱 기준일을 정의하기 어렵다면
임의로 정하지 말고 현재 데이터 계약을 먼저 확인하여 보고한다.

가능하면 추가로:

- 연 1회
- 분기 1회

민감도 테스트도 수행한다.

==================================================
6. 포트폴리오 구성
==================================================

중요:

TOP20 중 다시 3개를 임의 선정하지 않는다.

기본 전략은 최종 교집합에 들어온 모든 종목을 보유한다.

예:

자산 TOP20 = 20개
매출 TOP20 = 20개
영업이익 TOP20 = 20개

교집합 = 7개

그러면 7개 모두 보유한다.

교집합 = 15개

그러면 15개 모두 보유한다.

교집합 = 3개

그러면 3개 모두 보유한다.

교집합 = 0개

그러면 해당 리밸런싱 기간은 현금 100%로 처리한다.

포트폴리오 비중은 기본적으로 Equal Weight를 사용한다.

교집합의 개수가 매번 달라지는 것은 정상적인 결과로 취급한다.

13. 데이터 품질 검증
==================================================

백테스트 전에 반드시 확인:

- PIT violation = 0
- survivorship bias 여부
- duplicate
- missing financial data
- negative/zero denominator 문제
- 자산/매출/영업이익 값의 이상치
- 영업이익 적자 → 흑자 전환 종목 처리

특히:

또는

revenue(t-3) <= 0
assets(t-3) <= 0

인 경우 단순히 비정상적인 퍼센트 증가율을 만들어 TOP20에 넣지 않는다.

10. Debt Filter 효과가 실제로 존재하는가?
