# BF-1.1 — GATE-EP-1 재정의 검토: 가격 데이터 존재 여부 기준 비교 (2026-08-24)

```
★ 이것은 결정이 아니다. config/policies/exit.v1.json도
  docs/BF-1.1-백필계약.md §6.4의 GATE-EP-1 정의도 고치지 않았다 — 임계·
  분모 변경은 계약 변경(🔴)이고 사용자 결정 사안이다. 이 문서는 그 결정에
  필요한 실측 비교표만 제공한다.
```

## 배경

Tier A(179건)+Tier B(69건) 완료 후 A1b 1,223종목 대비 UNKNOWN이 975건
(79.7%)으로 GATE-EP-1 임계(5%)를 크게 초과한다는 게 확인됐다
([BF-1.1-exitReason-TierB-결과.md](BF-1.1-exitReason-TierB-결과.md)).
이 975건 중 715건은 A2b가 `exitAtConfirmed` 자체를 못 만든 종목인데, 그
715건의 구성(A2b `_diagnostics.json` 실측)을 보면 591건(83%)은 수집 구간
(2014-01-02~2026-08-14) 전체에서 KIS/KRX가 가격을 단 한 행도 반환하지
않은 종목이다 — Tier C를 아무리 설계해도 앵커 자체가 없어 분류가 원리적
으로 불가능한 구조적 한계다.

이 발견을 근거로 "GATE-EP-1의 분모(A1b 전체)가 가격 데이터 자체가 없는
종목까지 포함해서 재는 게 맞는가"라는 질문이 나왔다. 이 문서는 **정책을
바꾸지 않고**, 분모를 "가격 흔적이 있는 A1b"로 좁혔을 때 실제 수치가
어떻게 달라지는지만 계산한다.

## 방법 — "가격 흔적" 정의

A2b `_diagnostics.json`의 네 배타적 버킷(합 1,223 = `candidateCount`와
정확히 일치, 실측 확인)을 그대로 썼다:

```
tickersWithData(508)     kept — 품질 게이트 통과, exitAtConfirmed 있음
qualityExcluded(122)     raw 가격은 수집됐으나 품질 위반으로 통째 제외
                         (UNADJUSTED_CORPORATE_ACTION 107 · TRANSIENT_PRICE_SPIKE 15)
emptyCount(591)          수집 구간 전체에서 응답 자체가 빈 것
exceptionCount(2)        네트워크 예외 — 있었는지 없었는지 확인 안 됨
```

**"가격 흔적이 있음" = tickersWithData(508) ∪ qualityExcluded(122) =
630종목.** qualityExcluded는 raw 가격이 실제로 수집됐다는 사실 자체가
"흔적"이다 — 품질 게이트가 그 값을 신뢰 못 해 버린 것이지 데이터가
없었던 게 아니다(단, 그 raw 행 자체는 로컬에 안 남아 있다 — 재수집 없이는
이 122건을 실제로 분류할 수 없다, 아래 "한계" 참고).

exceptionCount(2)는 어느 쪽인지 확인할 수 없어 두 집단 모두에서 제외했다
— 추측하지 않는다(교훈57).

|---|---|---|
| 분모 | 1,223 | 630 |
| Tier A+B 분류 | 248 | 248 |
| UNKNOWN | 975 | 382 |
| UNKNOWN 비율 | **79.72%** | **60.63%** |
| GATE-EP-1 임계(5%) 대비 | 15.9배 초과 | 12.1배 초과 |
| 5% 통과에 필요한 UNKNOWN 상한 | 61건 | 31건 |
| 추가로 분류해야 할 건수 | 914건 | 351건 |

**재정의해도 여전히 임계를 12배 초과한다** — 분모를 바꾸는 것만으로
GATE-EP-1이 통과되지는 않는다. 다만 문제의 성격은 바뀐다 — "구조적으로
불가능"(591건 하나만으로 이미 5% 상한을 9.7배 초과하는 상태)에서 "매우
어렵지만 이론적으로 남은 범위 안"(추가 351건, 즉 남은 382건의 91.9%를
분류해야 함)으로 옮겨간다.

| 하위집단 | 건수 | Tier A+B 분류 | UNKNOWN | 비고 |
|---|---|---|---|---|
| exitAtConfirmed 있음(508) | 508 | 248 (48.8%) | 260 (51.2%) | Tier A/B가 실제로 적용된 집단 |
| qualityExcluded(122) | 122 | 0 (0%) | 122 (100%) | Tier A/B 대상에서 원천 제외 — exitAtConfirmed가 없어 이번 세션 파이프라인이 아예 보지 않음 |

122건은 "가격 흔적은 있지만 아직 아무것도 시도 안 한" 순수 미착수
상태다. 재수집(실행, 별도 승인 필요)이 선행돼야 이 122건도 Tier A/B
파이프라인에 들어갈 수 있다.

## 한계 — 이 비교표가 답하지 않는 것

- **qualityExcluded 122건의 raw 가격 행은 로컬에 없다.** 연도별
  `data/backfill/price/a2b/{year}.jsonl.gz`는 이미 품질 필터링 후 값만
  저장하고, `price-quality-excluded.jsonl.gz`는 위반 요약(위반 날짜
  샘플)만 갖고 있다 — 실측으로 확인(122건 전량 raw 행 0건). 이 122건을
  실제로 분류하려면 재수집이 필요하다(로컬 진단만으로는 못 늘린다).
- **GATE-EP-2**(Q5/Q1 UNKNOWN 제외율 비 ≥3.0)는 이번 비교에서 다루지
  않았다 — A5 채점(분위 배정)이 아직 안 돌아서 잴 수 있는 데이터가
  없다.
- 630/1,223(가격 흔적 있음 비율)을 GATE-EP-1의 "타당한 새 분모"로 쓸지는
  이 문서가 판단하지 않는다 — 그건 정책 판단이고 사용자 결정 사안이다.
  이 문서는 "이 정의를 쓰면 숫자가 이렇게 된다"는 계산만 제공한다.
