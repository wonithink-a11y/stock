## 한 줄 답

63건 중 **49건(77.8%)**이 가설대로였다(재무=원본, EPS=더 나중 정정본). 그러나
**12건(19.0%)은 방향이 반대**였고(재무 쪽이 오히려 정정본, EPS 쪽이 원본), **2건은
원본-정정 단순 쌍이 아닌 다단계 정정**이었다. 조회 실패 0건.

## 방법

45건(옛 수치, A3b 51% 시점)이 아니라 A3b finalize 후 실측된 **63건** 전체를 대상으로,
각 행의 두 접수번호(`a3_rcept`, `a3b_rcept`)를 DART 공시뷰어
(`https://dart.fss.or.kr/dsaf001/main.do?rcpNo=...`)에서 직접 조회했다. 63건×2 = 126회
전량 조회, 실패 0건.

## 우리 가설에 대한 판정

**부분 확인, 부분 반증.** "재무 수집기(`rows[0]`)=원본, EPS 수집기(`max(rcept_no)`)=정정본"
이라는 단일 방향 가설은 다수(78%)에서 맞지만, **19%(12건)는 정반대**다 — 재무 쪽이
나중에 접수된 정정본을, EPS 쪽이 오히려 원본을 가리켰다. 가설을 "둘 중 하나는 항상
정정본이고 나머지가 원본"으로 일반화할 수는 있으나, "EPS 쪽이 항상 정정본"이라는
방향성은 성립하지 않는다.

### B(방향 반대) 12건의 구조적 패턴

```
사업연도 분포   FY2019 11건 · FY2020 1건(00155586) — 사실상 FY2019에 집중
목록           00111218(044180) · 00112165(092200) · 00158219(033170) ·
               00267854(014100) · 00318662(056730) · 00349732(052400) ·
               00554352(175250) · 00632793(110020) · 00753643(109070) ·
               00781202(900100, KDR 외국법인) · 01063884(215090) · 00155586(024850)
```

12건 중 11건이 FY2019 하나에 몰려 있다. **원인은 조사 범위 밖이다** — 왜 그 해만
`rows[0]`(재무)이 정정본을, `max(rcept_no)`(EPS)가 원본을 가리켰는지는 수집기 쪽
동작을 다시 봐야 하는 별도 질문이고, 이 조사는 "무엇이 어떤 공시인가"만 확인했다.

### D(다단계 정정) 2건

- **00366793(080440, SJK)** — 두 rcept 다 정정본이다(1차 정정 vs 2차 정정). 진짜
  원본은 어느 쪽도 아니다.
- **00442455(082660, 코스나인, FY2024)** — 두 rcept가 같은 사업연도를 가리키는지조차
  불확실하다. a3측 접수일(2026-03-24)이 FY2024가 아니라 FY2025 사업보고서 시점으로
  보인다는 지적이 있었다 — **이건 공시 선택 문제가 아니라 A3/A3b 조인 자체(corp+FY
  매칭)의 별도 이상 신호일 수 있다.** 확인 필요, 미확정으로 남긴다.

## FY2025가 절반 가까이(28/63)인 이유

이번 조사에서 직접 답하지 못했다. FY2025 사례는 전부 A(정상 방향: 원본→정정)로
분류됐고, 정정까지의 간격이 짧다(대부분 2~4개월) — 최근 사업연도라 A3(2026-08 수집)
와 A3b(뒤이어 수집) 사이의 시점 차이 자체가 정정 발생 확률에 영향을 줬을 가능성이
있으나 **이건 추정이지 확인된 사실이 아니다.**

## Codex 재확인 (2026-08-12)

**독립 재확인 결과 — 일치.** Codex가 완전히 다른 방법(DART 웹페이지 열람이 아니라
`scripts/build-fundamentals-a3b.py`의 `build_record`/`pick_row` 코드를 읽고
A3·A3b의 `rceptNo` 앞 8자리(접수일자)를 직접 비교하는 방식, 네트워크 불필요)으로
재계산했다.

```
Codex          total 63 · a3Earlier 50 · a3Later 13 · a3LaterByFY {2019:11, 2020:1, 2024:1}
Claude 재현     동일 수치, 동일 corp 목록 (독립적으로 다시 돌려 대조함)
```

**이 문서의 A/B/D 분류와 정확히 들어맞는다:**

```
Codex a3Later(13) = 이 문서의 B(방향반대, 12건) + D의 00442455(1건)
Codex a3Earlier(50) = 이 문서의 A(정상방향, 49건) + D의 00366793(1건)
```

**무엇이 이걸로 강화됐고, 무엇은 아직인가.**

```
강화됨    63건이라는 총량, FY2019 집중(11~13건), B(방향반대) 그룹의 corp
          목록 — 전부 Claude와 무관한 별도 코드 경로로 재현됐다. 계산
          실수나 조인 오류일 가능성은 사실상 배제된다

아직 그대로   Codex는 rceptNo 날짜 선후만 비교했다 — DART 원문(보고서
          제목·[정정] 표시)을 직접 보지는 않았다. "A3가 실제로 원본을
          가리키는가, 정정본을 가리키는가"라는 질적 판정은 여전히 이
          문서 상단의 Claude WebFetch 열람 결과 하나뿐이다. 그 부분은
          아직 단일 출처다
```

**결론: 정량적 재현은 완료, 정성적(원문 내용) 검증은 여전히 단일 출처다.**
A5-5(2) 정책(flag-and-withhold)은 "어느 쪽이 맞는지 모른다"를 전제로 하므로
이 구분이 정책 자체를 흔들지 않는다 — 오히려 두 방법이 같은 63/13 분할에
도달했다는 것이 "단일 방향 규칙은 안 된다"는 근거를 더 단단하게 만든다.
