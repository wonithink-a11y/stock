## 0. 이 문서가 아닌 것

- 새 수집기의 골격 설계가 아니다. A3의 것을 쓴다 — 다른 곳만 여기 적는다.
- 점수 계약이 아니다. **무배당을 어떻게 채점할지는 A5가 정한다**(§5).
- 폐지 종목 재무 복구 계획이 아니다(§1).

## 1. 목표와 비목표

```
목표    현재 상장 종목의 valuation·shareholderReturn 을 열어 운영 채점을 가능하게 한다
        availableWeight  0.4475 → 0.68   (criteria.minimumDataCoverage 0.6)
        V1 지표 커버리지  10/19 → 13/19
비목표   폐지 법인의 재무 복구. A3b 의 성공·실패 판정에 넣지 않는다
```

**두 커버리지는 다른 산출식이다**(브리프 §1.1). 0.68과 0.6842가 붙는 것은 우연이며
한쪽 수치로 다른 쪽을 말하지 않는다.

폐지 법인을 비목표로 두는 근거는 소스 구조다. `alotMatter`는 A3와 **같은
`(corp_code, bsns_year, reprt_code)` 격자**를 보므로 사업보고서가 없으면 둘 다 빈
응답이다. 정찰 실측: A3 데이터가 없는 법인 표본 4건이 전부 `013`이었다.

그럼에도 **A3 데이터가 있는 폐지 440법인은 격자에 넣는다**(§3). 목표 밖인 것과 이미
확보한 것을 버리는 것은 다르다 — 그 440은 EPS만 얹으면 10/19에서 13/19로 넘어간다.

## 2. 소스 — 실측으로 확정됐다

```
endpoint     alotMatter.json          배당에 관한 사항
파라미터      corp_code · bsns_year · reprt_code(11011 사업보고서)
호출          (corp, 사업연도)당 1회
```

정찰 28셀 응답에서 확정한 것이다. **A3에서 참인 것을 옮겨 적지 않았다** — 다른
엔드포인트는 필드가 다르고, A3가 `fnlttSinglAcntAll`에서 `thstrm_dt`를 240건 전건
못 받은 것이 정확히 그 교훈이다(교훈50).

| | 실측 | 확정 |
|---|---|---|
| `rcept_no` 존재·형식·응답 내 단일값 | 28/28 · 28/28 · 28/28 | `availableFrom` 경로로 확정 |
| `stlm_dt` 존재·파싱 | 28/28 · 28/28 | `periodEnd` 경로로 확정 |
| `availableFrom` vs `periodEnd` | after 28 / 28 | 계약 1을 `>`로 확정 |
| A3 `rceptNo`와 일치 | 28/28 | 두 실행 사이 정정공시 0건 |

`stlm_dt`는 `"2025-12-31"` 형태로 단일값이다. A3의 `thstrm_dt`가 `"2023.12.31 현재"`
같은 문장형이었던 것과 다르다. **그래도 파서는 형태를 가정하지 않는다** — 문자열에서
마지막 날짜를 캐고 원문을 진단에 남긴다. 한 번의 관측으로 형태를 성질로 읽지 않는다.

### 2.1 `thstrm` 열만 쓴다

A3의 `thstrmOnlyNote`가 정한 규칙이 여기서도 그대로다. `alotMatter`도 `frmtrm`·`lwfr`을
함께 주므로 같은 유혹이 있고, 현행 `fetch-fundamentals-kr.js`의 `fetchDividend`는 실제로
3개 연도를 다 읽는다. **A3b는 그러지 않는다** — 전기·전전기 값의 `availableFrom`은
'그 보고서의 접수일'이라, 과거 연도를 실제보다 늦게 안 것으로 기록하게 된다(교훈47).

### 2.2 `se` 선별 순서

실측에서 라벨이 갈렸다 — `(연결)주당순이익(원)` 27 · `주당순이익(원)` 1.

```
epsPreference        ["(연결)주당순이익", "(별도)주당순이익", "주당순이익"]
dividendPreference   ["주당현금배당금"] · stock_knd 에 "보통주" 우선
```

A3의 `fsDivPreference`(CFS→OFS)와 같은 형태다. `(별도)주당순이익`이 함께 오는 경우는
**아직 관측되지 않았다** — 순서에 넣어 두되 미관측으로 남기고, 본 수집이 분포를 남긴다.

## 3. 격자 — A3 재사용 + 미확보 법인 스캔

```
① A3 가 보고서를 찾은 (corp, fiscalYear)          24,750 셀 = 24,750 호출
② A3 데이터가 없는 798 법인 × 사업연도 11개         8,778 셀 ≈ 1,600 호출 (조기 종료)
                        격자  33,528 셀   ·   호출  약 26,400   → 일 예산 16,000, 2일
```

**셀과 호출은 다른 수다.** ②는 격자에 전 사업연도가 들어가지만 조기 종료가 걸려 법인당
2~3호출에서 멈춘다. 남은 해는 **조회하지 않은 채 `EARLY_STOP`으로 기록**되므로 셀은
전부 남고 호출만 줄어든다 — `scannedCellsMismatch`는 셀 기준이고 예산은 호출 기준이다.
`--plan`이 네트워크 없이 이 수를 출력한다(실측: reuseCells 24,750 · missingCorps 798
= 폐지 783 + 현재 상장 15 · plannedCells 33,528).

①이 A3의 공백 7,326셀을 다시 두드리지 않게 한다. 전체 격자 재탐색(약 30,700)보다
싸고, 목표 집단(현재 상장 2,563법인)을 빠짐없이 덮는다.

②를 넣는 이유는 두 가지다. **그 798에 현재 상장 15법인이 들어 있고 그들은 목표
집단이다.** 그리고 `stopAfterConsecutiveEmptyYears` 2가 걸려 법인당 2~3호출에서
멈추므로 전체의 6%도 안 된다 — 그 값으로 A3 진단의 공백(§7)이 실측으로 닫힌다.

**①의 격자는 A3 산출물에서 읽는다.** `data/backfill/fundamentals/a3/*.jsonl.gz`의
`(corp, fiscalYear)`이며, 정정공시로 같은 키가 여럿이면 한 셀로 센다.

## 4. PIT — A3b는 독립 레코드를 낸다

```
availableFrom  = rcept_no 앞 8자리 (YYYYMMDD)
periodEnd      = stlm_dt
계약 1          availableFrom > periodEnd            FAIL
유일성 키       (corp, fiscalYear, availableFrom)     A3와 같은 모양
```

**A3의 `availableFrom`을 빌려 오지 않는다.** `alotMatter`는 `rcept_no`로 조회할 수 없어
A3가 본 것과 다른 정정본을 받을 수 있고, 그때 A3의 접수일을 붙이면 **그 시점에 없던
값을 그 시점에 알았다고 기록**하게 된다. 정찰에서 28/28 일치했지만 그것은 오늘의
관측이지 성질이 아니다.

대신 **A3의 `rceptNo`와 대조해 진단에 남긴다.** 다르면 두 실행 사이의 정정공시이며
결함이 아니다. 두 값이 독립 조회에서 나오므로 동어반복이 아니다(교훈72).

A5는 축마다 독립으로 PIT를 고른다 — `lib/a5/pitSelector.js`가 이미 그 모양이다.

## 5. 산출물 — 무배당은 결측이 아니다

```
data/backfill/fundamentals/a3b/{fiscalYear}.jsonl.gz
fields   corp · ticker · fiscalYear · availableFrom · rceptNo · periodEnd
         eps · epsSource
         dividendRowPresent · dividendPerShare · dividendStockKnd
sortKey  fiscalYear · corp · availableFrom       gzipMtime 0 · level 9
```

### ★ 5.1 배당 세 갈래

정찰 실측: `dividendRowFound` 28/28인데 `dividendThstrmNumeric`은 16/28이다.
**행은 늘 오고 값이 빈다.** 무배당 기업이 그렇다.

```
행 있음 · 값 숫자   dividendRowPresent true  · dividendPerShare <숫자>
행 있음 · 값 없음   dividendRowPresent true  · dividendPerShare 0        ← 무배당. 관측된 사실
행 없음            dividendRowPresent false · dividendPerShare null     ← 결측
```

`0`과 `null`을 합치면 **배당을 안 주는 회사가 전부 결측으로 잡혀 유보가 된다.** 반대로
`null`을 `0`으로 읽으면 조회 못 한 것을 무배당으로 단정한다. 둘 다 틀리므로 갈라 남긴다.

절대 규칙 1("결측 지표에 기본점수 금지")과 어긋나지 않는다. 기본점수를 주는 것이
아니라 **관측된 사실을 사실대로 적는 것**이고, 그 사실을 어떻게 채점할지는 A5가 정한다.

```
A3b   원천 상태를 보존한다. 0 / null / 숫자를 구분한다
A5    그 상태로 점수·coverage·유보를 판정한다
```

`eps`도 같은 처리다 — 행은 있는데 값이 없으면 `null`이다(무배당과 달리 '주당순이익
0'은 관측 가능한 값이므로, 빈 값을 0으로 읽지 않는다).

## 7. ★ 스캔 기록 — 결과가 없어도 남긴다

A3는 [build-fundamentals-a3.py:967](../scripts/build-fundamentals-a3.py:967)의
`if gaps: … else: pop` 때문에 **798법인 중 599의 조회 여부가 기록에 없다.** 같은 파일
주석이 의도를 이미 적어 뒀다 — "빈 dict를 두면 '스캔했으나 사유 없음'과 '스캔 안 함'이
같은 모양이 된다". 지금 그 둘이 구분되지 않는다.

```
scanned[corp][fiscalYear] = "OK" | "013" | "EARLY_STOP:<사유>" | "<status>"
스캔한 셀은 결과가 없어도 전부 남긴다. 빈 dict 도 남긴다
```

```
인수 조건   scannedCells == 격자 셀 수
            구성상 참이 아니다 — 격자는 입력에서, scannedCells 는 응답에서 온다(교훈72)
```

원시 사실은 수집 단계에서만 남길 수 있다. 그 자리에서 안 남기면 재수집 없이는 영영
얻을 수 없다(교훈75).

## 8. 인수 조건

```
FAIL   rceptNoPresentRate >= 0.99          정찰 1.0. 이분적 지표라 빈 구간에 긋는다
       availableFrom > periodEnd 위반 0     계약 1
       availableFromMissing 0 · periodEndMissing 0
       dateContractViolations 0 · corpContractViolations 0
       duplicateKeys 0                      (corp, fiscalYear, availableFrom)
       corpsIncomplete 0                    전 샤드가 담당분을 끝냈는가
       scannedCellsMismatch 0               §7
WARN   epsNumericRate          첫 관측 0.93 (28셀). FN-1.6 에서 승격 판단
       epsRowFoundRate         첫 관측 1.0
       currentListedEpsRate    목표 집단의 확보율. measured 후 승격 후보
```

**게이트로 만들지 않는 것**

```
dividendRowFound      정찰 28/28 = 1.0. 항상 참이라 통과가 정보를 주지 않는다(교훈61)
dividendNumericRate   첫 관측 0.57. 낮은 이유가 무배당이라 커버리지가 아니다.
                      회사 구성의 함수이므로 게이트가 아니다(FN-1.4 절차 §2.3)
폐지 그룹 확보율        A3b 의 성공 판정 대상이 아니다(§1). measured 에 기록만 한다
```

임계는 FN-1.4 승격 절차를 그대로 따른다 — **실측 전 임계는 WARN으로 시작하고, 첫 전수
수집이 `measured`를 채운 뒤 도출식으로 승격한다.** 정찰 28셀은 표본이라 게이트의
기준선이 될 수 없다.

## 9. `--revalidate` — 재판정 가능 범위를 미리 갈라 둔다

A3는 finalize가 샤드를 지워서 **임계를 올린 뒤 다시 판정할 길이 없다.** FN-1.4 승격
때 실제로 그 벽을 만났다(재수집 3~4일이라 하지 않기로 했다). A3b가 같은 구조를
물려받으면 FN-1.6에서 같은 자리에 선다.

**샤드 보존 정책은 바꾸지 않는다.** 대신 무엇을 재판정할 수 있는지를 계약에 적는다.

```
--revalidate   커밋된 산출물만으로 인수 조건을 다시 판정한다

산출물만으로 잴 수 있다   계약 1 위반 · 중복 키 · 날짜/corp 형식 · epsNumericRate
                        dividend 세 갈래 분포 · currentListedEpsRate
상태가 있어야 잴 수 있다   scannedCells · 응답 상태 분포 · rceptNoPresentRate
                        (산출물에 없는 행은 이유를 말하지 않는다 — 교훈75)
```

이렇게 두면 다음 승격에서 "샤드가 없어 재판정 불가"가 아니라 **"이 항목은 가능,
저 항목은 불가"**가 되고, 그것을 미리 안다.

## 10. manifest

```
stage         A3b
upstream      A1a · A1b · A3        A3 격자를 입력으로 쓰므로 A3 를 선언한다
policies      universe · fundamentals
target        data/backfill/fundamentals/a3b   kind dir   ext .jsonl.gz
```

`REQUIRED_UPSTREAM`에 `'A3b': ['A1a', 'A1b', 'A3']`을 추가한다. A3 선언이 필수인 이유는
**격자가 A3 산출물에서 오기 때문**이다 — 선언하지 않으면 어느 A3 스냅샷의 격자로
모았는지 기록이 없고, A3가 재수집돼도 `verifyUpstream`이 그 drift를 보지 못한다
(A1b가 A0.7을 선언하는 것과 같은 이유).

`REQUIRED_UPSTREAM.A5`에 `A3b`를 넣을지는 **별도 결정이다.** 넣으면 A3b 없이 A5를
돌릴 수 없게 되는데, valuation이 A3b에서 오므로 그 강제가 맞을 가능성이 높다. 다만
A5 운영 게이트 4(A4 재정규화)와 함께 정하는 것이 순서다.
