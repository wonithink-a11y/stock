# A3c 정책 초안 — 발행주식총수 (2026-08-12)

```
★ 이 문서는 초안이다. config/policies/fundamentals.v1.json에 아직 반영하지
  않았다. 표본을 30~50개로 넓혀 재검증(§5)에서 규칙이 안 깨지면 그때
  fundamentals.v1.json의 a3c 블록으로 승격한다(BF-1.1 §2 안A, A3b 신설 때와
  같은 절차 — docs/A3b-결정브리프.md → docs/A3b-1.0-배당EPS계약.md).
  이 문서 자체는 계약이 아니라 그 전 단계의 결정 기록이다.
```

## 0. 왜 필요한가

A5-3(peg) 구현 중 실측으로 발견: A2a 가격은 `adjusted:true`(수정주가, 액면분할 등을
소급 반영)인데 A3b EPS는 DART 원문 그대로(조정 없음)라, `per = price/eps`를 그대로
계산하면 분할을 겪은 종목에서 틀린 값이 나온다(005930/2016-04-08 실측, per=0.197).

해결책: EPS 원본 대신 `per = price / (netIncome / sharesOutstanding)`으로 우회한다.
`netIncome`(A3)은 분할과 무관하고, `sharesOutstanding`(발행주식총수, 이 문서의 대상)이
그 시점의 실제 주식 수를 담으면 분할 여부를 몰라도 결과가 정확해진다.

## 1. 소스

```
provider    DART OpenAPI
endpoint    stockTotqySttus.json (주식의 총수 현황)
field       istc_totqy (발행주식의 총수)
grid        (corp_code, bsns_year, reprt_code) — reprt_code가 4종(연 4회)이라
            A3/A3b(연 1회)보다 격자가 4배 크다
reprtCodes  11013(1분기)·11012(반기)·11014(3분기)·11011(사업보고서)
```

## 2. PIT 규칙 (확정 — §5 재검증 통과 시 승격)

### 2.1 기본 PIT
`availableFrom`(= rcept_no 앞 8자리) <= asOf인 레코드 중 최신을 쓴다. A3/A3b와 같은
메커니즘, 새 로직 불필요(실측: rcept_no 존재율 100%, PIT 앵커 가능 확인됨).

### 2.2 동일 접수일 tie-break — 사업보고서 > 반기 > 3분기 > 1분기
실측(00101220/KG케미칼, 2026-08-12)에서 1분기·반기 보고서가 **같은 날 접수**되는
실제 사례를 확인했다. `availableFrom`만으로는 어느 쪽을 쓸지 안 갈린다. 보고서
종류의 정보 우선순위로 정한다 — 재현 가능하고 데이터 품질(값의 유무)에 따라
선택 로직이 바뀌지 않는다(값 유무를 기준으로 삼으면 결측 문제가 선택 로직에
숨어버린다).

```
우선순위   사업보고서 > 반기 > 3분기 > 1분기
```

### 2.3 Carry-forward — 결측(`"-"`)이면 직전 정상값 유지
DART가 `dartStatus="000"`(성공)이면서도 `istc_totqy`를 포함한 모든 관련 필드를
문자열 `"-"`로 주는 경우가 실측으로 확인됐다(코드 버그 아님 — 원본 응답 자체가
비어 있음, 4건 rawdump로 확인). 선택된 보고서가 결측이면:

1. **같은 날짜의 다른 보고서로 옆으로 새지 않는다** — 그러면 §2.2의 우선순위가
   무의미해진다(가상 케이스로 검증: 우선순위 높은 보고서가 결측이어도 우선순위
   낮은 같은 날짜 값을 쓰지 않고 그 이전 정상값으로 넘어간다).
2. 그 시점 이전(같은 날짜 제외)의 가장 최근 정상값으로 carry-forward한다.
3. 이전 정상값 자체가 없으면 `None`이다 — 0이나 추정값을 지어내지 않는다.
4. `valueSource: DIRECT | CARRY_FORWARD`를 provenance에 남긴다.

### 2.4 기중 변경 구간은 정밀도 한계로 명시한다 (보정하지 않는다)
분할 등 기업행위가 실제 시행일과 다음 정기보고서 접수일 사이에 발생하면, 그
구간의 asOf는 (결측이 아니라) **직전 보고서의 DIRECT 값**을 그대로 쓴다 — 이건
carry-forward가 아니라 PIT 그대로다(그 시점엔 실제로 그 값만 알려져 있었다).
실측(005930/2018): 분할 시행일 2018-05-04, 이후에도 1분기 보고서(접수 2018-05-15)는
분할 전 값을 그대로 보고했고, 반기(접수 2018-08-14)에야 반영됐다 — **91일**의
정밀도 한계를 실측으로 확정했다. 미래의 반기 값을 과거 날짜로 당겨쓰지 않는다.

### 2.5 극단적 변화 감지 (진단용, 자동 보정 아님)
연속 DIRECT 값 사이의 비율을 계산해 `stockCountTransition`으로 남긴다. 임의로
분할 배율을 추정해 보정하지 않는다 — 진단으로만 남기고 사람이 본다.

## 3. Replay 검증 (2026-08-12, 표본 9~12개, 실제 정찰 데이터 기반)

```
케이스 A  005930(삼성전자) 2018 분할 — DIRECT/carry-forward 분리 정상 동작,
          1분기→반기 전환 50.0배 정확히 감지, gap 91일 실측
케이스 B  00101220(KG케미칼) 동일접수일 — 우선순위 규칙으로 입력 순서 무관하게
          결정론적 선택 확인(순서를 바꿔도 결과 동일)
케이스 C  00101433(경농) 1·3분기 연속 결측 — 3분기 결측을 건너뛰고 반기 값으로
          정확히 carry-forward. 반기 이전 시점은 정직하게 None
가상 케이스  우선순위 높은 보고서가 결측이어도 같은 날짜의 낮은 우선순위 값으로
          안 샌다 — 그 이전 정상값(사업보고서)으로 정확히 carry-forward
```

세 실제 케이스 + 1 가상 케이스 전부 통과. 스크립트는 저장소에 커밋하지 않은
1회성 검증(scratchpad)이었다 — 결과만 이 문서에 남긴다.

## 4. 원자료 특성 (첫 정찰 32건 + 분할검증 4건, 실측)

```
반기 확보율        9/9  (100%)
사업보고서 확보율    9/9  (100%)
1분기 확보율        6/9  (67%)  — 결측 3건, 전부 seSample=[비고,합계]뿐(보통주 행 없음)
3분기 확보율        8/9  (89%)  — 결측 1건
```

결측은 "DART가 분기보고서엔 원래 이 값을 안 준다"는 구조적 제약이 아니다 — 같은
법인의 반기·사업보고서는 100% 정상이고, 대다수 분기보고서도 정상이다. **일부
법인·일부 분기의 개별 결측**으로 판단한다(DART API 공식 문서에는 이 차이를
설명하는 유의사항이 없어 문서 근거로는 확인 불가 — 데이터 패턴 근거만 있다).

## 5. 다음 단계 — 표본 확대 재검증 (착수 대기)

```
표본        9~12개 → 30~50개(법인)
측정 항목    직접값 비율 · carry-forward 비율 · 최초 유효값 없음 비율 ·
            동시접수 건수 · 연속 결측 최대 길이
방법        scripts/probe-fundamentals-a3c.py 확장(mode=full, 표본 확대) +
            §2의 확정 규칙을 그대로 재생(replay)하는 집계 추가
승격 조건    이 재검증에서 §2 규칙이 깨지는 새 엣지케이스가 안 나오면
            fundamentals.v1.json의 a3c 블록으로 확정
```

**이 단계까지는 A3c 본수집을 시작하지 않는다.** 순서: 정책 초안(이 문서, 완료) →
소수 표본 검증(완료, §3) → 표본 확대 재검증(다음) → acceptance 확정 →
`fundamentals.v1.json` 반영 → 그다음에야 본수집.
