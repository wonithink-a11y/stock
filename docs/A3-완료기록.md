# A3 완료 기록

**이 문서의 존재 이유는 GitHub Actions run ID다.** 나머지(산출물·manifest·진단·
정책)는 전부 커밋에 있어 태그 하나로 고정되지만, run ID는 코드가 남기지 않았고
Actions 실행 목록은 보존 기간이 있다 — 이 저장소에서 유일하게 복구 불가능한 메타데이터다.

왜 코드가 안 남겼는가: `run_identity()`는 `GITHUB_RUN_ID`를 읽지만 `**ident`가
`hardSkipped` 항목에만 펼쳐진다(`scripts/build-fundamentals-a3.py:992`). A3는
하드 실패가 0이라 **성공 경로에 run ID가 하나도 저장되지 않았다.** finalize가
`_shards/`를 지우면 `runDates`(날짜)와 `runIdentityOk`(불리언)만 남는데, 하루에
여러 번 dispatch하고 재실행도 했으므로 날짜로는 로그를 찾을 수 없다.
다음 수집기는 `docs/MN-1.0-분봉Raw저장계약.md` §5의 `execution.*`가 막는다.

## finalize #1 실패 — 게이트가 막았다 (2026-08-08)

```
PIT regression test → ModuleNotFoundError: No module named 'requests'
  test-fundamentals-a3.py:527 fake_run → :500 run_shard
  → build-fundamentals-a3.py:845 require_requests() → :193 import requests
```

**finalize 잡에 `pip install requests`가 없었다.** collect 잡에만 있다(:62). persist는
`--summary`만 써서 지연 import로 살아남았고, finalize는 회귀 스위트가 `run_shard`를
밟아 가드에 걸렸다. 합성 픽스처라 호출은 나가지 않지만 **모듈은 있어야 한다.**

> **'네트워크를 쓰지 않는다'와 '그 라이브러리가 없어도 된다'는 다른 말이다.**
> 지연 import는 전자를 위한 장치이지 후자를 보장하지 않는다. 잡의 의존성 프로필을
> 스텝의 실제 필요가 아니라 잡 이름의 성격으로 정하면 이렇게 갈린다.

산출물·manifest는 쓰이지 않았다. 인수 조건 실패 시 산출을 쓰지 않는 계약(교훈43)이
설계대로 동작했고 **데이터는 손상되지 않았다.** `_shards/`도 그대로다.

고친 뒤에는 **Re-run이 아니라 새 Run workflow**로 돌린다 — 재실행은 그 실행이
시작된 커밋(`b84ce21`)을 다시 돌아 같은 오류가 영원히 난다(교훈78).
