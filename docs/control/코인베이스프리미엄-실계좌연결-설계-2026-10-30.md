## 4. A 의 변경 목록

### 4-1. 모델·위험 검사 (`autotrader/models.py` · `risk.py`)
- `MARKETS = ("KR", "US", "UPBIT")`. UPBIT 만: **소수 수량 허용**(소수 8자리), `order_type="market"` 허용, 금액 단위 원.
- 업비트 최소 주문 5,000원 미만 거부(위험 검사에서 — 거래소 거절 전에 막는다).
- 기존 KR/US 검증 규칙(정수 수량·시장가 KR 만·loc US 만)은 그대로 — 기존 회귀가 핀한다.

### 4-2. 브로커 (`autotrader/upbit.py`, 새 파일)
- 기존 `research/strategy-lab/engine/live/upbitClient.py` 를 감싼다(서명·요청 코드를 다시 쓰지 않는다).
- `positions("UPBIT")` = `/v1/accounts` 의 BTC(잔고+locked) · `cash` = KRW 잔고 · `quote` = 공개 시세 ·
  `open_orders` = 대기 주문 · `fills` = 주문 uuid 별 체결량·평균가·수수료.
- `place`: 매수는 **원 금액 시장가**(`ord_type=price`, 금액 = 수량×직전 시세), 매도는 **수량 시장가**(`ord_type=market`).
  업비트 API 자체가 비대칭이다(upbitBroker.py 주석). `dry_run` 이면 요청을 만들기만 하고 보내지 않는다.
- 키: 프로필 `key_prefix: "UPBIT_TRADE"` → `UPBIT_TRADE_ACCESS_KEY` / `UPBIT_TRADE_SECRET_KEY`.
  **기존 조회용 `UPBIT_ACCESS_KEY` 와 섞지 않는다**(잔고 조회 유닛은 그대로 조회 전용 키).
- 업비트에는 모의투자가 없다 → 이 프로필의 '모의'는 dry-run 뿐. `mode` 는 `live` 고정, 게이트가 실주문을 막는다.

### 4-3. 전략 (`autotrader/strategies/coinbase_premium.py`, 새 파일)
- `research/strategy-lab/run_coinbase_premium_paper.py` 의 `fetch_coinbase`·`fetch_binance`·`premium_z`·`scan_events` 를 import(복사 금지).
- 상태(`ctx.state`, 프로필별): `lastScanned` · `blockedUntil` · `position{signalT, orderUuid, qty(실제 체결량), entryAvg}`.
- 매 실행: ① 보유 중이고 T ≥ signalT+24h → **자기가 산 수량만** SELL ② 새 롱 사건·지연 ≤ 30분·미보유 → BUY(`notional_krw`)
  ③ 숏 사건·놓친 사건 → 차단만(모의와 같은 문구로 알림).
- **계좌에 사용자가 따로 가진 BTC 는 건드리지 않는다** — 매도 수량은 전략이 기록한 체결 수량이 상한.
- 매수 다음 실행에서 체결 확인(uuid) → 체결량·평균가·수수료를 상태에 적는다. 체결 0 이면 포지션을 만들지 않고 알림.

### 4-4. 일정·설정 (VM 프로필 `~/collector-venv/autotrader/profiles/cbprem.json`)
```json
{"strategy": "coinbase_premium", "broker": "upbit", "mode": "live", "key_prefix": "UPBIT_TRADE",
 "markets": ["UPBIT"], "symbol_allowlist": ["KRW-BTC"], "auto": "off",
 "run_at": ["00:02","01:02", "… 매시 …", "23:02"], "days": "daily",
 "params": {"notional_krw": 100000},
 "risk": {"UPBIT": {"max_order_value": 150000, "max_daily_value": 300000, "max_orders_per_run": 1,
                    "max_position_value": 150000, "allow_sell": true, "price_band_pct": 5}},
 "live": {"enabled": false, "api_reviewed": false}, "web_live_allowed": true}
```
- `run-due` 타이머(5분)가 :02~:07 사이에 돈다 — 30분 지연 한도 안. 같은 회차는 한 번만(기존 동작).
- 한도 = 웹이 뚫렸을 때의 최대 손실 상한(웹은 한도·종목·키를 못 바꾼다).

### 4-5. 원장·손익·웹·알림
- 원장·손익은 원 단위·소수 수량 표시. 웹 카드에 프로필이 하나 더 뜬다(보유·손익, 계좌번호 없음).
- 텔레그램 `매매•보안` 방: 실주문 접수·체결·실패·놓친/지연 신호 — 문구 머리에 **"실계좌"** 를 붙여 모의 알림과 구분.

## 5. 켜기 전 순서 (전부 사용자)

1. **업비트 Open API 키 새로 발급**: 권한 = 자산조회 · 주문조회 · 주문하기. **출금하기·입금하기는 체크하지 않는다.** 허용 IP = `129.225.145.14`.
2. VM `~/collector-venv/.env` 에 `UPBIT_TRADE_ACCESS_KEY=…` · `UPBIT_TRADE_SECRET_KEY=…` (Claude 에게 보내지 않는다).
3. 프로필 `auto: "dry"` 로 며칠 — 실계좌 키로 **조회만**, 신호 시각·판단이 모의 슬리브 로그와 같은지 대조(Claude 가 로그를 받아 대조).
4. (선택) **최소 금액 경로 시험**: `probe` 명령으로 5,000원 매수 → 즉시 매도 1회(사용자가 실행, 수수료 몇 원). 주문·체결 확인·알림 경로를 신호 없이 확인한다.
5. 프로필에 `live.enabled: true`, `api_reviewed: true` · 금액·한도 확정 · `autotrader.service` 환경에 `AUTOTRADER_ALLOW_LIVE`(이미 있으면 그대로).
6. 웹 → 지문(패스키) → **주문 켜기**. 끄기·킬 스위치는 웹에서 바로.
