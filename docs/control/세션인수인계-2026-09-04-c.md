## 1. 매도 규칙 다섯 개를 쟀고 하나만 살아남았다

| 규칙 | 판정 | 비용 대비 효과 |
|---|---|---|
| 손절 3xATR | **기각** | CAGR -0.75%p 로 MDD +2.1%p |
| **부분 익절 +20%/70%** | **HOLD (유일 생존)** | **CAGR -0.31%p 로 MDD +5.1%p** |
| 트레일링 손절 | **기각** | CAGR -3%p 이상, 지표 악화 |
| 노출 오버레이 | **기각(6번째)** | - |
| 점수 기반 청산 | **기각** | 증거가 반대 방향 |

반복 패턴 하나가 뚜렷하다 — **"이긴 포지션을 파는 것"은 수익에 손해다.** 다섯
규칙 전부 그 방향을 확인했고, 부분 익절만 그 대가가 낙폭 축소로 충분히 보상됐다.

60/15/25 로 절단**하는 방식(`run_pbr_combined_oos_validation.py` 와 동일).

## 2. 사이징 — N 은 수익으로 못 고른다, 수용력으로 고른다

`sizing-position-count-capacity-2026-09.md`

- N=10~100 을 실제 엔진에서 쟀다. **세 구간이 각각 다른 N 을 고른다**
  (TRAIN 100 / VALID 10 / TEST 50), 전체기간 Sharpe 는 중간(N=20)이 최악인 U 자.
  **안정적 최적값이 없다** - 그래서 기존값 30 을 존치한다(바꾸면 노이즈 최적화).
- 수용력 = `MIN_TURNOVER x 참여율상한 x N x 분할일수`.
- ★ **사용자 지적으로 정정** - 처음 결론("5억을 담으려면 독립 슬리브가 여러 개
  필요")은 **"하루에 다 산다"는 말하지 않은 가정** 위에 있었다. 참여율은 하루
  단위 개념이라 분할 매수가 훨씬 강한 지렛대다:

  | 분할 | 최악 종목 하루 참여율 | 5% 초과한 달 |
  |---|---|---|
  | 1일 | 15.6% | 100% |
  | 3일 | 5.2% | 65% |
  | **5일** | **3.1%** | **0%** |

  전략 분할은 약한 지렛대다(5억 단독 15.6% -> 2.5+2.5억 10.7%).
- 성과 귀속은 겹쳐도 정확하다(`positionStore` 가 strategy_id 별 장부). 유동성
  제약만 합산 주문에 걸린다. 겹침 49.1% 는 min() 분모라 오해를 부른다 - 실제
  동시 보유는 8~12종목이다.
- **분산은 겹침이 아니라 수익 상관으로 판단한다** - pbr x lowmom60 은 종목 겹침
  0.6% 인데 월수익 상관 **0.679**(둘 다 롱온리 주식이라 시장 베타가 지배).

## 3. ★★ 채점 엔진 배점 재검토 (가장 중요한 발견)

사용자 제기: "초반에 아무 데이터 없이 점수화 엔진을 설계한 게 문제 아닌가.
재무를 너무 많이 넣은 건 아닌지. 1차/2차/3차 버전으로 업그레이드하면 어떤가."

**말씀하신 방식이 이미 이 저장소의 설계다** - 규칙 5 는 "바꾸지 마라"가 아니라
"스냅샷을 고치지 말고 새 버전 파일 + registry 승격"이고, 오늘 아침 KR-2.3 이
정확히 그 절차였다.

### 3-1. 재백필 없이 재가중할 수 있다 (핵심 도구)

A5 패널이 축별 기여도 `c` 를 저장하는데 **이미 재정규화된 값**이다. 정확한 역산:

```
축 원점수 = c[축] x (존재 축 가중치 합) / W[축]
새 점수   = Σ 새W[축] x 축 원점수 / Σ 새W[존재 축]
```

★ **처음에 `c / W` 로 나눴다가 틀렸다.** 재정규화를 안 되돌리면 결측 축이 있는
행에서 조용히 어긋난다. 축이 둘만 있는 레코드의 기여합(44.4)이 그 축들의 가중합
상한(35)을 넘는 것을 보고 발견했다. 복원값 0~100.1 · 오차는 소수 1자리
반올림뿐(최대 0.2, 초과 0건).

### 3-2. 축 가중치 (`axis-weight-sweep-2026-09.md`) — PASS

현행 fundamental .35 / valuation .30 / technical .15 / supplyDemand .20

- 격자 286개 **TRAIN IC 상위 10개가 전부 supplyDemand=0**.
- `30/50/20/0` 이 **전체표본·공통표본 x 세 구간 = 6개 셀 전부에서** 현행을 이긴다
  (전체 TRAIN 0.0351->0.0469 · VALID 0.0491->0.0547 · TEST 0.0793->0.0845).
  커버리지 99.8% 유지. 난수 가중치 p95(0.0452) 통과.
- ★ **커버리지 교란을 통제했다** - TRAIN 최선인 valuation 단독(0/100/0/0)은
  **전체 행의 53.6% 에만 점수를 낸다**. 서로 다른 유니버스 비교라(같은 날
  lowmom60 에서 결론을 뒤집었던 실수) 공통 표본으로 재측정했고 거기선
  30/50/20/0 이 이긴다.
- **사용자 가설 셋 중 둘이 확인됐다** - 재무 비중이 과하다(35->30), 초기 설계가
  측정 없이 정해진 것이 실제 문제다. "재무 세분화"는 축 내부 문제라 답이 안 나온다.

### 3-3. 수급 축 정의 (`supply_demand_window_sweep.py`)

축을 버릴 것인가 정의를 고칠 것인가. A4 원본에서 5일/20일/연속값을 다시 만들어 쟀다.

- **재현 검증 완벽** - 112만 행에서 |차이| **1.0 초과 0건**(저장값이 소수 1자리
  반올림이라 이게 하한).
- **현행 수급은 정보가 없는 게 아니라 해롭다** - 축 단독 IC 가 TRAIN -0.0070
  (t=-2.8) · VALID -0.0079(t=-2.0) 로 **유의하게 음(-)**.
- **창 수정(5->20일)은 효과가 있다** - 전체 점수 IC 세 구간 전부 개선
  (+0.0351/+0.0491/+0.0793 -> +0.0380/+0.0557/+0.0825).
- **그래도 수급 제외가 TRAIN·TEST 에서 더 낫다**(0.0469/0.0845 vs 0.0380/0.0825).
- **라벨링 제거는 답이 아니다** - 20일 누적 연속값은 전체 점수를 세 구간 전부 악화.
- ★ **최종 판정: 정의를 고쳐도 축이 가중치를 못 받는다.** 20일 라벨로 갈아끼운 뒤
  가중치를 재최적화하니 **TRAIN 상위 8개가 전부 supplyDemand=0** 이고(상위 20개
  중 수급>0 은 3개), 수급>0 최선(`20/40/30/10`, +0.0455)이 수급 제외
  (`30/50/20/0`, +0.0469)보다 낮다. **`30/50/20/0` 이 KR-2.4 후보로 확정 유지.**
- 단 **"수급 데이터가 쓸모없다"가 아니라 "지금 쓰는 형태로는 쓸모없다"**다.
  A4 원본은 투자자 12분류 x 매수/매도 x 수량/금액인데 엔진은 외국인/기관 2분류 ->
  순매수 -> 5단계 라벨로 압축한다. 그 압축이 정보를 버리는지는 별도 연구다.
- ★ **구조적 발견**: `netBuysToTrend` 의 5단계 분류는 **창 길이에 따라 성질이
  바뀐다**. 5일에서 100점 0.3%·값 25종인데 20일에서는 100점 0.0%·네 값이 95.7%.
  "모든 날 순매수 -> 100점"이 창 길이에 스케일하지 않는다. **수급 축만의 문제가
  아니라 범주형 지표 설계 전반의 문제일 수 있다** - 오늘 아침 technical 축
  MA크로스의 방향이 틀렸던 것과 같은 계열이다.
