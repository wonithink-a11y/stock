  `.env` 에 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID` 추가. 사용자가 실환경에서 확인(테스트 메시지·실패/성공 알림·상세 바로 열림).

## 2. 이번에 겪은 함정 (다음 세션이 같은 실수를 안 하도록)

- **분류기 차단 3종**: (a) KIS 공식 문서 열람·`mkdir autotrader`가 `Real-World Transactions` 로 막힘 → 사용자가 Write 도구 사용을 명시적으로 재승인해 진행,
  (b) `git commit` 이 `Auto-Mode Bypass` 로 막힘 → **사용자가 PowerShell 에서 직접 커밋·푸시**, (c) 이후 커밋·푸시는 통과. 우회하지 않고 막힌 사실을 보고했다.
- **사용자의 셸은 Windows PowerShell 5.1** — `&&` 를 못 쓴다. 명령은 **한 줄씩 복붙** 가능하게, VM 안(bash)과 PC(PowerShell)를 명확히 구분해서 준다.
- **자리표시자를 글자 그대로 입력했다**(`파일이름` → No such file). 안내에는 가능하면 실제 값을 넣고, 자리표시자는 눈에 띄게 표시한다.
- **저장소 기록을 안 보고 새 소프트웨어(Caddy)를 권했다가**, 기존 nginx+certbot 이 이미 80/443 을 쓰고 있음을 뒤늦게 확인했다(사용자가 "Caddy 있음"이라 답해 혼선). 기존 인프라는 **문서에서 먼저 찾는다.**
  실제로 Caddy 는 설치만 돼 있고 서비스가 `enabled/failed` 였다 → 재부팅 시 nginx 와 포트 충돌 위험이 있어 `disable --now caddy` 했다.
- **미실현 손실을 잔고로 잘못 취급한 펀딩 캐리 설계 오류**를 스스로 발견해 정정(23af1b6). 새 모델을 짜다가 회계를 다시 따져서 발견.
- 컨테이너 `/tmp` 와 Windows Python 의 `/tmp` 가 다르다(Git Bash 히어독 → Python 에서 못 읽음). 스크래치패드(Windows 경로)를 쓴다.
- `@userinfobot` 이 응답하지 않음 → 우리 봇 자신에게 말을 걸어 채팅 번호를 찾는 `telegram-chat-id` 명령으로 대체. 토큰 앞 숫자는 **봇 번호**이지 사용자 채팅 번호가 아니다.
