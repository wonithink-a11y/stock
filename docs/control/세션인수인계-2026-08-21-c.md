# 세션 인수인계 — 2026-08-21-c — 투자대가 방법론 타당성 조사 → turnover20 tercile 테스트베드 결함 확정 → 오염된 2건 재검토로 PBR·LOWMOM60+수급 판정 뒤집힘

이 문서는 정본이 아니다 — 정본은 GitHub `main`의 실제 파일이다. `세션인수인계-
2026-08-21-b.md`("다음 방향은 A5-3 밸류에이션(peg/pbr)을 Strategy Lab에
결합" — §3)의 다음 세션이다. GPT가 제안한 "검증된 투자대가 방법론(버핏·린치·
그린블라트·오닐)을 한국시장 데이터로 정량화 → precheck → 후보 선별" 방향을
그대로 착수했으나, 세 번째 팩터(ROE/Buffett Quality)까지 돌린 뒤 **팩터
자체가 아니라 이 백테스트 인프라의 유동성 tercile 버킷이 수익을 만들고
있었다는 걸 플라시보 테스트로 확정**했다. 사용자 질문("왜 이렇게까지 유효한
검증이 없었나")을 계기로 한 걸음 더 파서, **`turnover20` rolling tercile을
"유동성 통제변수"로 쓰는 이 프로젝트의 관행 자체가 중립적이지 않고 그 자체로
강한 예측변수였음을 확정**했다(§"추가 확인" 참고). 이어서 사용자 질문("실험실
테스트를 다 다시해야 하나")에 정확한 영향 범위를 코드로 확인한 뒤, 그 오염된
방식을 실제로 쓴 2건(ChatGPT 저모멘텀+수급 A/B/C 기각, PBR 대형주 반전)을
중립성 검증된 절대임계값으로 재검토했더니 **둘 다 판정이 뒤집혔다** — 팩터
알파가 진짜 있었는데 오염된 통제변수 때문에 죽어 보였다(§"추가 확인 (같은
세션 재후속)"). **결과적으로 이 세션은 두 개의 새로운 유력 후보(PBR/A5-3
밸류에이션, LOWMOM60+기관수급)를 다시 열어놓은 채로 끝난다.**

## 추가 확인 (같은 세션 후속) — 테스트베드 설계 결함 확정, 이 라인 완전 종료

§4 메타패턴 확정 이후 사용자가 "A안(T3 정밀 재검토)"을 승인해 decile/IC
분석을 실제 롱 전략(하위 ROE 분위 배제)으로 구성해 백테스트했다. **여기서
ROE 신호 자체는 진짜였다** — decile 분석(§4-1)의 IC(t=8.06)와 정확히
일치하게, 저ROE 분위를 배제할수록 CAGR이 단조적으로 개선됐다(T3 baseline
-5.77% → 상위 4분위만 -1.68%, 최대 +4.1%p 개선). 하지만 **모든 변형이
여전히 마이너스**였고, 이게 사용자의 결정적 질문("이렇게까지 유효한 검증이
없는 이유가 뭐일까")으로 이어졌다.

기존 리포트(`2026-08-15-trend-breakout-v1-benchmark-analysis/universe_ew_
benchmark.json`)에 이미 있던 **전체 유니버스 동일가중 매수-보유 벤치마크
(2016~2026 CAGR +4.78%)**와 T3 baseline(-5.77%)의 격차(10.5%p)가 ROE 효과
(최대 +4.1%p)보다 훨씬 커서, "테스트베드 설계 자체가 잘못됐을 가능성"을
`testbed_mechanics_diagnostic.py`로 직접 검증했다 — tercile 제한을 완전히
빼고 전체 유니버스를 월별 리밸런싱만 했을 때 벤치마크와 얼마나 다른지,
비용을 0bps/30bps 둘 다 재서 "리밸런싱 메커니즘"과 "비용 가정"을 분리했다.

**결과 — 결정적**:

| 시나리오 | CAGR |
|---|---|
| 전체 유니버스, 월별 리밸런싱, 비용 0bps | +6.53% |
| 전체 유니버스, 월별 리밸런싱, 비용 30bps | **+2.94%** |
| 매수-보유 벤치마크(리밸런싱 없음, 재계산 아님) | +4.78% |
| T3(고유동성 tercile), 월별 리밸런싱, 30bps | **-5.77%** |
| T1(저유동성 tercile), 월별 리밸런싱, 30bps | **+11.97%** |

전체 유니버스를 tercile로 안 자르면 월별 리밸런싱+30bps 비용을 반영해도
+2.94%로 정상 범위다(비용 드래그 30bps×12≈연 3.6%로 설명되는 격차, 매수-
보유보다 살짝 낮은 정도). **리밸런싱 메커니즘도 비용 가정도 원인이 아니다.**
문제는 정확히 **turnover20(최근 20일 거래대금) 기준으로 tercile을 나누는
것 그 자체**다.

### 결론 — "왜 이렇게까지 유효한 검증이 없었나"에 대한 답

이 프로젝트가 시도한 **5DC·TREND-BREAKOUT-v1·LOWMOM60·REV20·PBR·PEG·ROE
7개 전략 전부가 "유동성과 무관하게 살아남는가"를 검증할 때 정확히 같은
turnover20 rolling tercile 방식을 유동성 통제변수로 썼다**(대부분
`lowmom60_robustness.py` 계열 코드 재사용). 그런데 이 tercile은 중립적인
통제변수가 아니라 그 자체로 강력하고 방향성 있는 예측변수였다 — 고유동성
(T3)은 거래량 급증 직후를 쫓아가 사는 셈이라 되돌림에 물리고, 저유동성
(T1)은 반대로 강하게 우상향한다(원인은 미확정 — 급증 후 되돌림, 저유동성
종목의 가격 데이터 특성, 혹은 둘 다일 수 있다). 서로 다른 경제적 근거를
가진 7개 가설이 하나같이 "저유동성에서만 플러스"로 수렴한 건 팩터 각각의
문제가 아니라, **공유된 "통제변수"가 실은 팩터보다 훨씬 강한 숨은 신호였기
때문**이다. 지금까지의 모든 "팩터 vs 유동성tercile" 대결은 애초에 공정한
대결이 아니었다.

### 이게 의미하는 것 — 앞으로 무엇을 바꿔야 하는가

- **turnover20 rolling tercile을 "유동성 통제"로 쓰는 관행 자체를 재검토해야
  한다.** 상대적 tercile 대신 절대 거래대금 임계값, 또는 시가총액 기반
  분류가 더 중립적일 수 있다(단, 이것도 검증 필요 — 절대 임계값 자체가
  같은 종류의 숨은 신호를 가질 가능성을 배제 못 한다).
- **오늘 이전에 이 tercile 방식으로 "채택 불가"라고 결론 낸 모든 판정
  (LOWMOM60·REV20·5DC 정밀 스윕·TREND-BREAKOUT)이 재검토 대상일 수 있다** —
  팩터가 진짜 나빴는지, 이 오염된 통제변수 때문에 나빠 보였는지 아직
  모른다. 이번 세션은 이걸 재검토하지 않았다(범위 밖).
- 전체 유니버스·월별 리밸런싱·30bps 비용 자체는 건전하다(+2.94%, 매수-보유
  대비 합리적) — 문제는 스코어링/랭킹이 아니라 "무엇을 유니버스로 삼는가"
  단계에 있었다.

신규 스크립트: `t3_factor_decile_check.py` · `t3_roe_quality_strategy_backtest.py`
· `testbed_mechanics_diagnostic.py` (전부 로컬 미커밋, 관례대로).

## 추가 확인 (같은 세션 재후속) — 오염된 2건 재검토, 둘 다 판정 뒤집힘

후보 A/B/C 기각(`lowmom60_institutional_eligible_precheck.py`) ②PBR "대형주

REV20의 **원래** robustness 검증(`lowmom60_robustness.py`·

사용자 승인("go") 후 이 2건을 재검토했다:

**1단계 — 대체 필터 중립성 검증**(`absolute_turnover_filter_validation.py`):

전체 유니버스 무필터 baseline(+2.94%, testbed_mechanics_diagnostic.py) 대비
고유동성(≥1억원) 버킷 EW 무작위 갭이 -0.68%p에 그쳐 **중립으로 검증됨**
(참고: 저유동성(<1억원) 버킷은 절대임계값으로 나눠도 여전히 강한 프리미엄
(+13.05%, 무작위도 +11.27%)을 보인다 — 이건 tercile 특유의 문제가 아니라
이 데이터셋의 진짜 저유동성 종목 자체가 가진 별개의 미해결 현상이다).

**2단계 — 오염된 2건 재실행**(v2, 유동성 필터만 절대임계값으로 교체, 나머지
로직 완전 동일):

| 결론 | v1(오염된 tercile) | v2(절대임계값, 중립 검증됨) |
|---|---|---|
| LOWMOM60+수급, 대형주/고유동성(`lowmom60_institutional_eligible_precheck_v2_absolute.py`) | -11.8% (기각) | **+13.90%** |
| PBR, 대형주/고유동성(`a5_valuation_factor_precheck_v2_absolute.py`) | -1.48% (반전, 기각) | **+7.06%** |
| PBR, 저유동성 대조군 | — | +7.48%(고유동성과 거의 같음 — 유동성 무관 알파) |

**둘 다 판정이 뒤집혔다.** 상대 tercile 방식이 낸 "채택 불가"는 팩터가
진짜 죽은 게 아니라 오염된 통제변수 때문에 죽어 보인 오판이었다.

## 추가 확인 (같은 세션 3차 후속) — PBR을 실제 Strategy Lab 엔진에 연결 시도, 겹침판정 결함 발견하고 중단

사용자 승인("PBR부터 진행")으로 위 재검토에서 살아난 PBR을 실제 Strategy Lab

### 아키텍처 발견 — 기존 엔진은 횡단면 랭킹 전략을 지원하지 않는다

`strategies/5dc_v1a_p`·`trend_breakout_v1`·`dummy_sma20`를 직접 열어보니 공유
계약(`strategies/base.py`)이 **종목 하나의 OHLCV 기술적 신호**만 다룬다 —
`generate_signals(symbol, features)`가 종목별 독립적으로 돈다. "이번 달
유니버스 전체에서 PBR 낮은 30개" 같은 횡단면 랭킹·월별 리밸런싱 개념 자체가
없다. 사용자에게 이 사실과 선택지(엔진 확장 vs 엔진 밖 독립 경로)를 보고,
"토큰량이 크지 않다면 엔진 확장(1번)"으로 승인받았다.

### 구현 — 엔진 파일은 거의 안 건드리고 새 전략으로 흡수

`research/strategy-lab/strategies/pbr_value_v1/`을 신설:
- `build_selection.py` — 오프라인으로 횡단면 랭킹(그 달 turnover20>=1억원
  안에서 PBR 오름차순 상위 30, `a5_valuation_factor_precheck_v2_absolute.py`
  와 동일 설계)을 계산해 `selection.json`(ticker -> [{date, holdSessions}])
  으로 저장 - `generate_signals(symbol, features)`가 종목 하나만 봐서 랭킹을
  못 하는 인터페이스 제약을 이렇게 우회했다.
- `policy.json` - 5dc_v1a_p와 같은 필드 구조, 이 전략은 가격 기반 stop/target이
  없는 순수 시간청산이라는 점을 `risk` 블록에 명시.
- `rule.py` - `risk_spec_for`가 도달 불가능한 stop/target(entry_price*100)을
  반환해 TIME_EXIT만 나오게 함. holdSessions은 `generate_signals`가 `features`
  DataFrame에 직접 컬럼을 써 넣어(같은 객체 참조를 runner.py가 이미
  `features_by_ticker`에 저장해 둔 뒤라 이 mutation이 그대로 반영됨)
  `risk_spec_for`가 나중에 읽게 하는 방식으로 전달 - `risk_spec_for(row)`가
  symbol을 모른다는 계약 제약(`strategies/base.py`)을 엔진 변경 없이 우회.
- `run_pbr_value_v1.py` - `engine.runner.run_smoke()`를 그대로 사용(파이프라인

비용·월별 리밸런싱으로 (a) T1/T3 버킷을 통째로 동일가중 매수하거나 (b) 버킷
안에서 무작위로 30종목을 뽑는(20개 시드 반복) 플라시보 백테스트.

**결과**:

| 시나리오 | CAGR |
|---|---|
| T1 버킷 전체, 동일가중(팩터 없음) | +11.97% |
| T3 버킷 전체, 동일가중(팩터 없음) | -5.74% |
| T1에서 무작위 30종목(20회 평균) | **+10.26%** (범위 +4.69%~+16.18%) |
| T3에서 무작위 30종목(20회 평균) | -6.86% (범위 -12.88%~-1.90%) |

**무작위로 뽑은 T1 30종목(+10.26%)이 PEG로 고른 T1(+4.08%)이나 ROE로 고른
T1(+8.68%)보다 높다.** 즉 팩터 기반 선별이 순수 무작위보다 나은 게 없었다
— 세 팩터가 측정한 건 팩터 알파가 아니라 T1 버킷 소속 여부 그 자체였다.

이 T1 프리미엄이 실제로 거래 가능한지는 §1 4번(A)(B)에 이미 정리한 대로
2026-08-18 REV20 검증이 부정적 근거를 이미 갖고 있다 — 현실적 비용 하에서
소멸을 확인한 바 있다.
