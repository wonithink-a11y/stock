# KRX 투자자별 옵션 거래 — 탐색 기록 (2026-09-28)

옵션 감마 사전등록(`research/strategy-lab/findings/kospi200-option-gamma-preregistration-2026-09.md`) §6 의
"딜러 부호를 자료로 추정하는 변형"이 가능한지 본 탐색. **수익률·감마는 계산하지 않았다.** 호출 약 15회.

## 결론

- **있다 — 단, 행사가별이 아니라 상품 × 콜/풋 × 투자자 단위의 일별 순매수(거래량·거래대금)다.** 투자자별 **미결제약정(보유 잔고)은 없다.**
- 경로는 공식 Open API 가 아니라 **KRX 정보데이터시스템(로그인)** — pykrx 1.2.8 의 로그인 세션을 빌려 `getJsonData.cmd` 에 직접 보낸다.
  pykrx 는 이 화면을 감싸지 않는다. 비공식 경로라 production PRIMARY 로 쓰지 않는다(data-source-availability.md 방침 그대로), 연구 전용.
- 2010-01 부터 나온다. 기간 조회(최대 약 2년/회)라 전 기간이 **수십 회 호출**이면 끝난다.

## 엔드포인트 (재현용)

| 항목 | 값 |
|---|---|
| 화면 | 통계 → 파생상품 → 거래실적 → 투자자별 거래실적 (`menuId=MDC0201050302`, jsp `MDCSTAT131`) |
| 데이터 | `POST https://data.krx.co.kr/comm/bldAttendant/getJsonData.cmd` |
| 하루 합계(투자자 11행) | `bld=dbms/MDC/STAT/standard/MDCSTAT13101` · `inqTpCd=1` |
| 일별 추이(투자자별 열) | `bld=dbms/MDC/STAT/standard/MDCSTAT13103` · `inqTpCd=2` · `prtType=QTY\|AMT` · `prtCheck=DO\|SU\|SUN`(매도·매수·순매수) |
| 상품 | `prodId=isuCd=KR___OPK2I`(코스피200 옵션). ★ pykrx 의 `KRDRVOPK2I` 를 넣으면 **오류 없이 전부 0** 이 온다 — 조용히 틀린다 |
| 콜/풋 | `isuOpt=C\|P` |
| 날짜 | `strtDd`·`endDd` = YYYYMMDD |

13103 열(2026-09-23 행 대조로 짐작, 13101 의 투자자명과 값이 맞는 것만 확정): A01 금융투자 · A03 투신 · A08 기타법인 · A09 개인 · A10 외국인.
A02·A04·A05·A06·A11 은 보험·은행·기타금융·연기금·(A10 과 같은 값 — 외국인 합계로 추정)으로 보이나 **미확정** — 쓰기 전에 13101 과 날짜별로 대조한다.
위클리·미니 상품 코드(`KR___OPWKI`·`KR___OPMKI` 추정)는 시험하지 않았다.

## 관찰 (판단 재료, 판정 아님)

- 2026-09-23 코스피200 옵션 콜 거래량: 외국인 21.6천 · 개인 12.4천 · **금융투자 1.1천(약 3%)**. 풋도 비슷하다.
  미국식 "딜러 = 증권사"를 금융투자로 옮기면 **시장의 몇 %만 본다** — 한국 옵션의 반대편은 주로 외국인과 개인이다.
  즉 사전등록의 부호 가정(딜러 = 콜 매수·풋 매도)은 한국에서 **누가 딜러인가부터 불분명**하다. 셀 T(부호 없음)를 둔 이유가 여기서 확인된다.
- 순매수는 흐름이지 잔고가 아니다. 잔고로 쓰려면 만기마다 끊기는 누적이 필요하고, 옛 만기분이 섞이는 오차가 남는다.
