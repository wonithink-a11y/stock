## 새 세션은 여기부터

1. **가장 중요한 사실 하나**: TREND-BREAKOUT-v1의 신뢰 가능한 baseline은
   **2,154건**(same-bar 스케줄링 버그 수정 후)이다. **1,400건 기준으로 나온
   이전 분석 결과(연도별 성과·국면 연결 통계·초기 MFE/MAE)는 오염
   가능성이 있어 재확인 없이 인용하지 않는다.** 아래 "1,400건 vs 2,154건"
   절 참고.
2. TREND-BREAKOUT-v1은 **research/strategy-lab 내부의 탐색적 후보
   전략**이다. production과 5DC-v1A-P는 이 세션에서 전혀 건드리지 않았다.
3. `engine/runner.py`의 same-bar 스케줄링 버그 수정은 이번 세션에서
   `research/strategy-lab` 공통 엔진에 실제로 반영됐다(아래 "커밋된 산출물"
   절의 커밋 해시 참고). 5DC-v1A-P를 포함해 이 엔진을 쓰는 모든 전략의
   재현 결과에 영향을 줄 수 있다 — 5DC-v1A-P의 2026-08-14 baseline은
   **이 수정 이전에 만들어졌다**(재실행 여부는 이 세션에서 다루지 않았고,
   결정도 내리지 않았다).
4. TREND-BREAKOUT-v1은 여전히 전략으로 채택되지 않았다 — 성과 자체가
   좋다는 결론은 어디에도 없다. 이번 세션의 산출물은 전부 진단/탐색용이다.

## 1,400건(수정 전) vs 2,154건(수정 후) — 반드시 구분

| | 1,400건 baseline | 2,154건 baseline |
|---|---|---|
| 상태 | **오염 가능** — same-bar 스케줄링 버그로 인해 서로 다른 두 거래의 진입/청산이 병합된 레코드 136건(9.7%) 포함, 종료시점 미청산 10건 전부 버그 산물 | 버그 수정 후 재실행, 신뢰 가능 |
| closed trades | 1,400 | 2,154 |
| open at end | 10 (전부 버그 산물로 확인됨) | 0 |
| win rate | 26.07% | 24.88% |
| profit factor | 0.834 | 0.783 |
| CAGR | -8.30% | **-12.25%** |
| MDD | -70.89% | **-83.34%** |
| Sharpe | -0.653 | -0.974 |
| 평균 보유기간 | 20.84일 | 13.69일 |
| STOP인데 pnl>0인 이례 사례 | 18건 (버그 신호) | **0건** (해소 확인) |

버그 수정 후 성과는 **개선이 아니라 악화**됐다. same-bar 거래가 그날 즉시
청산되면서 자본 회전이 빨라졌고(평균 보유기간 -34%), 같은 음의 기대값을
가진 거래에 더 자주 노출되는 복리 효과로 CAGR·MDD·Sharpe 전부 악화됐다
— 이는 재실행 직후 세션에서 나온 관찰이며, 이 문서에서 새로 해석을
더하지 않았다.

**1,400건 기준으로 실행됐던 다음 분석들은 재확인 전까지 신뢰하지 않는다**:
- B(55일 Donchian)·A(2.5×ATR) 실험 비교(exit type, capture ratio 등)
- 연도별 성과 분석(2019·2021·2022·2024 공통 손실연도 관찰)
- KOSPI/KOSDAQ 국면 분류(A: MA200+기울기, B: 52주고저±20%) 연결 통계
- 최초 MFE/MAE 분석(STOP+pnl>0 18건 발견의 근거가 된 그 실행)

이 분석들의 **방법론**(스크립트 구조, 계산 로직) 자체는 여전히 유효할 수
있으나, **입력 데이터가 오염된 1,400건**이었으므로 수치는 2,154건으로
재실행해 재확인해야 한다. 이번 세션에서 재확인된 것은 MFE/MAE
분석(2,154건판)과 ATR%×MFE 교차분석, ATR×2.0 stop 구조 검증 세 가지뿐이다
(아래 절 참고).

## 이번 세션에 뭘 했나 (시간 순)

### 1. TREND-BREAKOUT-v1 설계·구현
Donchian 채널 돌파 후보 전략을 조사·설계 후 구현. 5DC-v1A-P의
RiskSpec·execution·portfolio·cost 계약을 그대로 재사용(신규 코드는
`engine/indicators/donchian.py` 지표 하나뿐). 계약: 20일 Donchian
edge-triggered breakout, entry=next session open, stop=2×ATR[t],
target=entry+3×stop_distance, time-exit=60세션, cost/portfolio는
5DC-v1A-P와 동일 수치. survivorship 제한(A1A_ONLY, A2b 미수집) 동일하게
명시.

구현 파일: `strategies/trend_breakout_v1/policy.json`·`rule.py`,
`engine/indicators/donchian.py`, `tests/test_donchian.py`·
`test_trend_breakout_v1.py`. 회귀 통과 확인(단일 shift 계약 검증 포함
donchian 전용 테스트로 lookahead·이중지연 없음 확인).

### 2. 최초 SMOKE 실행 (20일/2.0×ATR) — 이후 오염으로 판명
2014-05-13~2026-08-03, A1A_ONLY 2,558종목. signal 157,643건 → closed
1,400건, open 10건. CAGR -8.30%, MDD -70.89%, Sharpe -0.653, win rate
26.07%, PF 0.834. **이 실행 결과는 same-bar 버그를 포함한 채로 나온
것이다** (버그는 이 시점엔 아직 발견 전).

### 3. B(55일)·A(2.5×ATR) 실험
파라미터 하나씩만 바꾼 두 실험을 실행하고 baseline으로 원복(현재
policy.json/rule.py는 baseline 값인 period=20, `_ATR_MULTIPLE=2.0`으로
확인된 상태). 최적화나 파라미터 채택 없이 관찰만 진행. **이 실험들도
1,400건 기준 엔진으로 실행됐다.**

### 4. exit-type·연도별·국면 분석 (1,400건 기준)
실제 편입 거래(157k 신호 모집단과 다른 모집단)의 STOP/TARGET/TIME_EXIT
분해, 연도별 성과, KOSPI/KOSDAQ 국면 분류(A: MA200+기울기 부호, B: 52주
고저 ±20%) 설계·실측·전략 성과 연결 통계(bootstrap CI, Welch t,
Mann-Whitney)까지 진행. **전부 1,400건 기준 — 위 표 참고, 재확인 필요.**

### 5. KOSPI/KOSDAQ 지수 데이터 확보·검증 (독립 조사, 오염과 무관)
Naver fchart(`fetchDailyCandlesKR`와 동일 경로)로 KOSPI/KOSDAQ 각
3,000건(2014-05-26~2026-08-14, count=3001 요청 시 3,000건 절단 확인)
확보. 전수 품질검사(중복 날짜 0·OHLC 논리오류 0·0값 0·비정상 공백 1건뿐

데이터 자체는 버그와 무관하며 유효하다.

이전상장(KOSPI↔KOSDAQ) 시장 매핑 규칙도 확정: `date>=listedAt`인 거래만

### 6. same-bar 스케줄링 버그 발견
MFE/MAE 분석(1,400건 기준) 중 "exit_type=STOP인데 실현손익이 양수"인
거래 18건 발견. `002630` 종목을 `resolved`(엔진 원본) 레벨까지 추적해
원인 확인: `engine/runner.py`의 날짜별 이벤트 루프가, 당일 진입+당일
청산(order_date == exit_fill.fill_date, same-bar) 거래의 청산을
"아직 오늘 admission 안 됨"으로 오판해 누락시키고, 그 심볼의 나중
거래(완전히 별개의 거래) 청산 이벤트가 오면 그걸로 대신 청산 — 서로 다른
두 거래의 entry/exit이 병합된 가짜 레코드를 만드는 구조적 버그였다.

전수조사(`resolved` 94,548건 대상): same-bar 거래 5,551건, 이 중 실제로
병합돼 나타난 건 136건(1,400건 baseline의 9.7%), 종료시점 미청산 10건은
전부(10/10) 이 버그의 산물. 총 146/1,410건(10.4%) 영향 확인.

### 7. 버그 수정
`engine/runner.py`: 날짜별 스케줄링 루프를 `_schedule_portfolio()` 함수로
추출(순수 구조 추출, 동작 무변경)한 뒤, same-bar 청산을 "오늘 진입 admission
이후 같은 날짜에 재시도"하도록 로직 추가. **진입/청산 파라미터
(Donchian·ATR·RiskSpec·cost·portfolio 계약)는 전혀 변경하지 않았다.**
신규 회귀 `tests/test_runner_scheduling.py`(3건: 병합 방지·후속거래 없어도
정상청산·기존 정상케이스 무변경)를 추가하고, 기존 14개 파일 포함 전체 15개
파일 회귀 통과 확인.

### 8. 수정 후 baseline 재실행 (2,154건)
동일 조건(20일/2.0×ATR, 2014-05-13~2026-08-03, A1A_ONLY)으로 처음부터
재실행. 위 "1,400건 vs 2,154건" 표 참고. `equityCurveReplayMatchesRunnerBookkeeping:
true`로 재현 정합성 확인. STOP+pnl>0 이례 사례 0건으로 버그 해소 재확인.

### 9. 2,154건 기준 재분석 — MFE/MAE
승/패·극단거래(상하위10%) 비교. 손실거래 75.1%, capture ratio 수익거래
중앙값 0.818 / 손실거래 -1.718. 이전 1,400건 분석과 구조적으로 비교했을
때, 큰손실 거래의 평균 보유기간이 43.2일(1,400건)→8.1일(2,154건)로
크게 짧아짐 — "정체된 포지션이 오래 방치된다"던 이전 관찰의 상당 부분이
버그로 인한 인위적 병합 결과였을 가능성이 있다는 점만 기록(새 결론 아님,
이미 그 실행 직후 나온 관찰).

### 10. 2,154건 기준 재분석 — ATR%×MFE 교차분석
ATR% 3분위(저/중/고변동, 데이터 자체 분포로 분할) 별 승률·평균수익률·PF·MAE·MFE
비교. 승률 차이는 카이제곱 p=0.215로 유의하지 않음. 평균수익률 차이는
유의하나(bootstrap 95%CI [-3.604%,-0.412%], Welch p=0.0127) 효과크기
작음(Cohen's d=-0.132). 손실거래의 78.3%가 MFE≥1%(한때 유리했다 반납)
유형이고, 이 그룹의 진입 ATR%가 대조군보다 유의하게 높음(+0.968%p,
95%CI[0.774%,1.156%], p<0.0001). ATR 3분위×MFE구간 카이제곱 매우
유의(p<0.0001) — 저변동은 "즉시 불리" 손실 비중이 상대적으로 높고(33.5%),
고변동은 "유리했다 반납"형이 압도적(88.3%).

### 11. 2,154건 기준 재분석 — ATR×2.0 stop 구조 검증
`stop_distance_pct == 2×atr_pct` 공식 검산 오차 0 확인. ATR% vs |MAE|
상관: Pearson r=0.820, Spearman ρ=0.878(매우 강함). MAE/stop_distance
비율이 ATR 3분위 전반 1.27~1.32로 거의 일정(추세 없음). "이론적 stop
대비 초과손실"의 고변동-저변동 차이는 통계적으로 유의하나 크기는 작음
(-0.1315%p, 95%CI[-0.2653%,-0.0257%], Welch p=0.0340) — 표준편차는
고변동에서 5배 커짐(0.27%p→1.40%p).

이 실행 직후 정리된 결론(새로 추가한 해석 아님):
- ATR×2.0 stop 구조가 손실 크기를 기계적으로 결정한다는 근거는 강함
  (r=0.82, MAE/stop 비율 안정적)
- 고변동 종목 고유의 "추가" 위험은 평균적으론 미미하나(초과손실 -0.13%p)
  꼬리 위험(표준편차)은 뚜렷이 큼
- 다음 실험 가설(미착수, 제안만 된 상태): stop_distance를 ATR 비례
  대신 고정폭/상한으로 바꿨을 때 고변동 구간의 평균 손실과 반납폭이
  실제로 줄어드는지 검증

   높다고 제안된 항목은 "다음 실험 가설" 절 참고, 실행 여부는 결정된 바
   없음
