# autotrader — 사용자 키로 돌리는 전략 교체형 자동매매 프로그램 설계 (2026-09-19)

**상태: 설계만 작성했다. 구현은 자동 모드 분류기가 막아서 착수하지 못했다**(§7). 사용자가 GO 했고(2026-09-19,
한국투자증권 첫 브로커), 이 문서는 구현이 재개될 때의 기준이다.

**경계(변하지 않는다)**: 프로그램은 **사용자가** 키를 넣고 **사용자가** 켜고 **사용자 서버(VM)** 에서 돈다. Claude 는
키를 입력·열람하지 않고, 실계좌 모드를 켜지 않고, 실주문을 내지 않는다. Claude 는 실계좌로 시험할 수 없으므로 실계좌 경로는
모의·가짜 브로커로만 검증된다 — 실전에서 정확히 동작한다는 보증은 없다.

## 1. 목표

- 사용자가 API 앱키·시크릿을 **gitignore 된 자리**에만 넣는다(저장소·로그·커밋에 절대 안 들어간다).
- 전략을 **플러그인 하나(파이썬 파일 하나)** 로 갈아끼운다. 전략은 "지금 낼 주문 목록"만 돌려준다.
- 모의(KIS 모의투자)와 실전(KIS 실계좌)이 **같은 코드 경로**를 타고, 실전은 여러 겹의 스위치 뒤에 잠긴다.
- 기본값은 항상 **dry-run**(주문 없음). 주문은 `--execute` 를 명시해야 나간다.

### 전략 인터페이스 (사용자가 갈아끼우는 부분)

```python
class Strategy:
    name = "my_strategy"
    markets = ["KR"]                     # "KR"(국내) / "US"(해외 나스닥)
    def decide(self, ctx) -> list[Intent]:
        # ctx.positions(market), ctx.cash(market), ctx.quote(symbol, market),
        # ctx.now(KST), ctx.state(dict, 실행 사이 유지), ctx.params(설정의 params)
        return [Intent("005930", "BUY", 3, market="KR", order_type="market", reason="...")]
```

`Intent` = 종목·매수/매도·수량·시장·주문유형(`limit`|`market`|`loc`)·지정가·사유. 전략은 **브로커를 직접 부르지 않는다**
— 주문은 엔진만 낸다(위험 검사가 모든 주문의 유일한 관문이 되도록).

## 3. KIS 어댑터

| 항목 | 모의(paper) | 실전(live) | 검증 상태 |
|---|---|---|---|
| 도메인 | `openapivts…:29443` | `openapi…:9443` | 모의는 기존 클라이언트로 검증, 실전 도메인은 표준값 |
| 키 | `KIS_VTS_APP_KEY/SECRET/ACCOUNT_NO` (기존 이름) | **`KIS_LIVE_APP_KEY/SECRET/ACCOUNT_NO` (신규 전용 이름)** | 실전 키는 시세용 `KIS_APP_KEY` 와 섞이지 않게 이름을 분리 |
| 국내 주문 | VTTC0012U(매수)·VTTC0011U(매도) | 같은 자리 앞 글자 V→T (TTTC0012U·TTTC0011U) | 모의 검증됨 / **실전 미확인** |
| 국내 잔고·체결 | VTTC8434R · VTTC0081R | TTTC8434R · TTTC0081R | 모의 검증됨 / **실전 미확인** |
| 해외 주문 | VTTT1002U·VTTT1001U | TTTT1002U·TTTT1006U | 기존 클라이언트 주석에 실전 값 명시 / 실전 미검증 |
| 해외 취소 | VTTT1004U | TTTT1004U | 공식 예제 원문으로 확인(2026-09-19) |
| 해외 잔고·미체결·매수가능 | VTTS3012R·3018R·3007R | TTTS3012R·3018R·3007R | 모의 검증됨 / **실전 미확인** |
| 국내 취소 | (만들지 않는다) | (만들지 않는다) | KRX 주문은 당일물 — 미체결은 장 마감에 소멸, 정합 단계에서 "오늘 미체결이 있으면 그 종목 건너뜀" |

**모의 TR_ID → 실전은 "앞 글자 V→T" 규칙**이 KIS 전반에 일관되지만, 이번 세션에서 실전 값을 공식 문서로 대조하는 열람이
막혀 **실전 TR_ID 는 전부 미확인**이다. 그래서 실전 모드에는 **`live.tr_ids_reviewed: true`**(사용자가 공식 문서
`open-trading-api` 예제와 대조했다는 표시)라는 별도 게이트를 둔다(§4).

- LOC(34) 등 실전 전용 주문유형은 `loc` 로 표현하고 **해외 실전에서만** 허용한다(모의는 지정가만).
- 주문은 **재시도하지 않는다**(중복 매수 위험, 기존 클라이언트와 같은 원칙). 조회만 EGW00201/00300 에서 재시도.
- 유량 제한: 프로세스 단일 리미터(계좌 단위 초당 건수). 토큰은 모드별 캐시 파일(gitignore).

## 4. 실계좌 모드 게이트 (전부 충족해야 열린다, 하나라도 빠지면 실행 거부 — 조용히 강등하지 않는다)

1. 설정 `"mode": "live"`
2. 설정 `"live": {"enabled": true}`
3. 설정 `"live": {"tr_ids_reviewed": true}` — 사용자가 §3 의 미확인 TR_ID 를 공식 문서로 대조했다는 확인
4. 환경변수 `AUTOTRADER_ALLOW_LIVE=I-ACCEPT-REAL-TRADES` — 설정 파일만 고쳐서는 못 켠다(서비스 환경에만 둔다)
5. `KIS_LIVE_*` 키 3종 존재
6. 킬 스위치 파일 `autotrader/state/KILL` 없음
7. 실행 인자 `--execute`

모의 모드는 3·4·5 대신 `KIS_VTS_*` 키만 필요. **어느 모드든 `--execute` 없으면 주문이 안 나간다(dry-run).**

## 5. 위험 검사 (전 주문의 유일한 관문, 순수 함수 — 시장별 통화 기준)

- 주문당 최대 금액 · 일일 최대 금액(원장 합산) · 1회 실행당 최대 주문 수 · 종목당 최대 보유금액
- 종목 허용목록(설정에 없으면 거부) · 매도 허용 여부 · **공매도·신용 없음**(잔고 이상 매도는 거부)
- 지정가 밴드: 지정가가 직전 시세의 ±X% 를 벗어나면 거부(호가 착오 방지)
- 수량 0 이하·소수·NaN 거부, 같은 실행 안 중복(같은 종목·같은 방향) 합산 한도
- 위반 시 그 주문만 거부하고 사유를 기록한다. **한도 초과가 심각한 오류(예: 일일 한도 초과 시도)이면 실행 전체 중단**
- 킬 스위치: 파일 하나(`autotrader kill` / `resume`) — 엔진은 매 주문 직전에 다시 확인한다

## 6. 정합·원장·재현성

- **원장(jsonl, gitignore)**: 실행ID·시각(KST)·모드·전략·종목·방향·수량·가격·주문번호·결과. 일일 한도의 근거이자 감사 기록.
- **우리가 낸 주문만 취소한다**(원장에 주문번호가 있는 것). 사용자가 수동으로 낸 주문은 절대 건드리지 않고, 같은 종목에 남의 미체결이
  있으면 그 종목은 건너뛴다(충돌 기록).
- 해외(US): 무한매수법 러너와 같은 **취소→재조회 확인→계좌 조회→재계획→재접수**, 미체결이 남으면 그 종목은 그날 주문 안 냄.
- 브로커 잔고가 정본이다 — 로컬 장부로 추측하지 않는다.
- 실행 리포트(JSON): 게이트 통과 내역·의도 목록·위험 거부 사유·주문 결과·건너뜀. 키·계좌번호는 마스킹.

## 7. 구현이 막힌 사유와 재개 조건

구현 착수(`mkdir autotrader/...`)를 **자동 모드 분류기가 "Real-World Transactions" 로 거부했다**. 이 세션 앞서 KIS 공식 문서
열람도 같은 사유로 막혔다. 우회하지 않았다. 재개하려면 사용자가 다음 중 하나를 한다:

- (권고) Claude Code 설정에 `autotrader/` 경로 쓰기·Bash 를 허용하는 규칙을 추가한다(Bash 권한 규칙 — 이 프로젝트는 유닛 파일
  때도 같은 방식으로 풀렸다). 그러면 이 설계대로 구현·모의 검증까지 진행한다.
- 또는 사용자가 디렉터리를 만들어 주면 그 안의 파일 작성부터 이어간다.
- 또는 이 설계만 두고 사용자가 다른 도구로 구현한다(이 문서가 명세다).

## 8. 검증 계획 (Claude 가 할 수 있는 범위)

- 회귀 `scripts/test-autotrader.py`(키·네트워크 없음): 게이트 7조건 각각이 빠졌을 때 거부, dry-run 기본, 위험 검사 각 규칙,
  일일 한도 합산, 우리 주문만 취소, 남의 미체결 종목 건너뜀, 킬 스위치가 주문 직전에 다시 확인됨, TR_ID 표(모의/실전) 오타 방지,
  키·계좌 마스킹.
- KIS 모의계좌에 대한 **읽기 전용 dry-run**(기존 방식). 모의 `--execute` 는 사용자가 원할 때.
- **하지 않는 것**: 실계좌 호출, 실계좌 키 사용, `--execute` + live.

## 9. 사용자 체크리스트 (실전 전환 전)

1. 전략을 모의로 충분히 돌려 동작·체결 차이를 본다.
2. KIS Open API 실전 앱키 발급 시 **주문 권한만**(가능하면 IP 제한).
3. §3 의 실전 TR_ID 를 공식 예제와 대조하고 `tr_ids_reviewed` 를 켠다.
4. 한도를 아주 작게(주문당·일일) 시작하고 며칠 관찰 후 올린다.
5. 킬 스위치 사용법을 미리 익힌다(`python -m autotrader kill`).
