# 장 마감 리포트 — 루틴 지시문 (정본)

Claude 루틴(클라우드 예약 실행)이 매번 이 파일을 읽고 따른다. 루틴 등록 프롬프트에는 모드(kr/us)와
"이 파일을 따르라"만 둔다 — 지시를 고칠 때 루틴을 다시 등록하지 않게.
설계·근거: `docs/control/시장마감리포트-설계-2026-10-13.md`.

**이 리포트는 시황 설명이다. 매수·매도 권유, 가격 목표, 확률 숫자를 쓰지 않는다.**

## 0. 모드와 시각

| 모드 | 실행 | 다루는 장 | 파일 |
|---|---|---|---|
| `kr` | 평일 18:10 KST | 오늘 한국 정규장 | `reports/market-daily/YYYY-MM-DD-kr.md` (YYYY-MM-DD = 한국 날짜) |
| `us` | 평일(화~토) 07:00 KST | 직전 미국 정규장 + 오늘 한국장 체크 | `reports/market-daily/YYYY-MM-DD-us.md` (YYYY-MM-DD = **미국 장 날짜**) |

## 1. 숫자 받기 — 숫자는 이것만 쓴다

```bash
git fetch origin main && git checkout -B main origin/main   # 루틴 체크아웃은 detached HEAD 라 pull 이 안 된다(10-13 실측)
python scripts/market-close-facts.py <kr|us> --out reports/market-daily/<날짜>-<kr|us>.facts.json
```

- **출처 대부분이 `error`(예: `Tunnel connection failed: 403`)면 네트워크 차단이다** — 리포트를 쓰지 않고, facts.json 을 지우고, 차단된 도메인을 보고하고 끝낸다.

- `us` 모드에서 실적 발표 종목의 시간외를 보려면 웹에서 어젯밤 실적 발표 종목을 먼저 찾고 `--ah SYM1,SYM2` 로 다시 돌린다(대형 기술주 8개는 기본).
- **`sessionOpen` 이 false 거나 `regularSessionEnded` 가 false 면 리포트를 쓰지 않고 끝낸다**(휴장·장중). facts.json 도 커밋하지 않는다.
- 리포트의 모든 숫자는 facts.json 에서 그대로 옮긴다. 웹 기사에서 숫자를 가져오면(경제지표 발표치·예상치 등) 반드시 출처 링크를 붙인다.
- 새 비율·합계를 만들지 않는다. 허용: 두 값의 차(예: RSP − SPY), 순위 정렬.
- `fresh: false` 인 값은 쓰지 말거나 "(○월 ○일 값)"으로 날짜를 붙인다. `missing` 항목은 리포트 끝 "수집 안 됨"에 그대로 적는다.
- `repoData` 의 저장소 JSON(급등락·수급·공시·뉴스·일정)은 **날짜가 다룰 장과 같을 때만** 쓴다. Actions 가 4~12시간 늦게 갱신하므로
  `kr` 모드에서는 거의 항상 전날 값이다 — 그러면 쓰지 않는다. `events.json` 은 앞으로의 일정이라 하루 지나도 쓴다.

## 2. 원인 찾기 — 리포트의 핵심

웹 검색으로 그날 움직임의 원인 후보를 찾는다. 후보마다:

1. **근거**: 무슨 일이 있었나 · 발표/보도 **시각(KST)** · 출처 링크(1차 출처 우선 — 기관 발표, 기업 공시, DART, SEC, 주요 통신사).
2. **시각 대조**: 그 사건이 가격 움직임보다 먼저인가. 장 마감 뒤 기사가 "○○ 때문에 하락"이라고 쓴 것은 근거가 아니라 해석이다.
3. **시장 반응**: facts.json 의 어느 숫자가 이 설명과 맞는가(업종 ETF·섹터·금리·환율).
4. **반대 증거**: 이 설명과 안 맞는 움직임.
5. **확신도**: 높음(1차 출처 + 시각 선행 + 관련 자산이 같은 방향) · 중간(둘만) · 낮음(언론 해석뿐).

근거가 부족하면 **"원인 미확정"** 이라고 쓴다. 그럴듯한 이야기로 채우지 않는다.

금지:
- **종목의 지수 기여도 수치**("반도체 2종목이 하락분의 70%") — 지수 구성 비중 데이터가 없다. 대신 "시총 1·2위 삼성전자 −8.6%·SK하이닉스 −9.0%"처럼 등락률과 시총만 쓴다.
- 정규장 등락률과 시간외 등락률을 더하기.
- 개별 종목 하나의 움직임을 업종 전체로 일반화하기.

## 3. 리포트 형식

텔레그램으로 그대로 간다(서식 없는 일반 텍스트). **표(|)를 쓰지 말고 짧은 줄로 쓴다. 전체 3,500자 이내.**
제목·소제목은 `■`, 항목은 `·` 로.

### kr 모드

```
■ 한국장 마감 YYYY-MM-DD(요일)
한 줄: (오늘을 한 문장으로)

■ 숫자

· 거래대금 KOSPI 00.0조 · KOSDAQ 0.0조
· 종목 수 KOSPI 상승 00 / 하락 000 (상한 0·하한 0)
· 수급(잠정, 억원) KOSPI 외국인 −0,000 · 기관 +0,000 · 개인 +0,000 / 프로그램 −0,000
· 원/달러 0,000.0 · 미국 지수선물(지금) S&P −0.0% · 나스닥 −0.0%
· 시총 상위: 삼성전자 −0.0% · SK하이닉스 −0.0% · ...(5개)

■ 업종 (ETF 기준, 상위 3 · 하위 3)

■ 왜 움직였나
1) (원인) — 확신도 높음/중간/낮음
   근거: ... (HH:MM, 출처 링크)
   반응: ... / 반대 증거: ...
2) ...

■ 장 마감 뒤 공시·뉴스 (15:30 이후, 시각 표기)

■ 내일 볼 것 (일정만 — events.json·경제지표·실적 발표)

■ 연구 메모 (4절 조건에 맞을 때만, 없으면 이 절 생략)

■ 수집 안 됨: (facts.json missing + 날짜가 안 맞아 뺀 것)
```

## 4. 연구 메모 — 조건이 맞을 때만, 조건과 함께

이 프로젝트가 과거 자료로 검증한 결과다. **아래 조건이 그날 실제로 성립할 때만** 해당 줄을 인용하고, 조건을 같이 적는다.
조건이 비슷하지만 다르면 쓰지 않는다(일반화 금지). 전부 "평균적으로 그랬다"이지 그날의 예측이 아니다.

| 조건 (그날 확인할 것) | 알려진 것 | 출처 |

## 5. 저장·전달

1. `reports/market-daily/<날짜>-<kr|us>.md` 와 `.facts.json` 을 커밋한다. 다른 파일은 건드리지 않는다(`git add` 에 두 파일만 명시).
2. 커밋 메시지: `report(market-daily): <날짜> <kr|us>`.
3. push. 거절되면 `git pull --rebase` 후 다시 push(force 금지). 3번 실패하면 멈추고 그 사실을 루틴 출력에 남긴다.
4. push 되면 `market-report-telegram` 워크플로가 1분 안에 텔레그램 1:1 방으로 보낸다. 루틴이 텔레그램을 직접 부르지 않는다.
5. **같은 날짜·모드 파일이 이미 있으면 새로 쓰지 않는다**(중복 발송 방지 — 이미 보낸 날이다).

## 6. 백필 모드 (과거 날짜를 몰아 쓸 때만)

프롬프트가 "백필"과 날짜 목록을 주면:

1. `reports/market-daily/<날짜>-<kr|us>.facts.json` 이 **이미 커밋돼 있으면 스크립트를 다시 돌리지 않고 그 파일을 쓴다**
   (로컬에서 `--date` 로 만들어 커밋한 것. 없으면 `python scripts/market-close-facts.py <kr|us> --date <날짜> --out ...`).
   `sessionOpen` 이 false 인 날(휴장)은 건너뛴다.
2. 원인 조사는 **그 날짜에 나온 기사·발표만** 쓴다. 그 뒤에 나온 기사(사후 해설)는 근거로 쓰지 않는다.
3. 과거 날짜엔 종목 수·프로그램·시총 상위·시간외가 없다 — "수집 안 됨"에 적는다. "내일 볼 것"·"오늘 한국장 체크"는 그날 시점에
   이미 알려진 것만 쓴다. **다음 날 실제로 어떻게 됐는지는 쓰지 않는다**(사후 지식 금지 — 그날 저녁에 쓴 리포트처럼).
4. 날짜마다 따로 커밋하지 않고 **한 번에 커밋**한다. 커밋 메시지에 반드시 `[no-telegram]` — 텔레그램으로 몰아 보내지 않는다(대시보드에만 실린다).
