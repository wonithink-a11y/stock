# 손절선 이탈 1분 알림 + 엔진 멈춤 알림 — 설계 (2026-11-15, 구현은 한도 리셋 뒤)

## 결정(사용자 11-15)
- 채널: **텔레그램 주, 카카오 보조**(카카오는 "나에게 보내기"라 푸시가 안 온다 — 보조·기록용). 알림 방은 무음 해제를 사용자가 확인.
- 반복: 이탈 시 **1분 간격 10번 → 이후 5분 간격**, 확인(ack) 신호를 보내면 멈춘다.
- 손절선 입력: **엔진(전략)이 계산해 올리는 것이 기본 + 직접 입력도 같이**.
- 성격: **알림이지 자동 매도가 아니다.** Workers 는 주문하지 않는다(실매매는 엔진·사용자). 한도는 계속 작게.

## 구조 (기존 `cloudflare/alerts` 확장, 무료 한도 안)
- cron `*/5` 를 `* * * * *` 로 바꿔 5개 cron 한도 안에서 1분 감시(기존 5분 작업은 `minute % 5 == 0` 일 때만 실행해 동작 동일).
- KV 키: `stops`(감시 목록 `{id,tkr,mkt,stop,src:"engine|manual",at}`) · `breach`(id→처음 이탈 시각, 한 번만 쓴다) · `ack`(id→시각) · `hb`(엔진 마지막 하트비트).
- 관리 HTTP(기존 `ADMIN_KEY` 인증 재사용): `POST /stops`(엔진·수동 입력) · `POST /ack` · `POST /hb`(태블릿 `run-loop.sh` 가 5분마다 호출) · `GET /stops`.
- 발송: 이탈 지속 중 `elapsed = now - breach[id]` 로 몇 번째인지 **계산**한다(분마다 KV 에 쓰지 않음 — 쓰기 하루 1,000회 한도 보호). 1~10분차는 매분, 그 뒤는 5분마다. ack 면 중단, 가격이 손절선 위로 회복되면 `breach` 삭제 + 회복 알림 1회.
- **엔진 멈춤 알림**: 감시 목록이 비어 있지 않을 때만, 하트비트가 20분 넘게 없으면 텔레그램(+카카오) — 30분마다 반복, 하트비트가 돌아오면 해제. 목록이 비면 알리지 않는다(주말 외출 오탐 방지).

## 무료 한도 계산 (공식 문서 확인 11-07·11-14)
- 요청: cron 1,440/일 + 하트비트 288/일 ≪ 10만/일. KV 읽기 실행당 ~4회 × 1,440 ≈ 5,800/일 ≪ 10만. KV 쓰기: 손절선 갱신·이탈 시작·ack 정도(수십/일) ≪ 1,000.
- 실행당 외부 요청 50건 한도: 감시 종목 **40개 이하**로 제한(종목당 시세 1건 + 발송). CPU 10ms: 네트워크 대기는 제외라 가능.

## 구현 순서·시험
1. `core.js` 에 이탈 판정·반복 스케줄 순수 함수 + `test/` 단위 시험(반복 횟수·ack·회복·시계 경계). 기존 `parity.mjs` 는 건드리지 않는다.
2. `index.js` 에 cron 분기·관리 HTTP. 로컬 `wrangler dev` 로 시세 없이 모의 시험.
3. 태블릿: `run-loop.sh` 에 하트비트 호출(관리 키는 폰 `.env` 에서, 대화에 안 붙임).
4. 엔진: 손절가를 `POST /stops` 로 올리는 훅은 **실주문 코드가 아니라 읽기·알림 코드** — 별도로 🟡 검토 후.
5. **배포는 사용자**(`npx.cmd wrangler deploy`). 첫 배포는 감시 목록을 비워 두고 하트비트만 확인.

## 합격 기준(사전 고정)
- 시세 지연 실측: 장중 네이버(국내)·야후(미국) 값과 증권사 화면을 며칠 비교해 **지연이 2분 이내**인지 기록한다. 초과하면 "1분 알림"은 의미가 약하니 KIS 시세 키 사용을 새로 검토(별도 결정).
- 모의 손절선으로 이탈 알림이 텔레그램에 1분 간격으로 오고 ack 로 멈춘다.
- 하트비트를 끊으면 20분 뒤 멈춤 알림이 온다.
