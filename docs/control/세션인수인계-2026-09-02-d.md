## 1. ETF 분배금 배포 문제 — workflow_run 이슈 실전 확인·해결

### 증상
사용자가 실사이트에서 "연분배율·분배횟수 컬럼은 생겼는데 값이 하나도
없다"고 보고.

### 원인
오늘 아침 CLAUDE.md에 "workflow_dispatch로 시작된 소스는 workflow_run
자동배포가 잘 안 붙는다"는 가설을 적어뒀는데, 그 가설이 몇 시간 뒤
스스로 실전에서 재현됐다. `docs/index.html`(컬럼 렌더링 코드)은 사람이
직접 push해서 즉시 배포됐지만, 실제 분배금 데이터(`98ef620`, ETF
워크플로가 workflow_dispatch로 커밋)는 배포를 못 일으켜, 라이브
사이트가 "새 컬럼 + 옛 데이터(데이터 파일 자체가 없음)" 상태로 떠 있었다.

### 해결
`gh workflow run deploy-pages.yml`로 수동 재배포 트리거 → 실사이트에서
값 정상 표시 확인(브라우저로 직접 확인, +1.8423% 등 실제 값 렌더링됨).
CLAUDE.md에 이 실전 재현 사례를 기록(★ 후속4).

**교훈**: docs/data/를 갱신하는 workflow_dispatch 실행 뒤에는
deploy-pages도 같이 수동 트리거해야 한다. 다음 세션이 뭔가 workflow_
dispatch로 데이터 갱신 워크플로를 돌릴 때마다 유념할 것.

## 2. 실시간 탭 관심종목 — 실전계좌 잔고조회 자동연동

### 배경 (대화 흐름)
사용자가 실시간 탭에서 종목 변경이 안 보인다고 문의 → 조사해보니 실은
잘 되고 있었고(브라우저 확인 완료) → "20개 고정 말고 내가 원하는 종목
으로 바꾸고 싶다" → "나중엔 내가 투자한 종목으로 자동 연동하고 싶다" →
KIS 웹소켓 세션 구독 상한(41건, 사용자가 직접 조사해 온 자료)을 함께
검증 → 실전키/모의투자키 역할 분담을 문답으로 확인 → "자동연동 구현
시작해줘".

### 공개 범위 확인 (구현 전 필수 관문)
이 저장소·사이트는 전체 공개다. 실제 보유종목을 그대로 공개 데이터
파이프라인(docs/data/)에 얹으면 "사용자가 실제로 어떤 종목을 갖고
있는지"가 인터넷에 공개된다 — 이건 지금까지 다룬 시장 데이터(ETF 분배금
등)와 성격이 완전히 다르다. AskUserQuestion으로 명시적으로 확인받았고,
**"비공개 유지"**로 확정 — VM 로컬 파일로만 존재하고 git에 절대 안 올림.
이 결정이 이후 전체 설계를 결정했다.

### 구현
- **`scripts/kis-portfolio-holdings.py`** 신설 — 실전계좌 잔고조회
  (TR_ID `TTTC8434R`). `research/strategy-lab/engine/live/
  kisVtsClient.py`(모의투자, 이미 검증된 코드)의 `inquire_balance()`와
  완전히 같은 요청 구조를 실전 도메인으로 옮긴 것 — 새로 설계 안 함.
  결과는 `~/.kis-holdings.json`(홈 디렉터리, 저장소 밖)에만 쓴다.
  KIS 웹소켓 세션 구독 상한(41건)에 맞춰 평가금액 큰 순 41개까지만
  남긴다. `--selftest`(0주 보유 제외·정렬·41건 상한)와 `--dry-run`
  둘 다 갖춤.
- **`scripts/kis-live-relay.py`** 수정 — `load_watchlist()`가 이
  보유종목 파일을 먼저 읽고, 없거나·비었거나·깨졌으면 기존 정적 목록
  (docs/data/live-watchlist.json)으로 fail-soft 폴백.
- **`deploy/kis-portfolio-holdings.service`/`.timer`** 신설 —
  systemd `+` 접두사로 `User=ubuntu` 유닛에서도 relay 재시작 한 줄만
  root 권한(별도 sudoers 불필요). 주기는 처음 08:50(장전) 1회로
  시작했다가, 사용자 요청으로 09:00~15:50 10분 간격(`intraday-
  check.js`와 동일 주기)으로 재조정.

### 41건 근거 검증 (사용자가 가져온 자료 팩트체크)
사용자가 ChatGPT 조사 결과("KIS 웹소켓 세션당 41건, 2026-04-20 공지
기준")를 갖고 왔다. 직접 검증 시도 — KIS 공식 커뮤니티 공지 페이지는
로그인 필요라 못 열어봄. 대신 WikiDocs 변경이력(2022-08-30 20건→
2022-09-08 40건, 마지막 편집 2023-05-30)과 독립 개발자 블로그(hky035.
github.io, 2025-10-22 작성, "세션당 41건")를 교차확인 — 방향 일치.
**"41건" 숫자는 신뢰할 만하나 "체결+호가+체결통보+해외/파생 전부 합산"
이라는 세부 문구·정확한 공지일자는 원문에서 직접 확인 못 했다**는 걸
사용자에게 명시했다. 다행히 우리 relay는 체결가만 구독(호가 안 씀)이라
이 세부사항과 무관하게 41건이 그대로 적용된다.

### 실전키/모의투자키 분리 이유 (사용자 질문에 답하며 재확인)
- **실전키(KIS_APP_KEY)**: `build-etf-etn-daily.py`·`build-price-
  a2b.py`(GH Actions)·`collect-minute-kis.py`(VM 크론) — 전부 잠깐
  돌고 끝나는 배치.
- **모의투자키(KIS_VTS_APP_KEY)**: `kis-live-relay.py`(상시 웹소켓)·
  `kis-minute-history-api.py`·페이퍼트레이딩 엔진.
- 상시 연결이 실전키를 쓰면, 배치 작업이 새 토큰을 발급받을 때(GH
  Actions는 매 실행이 별 VM이라 캐시가 안 남아 사실상 매번 재발급)
  같은 앱키의 기존 토큰이 무효화돼(EGW00123) 상시 연결이 끊긴다 — 그래서
  앱키를 완전히 분리해뒀다. 새로 만든 잔고조회는 상시 연결이 아니라
  가끔(10분마다) 호출하는 REST라 이 위험이 없어 실전키를 그대로 써도
  안전하다.

### 배포 중 발견·수정한 것들
1. **VM(`~/collector`)에 미커밋 로컬 diff 2건 존재** —
   `docs/data/live-watchlist.json`·`scripts/kis-minute-history-api.py`.
   `git diff origin/main`으로 대조하니 둘 다 diff 0(다른 경로로 이미
   커밋된 내용을 과거에 scp로만 VM에 올려두고 git엔 안 올린 상태) —
   안전하게 폐기 후 pull.
2. **`KIS_ENV_PATH` 간접참조를 새 스크립트가 몰랐다** — 이 VM은
   systemd `EnvironmentFile`(collector.env)에 실제 키를 안 두고
   `KIS_ENV_PATH`로 실제 `.env`를 한 단계 더 가리킨다(`collect-minute-
   kis.py`가 이미 쓰던 패턴). 배포 직전 발견·수정 — 안 고쳤으면 VM에서
   인증 실패했을 것.
3. **`KIS_ACCOUNT_NO`를 값 노출 없이 VM에 전달** — 로컬 `.env`에 이미
   저장돼 있던 값을 `grep '^KIS_ACCOUNT_NO=' .env | ssh stock-new "cat
   >> ..."` 파이프로 전달 — 값이 커맨드 텍스트·로그 어디에도 안 남는
   방식.

### 검증
수동 1회 트리거로 전체 체인 확인 — 잔고조회(보유 0건, 정상)→파일 저장→
`kis-live-relay` 자동 재시작(systemd 로그로 확인)→20종목 재구독 완료
(relay.log로 확인). 현재 실전계좌에 보유종목이 없어 폴백 경로만 실측
됐다 — 진짜 보유종목이 있을 때의 전환은 아직 미확인(위 "다음 세션이
확인할 것 ②" 참고).
