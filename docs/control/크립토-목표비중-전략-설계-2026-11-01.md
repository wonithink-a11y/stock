# 크립토 목표 비중 전략(`crypto_weights`) 설계 (2026-11-01)

> **설계만이다. 코드는 아직 없다.** 실계좌 주문에 닿는 새 전략이라 🔴 — 아래 '결정 4건'에 사용자 GO 뒤 구현한다. Claude 는 실계좌를 켜지 않는다(켜기는 지금처럼 패스키).
> **수익을 주장하지 않는다.** 이 전략은 알파 신호가 아니라 '여러 코인을 정한 비중으로 들고 가는 규칙' 이다 — 검증된 신호 전략(`coinbase_premium`)과 별개 프로필로 동시에 켤 수 있다.

## 1. 하려는 것

BTC 만 사던 구조에서, **BTC·ETH·XRP 등 사용자가 정한 코인을 정한 비중으로** 사 모으고, 비중이 어긋나면 되맞춘다.
신호가 없으므로 판단이 필요 없고(= 사후 가설·다중검정 문제 없음), 한도·킬 스위치·패스키는 기존 엔진이 그대로 강제한다.

## 2. 지금 구조와 맞는 점·모자란 점 (읽고 확인)

- 전략은 플러그인(`autotrader/strategies/*.py`, `STRATEGY = 클래스`)이고 프로필(`profiles/*.json`)이 전략·키·허용 종목·한도를 묶는다. 프로필 둘을 동시에 켤 수 있다.
- `target_weights` 는 **KR·US 전용**이고 수량을 정수 주(`math.floor`)로 계산한다 — 크립토는 소수 수량이다.
- 업비트 브로커는 허용 종목만 있으면 여러 코인을 받는다. 주문은 **시장가만**: 매수 = 원 금액(`ord_type=price`), 매도 = 수량(`ord_type=market`, 소수 8자리 `_vol`). 최소 주문 5,000원.
- `coinbase_premium` 은 **자기가 산 수량만** 판다(개인 보유 BTC 불가침)는 원장·체결 확인 방식이다. 목표 비중 전략도 같은 방식이 안전하다.

## 3. 설계

- 파일 `autotrader/strategies/crypto_weights.py`, `name = "crypto_weights"`, `markets = ["UPBIT"]`. `target_weights` 를 복사해 크립토용으로 바꾸고 원본은 건드리지 않는다.
- **params**(프로필 파일, 사용자 SSH):
  - `weights`: `{"KRW-BTC": 0.5, "KRW-ETH": 0.3, "KRW-XRP": 0.2}` — 합 ≤ 1(나머지는 원화). 프로필 `symbol_allowlist` 와 같은 코인만(어긋나면 설정 오류).
  - `capital_krw`: 이 전략이 쓰는 자본(예: 1,000,000). 비중은 이 자본 기준 — **계좌 전체 원화가 아니다.**
  - `band_pct`(기본 5.0): 목표 대비 허용 오차(%p). 안쪽이면 건드리지 않는다.
  - `max_order_krw`(기본 `capital_krw` 의 20%): 한 번에 낼 수 있는 한 주문 금액 — 처음 진입을 며칠에 나눠 들어가는 슬라이스.
- **결정 로직(하루 한 번, `run_at` 예: 09:05)**:
  1. 이 전략의 보유 = **원장·체결 확인으로 센 자기 수량**(`state.holdings[symbol]`, `coinbase_premium` 과 같은 `pending` → `order_fill` 확인). 개인 보유는 보지도 않는다.
  2. 기준 가치 = `capital_krw` 에서 시작해 자기 보유 평가액이 늘면 그만큼 커진 값(= 자기 현금 + 자기 보유 평가액). 목표 금액 = `weight × 기준 가치`.
  3. 차이가 `band_pct` 밖인 코인만: 부족 → `price` 매수(원 금액, `min(차이, max_order_krw, 남은 현금)`), 초과 → `market` 매도(자기 수량 한도 안, 소수 8자리 내림). 5,000원 미만 주문은 만들지 않는다.
  4. 매도 먼저, 매수는 자기 현금 안에서. 한 실행에서 낼 수 있는 주문 수는 프로필 `max_orders_per_run`(코인 수 이상으로 올린다).
- **엔진이 강제하는 것(변경 없음)**: 허용 종목 · `max_order_value` · `max_daily_value` · `max_position_value`(코인별 계좌 전체 평가액) · 킬 스위치 · `live.enabled` · 패스키 켜기. 새 전략이 실수해도 이 범위를 못 넘는다.
- **웹**: 크립토 화면은 프로필마다 카드가 이미 나온다. 이 프로필 카드는 `weights` 와 현재 비중을 한 줄로 보여준다(구현 시). 금액·비중 변경은 SSH 파일 — 웹에서 바꾸는 것은 이번 범위 밖(`cbprem` 금액 설정과 같은 패턴으로 나중).
- **시장가 슬리피지·수수료**: 업비트 원화 시장가 수수료 약 0.05%. 밴드 5%p 는 수수료·스프레드보다 충분히 크다 — 잦은 매매로 비용이 쌓이지 않게.

## 4. 결정 4건 (사용자)

| # | 결정 | 권고 |
|---|---|---|
| 1 | 코인·비중·자본 — 예: BTC 50 · ETH 30 · XRP 20, 자본 100만원 | 유동성 큰 코인(BTC·ETH)을 중심으로, 첫 가동은 자본 작게(예: 30만원) |
| 2 | 점검 주기와 밴드 — 하루 1회 + 밴드 5%p | 권고대로(주 1회 + 밴드도 가능, 값만 바꾸면 됨) |
| 3 | 보유 계산 — 자기 체결 수량만(개인 보유 불가침) vs 계좌 전체 | **자기 수량만**(`coinbase_premium` 과 같은 안전 쪽, 구현이 약간 더 복잡) |
| 4 | 진입 방식 — 슬라이스(`max_order_krw`)로 며칠 나눠 vs 첫날 한 번에 | 슬라이스(고점 한 번에 사는 위험 완화) |

## 5. 구현 범위·검증 (GO 뒤)

- 신규 `strategies/crypto_weights.py` + 회귀 `scripts/test-autotrader-cryptoweights.py`: 소수 수량 내림·8자리 · 5,000원 미만 건너뜀 · 밴드 안 무주문 · 슬라이스 상한 · 자기 수량만 매도(개인 보유 있어도 불변) · 매도 먼저·현금 한도 · 비중 합>1·허용목록 불일치 설정 오류 · 부분 체결·미체결 처리(`pending`) · 같은 `identifier` 중복 방지 · 킬 스위치에서 무주문.
- 기존 `FakeBroker`/`UpbitBroker` 테스트 패턴 재사용. 새 부작용 없음(주문 경로·키·한도는 기존).
- 배포: PR → VM pull → 프로필 **dry-run** 으로 며칠 계획만 보고 `state/.../strategy_crypto_weights.json` 의 `log` 가 의도대로인지 사용자가 확인 → 켜기는 README §11 순서(upbit-probe → live.enabled → 패스키).
- `target_weights` 는 그대로 둔다(KR·US).

## 6. 하지 않는 것

신호 기반 코인 선택(모멘텀 등 — 검증 없이 안 만든다, 새 사전등록 뒤) · 레버리지·선물 · 웹에서 비중·한도 변경 · 자동 켜기 · 개인 보유 코인 매매.

## 7. 추가 요청(11-01): 비율을 웹에서 바꾸기 + '기타' 묶음 — 설계 초안·결정 대기

요청: "비트 50 · 이더 20 · 기타 30 — 기타는 XRP 포함 모든 코인". 코어 전략(§3, 코드·회귀 완료)은 코인별 고정 비중이라 아래가 더 필요하다. **구현 전 결정 3건.**

- **웹에서 비율 변경**: `cbprem` 1회 금액 설정과 같은 패턴 — 웹은 희망 비중 파일(`weights_override.json`)만 쓰고, 패스키 전용·값을 지문 챌린지에 묶고, 합계 ≤ 100%·단위 정수 %·서버 허용 목록과 한도 안에서만 저장, 이력 기록, 다음 실행부터 적용. 서버 프로필이 `params.web_weights: true` 로 허락한 경우에만.
- **'기타' 묶음 = '모든 코인'은 그대로 못 한다.** 업비트 원화 마켓은 약 200개인데 ① 최소 주문 5,000원 — 자본 100만원의 30%(30만원)를 200개로 나누면 코인당 1,500원이라 주문이 안 된다 ② 거래대금이 작은 코인은 시장가 슬리피지가 크다 ③ 투자유의·상폐 위험 코인이 섞인다.
  → 제안: **기타 = 거래대금 상위 N개(BTC·ETH 제외, 투자유의 제외) 균등** (N 기본 5, 설정 가능). 목록은 월 1회 고정해 쓰고(매일 바뀌면 불필요한 매매), XRP 가 상위면 자동 포함.
- **허용 목록 문제**: 엔진은 프로필 `symbol_allowlist` 밖 코인 주문을 막는다(웹이 못 늘리는 안전장치). 기타에 들어갈 코인을 서버가 미리 허용해야 한다.

| # | 결정 | 권고 |
|---|---|---|
| 5 | '기타'의 범위 | 거래대금 상위 N(기본 5) 균등, 투자유의 제외, 월 1회 갱신 — '업비트 전체'는 주문 불가능 |
| 6 | 허용 목록 | 서버 프로필에 후보 코인(예: 상위 20개)을 SSH 로 적어 둔다. 웹은 그 안에서만 비중을 정한다 — 와일드카드(`KRW-*`)는 위험 한도를 사실상 푸는 것이라 권고 안 함 |
| 7 | 웹 비율 입력 단위 | 정수 %, 합 ≤ 100, 나머지는 원화. 3칸(BTC·ETH·기타) 입력 |

필요한 새 코드: 업비트 시세 목록·거래대금 조회(브로커 확장) · 기타 선정·월 고정 · 비중 override 읽기/웹 쓰기·패스키 값 묶기 · 크립토 화면의 비율 칸.
