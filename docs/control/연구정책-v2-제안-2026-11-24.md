# 연구 정책 v2 제안 — "많이 돌리고, 믿는 건 따로" (2026-11-24, 초안·미발효)

> 상태: **제안서다. 발효 전이다.** 연구 규칙 변경은 🔴 등급이므로 사용자 GO 뒤에 §5 순서로 바꾼다.
> v1(현행)은 지우지 않고 남겨 두며, 되돌릴 때는 §6 그대로 하면 된다.

## 0. 왜 바꾸나 — v1 이 막은 것과 지킨 것

v1(현행)의 핵심은 **"결과 보기 전에 기준 고정 · 같은 표본 재판정 금지 · 닫힌 축 재시도 금지"** 다. 덕분에 80여 건을 싸게 닫았고 가짜 통과를 막았다(54축 전수 스윕에서 난수 팩터도 t 3.21).
그 대가로 다음이 막혔다(11-23 실례):

| 막힌 것 | 막은 v1 규칙 | 실제로 필요했던 것 |
|---|---|---|
| 진바닥 3조건(문턱이 10%/22%, 40%/20% 둘씩) | "문턱을 결과 전에 하나로" → WATCH | 후보 문턱을 **전부** 격자로 넣고 보정하면 됐다 |
| PBR 바닥 밴드 | "회계·가치·품질 축 새 데이터 없이 재시도 금지" | 같은 표본을 **다시 보는 값(보정 강화)** 을 치르고 보게 하면 됐다 |
| 이벤트성 급락 매수 | "사후 분류라 규칙화 불가" | 기계적 대용 정의 여러 개를 동시에 시험 |
| 시뮬레이션(trade-odds 등) | 판정 체계에 자리 없음 | 판정 없는 '놀이터' 자리 |

v2 의 생각은 하나다. **탐색은 거의 자유롭게, 대신 몇 번 봤는지 자동으로 세고, '믿는다'는 말은 독립 표본 확인만 할 수 있다.**
v1 은 "보는 것 자체"를 막았고, v2 는 "본 횟수만큼 보정을 엄격하게" 해서 같은 안전을 산다.

## 1. 세 갈래(레인)

| 레인 | 하는 일 | 사전등록 | 통계 문턱 | 결과의 지위 |
|---|---|---|---|---|
| **S 놀이터** | 아무 시뮬레이션·파라미터 스윕·몬테카를로·시각화. 영상·SNS 아이디어 즉시 돌려 보기 | **없음** | 없음 | `SANDBOX` — 판정이 아니다. CLAUDE.md·점수·매매·UI 판정 목록에 못 들어간다. 시도 횟수만 장부에 자동 기록 |
| **E 탐색** | 가설을 정식으로 한 번 잰다. 후보 문턱·조건을 **여러 개 한꺼번에** 격자로 | **짧은 사전등록**(설정 JSON + 한 문단, 도구가 자동 생성) | 격자 전체에 BH-FDR **10%**(v1 5%), 사건 ≥ **10건**(v1 20) | `탐색 통과(후보)` — 신뢰 아님. 확인으로 보낼 자격만 |
| **C 확인** | 탐색 통과 규칙을 **그대로** 독립 표본(홀드아웃·forward)에서 한 번 | v1 그대로(정식) | v1 그대로: 단일 검정 단측 p ≤ 0.05 + 효과·경제성 | `확인됨` — 점수·매매 반영은 여기서만, 그것도 🔴 별도 GO |

**놀이터에서 E 로 올리는 길**: 놀이터에서 재미있어 보인 것은 그 설정을 그대로 E 사전등록에 넣는다. 단 놀이터에서 본 표본은 "이미 본 표본"이라 E 의 보정 가족 크기 K 에 놀이터 시도 횟수를 더한다(§2).

## 2. 같은 표본을 다시 봐도 된다 — 대신 "누적 K"를 낸다

v1 "같은 표본 재판정 금지"를 **"재사용 허용, 대가는 누적 보정"** 으로 바꾼다.

- 표본마다(예: `KR 일봉 2016~2026`, `US PIT 2016~2026-09`, `S&P500 지수 1990~`) **시도 장부** `research/strategy-lab/trial-log.jsonl` 에 시도 1건 = 1줄을 자동으로 남긴다(레인·가설·칸 수·날짜).
- E 레인의 보정 가족 크기 = **이번 격자 K + 그 표본의 과거 누적 시도 수**. 많이 본 표본일수록 문턱이 저절로 높아진다.
  - 예: KR 일봉은 v1 동안 이미 수백 칸을 봤다 → 거기서 새 가치 축을 E 로 보면 BH 가 매우 엄격해진다. 막는 대신 **비싸게** 만든다.
- 닫힌 연구 80여 건의 REJECT 판정은 **번복하지 않는다**(기록 수정 금지). 다시 보는 것은 새 시도로 장부에 쌓인다.

## 3. v1 대비 바뀌는 것 / 안 바뀌는 것

| 항목 | v1 (현행) | v2 (제안) |
|---|---|---|
| 사전등록 | 모든 시험에 정식 문서 | S: 없음 · E: 자동 생성 짧은 형식 · C: 정식 |
| 문턱이 모호한 아이디어 | WATCH(멈춤) | 후보 문턱 전부 격자로 E |

| 회계·가치·품질 축 | 새 데이터 없이 금지 | S·E 허용(누적 K 큼 — 사실상 강한 문턱) |

| 시뮬레이션 | 자리 없음 | S 의 1급 시민(trade-odds·부트스트랩·몬테카를로·파라미터 스윕) |
| 사후 분류(이벤트성 등) | 규칙화 불가 | 기계적 대용 정의 여러 개 동시 E |

| 점수·매매 반영 | 확인 + 🔴 GO | **그대로** |
| 절대 규칙 1~9 | — | **전부 그대로**(결측 기본점수 금지·시크릿·KST·data/backfill·동결 기준·정책 임계 버전 승격·무료 우선 등) |
| 실계좌 | Claude 가 켜지 않음 | **그대로** |

**한 줄 요약: 입구는 넓히고, 출구(확인·점수·매매)는 v1 그대로 좁다.**

## 4. 유연해진 만큼 생기는 위험과 막는 장치

| 위험 | 크기 | 장치 |
|---|---|---|
| 가짜 '탐색 통과'가 늘어난다 | BH 10% 면 통과 칸의 약 10%는 우연이 기대값. 놀이터는 통제 없음 | 탐색 통과는 '후보'라고만 부른다. 확인 단계(독립 표본)가 걸러 준다 |
| 확인용 독립 표본이 빨리 소진된다 | KR 홀드아웃(2010~2016)은 한 번 열면 끝 | 확인 대기열을 효과 크기 순으로 줄 세우고 월 2건 상한. 나머지는 forward 로 |
| 놀이터 결과가 판정처럼 퍼진다 | 사용자·화면에서 '좋은 숫자'로 기억됨 | `SANDBOX` 라벨, findings 판정 목록·대시보드에 안 올림, 결과 첫 줄에 "판정 아님" 자동 출력 |
| 결과 보고 문턱 바꾸기 | v1 의 핵심 위험 | S 에서는 자유, **E·C 로 올릴 때 설정이 동결**되고 그 뒤 변경은 새 시도(K +1) |
| 토큰·시간 폭증 | 많이 돌리기 = 비용 | 무료 도구만(규칙 9). 대량 위임 전 확인 규칙은 그대로 |

**v2 의 성공 기준(1개월 뒤 점검)**: 확인 단계 통과율. 탐색 통과 후보가 확인에서 5% 안팎만 살아남으면 탐색이 우연을 걸러 주지 못한다는 뜻 → BH 를 5% 로 되돌린다. 15% 넘게 살아남으면 v2 유지.

## 5. 바꾸는 순서(가이드) — GO 뒤 한 세션, 약 1~2시간

1. **정책 문서 한 장으로 모으기**: `docs/연구정책-RP-2.0.md` 신설(이 제안의 §1~§4 를 규칙 문장으로). 지금은 규칙이 CLAUDE.md·스킬 3개에 흩어져 있어 버전이 없다 — 이번에 처음 버전을 단다(v1 = `RP-1.0`, 현행 문장을 그대로 옮겨 기록).
2. **시도 장부**: `research/strategy-lab/trial-log.jsonl` + 작은 도우미 `research/strategy-lab/trials.py`(`log`·`count <표본>`). 기존 `_registry.jsonl`·`idea-ledger.jsonl` 에서 표본별 과거 시도 수를 한 번 역산해 시작값으로 넣는다(역산 근거를 문서에 적는다).
3. **놀이터 자리**: `research/sandbox/`(코드·출력). 결과 머리말 `verdict: SANDBOX`. `build_findings_registry.py`·`build_ui_findings.py`·`build-research-index.py` 가 SANDBOX 를 판정 목록에서 빼도록 한 줄씩.
4. **스킬 고치기**: `preregistered-research`(레인 표·E 짧은 형식), `condition-grid`(BH 10%·사건 10·누적 K), `idea-intake`(WATCH → S 로 보내는 길). `youtube-analyze`·`inspect-social-post` 의 후속 단계에 "S 에서 바로 돌려 보기" 한 줄.
5. **CLAUDE.md**: "안 한다" 머리 문장 "같은 표본 재판정 금지, 재개는 새 사전등록·새 표본/forward 로만" → "재사용은 RP-2.0 누적 K 로, 확인은 독립 표본으로만". 절대 규칙·검증 강도 표는 손대지 않는다.
6. **시범 2건**: ① 진바닥 조건 E(애플 낙폭 10%·22% × S&P500 50일선 위 비율 40%·20% = 4칸, US PIT 패널) ② PBR 바닥 밴드 S(삼성전자·하이닉스, 판정 없음).
7. 회귀 전부 + 인수인계 + 1개월 뒤 점검 날짜(2026-12-24)를 월간 점검 표에 한 행.

## 6. 되돌리기

`RP-1.0` 문서가 남아 있으므로: 스킬·CLAUDE.md 변경 커밋을 `git revert` → 시도 장부·놀이터 폴더는 남겨 둔다(기록이라 무해). v2 기간에 나온 '탐색 통과'는 v1 기준으로 다시 보지 않는다 — 확인 단계를 통과한 것만 유효했으므로 되돌려도 잃는 판정이 없다.
