# 세션 인수인계 — 2026-08-18 (b) — SB-1.0 KR_4AXIS 정찰, 보류

같은 날 첫 인수인계(`세션인수인계-2026-08-18.md`, A4 finalize)와 별개 주제라 `-b`로
분리했다(2026-08-14/2026-08-14-b와 같은 관례). **정본이 아니다** — 정본은 이 문서가
가리키는 스크립트·`config/policies/scoreBasis.v1.json`(SB-1.0)이고, 여기는 "오늘 뭘
했고 왜 멈췄는지"만 모은다.

## 새 세션은 여기부터

1. **SB-1.0 KR_4AXIS 백테스트 트랙은 보류 중이다.** A4(수급) 완료로 착수 가능해진
   건 맞지만, 정찰 결과 **valuation 축이 resolver.js에 아직 안 붙어 있어서
   (A5-3 블로커) 지금 구조로는 재현이 안 된다**는 게 확인됐다 — 아래 §3.
2. **재개하려면 먼저 A5-3(valuation/peg)을 열지 결정해야 한다.** 별도 🔴 승인 —
   이 세션이 대신 결정하지 않았다. 사용자가 "보류"를 선택했다(2026-08-18).
3. 스크립트 둘(§4)은 재사용 가능하게 커밋해 뒀다 — 종목·기간 파라미터만 바꾸면
   재실행된다. valuation이 열리면 그때 다시 쓴다.

---

## 1. 배경 — SB-1.0이 뭔지 모르면

`config/policies/scoreBasis.v1.json`이 KR_4AXIS(fundamental+technical+valuation+
supplyDemand, 운영 모델)와 KR_3AXIS(수급 빠짐, 백필 채점용)를 선언한다. A4(수급
백필)가 2026-08-18 완료되면서 "KR_3AXIS 백테스트와 KR_4AXIS 백테스트를 나란히
돌려 비교"가 이론적으로 열렸다 — CLAUDE.md "착수 가능 ④".

## 2. 1단계 — 소규모 정찰 (5종목 × 6주, 통과)

`scripts/probe-a4-supplydemand-vertical-slice.js` 최초 버전. `resolve()`·`score()`·
`config/policies/*` 무변경, production 코드 그대로 두 번 호출(수급 있음/없음)해서
비교. `probe-bf11-vertical-slice.js`(2026-08-12, 820f097)와 같은 원칙 —
`data/backfill/scores/`나 manifest에 아무것도 안 씀(교훈43).

**★ 실행 전 코드로 발견한 것 — 이후 이 트랙 전체를 가른 사실.** `lib/a5/resolver.js:
170-196`을 보면 `resolve()`는 **valuation을 stockData에 절대 안 붙인다**
("valuationFrom()은 정의만 하고 여기서 안 부른다" — A2a 수정주가 ↔ A3b 원본 EPS
조정 불일치, A5-3 블로커, peg와 같은 원인). 그래서 오늘 resolver.js로 실제 만들
수 있는 건 SB-1.0이 선언한 KR_3AXIS/KR_4AXIS 어느 쪽도 아니고, valuation이 빠진
`baseline=[fundamental,technical]` 대 `+supplyDemand=[fundamental,technical,
supplyDemand]`다. 이후 스크립트 전부 이 이름을 쓴다 — "KR_3AXIS"/"KR_4AXIS"라고
안 부른다.

**결과**: 30/30칸 통과, scoreError 0, PIT 위반 0, A4 5일 창 join 100%, 수급 축이
실제 basis에 편입된 비율 100%, delta 0 아닌 비율 100%(범위 -12.8~+9.6), 방향성도
그럴듯함(순매도 종목 delta 음수, 순매수 종목 delta 양수).

## 3. 2단계 — 확대 (35종목 × 2016~2026 전체 주간 553개, 19,355칸)

같은 스크립트를 종목·기간만 키움. 대형주 5개(1단계) + KOSPI·2015-01-01 이전
상장 652종목에서 균등추출 30개 = 35종목.

**성능 문제 둘, 둘 다 A4 finalize OOM(전날)과 같은 교훈으로 고쳤다:**
- 1차 시도: 종목×날짜(30칸)마다 연도 파일을 통째로 다시 훑어 2분 넘게 안 끝나
  중단. → 연도 파일을 정확히 한 번만 읽어 대상 종목만 뽑는 색인(`buildTickerIndex`)
  으로 교체.
- 2차 시도(색인 버전): 대상 종목이 전체의 1~2%뿐인데 매 줄을 `JSON.parse`부터
  해서 3분 넘게 안 끝나 중단. → 정규식으로 후보 줄만 먼저 거른 뒤 `JSON.parse`.
  **그 정규식 자체에 버그가 있었다** — `"ticker":"005930"`로 짰는데 실제 파일은
  콜론 뒤 공백이 있다(`"ticker": "005930"`, Python `json.dumps` 기본 포맷).
  매칭이 전부 실패해 색인이 텅 비었고 결과가 전부 null로 나왔다 — 숫자가
  이상해서 바로 원인을 찾아 고침(`\s*` 추가). **보고 전에 항상 이상치를 의심한다.**

**결과**: 19,355칸, scoreError 0, PIT 위반 0, join率 100%, basis 편입률 100%,
delta≠0 비율 99.3%(나머지 144건은 우연히 정확히 0, 확인함), 범위 -39.3~+35.8,
평균 -0.83·표준편차 7.28. 연도별 평균: 2016~2022 대체로 음수(-1.0~-1.8), 2024~
2025 양수 전환(+0.45~+0.54).

## 4. 3단계 — `runBacktest()`로 forward return까지 (보류 직전 마지막 작업)

`scripts/probe-a4-runbacktest-comparison.js`(신규). 2단계와 같은 35종목×553snapshot에
`calendar.tradingDays` 기준 정확한 거래일 수(달력일 근사 아님)로 d20/d60/d120
forward return을 계산해 `lib/backtester.js`의 `runBacktest()`에 두 번 태움(baseline
snapshot 집합 / +supplyDemand snapshot 집합). `runBacktest()`·`resolver.js`·
`scoringEngine.js`·정책 전부 무변경.

- **axisModel 미선언** — SB-1.0에 등록된 KR_3AXIS/KR_4AXIS 둘 다 valuation을
  요구해서 실제 관측 basis와 안 맞는다(§2 참고). 대신 basis가 동질인 두 snapshot
  집합의 A/B 비교로 했다. `runBacktest()`가 "axisModel 미선언 — 다른 실행과
  비교 말라"는 경고를 다는데, 이건 KR_4AXIS 운영 성능으로 오독하지 말라는
  뜻이지 이 A/B 비교 자체를 막는 게 아니다.
- **benchmarkReturns 없음** — 이 저장소에 KOSPI 지수 백필이 없다(`docs/BF-1.1-
  백필계약.md` §10: "KRX 지수 — 차단"). 프록시를 임의로 만들지 않았다(정직한
  결측) — 벤치마크 초과수익·국면 필터 비교는 이 결과에서 항상 계산 불가.

**★ 핵심 발견 — 이래서 보류한다.**

```
baseline (fundamental+technical, 2축)     eligible 0 / 19,355   전량 INSUFFICIENT_COVERAGE
+supplyDemand (+수급, 3축)                 eligible 14,803 / 19,355 (76.5%)
```

**이건 "수급이 있는 게 없는 것보다 나은가" 비교가 아니다.** valuation이 통째로
빠진 상태에서 fundamental+technical 둘만으로는 절대 규칙 1(커버리지 60% 미만 →
유보)을 단 한 건도 못 넘는다. 수급 축을 더해야 겨우 커버리지가 60%를 넘기
시작한다 — **valuation 결측은 라벨링 문제가 아니라 이 재현 경로 전체가 돌아가는
전제조건**이라는 뜻이다.

유일하게 측정 가능한 조합(+supplyDemand)의 예측력도 약하다: 평균 IC 0.004
(d20 0.01·d60 0.001·d120 0.00, "예측력이 약합니다" 구간), 등급 단조성 불충족,
**A등급이 d60(-3.26%)·d120(-0.95%)에서 오히려 최하위권**(B~E는 전부 양수).

**제약**: 35종목(전체 2,578 아님), 수급 5일 추세 분류 규칙 여전히 잠정,
`observedBasis`에 fundamental 자체가 빠진 케이스 2,194건이 있었으나(초기 연도
일부 종목 재무 데이터 미도달로 추정) 원인 확인 안 함.

## 5. 결정 — 보류 (2026-08-18, 사용자)

전체 2,578종목으로 확대해도 지금 구조(valuation 없음)로는 비슷하게 약한 결과가
나올 가능성이 높다고 판단 — valuation을 안 열고 규모만 키우는 건 정보 가치가
낮다. **A5-3(valuation/peg, A2a 수정주가 ↔ A3b 원본 EPS 조정 불일치)를 열지
여부를 사용자가 아직 결정하지 않았다.** 이 세션은 여기서 멈췄다.

CLAUDE.md의 "착수 가능 ④ SB-1.0 KR_4AXIS 백테스트" 항목은 이 보류 상태를 아직
반영하지 않았다 — 다음 세션이 CLAUDE.md를 갱신할지는 별도 판단.
