# 세션 인수인계 — 2026-08-14 (Strategy Lab · 5DC-v1A-P SMOKE baseline)

> 이 문서는 **정본이 아니다** — 상태의 정본은 언제나 `CLAUDE.md`와
> `docs/control/TASKS.md`다. 이 문서가 그 둘과 다르면 그쪽이 맞다. 역할은
> "이번 세션에 뭘 했고 왜 그랬는지"의 서사와 "다음에 정확히 뭘 해야 하는지"를
> 한 곳에 모아 다음 세션이 컨텍스트를 다시 파지 않게 하는 것뿐이다.

## 새 세션은 여기부터

1. `CLAUDE.md`를 읽는다 — 이 세션 마지막 커밋까지 반영해 뒀다.
2. **`research/strategy-lab/`는 이번 세션에 완전히 새로 만든 독립 연구 영역이다.**
   production(`data/`·`config/`·`lib/`·`scripts/`)과 격리돼 있고, A2a를
   읽기 전용으로만 쓴다. 커밋 `364e279` 하나에 전부 들어 있다.
3. **5DC-v1A-P는 지금 동결 상태다.** A2b(폐지종목 가격) 완료 전까지 전략
   로직·정책·파라미터를 건드리지 않는다 — 사용자가 명시적으로 지시했다.
4. **다음 진짜 작업은 A2b다.** 이건 Strategy Lab이 새로 만든 과제가 아니라
   `CLAUDE.md`의 "T1 대기 ② A2b 수집"에 이미 있던 그 항목이다 — Strategy
   Lab의 PRIMARY 전환도 정확히 같은 것을 기다린다. A2b가 오면:
   - `research/strategy-lab`는 코드 변경 없이 `UniverseProvider(include_delisted=True)`
     + A2b provider 연결만으로 A1A_A1B_MERGED로 확장되도록 이미 설계돼 있다
     (Phase 1 design item E, 실제로 그렇게 구현됨 — `engine/data/universeProvider.py`
     참고).
   - 그 재실행 결과가 나와야 `runClass=PRIMARY`로 승격할 수 있다. 지금
     결과(SMOKE)로 정책·파라미터를 바꾸지 않는다(사용자가 여러 번 명시).

### Phase 1~2 — 아키텍처 설계 승인 → 공통 엔진 구현

`research/strategy-lab/engine/`:
```
data/       priceProvider(추상)·a2aProvider(런당 단일 스캔+parquet 캐시)·
            universeProvider(A1a(+A1b))·calendar(calendar.json 읽기 전용)·
            pit(PITBars — 미래 접근 시 예외)·cacheKey·fastBars(성능,아래 참고)
```

2~4분 걸린다 — 타임아웃 넉넉히 잡을 것.

### Phase 3 — 5DC-v1A-P 계약 동결 + 실데이터 SMOKE

계약 전문: `research/strategy-lab/strategies/5dc_v1a_p/policy.json`.
```
BB(20,2)·CCI(20,threshold=-100)·ATR(14,Wilder)
Signal: Close[t]>BB_mid[t] AND CCI[t-1]<=-100 AND CCI[t]>-100, LONG only
Entry: next session Open. Stop: entry-2×ATR[t]. Target: entry+3×stop_distance
Time exit: 진입일 포함 60세션째 종가. Cost: entry 15bp+exit 15bp, slippage 0
```

**첫 실행에서 실제 데이터 버그를 발견했다.** A2a에 거래정지일(open=high=low=0,
volume=0, close만 직전 기준가 유지) 패턴이 존재해 진입가 0원 시도
(ZeroDivisionError)와 ATR 왜곡(최대 9.5배 가짜 급등, 225570 실측)이 났다.
`config/policies/price.v1.json`의 `returnTransition.requireBothVolumePositive`가
연상되지만 **그 규칙과 정확히 같지 않다** — price.v1.json은 행을 지우지 않고
pairwise 계산에서만 제외하며, 소비자 목록(`A2a·A2b·A5`)에 rolling indicator
엔진이 없다. 그래서 새 규칙(`_drop_suspension_rows`, `engine/runner.py`)을
만들었고, **처음엔 `volume>0`으로 과잉 필터링했다가** 검증 중 volume=0인
128,491행 중 55,275건이 실제로는 유효한 평탄 시세(open=high=low=close,
전부 0 아님)임을 발견 — 사용자가 **`open==high==low==0`만 제거**하도록
확정, 5종목 실측(ATR 급등 해소·오류 0건)으로 재검증.

전체 A1A_ONLY(2,558종목, 2014-05-13~2026-08-03) SMOKE 결과:
`research/strategy-lab/reports/2026-08-14-5dc-v1a-p-baseline/SUMMARY.md`.
26,090건 execution 계약 전수검증 위반 **0건**.

### B0~B3 Ablation — 성능 사고와 최적화

B0(Buy&Hold)·B1(BB-only)·B2(CCI-only)·B3(=5DC-v1A-P 재사용)로 5DC의 성과가
어디서 오는지 분해. 구현 전 계약 충돌 2건을 사용자 확인 후 진행:
- B0: max_positions=10을 적용 안 함(시장 전체 균등가중 buy&hold이므로 집중도
  제약이 안 맞음), 진입=첫 유효일 종가·청산=마지막 유효일 종가·재조정 없음
- B1: "Close>BB_mid"를 edge-triggered로 좁힘(`Close[t-1]<=BB_mid[t-1] AND
  Close[t]>BB_mid[t]`) — level condition 그대로면 원시 신호가 수백만 건

**첫 전체 실행이 수 시간대로 늘어나 사용자가 중단 지시.** cProfile로 원인
특정: `simulate_trade`가 신호당 최대 60번 `bars.loc[date]`를 호출하는데,
`date`가 항상 문자열이라 pandas가 매번 문자열→Timestamp 파싱을 반복하는 게
병목이었다(전체 시간의 ~75%). **`engine/data/fastBars.py`(티커당 1회
문자열 키 dict 사전 생성) + `TradingCalendar.next_n_sessions`(60일만 슬라이스,
남은 캘린더 전체를 복사하던 것 제거)로 수정 — execution/portfolio/cost/PIT
계약 자체는 한 글자도 안 바꿨다.** 기존 execution 테스트 전부 재통과 +
전용 회귀(`tests/test_fast_bars_equivalence.py`)로 최적화 전/후 동일 fixture에서
byte-for-byte 동일 결과 확인 후 20종목 subset 재검증 → 전체 재실행(약 20분,
이전 추정 대비 대폭 단축).

최종 결과: `research/strategy-lab/reports/2026-08-14-5dc-v1a-p-baseline/`의
`SUMMARY.md`(비교표)·`ablation_b0_b3.json`(원본). 요지 — BB 단독이 가장
나쁘고(CAGR -4.5%·MDD -53%), CCI 단독이 가장 양호, 결합(5DC-v1A-P)은 둘
사이 어딘가로 CCI 단독보다 뚜렷한 개선은 없었다(판정 아님, 관찰만).

## 알아두면 좋은 것 (운영상 함정)

- **A2a 캐시**(`research/strategy-lab/.cache/a2a/`, gitignore)는
  (manifest hash·universe hash·ticker set·시작일·종료일)이 전부 같아야
  히트한다. 티커 부분집합으로 먼저 테스트하면 전체 실행 때 캐시가 안
  맞아 다시 3~4분 스캔이 돈다 — 정상이다, 버그 아니다.
- **첫 전체 스캔은 cold일 때 3~4분** 걸린다(6M행 gzip+JSON 파싱). 캐시
  히트 시 수 초.
- `_drop_suspension_rows`의 정확한 predicate는
  `bars[~((open==0)&(high==0)&(low==0))]`다. `volume>0`이 아니다 — 과거
  버전이 그거였다가 과잉제거로 기각됐다(위 Phase 3 참고). 다시 건드릴
  일이 있으면 `research/strategy-lab/engine/runner.py`의 함수 docstring에
  전체 근거가 있다.
- **PIT 위반 검증은 두 층위다** — 접근 차단(`PITBars`가 미래 날짜 요청 시
  예외)과 인과성 검증(잘라낸 시계열로 재계산해도 값이 같은지, `test_pit_contract.py`).
  전자만으론 지표 공식 자체가 미래를 보는 버그를 못 잡는다.
- `engine/runner.py`의 `run_smoke()`는 `rule_module` 파라미터로 임의의
  규칙 모듈을 주입할 수 있다(B1/B2가 이 경로로 5dc_v1a_p의
  compute_features/risk_spec_for를 재사용) — 오케스트레이션만 공유,
  execution/portfolio 계약 파일은 안 건드림.
- **5DC-v1A-RANK(tie-break만 다른 변형)는 아직 없다.** 필요해지면
  `strategies/common/5dc_core/`로 공유 지점을 분리하기로 Phase 2에서
  이미 설계해 뒀다(승인됨, 미구현) — `strategies/5dc_v1a_rank`가 `5dc_v1a_p`를
  직접 참조하게 만들지 않는다.
