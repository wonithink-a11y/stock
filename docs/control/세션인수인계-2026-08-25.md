## 1. Paper Trading 모의투자 파일럿 — 실주문 직전 상태

### 1.1 지금까지 한 것

- `research/strategy-lab/engine/live/paperEngine.py`: `poll_once()`에
  `is_still_selected` 콜백 추가(기존 stop/target 전략 동작 무변경) +
  `scan_rebalance_signals()` 신설 — 월별 교체매매 전략(PBR·LOWMOM60)을
  기존 poll_once 상태기계에 태우는 핵심 로직. 신규 회귀 12건 + 기존
  32건 전부 통과.
- `research/strategy-lab/run_monthly_rebalance.py`: 실행 진입점.
  ```
  python run_monthly_rebalance.py --strategy pbr_value_v1 --as-of 2026-08-03 --capital 5000000
  python run_monthly_rebalance.py --strategy lowmom60_v1 --as-of 2026-08-03 --capital 5000000
  ```
  위(파라미터 그대로)는 dry-run으로 이미 실행 완료 — PBR 29건·LOWMOM60
  30건 매수 의도가 `research/strategy-lab/data/paper/{strategy}_positions.json`
  에 PENDING_ENTRY로 기록돼 있다(리셋 안 함 — 데모가 아니라 실제 준비
  단계). **KIS에는 아직 아무 주문도 안 나갔다.**
- `--as-of`는 "오늘 날짜"가 아니라 "어느 리밸런싱 신호를 쓸 것인가"다 —
  `selection.json`엔 매월 첫 거래일만 키로 있어서 8월엔 `2026-08-03`
  하나뿐이다(8/24 등 중간 날짜는 빈 목록, 정상).

### 1.2 다음 세션이 할 일 (사용자 확인 필요, 장중에만 가능)

```bash
python research/strategy-lab/run_monthly_rebalance.py \
  --strategy pbr_value_v1 --as-of 2026-08-03 --capital 5000000 --enable-live-orders
python research/strategy-lab/run_monthly_rebalance.py \
  --strategy lowmom60_v1 --as-of 2026-08-03 --capital 5000000 --enable-live-orders
```

- **반드시 KRX 정규장(평일 09:00~15:30 KST) 중에 실행**한다. 장 마감
  후/휴일에 KIS 모의투자 API가 어떻게 반응하는지 이 프로젝트가 검증한
  적이 없다(08-24 밤 사용자가 실시각 확인 요청, "장 열리면 진행"으로
  일시 중단됐다).
- **이 세션의 로컬 셸 시계(`date` 명령)를 신뢰하지 않는다** — 이번
  세션에서 세 번 서로 다른/역행하는 값을 반환했다(실측, 08-24 참고).
  현재 실제 시각은 사용자에게 직접 물어보거나 시스템 프롬프트의
  currentDate만 참고한다.
- 최초 실행 한 번으로 안 끝난다 — PENDING_ENTRY → ENTRY_SUBMITTED → OPEN
  전환이 KIS 체결 확인(비동기)을 거치므로 며칠에 걸쳐 반복 실행해야
  한다(`poll_once()` 자체 설계, `run_monthly_rebalance.py` 문서 참고).
- 실행 전 **자본배분 재확인**: KIS 모의투자 계좌(5019****/01) 가상자금
  약 1,000만원, 사용자가 반반(각 500만원)으로 결정(08-24). 계좌를
  건드린 적 없으니 재확인 없이 그대로 써도 된다.
- 9월 1일 근처 자동 리마인더(클라우드 루틴, 읽기전용)가 이미 잡혀있다 —
  `https://claude.ai/code/routines/trig_01FUr8H6AdMYLpzhU3SrNraq`. 8월
  진입이 이번에 끝나면 9월 1일은 "정상적인 다음 리밸런싱"이 된다.

### 1.3 사용자가 밝힌 장기 비전 (판단 기준으로 참고)

  지금은 반자동, 장기적으로 완전자동.

  신호로 일정 비율 자동매도를 원함(부분 익절/트레일링 손절 성격).
- **Claude가 명시한 경계**: 모의투자(가상자금)는 완전자동까지 제약 없음.
  **실제 돈이 걸린 거래는 아무리 승인받아도 Claude가 직접 주문 실행은
  못 한다** — 이건 프로젝트 정책이 아니라 Claude 자체의 제약이라 안

  규칙(일정% 익절/손절)을 얹었을 때 그냥 들고 가는 것보다 나은지 백테
  스트로 먼저 검증 — 5DC·TREND-BREAKOUT의 기존 stop/target(진입가
  ±2×ATR, 손익비 1:3, 60거래일 시간청산)은 리스크계약 자체는 이미

  그 청산을 물린 두 전략 모두 CAGR 마이너스라 실전 배치 후보가 아니다.

  맞다는 논리. **착수 여부는 다음 세션 판단.**

## 3. FRED 매크로 데이터 확장 + 로컬 스케줄

### 3.1 무엇을 받았나

`research/strategy-lab/build_fred_extended_backfill.py` — 사용자가 준
FRED 우선순위표(금·은 제외) 21개 시리즈를 기존 `macro_common.py`(FRED
조회 + PIT asOf 조인 유틸, 이 프로젝트가 이미 쓰던 것)로 그대로 받는다.
DFF·DGS10·NASDAQCOM·DEXKOUS는 기존 `market_regime_features.parquet`에
이미 있어 스킵.

**실측으로 확인한 것(추측 아님, 직접 FRED에 재확인함)**:
- 금(`GOLDAMGBD228NLBM`)·은(`SLVPRUSD`)은 **2025년에 라이선스 문제로
  폐지**됨, FRED에서 아예 안 받아진다 → `notAvailable`로 UI에 정직하게
  표시(지어내지 않음).
- S&P500(`SP500`)·나스닥100(`NASDAQ100`)은 **실제로 받아진다**(이전
  세션에 Claude가 "나스닥100은 FRED에 없다"고 잘못 말한 것 정정됨).
  단 SP500은 **라이선스 제약으로 최근 10년치만** 서빙돼 이 프로젝트
  분석기간(2014~)의 21%가 결측이다(정상, 버그 아님).
- 하이일드·투자등급 스프레드(BAML)는 FRED가 **2023-08-25부터만**
  서빙한다(직접 curl로 재확인함) — UI의 최근 1년 창(250거래일)에는
  전부 들어있어 화면상 문제 없음.
- 월별/분기별 경제지표(CPI·PCE·고용·GDP 등)는 관측일과 실제 발표일이
  다르다 — 시리즈별 보수적 lag(예: CPI +18일, GDP +32일, 고용 +38일)을
  적용해 PIT 위반 없게 함(셀프테스트 6/6 통과, `--selftest`로 재현
  가능). **정확한 BLS/BEA 공표일정 대조는 안 함 — 보수적 추정**이라는
  한계는 그대로 남아있다(기존 한국 CPI lag과 같은 한계).

`--tier {1,2,all}` 옵션으로 daily/weekly(tier1, 시장이 매일 움직이는
만큼 값도 움직임)와 monthly/quarterly(tier2, 발표 사이엔 안 바뀜)를
따로 받을 수 있다. 한쪽만 받아도 다른 tier 컬럼을 안 지우고 병합
(양방향 실측 확인).

`market_regime_features.parquet`(정본, 기존 25컬럼)에는 **아직 병합
안 함** — 독립 산출물(`data/market-regime/fred_extended_daily_kr.parquet`)
로만 존재한다. UI 반영은 `build_ui_macro.py`가 이 파일을 별도로 읽어서
한다.

### 3.2 UI에 반영된 것

`build_ui_macro.py`가 이제 세 소스를 합친다:
1. `market-regime-feature-dataset/v1/features_daily.parquet`(기존 10개)
2. `data/market-regime/fred_extended_daily_kr.parquet`(신규 10개 —
   1차 5개: S&P500·나스닥100·미국2년물·10Y-2Y금리차·하이일드스프레드 /
   2차 5개: CPI·근원PCE·실업률·산업생산·실질GDP)
3. `docs/data/macro.json`(미국 레짐 스냅샷, 최신값만)

`macro.js`는 무변경 — `series` 딕셔너리를 그대로 순회해 카드를 그리므로
새 키가 자동 반영된다. 매크로 탭 총 20개 시계열 + 레짐 스냅샷 8개 +
미제공 2개(금·은).

### 3.3 로컬 스케줄 — 다음 세션이 확인할 것

```
StockUI-FRED-Tier1-Daily    매일 07:30    다음 실행 2026-08-26 07:30
StockUI-FRED-Tier2-Weekly   매주 월요일 07:35   다음 실행 2026-08-31 07:35
```

Windows 작업 스케줄러(`schtasks`)에 등록 — **세션이 꺼져도 계속 돈다**
(Claude Code 내장 cron 도구는 세션 종속 + 7일 자동만료라 부적합, OS
스케줄러가 맞는 선택이었다). 실행 배치파일:
`research/strategy-lab/run-fred-tier1-daily.bat` /
`run-fred-tier2-weekly.bat` — 각각 `build_fred_extended_backfill.py
--tier N` → `build_ui_macro.py` 순서 실행, 로그는 같은 폴더의
`fred_tier1_daily.log`/`fred_tier2_weekly.log`(gitignore 처리됨).

**★ 다음 세션 할 일**: `schtasks /query /tn "StockUI-FRED-Tier1-Daily"
/fo LIST /v`로 `Last Run Time`·`Last Result`(0=성공)를 확인하고, 로그
파일 내용도 읽어서 실제로 정상 갱신됐는지 검증한다. 이 확인 자체를
이 세션이 밤새(2026-08-26 아침) 자동으로 하고 있을 수도 있다 — 먼저
이 문서 갱신 여부·대화 이력을 확인해서 중복으로 또 확인하지 않는다.
