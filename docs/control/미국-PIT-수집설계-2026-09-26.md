# 미국 S&P500 PIT 가격·재무 수집 설계 (2026-09-26)

목적: 한국에서 유일하게 살아남은 가치 축(PBR)을 **미국 S&P500 2016~ PIT 표본**으로 독립 재검증할 재료를 만든다.
이 문서는 수집 설계까지다 — 가설·판정 기준은 수집 뒤 별도 사전등록에서 결과 전에 고정한다.
선행 조사: `미국-폐지종목-가격-무료소스-조사-2026-09-25.md`(§5 무료 키 실측). 여기 숫자는 전부 2026-09-26 실측.

## 0. 한 줄 요약

**구성 명단(fja05680, MIT) → 보안 마스터(구간별 CIK·가격 티커) → 가격(생존 종목은 이미 쌓는 yfinance, 편출 종목만 Tiingo)
→ 재무(EDGAR companyfacts, 제출일 기준) → 자동 게이트.** Tiingo 는 **편출 ~242 + 대조용 50 ≈ 300 종목**만 쓰므로
**무료 한도(월 500) 한 달 안**에 끝난다. 원자료는 로컬 전용(gitignore), 커밋은 명단·마스터·manifest 뿐.

## 2. 단계

### S1 명단 → 멤버 구간
- fja05680 파일을 **커밋 sha + sha256 으로 고정**해 `research/strategy-lab/data/us-pit/membership_intervals.csv` 로 커밋(출처·라이선스 머리말).
- 2026-08-18 이후는 VM 위키 스냅샷의 편입·편출로 잇는다(3종목 차이 = BE·ILMN·P 편입 / BLDR·TAP·TTD 편출).
- fja 는 **티커 변경도 '편출+편입'으로 적는다**(BK·MMC 2026 편출 = 위키엔 없음 → 티커 변경으로 보임). S2 에서 CIK 가 같으면 한 구간으로 합친다.

### S2 보안 마스터 (구간 → CIK · 가격 티커 · 상태) — 이 단계가 정확도를 결정한다
구간마다 아래 순서로 **첫 규칙이 걸리면 멈춘다.** 결과 `security_master.csv`(커밋 — 우리 판단과 공개 사실만, Tiingo 값은 안 싣는다).

| 규칙 | 대상 | 방법 | 검증 |
|---|---|---|---|
| R1 현재 멤버 | 503 | 위키 CIK · 가격 = yfinance 같은 티커 | CIK 가 SEC 맵과 일치 |
| R2 개명(생존) | 편출 중 새 티커로 살아 있는 회사 | `renames.csv`(옛→새 티커·날짜·근거, 손으로 관리 ~40행) · 가격 = yfinance 새 티커 | 새 티커 가격 시작일 ≤ 구간 시작 **그리고** 그 CIK 가 구간 안에 10-K/10-Q 제출 |
| R3 Tiingo 직접 | 폐지·인수 | Tiingo 메타 기간이 구간을 ±10일로 덮음 | Tiingo 이름 ↔ cik-lookup 이름 정규화 일치 → CIK, 그 CIK 가 구간 안에 제출 |
| R4 파산 Q 티커 | SIVBQ 등 | 티커+Q/QQ 메타 | R3 과 같음 |
| R5 도달 불가 | 재사용 17 + 결손 | 상태 `UNREACHABLE`, 사유 기록 | 명단 자체가 산출물 |

- **티커로 조인하지 않는다.** 모든 하류 조인 키는 CIK(재무)와 `price_symbol`(가격) 두 개다 — FB 가 지금 ETF 를 가리키는 실례(교훈 81 과 같은 모양: 성공 응답이 내 질문의 답이 아니다).
- 이름 불일치·후보 여럿은 자동 판정하지 않고 `review.csv` 로 뺀다 → Claude 가 근거와 함께 판정, 사용자 확인.

### S3 가격
- **생존·개명 종목은 이미 있는 yfinance 데이터**를 쓴다(VM → PC 로 복사). Tiingo 는 R3·R4 구간만.
- Tiingo 는 원시 종가 + `splitFactor` + `divCash` 를 받아 **분할조정 종가 + 배당 열**로 yfinance 와 같은 형태로 맞춘다
  (`adjClose` 는 저장 안 함 — 배당 소급 조정이라 이미 us_universe_snapshot 이 같은 이유로 안 쓴다).
- **소스 혼합 게이트**: 현재 멤버 50종목을 Tiingo 로도 받아 yfinance 와 겹치는 구간을 대조 — 분할조정 종가 일별 차이 중앙값 < 0.1%, 99분위 < 1% 가 아니면 혼합하지 않고 멈춘다.
- 기간: 2015-01-01~(2016 첫 신호의 1년 룩백).
- 속도: 무료 시간당 50회 → ~300 종목 약 6시간. **재개 가능**(종목별 파일, 있으면 건너뜀) · 월 고유 종목 카운터를 파일에 남겨 480 에서 멈춘다.

### S4 재무 (EDGAR)
- CIK 별 companyfacts 1회(초당 10회 한도 → ~750건 수 분). 원본 JSON gzip 로컬 보관(수 GB 예상 — 첫 50건으로 크기 실측 후 확정).
- 패널: `(cik, 항목, 회계기간말, 값, filed, form)` — **가용일 = filed 다음 거래일**. 같은 기간 정정 공시는 그 filed 부터 새 값(과거 소급 금지).
- 항목 매핑(자본총계·발행주식수 대체 태그)은 A3e 처럼 **감사 후 버전 동결**(`us_account_map.py`, us-map-1.0). 이 문서에서 정하지 않는다.

### S5 자동 게이트 (manifest 계약과 같은 원칙 — 실패하면 산출물을 안 쓴다)
1. 매 거래일 멤버 수 495~505.
2. **멤버-일 가격 커버리지 ≥ 97%**(2016~), 빠진 멤버-일은 전부 `UNREACHABLE` 명단으로 설명돼야 한다(설명 안 되는 결손 0).
3. 가격 구간이 멤버 구간을 ±10일로 덮는다(재사용 티커 오염 방지).
4. 소스 혼합 대조(S3) 통과.
5. 멤버-분기 재무 커버리지(자본총계·주식수) 보고 — 판정 기준은 사전등록에서.
6. manifest: 입력(fja sha·SEC 파일 sha256·Tiingo 조회일)·산출물 sha256·규칙별 건수.

## 4. 알려진 한계 (사전등록에 그대로 옮긴다)

- 2010~2015 는 쓰지 않는다(폐지 ~40종 결손).
- `UNREACHABLE` ~7% 는 **전부 피인수 기업** → 유니버스 수익률이 약간 낮게 잡힌다(방향 알려짐).
- 업종(GICS)은 **현재값만**(과거 업종 무료 소스 없음) — 업종 중립 분석은 제한된다.
- 구성 명단은 위키 기반 수동 갱신 — 유지자 본인이 불완전하다고 적었다. 게이트 1 이 큰 오류는 잡지만 하루 이틀 어긋남은 못 잡는다.
