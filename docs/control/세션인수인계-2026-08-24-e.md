### 1.3 GATE-EP-1 Tier C 타당성 조사 — "만들어도 소용없다" 확정

사용자 지시로 Tier C 착수 전에 타당성부터 조사(신규 DART 호출 0건, 이미
커밋된 A1b·A2b·EO만으로 재구성). 975건 UNKNOWN의 구성:

```
Group A 미분류        260건 (noSignal 204 · ambiguousAuditCapital 56)
품질게이트 제외        122건 (anchor 자체 없음, 재수집 필요)
가격 흔적 자체 없음    593건 (dartModifyDate≈2017 배치값 몰림 474 · 나머지 119)

**결정적 산수**: GATE-EP-1 통과에는 UNKNOWN≤61건(5%)이 필요한데, reachable
501건(260+122+119) **전부** 100% 분류해도(현실 Tier B 성공률은 같은 유형
21.0%뿐이었다) UNKNOWN은 여전히 474/1223=38.8% — 임계의 7.8배. 474건
(pre-2014 추정 폐지)은 anchor 자체가 없어 이 프로젝트 방법론으로 접근
경로가 없다. **결론: Tier C는 만들지 않는다** — 260·122건을 붙잡아도
GATE 통과에 산수로 기여 못 한다. A6 Primary는 이 GATE 프레임워크 위에서
**무기한 HOLD로 남는다** — 이것도 정직한 결론이다.

## 3. Strategy Lab PRIMARY 정식 승격

### 3.1 만든 것

`A2bProvider`(폐지종목 가격, `data/backfill/price/a2b` 읽기) +
`MergedPriceProvider`(A1a→A2a, A1b→A2b 라우팅) — `PriceProvider`
인터페이스가 원래 예상해 둔 확장 경로 그대로. `engine/runner.py`의
`A1A_ONLY` assert를 `A1A_A1B_MERGED`도 허용하도록 완화.

### 3.2 실행 중 발견 — PRIMARY 기준 자체가 GATE-EP-1과 같은 구조

실제 병합 유니버스(3,801종목)로 5DC-v1A-P를 전체 기간(2014-05-13~
2026-08-03) 재실행하니 `missingPriceTickers 734/3801(19.3%)`로 기존
policy.json의 "PRIMARY requires **full** A2a+A2b coverage" 기준을
**절대 못 넘는다**는 게 드러났다 — 폐지종목 상당수가 원리적으로 가격
흔적 자체가 없다는, §1에서 확인한 것과 정확히 같은 원인.

사용자 확인 후 PRIMARY 기준을 "100% 커버리지"에서 "병합 유니버스로
실제 실행했는가"로 재정의 — 결측은 숨기지 않고 `diag.universeCoverage`에
그대로 남긴다(exitReasonCoverage와 같은 패턴). `strategies/5dc_v1a_p/
policy.json`의 mode를 `A1A_A1B_MERGED`로 전환해 **이 전략만** PRIMARY로
승격, 다른 전략(PBR·TREND-BREAKOUT-v1 등)은 무변경.

검증: 신규 회귀 8건(`test_a2b_and_merged_provider.py`·
`test_run_class_merged.py`) + 기존 126건 전부 통과, 실제 전체 기간
백테스트 완주(847.6초, closedPositionCount 1581). 이 재실행 자체의 성과
수치(CAGR -7.94%)는 2026-08-17 비교(-8.1847%)와 정확히 일치하지 않는데,
그 사이 engine이 same-bar·portfolio scheduling 등 여러 번 고쳐졌기
때문 — "냉동 baseline은 engine commit 바운드로만 유효" 원칙 그대로,
새 이상 신호 아님.

## 4. LOWMOM60+기관수급(ChatGPT A/B/C) 재개 — 후보 C만 구현

### 4.1 착수 전 발견 — "A/B/C 검증됨"은 부정확한 표기였다

재개 전 코드를 직접 확인하니, "+13.90%로 재검증됨"이라던 사전점검
(`lowmom60_institutional_eligible_precheck_v2_absolute.py`)이 **A4
기관수급 데이터(foreign_nb_20d·inst_nb_20d 등)를 전혀 쓰지 않고** LOWMOM60
+절대유동성필터만 쓴다는 걸 발견했다. 이건 후보 C(저모멘텀+유동성필터)의
재검증이지, 후보 A/B(저모멘텀+실제 기관/외국인수급 결합)가 아니다. A/B는
필터/순위 결합 방식이 이 프로젝트 어디에도 구체적으로 정의된 적이 없다
(원 ChatGPT 제안 원문 미보존). **사용자 확인 후 C만 구현.**

### 4.2 구현 + 실제 엔진 결과

`strategies/lowmom60_v1/`(policy.json·build_selection.py·rule.py)을
pbr_value_v1과 완전히 같은 패턴(오프라인 selection.json + engine 무변경)
으로 신설. PBR이 겪은 고정 21일 근사 문제를 처음부터 정확 holdSessions
계산으로 피했고, `scheduling.continuousHoldOnRenewal: true`도 처음부터

```
