  포맷만 바꾸는 순수 export 함수다(`graphify.export.to_obsidian`·`to_canvas`·
  `graphify.wiki.to_wiki`, 코드로 확인 2026-08-17). **LLM 재호출 없음 — 비용 걱정
  없이 돌려도 된다.**

### 비용 발생 — 문서/계약/정책(.md, docs/*, .github/workflows/*.yml 등) 의미 추출뿐

이번 세션 실측:

  결국 절반은 안 씀(사용자가 중도에 멈춤 지시)

### 규칙 (우선순위 순서)

```
1. GEMINI_API_KEY가 있으면 무조건 그것부터 쓴다.
   graphify.llm.extract_corpus_parallel(files, backend="gemini", ...)
   클로드 서브에이전트를 먼저 시도하지 않는다.

2. 로컬에서 사용자나 서브 프로젝트 개발자가 직접 돌릴 수 있는 작업이면
   (예: 대량 코퍼스 재추출, Gemini 키를 가진 쪽에서의 실행) 클로드가
   서브에이전트로 대신 하지 않고 작업지시서로 넘긴다.
   형식은 docs/AI협업-업무분담.md §3(Task ID·목적·입력·기대 출력·제약)을 따른다.

3. 1·2가 둘 다 안 되면(Gemini 키 없음, 위임 불가) — 서브에이전트를 실제로
   디스패치하기 전에 반드시 예상 비용(파일 수·청크 수·대략 토큰)을 먼저
   보고하고 사용자 승인을 받는다. 오늘 이 확인을 건너뛰어 71만 토큰을
   날렸다(2026-08-17 실측) — 승인 없이 진행하지 않는다.
```

### Gemini 무료 티어 운영 메모

- 분당 5요청 · 분당 25만 입력토큰으로 매우 낮다(모델 `gemini-3-flash`,
  429 실측 2026-08-17). 8청크 동시 디스패치(`max_concurrency` 기본값 4)에서
  2개 실패.
- 대응: `max_concurrency=1~2`로 낮춰 재시도. **매 라운드 끝나면
  `graphify.cache.save_semantic_cache(...)`로 즉시 캐시 저장** — 안 하면
  다음 재시도가 이미 성공한 파일까지 처음부터 다시 돌려서 토큰을 또 태운다
  (이번 세션에서 이 실수로 한 번 더 비용이 날 뻔했으나 중간에 캐시 저장을
  추가해 막음).
- 모델이 청크 안 파일 일부를 응답에서 그냥 누락하는 현상 있음(재시도해도
  같은 파일이 반복 누락 — `.claude/skills/graphify/references/*.md` 9개 +
  `.claude/CLAUDE.md`가 3회 재시도 후에도 계속 빈 응답). 3회 이상 실패하면
  포기하고 갭으로 남기는 게 비용 대비 낫다(2026-08-17 판단 — graphify 자체
  도구 문서라 프로젝트 실질 내용과 무관했음).
