## 3. Opening Fade · CAND1 · H6 — regime-conditional 검증

공통 원칙(세 전략 다): §2-5의 고정 regime 정의를 바꾸지 않음, 각 전략의
**기존** 신호·체결·비용 규칙을 바꾸지 않고 그대로 재사용(import 또는
verbatim 복사, 원본 무변경), threshold 역최적화 없음.

### Opening Fade
(`findings/opening-fade-regime-conditional-2026-08.md`, 커밋 `1972839`) —
Q1롱+Q5숏, RT=30bp. baseline net=+9.19bp(T+5)이지만 **최대 비중(Neutral,
~52%)에서 순손실(-14.44bp)**, 후반부엔 baseline 자체가 음전환(-4.32bp).
→ **"conditional candidate"로 유지**(robust 전략 아님, Risk-On 국면
의존 가능성).

### CAND1(PMCRASH_REVERSAL) — 셋 중 유일한 강한 후보
(`findings/cand1-regime-conditional-2026-08.md`, 커밋 `6745dc5`) —
thr=0.02·vthr=1.5·entry=n_open·exit=n_c0935·cost=20bp. **3개 regime
전부 순이익**(10.01~24.03bp), **전후반 전부 순이익**(28.69→13.73bp).
TEST 구간 재현이 기존 보고(+0.369%/일, t=3.94)와 **완전히 일치**(감사
통과 — audit 도중 신호일/진입일 그룹핑 버그 1건 발견·수정).

### H6(마감 급등 되돌림) — REJECTED
(`findings/h6-regime-conditional-2026-08.md`, 미커밋) — 기존 15:20 정의는
결함 확정(15:20 봉 자체가 거의 없음, 이전 세션 발견)이라 안 쓰고, 대안
**15:19(마지막 연속봉)·15:30(장마감 단일가) 두 독립 버전**을 검증. **둘
다, 3개 regime 전부, 양 반기 전부 순손실**(-45~-70bp대, 승률 32~45%,
PF 0.57~0.87) — 예외 없음. 원본의 되돌림 가설이 실제 거래 단위에서는
성립하지 않고 오히려 모멘텀 지속에 가까움을 이번에 처음 확인.

### 종합
(`findings/regime-conditional-synthesis-2026-08.md`, 미커밋) — 위 셋을
한 표로 비교. 공통 한계: 세 전략 다 분봉 기반이라 데이터 창이

## 5. CAND1 엔진 연결 — 옵션 A/B 설계 비교 → 옵션 B 구현·검증 PASS

### 설계 비교
(`findings/cand1-engine-integration-design-2026-08.md`, 미커밋) —
`executor.py`/`contracts.py` 실측(진입은 이미 정합, 청산 3경로 STOP/
TARGET/TIME_EXIT 전부 일봉 단위라 특정시각 청산 표현 불가 확정) 기반
비교표. 옵션 A(근사)는 "사실상 다른 전략", 옵션 B(확장)는 "검증된 것과
같은 걸 검증"하지만 비용이 크다 — 단 CAND1은 stop/target이 없어 PBR보다
격리하기 쉬울 가능성. 어느 쪽도 결정하지 않고 사용자에게 넘김.

### 사용자가 옵션 B 승인 → 구현·검증
(커밋 `17c3858`) — `engine/execution/intraday_exit.py` 신설, **기존
`executor.py`·`contracts.py`는 diff 0**(직접 확인). CAND1은 stop/target이
없어 기존 매칭 루프를 안 쓰는 완전 격리 경로로 구현, 새 `fill_type`
("INTRADAY_TIME_EXIT") 문자열 하나만 추가.

- **구현 전 검증**(지시 순서): MinuteProvider 실측 — tz-aware KST,
  **09:35 봉이 09:00 대비 78.85%만 존재**(결측 유의미, 보간 안 하고
  `None` 반환으로 반영). `tests/test_intraday_exit.py` pytest 10건
  전부 PASS(PIT 직접 증명, 결측 처리, 비용공식, 독립성 — 겹침방지 로직
  자체를 안 써서 PBR이 겪은 공유 스케줄링 버그가 구조적으로 발생 불가).
  기존 회귀 126개 전체 재확인, 무영향.
- **구현 후 대조**(`findings/cand1-intraday-exit-engine-verification-2026-08.md`,
  커밋 `17c3858`) — standalone 12,804건(entryDate 매핑 가능 전체 — 기존
  13,329건과 차이는 calendar.json 끝단 문제로 정정 기록, 버그 아님) 각각의
  09:35가를 MinuteProvider로 재조회. **커버리지 82.0%**(나머지 18%는
  정확히 그 분 틱 자체가 없어 제외, 지어내지 않음 — 이건 연구의 공백이
  아니라 MinuteProvider 자체의 결측이고, standalone 그리드 기준
  12,804건은 전부 데이터가 있었다). 겹치는 10,502건에서 **가격
  근접일치율 99.81%, net 차이 -1.33bp**(그리드 23.74bp vs MinuteProvider
  22.41bp) — 사전설정 기준(>99%·<2bp) 충족 **PASS**. 12,804건 전체
  net도 21.65bp로 기존 baseline과 정확히 일치.
  버그 2건 발견·즉시수정(대조 스크립트 자체의 버그, 컬럼명 충돌·포맷
  문자열 인자수 불일치 — `intraday_exit.py`는 무관).

### 사용자 결정으로 여기서 조사 마무리
18% 결측 신호(MinuteProvider 한정 — standalone 검증엔 이미 영향 없음)를
더 파고들지 여부를 사용자에게 물었고, **"연구 가치는 낮다(구현 디테일이지
전략 유효성 질문 아니다), 마무리하고 나중에 백테스트하자"**로 정리.
결측 틱 fallback 설계는 향후 실제 SMOKE/배포 재개 시점으로 미룬다.
