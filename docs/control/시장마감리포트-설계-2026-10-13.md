# 장 마감 리포트 — 설계와 실측 (2026-10-13)

사용자 요청: 한국·미국 장 마감 뒤 "오늘 왜 올랐나·떨어졌나" 리포트를 매일 받기. ChatGPT 안 두 차례 검토 반영.

## 1. 구조

```
평일 18:10 KST  루틴 kr  ┐
평일 07:00 KST  루틴 us  ┴→ ① python scripts/market-close-facts.py  (숫자 — 코드만)
                            ② 웹 검색으로 원인 후보·근거·시각 대조     (해석 — Claude)
                            ③ reports/market-daily/<날짜>-<kr|us>.{md,facts.json} 커밋·push
                                 ↓ push 이벤트(1분 안)
                            market-report-telegram.yml → 텔레그램 1:1 방
```

- 리포트 3개(한국·미국·아침 통합) → **2개**: 미국 정규장 종료는 05:00 KST(서머타임, 11-02부터 06:00)라 미국 마감 리포트와 07:00 아침 브리핑이 같은 시각이다. 07:00 한 번이면 서머타임 계산도 필요 없다.
- 루틴 지시문은 `docs/control/시장마감리포트-루틴지시.md` 하나가 정본(루틴 재등록 없이 고친다).
- 기존 자동매매·연구 파이프라인은 건드리지 않는다. 새 파일 4개 + notify-failure 대상 1줄.

## 2. GitHub Actions 지연 실측 (최근 60회, 2026-10-13)

`gh run list --event schedule` 의 실행 생성 시각 − cron 예정 시각.

| 워크플로 (예정 KST) | 시작 지연 중앙 | p90 | 최대 |
|---|---|---|---|
| daily-analysis (16:40) | 4.6h | 7.7h | 11.9h |
| macro (16:40) | 4.6h | 7.7h | 11.9h |
| market-flows (18:20) | 4.3h | 7.8h | 11.6h |
| disclosures (18:10) | 4.4h | 7.9h | 11.6h |
| market-movers (20:10 · 08:40, n=13) | 5.4h | 8.4h | 9.1h |
| events (05:00, n=17) | 3.5h | 5.1h | 5.8h |
| **push 트리거 (n=40)** | **0.1분** | **0.2분** | **0.2분** |

(news 는 30분 간격이라 가장 가까운 예정 시각에 붙어 지연이 작게 보인다 — 비교에서 뺀다.)

**리포트에 주는 영향**

| 질문 | 결과 |
|---|---|
| 18:10 한국 리포트 때 오늘 값이 저장소에 있나 | macro 14/60 · market-flows **0/60** · disclosures **0/60** |
| 07:00 미국 리포트 때 전날 한국 값이 있나 | macro 60/60 · market-flows 60/60 · market-movers 7/13 · events(당일 05:00분) 0/17 |
| market-movers 의 asOf | 실측 당일 `20261008` — 5일 묵었다(KRX Open API 공표 시차 + 지연) |

결론:
1. **한국 리포트는 저장소 JSON 에 기댈 수 없다** → 숫자 묶음 스크립트가 직접 받는다(네이버 모바일 API·Yahoo, 키 없음). 저장소 JSON 은 `repoData` 로 날짜만 알려주고 루틴이 날짜가 맞을 때만 쓴다.
2. **전달은 cron 이 아니라 push 로** — 지연 0.2분.
3. 루틴 자체는 Actions 가 아니므로 이 지연과 무관. 루틴의 정시성은 등록 뒤 첫 실행들로 따로 잰다(§4).

## 3. 숫자 출처 실측 (2026-10-13 11:40~12:00 KST, 장중)

| 항목 | 출처 | 결과 |
|---|---|---|
| 지수·업종 ETF 15·섹터 ETF 11·VIX·10년물·달러·원자재·BTC·지수선물·EWY·RSP | Yahoo chart v8 | 전부 응답. 업종 ETF 이름(longName) 대조 완료 |

| 국내 상승/하락 종목 수·투자자별 순매수·프로그램·거래대금·시총 상위 10 | 네이버 `m.stock.naver.com/api/index/{KOSPI,KOSDAQ}/integration` · `polling.finance.naver.com` | 응답. `marketStatus`(OPEN/CLOSE)·`bizdate` 로 확정 여부 판정. 투자자별은 잠정치 |

| 국내 시간외 단일가 · 종목 지수 기여도 · 미국 상승/하락 종목 수 | — | **미수집**(키 없는 출처 없음·비중 데이터 없음). 리포트에 "수집 안 됨"으로 적고 기여도 수치는 금지. 미국 시장 폭은 RSP−SPY 로 대체 |

장중 실행 시 `regularSessionEnded=false` 로 나오는 것을 확인했다(루틴은 쓰지 않고 끝낸다).

## 4. 남은 확인 (루틴 등록 뒤 실측)

- 루틴 클라우드 환경에서 Yahoo·네이버·FRED 접속 가능 여부(네트워크 허용 범위).
- 루틴의 push 허용 브랜치(main 직접인지 `claude/` 접두 브랜치인지). 워크플로는 둘 다 받는다.
- 루틴 실행 시각의 정시성(예정 대비 실제 시작).
- 첫 kr·us 리포트가 텔레그램에 도착하는 데 걸린 시간.
