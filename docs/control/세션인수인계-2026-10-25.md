README 확인: 엔진(`core/`)·한도는 에이전트가 못 고치고 CI 가 막음, 모의 체결은 스프레드를 가로지름, 지표는 `brier_delta`(내 확률이 시장 가격보다 나은가). **우리 구조와 같은 방향**(사전등록·결과 보고 규칙 안 바꿈)이라 코드 도입은 안 하고 아이디어만.

### 설계 합의(사용자 제안 + Claude 정리)
1. **규칙 기반 '연 1회 수정 vs 동결' — 먼저, 지금 바로 가능**: 결합 순위 모델(현재 2016~2025 1회 학습 동결, `model_h5.txt`) 을 매년 직전까지 데이터로 다시 학습하는 판 vs 동결판을 같은 기간에 비교(워크포워드). 사람·LLM 이 아니라 정해진 규칙이 수정하므로 오염 없음.
   - 후보 수정 규칙(매년 재학습·2년 창·확장 창 등)과 **시험 횟수를 결과 전에 사전등록**하고 다중검정 보정(바닥선·난수 귀무)을 적용. 사용자가 다중검정을 감수하겠다고 했으니 '횟수를 세어 보고'하는 방식으로.
   - 비용 33.5bp(연속 시장) 고정, 시기 세 칸(2016~23 / 2024 / 2025~) + 반도체 제외 한 줄(시기 분리 규칙). 비교 횟수가 ~10번이라 검출력 약함 — 결과가 '차이 없음'이면 이 라인 접기.
2. **LLM 판단 전략은 과거 백테스트 금지**: Claude·Gemini 는 2016~2025 가격·뉴스를 학습해서 과거 구간 예측이 오염된다(모델 학습 이후 forward 만 깨끗). → **병렬 A/B forward**: 같은 날부터 '고정 규칙판'과 '회고로 수정하는 판'을 동시에 기록, 같은 표본으로 비교. 1번 결과가 "수정이 낫다"일 때만 시작.
3. 'Phil-lite' forward(별도): 매일 5건 안팎 '5거래일 뒤 시장 대비 초과수익 확률'을 기록, Brier 로 자동 채점, 기준선 = 결합 순위 모델 h5 확률 또는 기저 확률, 비용 33.5bp 반영, 100건·20거래일 뒤 1회 판정. 자기 수정은 '제안'까지만(채택은 새 사전등록). **주문 연결 없음**(KIS 모의 `plan_trader` 는 효과가 보인 뒤에).
   - 돌리는 쪽: Claude 루틴은 Claude 토큰을 쓰므로(사용자 한도 빠듯) VM 에서 Gemini 로 돌리는 안을 권고(무료 한도 내, 품질은 낮을 수 있음).
- 관련 기존 forward: 종목 종합 분석 예측 고정(10-19, 12개월 판정)·유망 테마 예측 고정 — 피드백이 느려서 Phil-lite 로 보완.
