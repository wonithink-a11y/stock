## 3. 크립토 뉴스 속보 — 만들기로 한 설계 (미구현)
사용자 요청: 비트코인·크립토 뉴스를 빠르게 받기. X(트위터)는 API 유료·스크래핑 약관 위반이라 **X 를 미러링하는 텔레그램 공개 채널**이 1순위, 영문 RSS·국내 속보는 보조. 예측(가격 전망)은 **하지 않고** 상황 정리·시나리오만(프로젝트 규칙: 가격 목표·확률 금지, 투자 권유 아님).

### 소스 (10-25 브라우저로 `t.me/s/<채널>` 직접 확인, 최근 글 있음)
| 역할 | 채널 |
|---|---|
| 1순위 | `wublockchainenglish`(크립토 속보) · `WalterBloomberg`(거시·지정학, 비공식 재게시) · `CoinNessKR`(국내 속보·청산 요약) · `lookonchainchannel`(온체인) |
| 보조 | `cointelegraph` · `whale_alert_io`(자동 알림이라 많음 — Gemini 가 거름) |
| RSS 보조 | CoinDesk · Cointelegraph RSS (**접속 미확인** — 만들 때 VM 에서 먼저 확인) |
- 제외: `TreeNewsFeed`(미리보기가 10-14 에서 멈춤) · The Block·CoinDesk·블록미디어 텔레그램(미리보기 안 열림) · `tokenpost_kr`(노이즈 큼, 요청 시 추가).
- 파싱: `https://t.me/s/<채널>` HTML 에서 `data-post="채널/ID"`, `<time datetime=…>`, `tgme_widget_message_text`. 미리보기는 최근 ~20건.

### 동작(계획)
- `scripts/crypto-news.py` + `deploy/crypto-news.{service,timer}`(VM 5분, `YT` 유닛과 같은 형태).
- 첫 실행은 **알림 없이 기존 글을 seen 처리**(폭주 방지). 새 글을 Gemini(Flash-Lite, 텍스트만)에 묶어 보내 `importance 0~2` + 한국어 한 줄 요약을 받고, 2 만 텔레그램 1:1 방에 묶음 발송(1 은 로그만). 같은 사건은 최초 1건만(이미 알린 요약 최근 20개를 프롬프트에 넣음). Gemini 실패 시 seen 처리하지 않고 다음 실행에서 재시도(60분 지난 글은 버림).
- **지연 측정용 로그**: 매 항목의 `published` 와 `seenAt` 을 `news-log.jsonl` 에 남겨 소스별 지연을 나중에 비교(사용자가 "원문 X 보다 얼마나 늦나"를 궁금해함, 아직 실측 안 함).
- 원문·로그는 VM `~/collector-venv/crypto-news/` 에만(개인 열람, 저장소·공개 대시보드 금지). 점수·매매 불사용(절대 규칙 1).
- 일일 정리·시나리오 요약은 이번 범위 아님(속보 알림 먼저, 기록이 쌓이면 판단).
