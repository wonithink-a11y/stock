# 장중 급등락 알림에 '유형 + 뉴스 + 공시' 붙이기 — 설계 (2026-10-13)

> 사용자 요청: "장중 급등 알림에 유형이랑 뉴스 붙이는 설계". **조회·알림 전용** — 매매·점수에 연결하지 않는다.
> 이 문서는 설계까지다. 구현·배포는 §9 결정 뒤.

## 0. 왜

8~10월 급등 256건을 분봉으로 나눠 보니(`research/strategy-lab/why_surge.py`, b201f7be) **163건이 '혼자, 공시 없이'** 올랐다. 알림을 받은 사람이 지금 하는 일은
"이게 왜 오르지?"를 직접 검색하는 것이다. 알림이 그 첫 10초를 대신한다: **시초가부터인지 장중인지 · 혼자인지 업종 전체인지 · 뉴스·공시가 있는지.**

## 1. 지금 구조 (scripts/intraday-check.js, VM 타이머 10분)

- 관심종목 KR 353(+US) → 네이버 fchart 일봉 최근 3개(현재가·전일 종가) → `detect()` 가 전일 대비 5%p 단계 / 직전 체크 대비 ±5% 판정 →
  텔레그램 1:1 방에 한 메시지(최대 40줄, `buildMessage`). 쿨다운·단계 도장은 **전송 성공 뒤**(`stampAlerts`).
- 상태 `~/collector-venv/intraday/state.json`, 국내 스냅샷 `kr-snapshot.json`(히트맵 '장중').
- 같은 VM 에 이미 있는 것: `news-alert`(매시 08~18시) → `~/collector-venv/news/news.json` `byTicker`(관심종목 345, 기사 제목·요약·pubDate, 3일 보존).
  VM `.env` 에 **NAVER 키 있음 · DART 키 없음**(2026-10-13 이름만 확인).

## 2. 붙일 것 — 알림 한 줄 밑에 맥락 한 줄

```
[KR] 가온전선(000500) 전일 대비 +12.3%
   └ 장중 무리형 · 전력·에너지 인프라 7/12 동반 · 뉴스 10:42 "북미 전력망 수주…" · 공시 없음
```

### 2-1. 유형 (why_surge.py 와 같은 이름·문턱, 실시간 근사)

| 유형 | 판정(먼저 맞는 것) | 재료 |
|---|---|---|
| 시초 갭형 | 시가 갭 ≥ 현재 상승의 70% | fchart 일봉 시가(이미 받는 응답의 `data[1]`, 지금은 버림) |
| 장중 무리형 | 동료 ≥ 5종목 중 같은 방향 ±2% 이상 비율 ≥ 30% | 동료 = 테마 트리 소그룹 ∪ `sector-strength.json` 의 `g`(업종). 현재가는 **같은 실행에서 이미 받은 353종목** — 추가 호출 0 |
| 단독+공시 | 위 둘 아니고 오늘 공시 있음 | §2-3 |
| 단독 | 그 밖 | — |

- 배치(분봉 ±10분 창)와 다르다: 실시간은 10분 스냅샷뿐이라 동료를 **전일 대비 등락**으로 본다. 그래서 배포 전에 §6-2 재현 점검을 한다.
- 하락(−) 알림도 같은 규칙을 방향만 바꿔 쓴다.

### 2-2. 뉴스

1. `news.json` `byTicker[코드].items` 중 **pubDate ≥ 전 거래일 15:30 KST** 인 기사.
2. 없거나 news.json 이 40분보다 오래됐으면 그 종목만 **네이버 검색 1콜**(종목명, 최신순 5건, 같은 시간 필터·제목에 종목명).
3. **재료 기사 / 시황 기사 구분** — 주가 움직임 자체를 보도하는 기사(`특징주|급등|급락|상한가|하한가|강세|약세|\d+(\.\d+)?%\s*(상승|하락|오른|내린)|주가.*(휘청|들썩)`)는 원인이 아니다.
   재료 기사 하나를 우선 보여 주고(시각·제목 40자), 없으면 `시황 기사만 N건`, 그것도 없으면 `뉴스 없음`.
4. 예산: 실행당 직접 호출 ≤ 10. news-alert 가 매시 약 380콜 × 11회 ≈ 4,200/일, 여기에 최대 10 × 42회 = 420 — 한도 25,000/일 안.

### 2-3. 공시

- DART `list.json?corp_code=…&bgn_de=오늘&end_de=오늘`(종목당 1콜, 그날 결과는 상태에 캐시). 제목만 — **접수 시각은 없다**(점화 전후를 못 가린다, 한계로 표시).
- corp_code 는 저장소의 `data/backfill/dart/corpcode.jsonl`(VM 체크아웃에 있음).
- **VM 에 DART 키가 없으면** 이 칸은 `공시 확인 안 함` — 나머지는 그대로 동작.

## 3. 메시지 길이

- 맥락은 **KR 알림 중 |등락| 큰 순 10건만**. 나머지 알림은 지금처럼 한 줄.
- 40줄 상한을 **글자 수 상한(3,800자)** 으로 바꾼다 — 맥락 줄이 붙으면 줄 수로는 4,096자를 못 지킨다(2026-09-11 HTTP 400 사고와 같은 모양). 잘라낸 건수는 지금처럼 밝힌다.

## 4. 실패해도 알림은 간다 (가장 중요)

- 맥락 수집(뉴스·공시·분류)은 **전부 fail-soft**: 예외·시간 초과면 그 종목은 `맥락 없음(오류)` 한 단어로 대체하고 알림은 그대로 보낸다.
- 호출마다 5초 타임아웃, 맥락 전체 60초 예산(유닛 TimeoutStartSec 8분 안). 예산을 넘기면 남은 종목은 맥락 없이.
- 쿨다운·단계 도장 규칙(`stampAlerts`)은 바꾸지 않는다. 맥락 실패가 도장을 막거나 찍지 않는다.

## 5. 코드 모양

- `scripts/intraday-check.js`: `fetchQuoteKR` 가 `open` 도 돌려준다(같은 응답). `main()` 이 알림이 생긴 뒤 `addContext(alerts, quotes, state)` 를 부른다.
- 새 파일 `scripts/lib/surge-context.js`(순수 함수 + 얇은 fetch): `classifySurge(quote, peerMoves)` · `pickCauseArticle(items, sinceMs, name)` · `isMarketRecap(title)` · `fetchDartToday(corp)` · `searchNaver(name)`.
  `fetch-news-kr.js` 는 모듈이 아니라(키 없으면 최상위에서 종료) 가져다 쓰지 않는다 — 네이버 호출 20줄을 따로 둔다.
- 상태: `state._ctx = { day, dart: {corp: [titles]} }` — 기존 종목 키와 섞이지 않게 밑줄 키 하나.

## 6. 검증

1. `scripts/test-intraday-check.js` 에 회귀 추가: 유형 4가지 경계(갭 69%/70%, 동료 4/5종목, 29%/30%) · 시황 기사 판별(실제 news.json 제목 예시) ·
   글자 수 상한 · **맥락 함수가 예외를 던져도 deliver 가 호출되고 도장이 찍힘** · DART 키 없음 경로.
2. 재현 점검(배포 전 1회): 8~10월 분봉에서 10분 간격 스냅샷을 흉내 내 `classifySurge` 를 돌리고 why_surge 배치 라벨과 일치율을 본다.
   시초 갭형·무리형 일치율이 낮으면(< 70%) 문턱이 아니라 **실시간 근사의 한계**로 문서에 적고 라벨 문구를 '추정'으로 바꾼다.
3. 배포 첫날: 장중 알림 원문을 사용자가 매매·보안 방이 아닌 1:1 방에서 확인, 오류 단어(`맥락 없음(오류)`) 빈도를 journalctl 로 본다.

## 7. 배포

- 코드만 바뀐다(새 유닛·nginx·외부 소스 없음 — 네이버·DART 는 이미 쓰는 소스). VM 은 06:30 pull 로 받는다 → **main 에 커밋하는 순간이 배포**다.
- DART 키: 사용자가 VM `~/collector-venv/.env` 에 `DART_API_KEY=` 한 줄 추가(값은 로컬 `.env` 와 같음). Claude 는 키를 옮기지 않는다(절대 규칙 2·메모리 규칙).
- 되돌리기: 해당 커밋 revert → 다음 pull 에 원래 알림.

## 8. 하지 않는 것

- 유형별 "다음 날 경향" 문구(단독 −0.8%·무리 +0.5% 등) — 두 달 사후 관찰이라 알림에 넣으면 예측처럼 읽힌다.
- 미국 종목 맥락(미국은 SEC 8-K 알림이 따로 있다), 점수·매매 연결, 뉴스 감성 점수.
