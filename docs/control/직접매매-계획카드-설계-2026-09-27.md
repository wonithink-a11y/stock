# 직접매매 계획 카드 — 설계 (2026-09-27, 착수 전 · 사용자 GO 대기)

계기: 인스타 게시물 'GPT-6 아스트라 24시간 AI 트레이더' 대조(같은 날 대화). 신호·리스크·감시는 이미 있거나 REJECT 됐고,
가져올 것은 **"사기 전에 진입·손절·목표·무효 조건을 적는다"** 하나다. 사용자가 직접매매를 하고 있어서 그 매매의 기록·알림 도구로 만든다.

## 0. 한 줄 정의와 경계

**직접매매를 하기 전에 계획을 적어 두면, VM 이 가격을 보고 손절·목표·진입 구간에 닿을 때 텔레그램으로 알린다.
결과가 쌓이면 내 매매의 실제 기대값(R 배수)이 숫자로 나온다.**

| 한다 | 안 한다 |
|---|---|
| 계획 입력·검증·수량 계산 | **주문** — 주문 경로(`place`·`--execute`)에 닿는 코드 없음 |
| 가격 도달 알림(매매·보안 방) | 신호 생성·종목 추천·AI 가 계획을 대신 짜기 |
| 결과 기록·통계 | 체계적 전략(PBR·RV20·크립토·무한매수)에 승인 단계 추가 — 검증한 규칙이 바뀐다 |
| VM 상태 폴더에만 저장 | 저장소·공개 대시보드에 개인 포지션 올리기(저장소는 PUBLIC) |

## 1. 기존 부품 재사용 — 새 VM 유닛·nginx·권한 변경 없음

| 역할 | 쓰는 것 | 근거 |
|---|---|---|
| 입력 화면 | autotrader 웹(로그인·CSRF·지문 이미 있음)에 `/plans` 페이지 추가 | `autotrader/web.py` |
| 저장 | `~/collector-venv/autotrader/state/plans.json` + `plans-log.jsonl`(추가 전용) | 웹 유닛은 `state/` 에 **이미 쓰기 권한**(`BindPaths`) — 유닛 수정 불필요 |
| 가격 감시 | `autotrader-snapshot`(5분마다, KIS 키 보유)에 계획 점검 한 단계 | `autotrader/snapshot.py`, 타이머 `*:0/5` |
| 알림 | `notify.trade_chat()` → 그룹 `매매•보안` | 웹 프로세스는 텔레그램 토큰을 못 본다 — 알림은 스냅샷이 보낸다(지금 구조 그대로) |

## 2. 계획 한 장의 필드

```
id            자동(날짜+순번)
symbol·market 6자리 ticker(normalizeTicker 규칙) · KR/US
side          long 만 (국내 개인 공매도 불가 — 선택지 자체를 두지 않는다)
entryLow/High 진입 구간(한 값이면 둘 다 같게)
stop          손절가        target  목표가
invalidation  무효 조건(자유 글) — 예: "실적 발표 전 거래량 없이 20일선 이탈"
thesis        근거 한 줄(자유 글)   tag  분류(자유: 돌파·눌림·실적·뉴스 …)
riskPct       이 거래에서 잃어도 되는 자본 비율(%)
validUntil    계획 만료일(기본 입력칸 +10거래일, 지나면 '만료'로 닫는다)
createdAt     KST
```

**입력 검증(저장 거부)**: `stop < entryLow ≤ entryHigh < target` · 가격 > 0 · riskPct 0 초과 5 이하.
**계산해서 보여 주는 것**(저장하지 않고 매번 계산 — 교훈75 '파생은 계산'):
- 손익비 = (target − 진입 중앙) ÷ (진입 중앙 − stop). 1.5 미만이면 **경고만**(막지 않는다 — 기준을 정한 연구가 없다).
- 수량 = floor(자본 × riskPct ÷ (진입 중앙 − stop)), 그 수량의 금액과 자본 대비 %.
  **자본을 설정하지 않았으면 수량을 계산하지 않고 '자본 미설정'으로 보인다**(모르는 것은 0이 아니다 — 교훈57).

## 3. 상태와 전이

```
대기 ──(사용자: '진입함' + 실제 체결가·수량)──▶ 보유 ──(사용자: '청산함' + 실제 청산가)──▶ 종료
  │                                            │
  ├─ 만료(validUntil 경과)                       └─ (알림만) 손절 도달 · 목표 도달 · 무효 확인 요청
  └─ 취소(사용자)
```

- **진입·청산은 사용자가 누른다.** 시스템은 주문을 안 내므로 실제 체결을 모른다. 자동 추정(실계좌 잔고 대조)은 v2 후보 — 지금 넣지 않는다.
- 알림은 **상태를 바꾸지 않는다.** "손절가에 닿았다"는 사실만 알리고, 실제로 팔았는지는 사용자가 기록한다.
  그래야 "계획대로 지켰는가"를 따로 잴 수 있다(§5).

## 4. 가격 감시 — 5분 점검의 구멍을 막는 법

- 국내: KIS 현재가 응답의 **당일 고가·저가**(`stck_hgpr`·`stck_lwpr`)로 닿음을 판정한다. 5분 사이에 찍고 돌아온 것도 잡힌다.
  지금 `kis.quote()` 는 현재가만 돌려주므로 고가·저가를 같이 주는 조회를 하나 더한다(같은 TR, 추가 호출 없음).
- **같은 날 손절과 목표를 둘 다 찍으면 순서를 모른다** → '둘 다 닿음·순서 불명'으로 표시한다. 어느 쪽으로도 채점하지 않는다.
- 미국: 1차는 현재가만(해외 현재가 TR 에 고가·저가가 없다) — 찍고 돌아온 것을 놓칠 수 있다고 화면에 적는다.
  필요해지면 해외 상세 시세 TR 로 넓힌다.
- 장 시간 밖에서는 조회하지 않는다(국내 09:00~15:30, 미국은 정규장). 활성 계획이 없으면 조회 0회.
- 같은 사건은 한 번만 알린다(계획별 `alerted` 집합을 상태에 둔다).

알림 문구 예:
```
[계획] 삼성전자 손절가 도달 — 71,200 (계획 손절 71,300) · 보유 중
   진입 74,000 · 목표 80,000 · 무효: 20일선 이탈 · 청산하면 웹에서 '청산함' 기록
```

## 5. 결과 기록과 통계 — 이 기능의 실제 값

종료된 계획마다 R 배수 = (청산가 − 진입가) ÷ (진입가 − 손절가) 를 계산한다(실제 체결가 기준).
`/plans` 아래 요약:

| 지표 | 뜻 |
|---|---|
| 건수 · 승률 · 평균 이익 R · 평균 손실 R | 기본 |
| **기대값(평균 R)** | 0보다 크면 계획대로 한 매매가 돈이 됐다 |
| 손절 준수율 | 손절가 도달 알림 뒤 실제로 청산한 비율 · 손실이 −1R 보다 컸던 건수 |
| 태그별 | 태그마다 위 지표 — **건수 n 을 항상 옆에 적는다** |

**미리 정해 두는 읽기 규칙**(우리 연구 방식 그대로, 결과 보기 전에 고정):
- **종료 30건 전에는 기대값을 판정에 쓰지 않는다.** 화면에 "표본 부족(n/30)"을 띄운다.
- 태그별 비교는 각 태그 20건 이상일 때만 '비교 가능'으로 표시한다. 그 전에는 "좋아 보이는 태그"를 고르지 않는다.
- 이 통계는 **계획을 적은 매매만** 본다. 계획 없이 한 매매는 안 잡힌다 — 전체 성과가 아니다(화면에 적는다).

## 6. 보안·개인정보

- 저장은 VM `state/` 에만. 저장소·`docs/data/`·공개 대시보드에 절대 안 나간다.
- `/plans` 는 로그인 필수, 금액이 보이므로 **지금의 '금액 보기' 규칙(지문, 5분)** 을 그대로 따른다. 쓰기(POST)는 CSRF.
- 웹 프로세스는 계속 키·토큰을 못 본다. 새 파일 `plans.json` 은 이미 쓰기 허용된 `state/` 안이라 허용목록 변경이 없다.
- 계좌번호·실계좌 잔고는 이 기능에서 읽지 않는다.

## 7. 구현 범위와 검증

| 파일 | 내용 | 규모(추정) |
|---|---|---|
| `autotrader/plans.py` (신규) | 모델·검증·수량·R 계산·닿음 판정·통계 | ~180줄 |
| `autotrader/web.py` | `/plans` 목록·입력·진입함·청산함·취소 | ~150줄 |
| `autotrader/snapshot.py` · `kis.py` | 계획 점검 단계 · 고가·저가 조회 | ~50줄 |
| `scripts/test-autotrader-plans.py` (신규) | 검증 거부·수량·R·같은 날 둘 다 닿음·중복 알림 없음·장외 무조회 | ~150줄 |

- 기존 autotrader 회귀 전부 + 새 회귀. **주문 경로 불변 확인**: `broker.place` 호출이 새 코드에 없음을 grep 으로 보인다.
- 배포는 정형 VM 운영: `git pull` → `autotrader-web` 재시작(스냅샷은 다음 5분부터 자동). 새 유닛·nginx 없음.
- 첫 실물 확인: 계획 1건(작은 종목)을 넣고 장중에 알림 1회 도달·중복 없음을 본다.

## 8. 사용자가 정할 것 (권고 포함)

1. **직접매매 자본 금액** — 수량 계산의 분모. 웹 설정에 한 번 입력(VM 상태에만 저장). 권고: 실제로 직접매매에 쓰는 금액만.
2. **riskPct 입력칸 기본값** — 권고 **1%**(한 번 틀려도 자본의 1%). 계획마다 바꿀 수 있다.
3. **알림 방** — 권고 **`매매•보안` 그룹**(체결 알림과 같은 성격, 뉴스 방과 섞지 않는다).

## 9. 나중 후보 (지금 안 함)

- 실계좌 잔고와 대조해 '진입함'·'청산함' 자동 제안(실계좌 요약 수집이 이미 있다).
- 종목 상세 화면(점수·공시 해독·지분 카드)을 계획 입력 옆에 붙이기 — 근거를 적을 때 참고용.
- 해외 고가·저가 TR.
