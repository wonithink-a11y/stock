## 0. 왜 그림자인가

`partial-exit-scale-out-2026-09.md` 가 HOLD 로 남은 이유는 **같은 표본을 더 파면 과최적화만
늘기 때문이다.** 후속 `partial-exit-segment-noise-test-2026-09.md` 가 재개 조건을 스스로
적었다 — "다른 전략 독립 표본에서 같은 규칙의 **forward 관측**". 시가총액 세그먼트·트리거·
트레일링 스윕 확대는 재개 사유가 아니라고 닫았다. 그림자가 그 조건에 정확히 맞는다.

## 1. 동결할 것 (이 셋 외에는 안 바꾼다)

| 항목 | 값 | 근거 |
|---|---|---|
| 규칙 | **+20% 도달 시 70% 매도, 잔여 전량 보유(트레일링 없음)** | 09-04 finding 이 권고한 유일한 안 — 전 격자 개선 + VALID 부호 유지. 트레일링 3%·+40%/50% 는 중형주 스윕에서 **골랐으므로 선택편향**(noise-test §3.5) — 제외 |
| 대상 | **`pbr_value_v1_combined`** (실제 가동 중인 슬리브) | 근거 표본은 `pbr_value_v1`(767건, `--end 2026-08-14`)이었다. 배포된 건 combined 다 |
| forward 창 | **신호일 ≥ 2026-08-15** (근거 스윕 데이터 끝 다음 날) | 첫 코호트 = 2026-09-01 리밸런싱, 진입 09-02 |

**독립성의 한계를 숨기지 않는다:** combined 는 `pbr_value_v1` 의 dropout·MAX 제외 파생이라
보유 종목이 상당히 겹친다. 그래서 "다른 전략의 독립 표본"이 아니라 **"같은 규칙의 시간상
독립 표본"** 이다. 시간 독립은 지켜지고(2026-08-15 이후 가격은 스윕이 본 적 없다), 종목 독립은
부분적이다.

## 2. 무엇을 재는가

- **반사실 계산이다.** 실제 슬리브 주문은 **한 줄도 안 바꾼다.** 규칙을 켠 가상 곡선과 안 켠 가상
  곡선을 같은 진입·같은 비용(왕복 30bp)으로 만들어 비교한다.
- 재사용: `partial_exit_sweep.py` 의 `load_run` · `scale_out_events(0.20, 0.70)` ·
  `random_timing_control`, `pbr_vs_ew_monthly_mtm.schedule_with_monthly_mtm(partial_exits=…)`,
  `curve_metrics`. **새로 짤 것은 forward 창으로 자르고 관측을 누적하는 얇은 껍데기 하나**
  (`run_partial_exit_shadow.py`, 약 60줄 예상)뿐이다. 엔진은 안 건드린다.
- 회계는 **월별 MTM** 이다(실현손익 누적 아님 — CLAUDE.md 의 09-02 함정 5번 그대로).
- **이 그림자가 못 재는 것:** KIS 모의 체결의 현실(지정가만·부분체결). 규칙의 값을 재는 것이지 VTS
  체결 품질이 아니다. 모의 숫자를 전략 판정에 안 쓴다는 기존 원칙과 같다.
- 데이터 의존: 가격은 A2a(월 1~5일 증분)까지만 최신이다 → **관측은 월 1회**, A2a 직후에 돈다. 첫
  코호트의 21세션 청산은 9월 말이므로 **첫 실관측은 2026-10월 초**다(2026-10-01 월간 자동화
  검증과 같은 시기).

## 3. 판정 규칙 (결과 전에 고정)

**판정은 1회.** 그 전에는 월별 관측치를 **기록만** 하고 판정하지 않는다(크립토 슬리브와 동일).

- 시점: **12개 코호트가 전부 청산되고 닫힌 거래 ≥ 300건**(월 약 26.6건 → 대략 2027-10월).
- 기준선: 같은 창의 전량 보유 곡선.

| 판정 | 조건 (전부) |
|---|---|
| **KEEP 후보** | ① 창 내 ΔSharpe > 0 ② MDD가 기준선보다 나쁘지 않고 Calmar 우위 ③ 연환산 CAGR 손실 ≤ 0.5%p (백테스트는 −0.31%p) ④ 무작위 시점 대조군(seed 고정)보다 ΔSharpe 우위 — **타이밍이 아니라 그냥 일부를 미리 판 효과면 규칙의 값이 아니다** |
| **REJECT** | ΔSharpe < 0 **그리고** MDD 가 기준선보다 나쁨 |
| **INCONCLUSIVE** | 그 외, 또는 **창 내 기준선 MDD < 10%**(부분 익절의 값은 하락장에서 나온다 — 하락이 없었으면 잴 수 없다). 24개 코호트까지 연장하고 **1회만** 다시 본다 |

KEEP 후보가 나와도 **채택이 아니다.** `portfolio.v1.json` 에 값을 넣는 건 🔴이라 GO/STOP 이 따로 필요하다.

## 4. 솔직한 기대치

검출력이 약하다. noise-test 에서 같은 N 의 ΔSharpe 무작위 sd 가 0.16~0.18 이었고 표본 내 개선은
+0.17 이다 — **1σ 안쪽**이라 12개월 forward 로 유의하게 확인하기 어렵다. 그래서 가장 현실적인
결과는 **INCONCLUSIVE** 다. 이 그림자의 실질 가치는 "확정"이 아니라 **REJECT 를 값싸게 잡는 것**
(전량 보유보다 나쁘면 개선이 TEST 편중 잡음이었다는 증거)과, 하락장이 오면 그때의 실제 작동을
보는 것이다. 12월짜리 Sharpe 는 월 12점이라 특히 흔들린다 — 그래서 ΔSharpe 하나로 KEEP 을
안 주고 MDD·CAGR·대조군을 함께 건다.

## 5. 산출·운영

- 출력: `research/strategy-lab/reports/2026-09-partial-exit-shadow/observations.jsonl` — 월 1행
  (asOf, 코호트 수, 닫힌 거래 수, 규칙·기준선 CAGR/MDD/Sharpe, 부분매도 건수, 대조군 Δ).
  같은 asOf 재실행은 중복 append 안 함(F2 shadow 와 같은 규칙).
- 실행: **수동 월 1회**로 시작한다. 워크플로에 얹는 건 관측이 두어 번 돈 뒤에 별도 판단
  (`refresh-selections` 가 이미 A2a 뒤에 커밋하는 자리라 붙이기는 쉽다).
- 회귀: 순수 함수라 네트워크 없이 도는 selftest 를 붙인다(기존 `partial_exit_sweep --selftest`
  6건이 부분청산 경로를 이미 핀한다 — 새로 짜는 건 forward 창 자르기·중복 append·판정 함수).
- **금지:** 규칙·창·판정 조건을 결과를 본 뒤 바꾸지 않는다. 바꾸려면 새 사전등록이다.
