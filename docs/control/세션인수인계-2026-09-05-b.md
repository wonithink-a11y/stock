## 4. ★★ 다음 세션이 결정해야 할 것 둘

### 4-1. §8이 지금 상태로는 코드로 안 옮겨진다

```
signal(t) = futures_return(t)      ← 모든 종목에 같은 값 하나
```

**시점 t에 횡단면 분산이 0이라 횡단면 IC가 정의되지 않는다.**
성립하려면 예측변수가 종목별로 달라야 한다:

```
signal_i(t) = exposure_i × futures_return(t)
```

`exposure_i`는 §18-2의 **베타** 또는 §18-3의 **편입비중**이다. 즉 §18-2·18-3은
"추가 축"이 아니라 **§8이 계산되기 위한 필수 구성요소**다.

★ **아직 사전등록 본문에 이 정정이 안 들어가 있다.** S2를 짜기 전에
`§16-F. exposure 정의`를 신설해 못 박아야 한다. 결과를 보기 전이므로 지금
넣으면 확증적 가설로 남는다 — 결과를 본 뒤에 넣으면 §15 위반이다.

**기본안**: 상품별로

## 10. 이 세션의 함정 기록

1. **무인 실행 루프에 예외 처리가 없으면 순간적 파일 락 하나가 19시간을
   날린다.** 수집 VM 기준 5번(fail-soft)이 선물 수집기엔 안 들어가 있었다.
2. **날짜 형식은 조용히 어긋난다.** `'2025-08-26' < '20250515'`가 참이다.
   같은 형태로 2026-08-12 `pitSelector`가 이미 틀렸었다. selftest가 아니었으면
   §18-3 검정이 통째로 사라졌을 것이다.
3. ★ **분류 기준을 키 이름으로 잡으면 틀린다.** `resultTable` 존재로 "절대수치를
   뱉는가"를 판정해 C를 6건으로 냈는데 실제는 20건이었다. **재는 대상이 아니라
   재는 방법을 먼저 의심한다.**
4. ★ **세는 단위를 확인 안 하면 규모를 3분의 1 놓친다.** findings를 200건으로
   알고 지시문을 설계했는데 실제는 279건이었고, 이미 있던
   `_classification.jsonl`(242건)도 몰랐다.
5. ★★ **두 조사를 각각 읽으면 안 보이고 교차해야 보이는 위험이 있다**(§7-2).
   "수치를 채운다"와 "그 스크립트가 무효 회계다"가 따로 있으면 둘 다 맞는 말인데
   합치면 사고가 된다.
6. **위임의 경계는 난이도가 아니라 대상 열거 여부다**(§6). 대상이 열거된
   조사는 잘하고, 전수 스캔은 규모에 눌린다.
7. **정정은 숫자만 바꾸지 말고 경위를 남긴다.** findings 원문 둘에 정정 절을
   추가했다 — 안 그러면 다음 세션이 왜 달라졌는지 못 찾는다.
