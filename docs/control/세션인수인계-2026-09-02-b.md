### 1. workflow_run 자동 재배포가 평일 스케줄에서 실제로 도는지

`deploy-pages.yml`에 ETF 워크플로를 workflow_run으로 등록해 놨는데, 오늘
**수동(workflow_dispatch) 트리거로는 두 번 다 자동 재배포가 안 붙었다.**
GitHub API로 원인을 좁혔더니 — 기존에 이미 잘 작동하던 macro.json 항목도
과거 workflow_dispatch 실행(8/30, 3건)에서는 똑같이 안 붙었고, **schedule로
시작된 실행(9/1)에서만 실제로 발동한 이력**이 있었다. 즉 "workflow_dispatch
로 시작된 소스 실행은 workflow_run 리스너에 잘 안 붙는다"는 이 저장소의
경험적 성질로 보이고, 설정 자체(YAML 문법)는 문제없다.

**확인 방법** (다음 평일 17:20 KST 이후):
```bash
gh api "repos/wonithink-a11y/stock/actions/workflows/deploy-pages.yml/runs?event=workflow_run&per_page=5" \
  -q '.workflow_runs[] | "\(.created_at) \(.conclusion)"'
```
최근 실행에 오늘 날짜가 찍히면 정상 작동 확인된 것 — 안 찍히면 workflow_dispatch
가설이 틀렸다는 뜻이라 재조사 필요. 세부: CLAUDE.md "완료" 섹션의
"★ 같은 세션 후속" 항목(ETF 탭 신설 항목 안).

## 1. ETF 탭 신설 + 자산군 분류 (전부 배포 완료)

### 배경
사용자가 "ETF 탭 만들고 1일~1년 수익률 보여줘, 필터링도 되게" 요청.

### 구현
- `scripts/build-etf-price-history.py` — KRX Open API(`etp/etf_bydd_trd`)로
  ETF 전종목 일별 종가 이력 백필(ETN 백필과 동일 패턴), 기본 시작일
  2025-07-01(1년+버퍼)
- `scripts/build-etf-returns.py` — 1일/1주/1개월/3개월/6개월/1년 캘린더일
  수익률 계산(`fetch_macro.py`의 `HORIZONS`/`value_asof()` 관례 재사용,
  d7만 추가) → `docs/data/etf-returns.json`
- `.github/workflows/build-etf-price-history.yml` — 평일 17:20 KST 자동
  실행(ETN 17:10 KST 10분 뒤, 커밋 경합 완화)
- `docs/index.html` — ETF 탭 신설, 컬럼 클릭 정렬 + 이름/코드 검색

### 자산군 2단 분류 (실측 기반)
KRX API가 정형 카테고리를 안 줘서 **종목명 키워드 패턴 매칭**으로 분류
(SPAC 판정과 같은 원칙). 실제 1,167개 종목명을 전부 열어서 검증했고,
**브랜드명(첫 토큰)에 키워드가 우연히 포함되는 오탐**(예: "DAISHIN"에
"AI"가 끼어 잡히던 것, "금융/금리"에 "금"이 걸려 원자재로 오분류되던
것)을 실측 중 발견해 "브랜드명을 뗀 나머지에서만 키워드 검사"로 수정.

```
1단(자산군 7개): 국내주식(549) 해외주식(386) 채권(185) 원자재(22)
                통화(11) 리츠·부동산(13) 혼합자산(1)
2단(서브탭, 해당 3개만):
  해외주식 → S&P500(49) 나스닥100(26) 미국관련(149) 그외국가(162)
  채권     → 한국국채(12) 미국국채(36) 회사채(26)
             채권혼합형·자산배분·구조화(58) 기타채권(53)
  국내주식 → 코스피·코스닥(지수)(123) 반도체(31) 2차전지(17) AI(20)
             배당(34) 단일종목·개별주식형(16) TDF·자산배분(13) 기타테마(295)
```

`classify_asset()`/`classify_sub()`가 `scripts/build-etf-returns.py`에
있고, selftest 9건(실측 케이스 + 브랜드명 오탐 회귀) 포함. 브라우저로
배너 전환·서브탭 필터·자산군 전환 시 서브탭 리셋·서브탭 없는 자산군(원자재
등) 전부 확인 완료.

## 2. UI 백테스트 등급역전 조사 → production technical 축 결함 발견·OOS 검증 PASS

### 시작
사용자가 백테스트 탭에서 "A등급 승률 0%·마이너스, 등급 낮을수록 이익률
높음"을 발견해 질문. `docs/data/backtest.json`(37일 창) IC=-0.245 확인.

### 1차 조사 (37일 창, 나중에 부분적으로 틀렸다고 정정됨)
4축을 `lib/scoringEngine.js`의 `scoreStock()`으로 직접 분리 측정 —
처음엔 기술·수급(추세추종) 축을 의심했으나 반전시켜도 IC가 거의 안
움직임(-0.255→-0.221). 실제로는 **valuation 단독 반전 시 IC가 +0.088로
뒤집히는** 게 37일 한정 범인이었음.

### 2차 조사 (10년 백필로 재검증, 결론이 뒤집힘)
37일은 사건 하나라 OOS 검증이 안 돼서, 이미 완료된 A5 10년 백필
(`data/backfill/scores/`, 638,108건)로 같은 분해를 재실행 — **정반대**:
10년 통합 IC=+0.052(정상), valuation도 10년 중 9년 양수. **37일의
결론(valuation이 범인)은 그 창 하나의 우연이었다.** 대신 **technical
축만은 10년 중 9년 지속 마이너스**라는 새 사실을 발견(37일 결론과는
다른, 진짜 구조적 문제).

### 3차 조사 (technical 하위지표 분해)
`lib/a5/technicalFrom.js`(운영과 동일 계산식)로 A2a 10년 가격이력에서
하위지표(이동평균크로스·RSI·MACD·거래량동반)를 재계산해 개별 IC 측정 —
**이동평균크로스**(technical 축 내부가중 35%, 최대)가 주범(IC -0.053,
나머지 3개는 -0.02 이하).

### 4차 — TRAIN/VALID/TEST OOS 검증 (PASS)
"MA크로스 반전" 변형을 TRAIN(2016-01~2021-12)에서만 고른 뒤 VALID
(2022-01~2023-06)·TEST(2023-07~2025-12)에서도 확인 — IC가 3구간 전부
개선(0.0195→0.0341, 0.0031→0.0331, 0.0321→0.0438), **부호반전 0건**.
earnings_yield·PBR combined와 같은 "production 결정을 실제로 고려해볼
후보" 등급으로 상향. 단 production(`config/criteria/KR-2.2.json`, 동결)
에는 즉시 반영 안 함 — 별도 🔴 결정.

findings: `research/strategy-lab/findings/kr-production-technical-
macross-reversal-2026-09.md` (로컬 전용, 미커밋 — 컨벤션대로)
재현 스크립트: `research/strategy-lab/kr_production_technical_macross_oos.js`

## 3. A5 supplyDemand 축 결측 원인 조사 → 실제 구현

### 원인 (2번 조사 중 우연히 발견)
`lib/a5/resolver.js`의 `resolve()` 함수 자체가 supplyDemand 파라미터를
안 받았다 — `scripts/build-a5-backfill.js`도 넘기려는 시도조차 없었고,
`lib/backfillManifest.js`의 `REQUIRED_UPSTREAM['A5']`에 A4도 없었다.
타이밍 문제(A4가 A5보다 늦게 완성됐다든가)가 아니라 **애초에 A5 설계
범위에 supplyDemand가 없었다** — A4는 2026-08-18에, A5는 2026-08-24에
완성됐으니 A4가 먼저 준비돼 있었는데도 아무도 연결을 안 한 것.

실시간 운영(`scripts/collect.js`)은 네이버 API를 라이브 호출해서 얻는데
이건 "오늘 기준 최근 20일"만 주는 API라 애초에 과거 임의 시점을 못 물음
(PIT 불가능) — A5(과거 임의 시점 필요)에는 원리적으로 못 쓴다. 대신 A4
(`data/backfill/supplyDemand/a4/`, KRX 투자자별 매매 원본, 2016~2026
PIT-safe)가 유일하게 쓸 수 있는 소스였는데 그동안 안 쓰였다.

### 구현 (커밋 `246cd07`, push 완료)
- `lib/a5/supplyDemandFrom.js` 신설 — `scripts/collect.js`의
  `netBuysToTrend()`(운영과 동일 계산식, 복사)로 A4 원본에서 PIT-safe
  5일 외국인/기관 순매수 추세 계산. 외국인=['외국인'], 기관=[금융투자·
  보험·투신·사모·은행·기타금융·연기금·기타법인] 매핑(기존
  `probe-a4-supplydemand-vertical-slice.js`가 검증해 둔 구성 재사용,
  단 그 프로브의 "잠정 분류" 대신 진짜 production 규칙 사용)
- `lib/a5/resolver.js`에 연결 — `supplyDemandRecords` 파라미터 추가,
  `stockData.supplyDemand`·missing 추적·provenance 전부 기존 축(technical
  등)과 동일 패턴으로 배선
- `lib/backfillManifest.js`의 `REQUIRED_UPSTREAM['A5']`에 A4 추가
- `scripts/build-a5-backfill.js`에 `findByTickerAcrossYears()` 신설
  (A4는 corp가 아니라 ticker로 키가 잡혀 있어서 기존 `findByCorpAcrossYears`
  와 다른 함수 필요) + `loadStaticBundle()`·`resolve()` 호출에 연결
- `scripts/test-a5-framework.js`에 회귀 5건 추가(consistentBuy/netBuy
  분류·PIT 필터링·미구축 축 구분·결측 정직 처리) — 신규 포함 전체 78건
  통과. 다른 JS 회귀 12개 파일도 전부 재확인(영향 없음, 전부 통과).
  Python 회귀도 재확인(관련 없는 3개 파일만 이 환경의 cp949 콘솔
  인코딩 문제로 실패 — 내 변경과 무관, 기존 이슈).

### 로컬 검증
`node scripts/build-a5-backfill.js --shard 0 --shards 1 --universeLimit 10`
→ `--finalize` → `c.supplyDemand` 실제 값(예: 17.2) 채워지는 것 확인
→ `git checkout -- data/backfill/scores/`로 원복(규칙 4). 저장소는
깨끗함, 실제 3,801종목 전체 재백필은 위 "지금 당장 확인할 것 ②" 참고.
