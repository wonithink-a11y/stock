## 이번 세션 요약 — 처음부터 여기까지

사용자가 "우리한테 유용한 데이터를 더 모을 수 있을까"를 물어 KIS/KRX/DART
데이터 갭을 브레인스토밍했고, **공매도(short-selling)부터 시작**하기로 했다.

### 1. 정찰 — "차단" 기록을 뒤집었다

`docs/operations/data-source-availability.md`가 공매도를 "차단"(무자격
재실측 확인)으로 남겨뒀었는데, A4(수급)가 이미 KRX_ID/KRX_PW 로그인 세션으로
뚫렸다는 걸 알고 있었으므로 같은 세션으로 재확인(교훈52: 전제가 바뀌면
다시 잰다). 로컬엔 그 자격증명이 없어 GitHub Actions로만 확인 가능 —
`scripts/probe-shorting-krx.py` + `.github/workflows/probe-shorting-krx.yml`
(수동 트리거 전용, data/backfill 미기록, manifest 없음)을 만들어 실행(run
32502926508). **결과: `get_shorting_status_by_date`가 종목당 1콜로 [거래량,
잔고수량, 거래대금, 잔고금액]을 전부 반환함을 확인** — `data-source-
availability.md`를 갱신(커밋 `b785b23`).

### 2. 정책·수집기·워크플로 설계 (커밋 `010112a`)

스테이지 번호 확인부터 했다 — **A5·A6·A7이 전부 이미 다른 용도로 예약돼
있었다**(`lib/backfillManifest.js`의 `REQUIRED_UPSTREAM`: A5=resolver,
A6=분석단계, A7=A5에 의존하는 또 다른 단계). 진짜 빈 번호는 **A8**.

- `config/policies/shortSelling.v1.json`(SS-1.0) — A4(`supplyDemand.v1.json`)를
  그대로 본떠 설계. 종목당 1콜(`get_shorting_status_by_date`)이면 충분함을
  정찰 응답의 **실제 값 대조**(터미널 인코딩 문제로 컬럼명이 안 보여서
  artifact를 다운받아 직접 확인)로 확인 — `get_shorting_balance_by_date`는
  이 함수의 완전한 부분집합(잔고수량/잔고금액이 바이트 단위로 동일)이라
  별도 수집 안 함.
- `scripts/build-short-selling-a8.py` — `build-supply-demand-a4.py` 골격
  재사용(chk/warn/_abort → fetch → run_shard → 스트리밍 validate → finalize).
  A4와 다른 점: 종목당 1콜이라 4-way 카테고리 교차검증·시장청산조건 검사가
  없음(애초에 카테고리 구조 자체가 없다). `--anchor` 서브커맨드 신설(아래
  참고). self-test 6개 통과.
- `.github/workflows/short-selling-a8.yml` — A4 워크플로 구조 그대로(16샤드,
  limit=스모크/본수집 구분, sourceRunId=finalize 재실행, anchor=별도 잡).
- `lib/backfillManifest.js`(REQUIRED_UPSTREAM.A8·REQUIRED_POLICIES.A8) ·
  `config/policies/registry.json`(dataPolicies.shortSelling) ·

### 3. anchor 확인 — collectFrom 가정이 틀렸음을 발견 (커밋 `43ff84c`)

정책 초안에 A4 값(2016-01-04)을 잠정 넣어두고 ★ 미검증으로 표시해 뒀는데,
`--anchor` 잡으로 실제 확인하니 **2016-01-04는 빈 응답**이었다. 이분탐색
(8회 워크플로 실행)으로 정확한 경계를 찾았다:

```
2014-01-02 ~ 2016-06-27  빈 응답 (6개 날짜로 확인)
2016-06-30 ~             데이터 있음
```

**한국 공매도 잔고 공시 제도 시행일(2016-06-30)과 정확히 일치.** 중간에
KRX 로그인이 연속 요청으로 한 번 일시 rate-limit(JSONDecodeError, 재시도로
해결)됐다 — 이건 데이터 유무와 무관한 인프라 이슈였다. `collectFrom`을
`2016-06-30`으로 정정하고 실측 run ID 전량을 근거로 정책 파일에 남겼다.

### 4. 스모크 트리거 — 진행 중 PC 종료

`gh workflow run short-selling-a8.yml -f limit=15` (run `32506426666`,

**GitHub Actions는 클라우드에서 도니 이 실행 자체는 끊기지 않는다** — 다음
세션이 확인만 하면 된다(§"새 세션은 여기부터" 1번).
