# 연구 데이터 VM 보관 + 클라우드 세션 내려받기 — 설계 (2026-10-30, 미구현)

목표: PC 를 안 켜고 폰(claude.ai/code 클라우드 세션)으로 실험할 때, 우리가 모아 둔 연구 데이터를
처음부터 다시 받지 않고 VM 에서 몇 초~몇 분 안에 받아 쓴다.

## 1. 역할 나누기

```
PC          데이터를 만든다(수집·캐시) ──push──▶ VM
VM          보관하고 키로 내준다(읽기 전용)  ──get──▶ 클라우드 세션
클라우드 세션 실험하고 GitHub 에 쓴다(PR)        ← GitHub 쓰기는 여기, VM 은 여전히 Git 에 안 쓴다
```

- VM 에 GitHub 자격증명을 넣지 않는다는 규칙은 그대로다. 클라우드 세션은 GitHub 앱 연동으로 이미 PR 을 만든다(10-29~30 PR #5~#8).
- 클라우드 세션은 VM 에 SSH 로 못 들어간다 → HTTPS(nginx) 로만 받는다.

## 2. 용량 (실측 10-30)

| 항목 | 값 |
|---|---|
| VM 디스크 | 45GB 중 11GB 사용 · **34GB 남음** |
| 올릴 데이터(PC 전용) | 약 11.3GB — crypto 5.0 · .cache 4.3 · a4 0.96 · etf-ohlc 0.83 · dart_event_titles 0.07 · order-contracts 0.09 · quarterly-earnings 0.01 |
| 올린 뒤 남음 | 약 22GB |
| 증가 속도 | 연 약 4GB(호가 기록 6MB/일 · 미국 스냅샷 4MB/일 · git 자동 커밋) |

모자라면: 오라클 Always Free 블록 볼륨은 **부트+블록 합계 200GB**(공식 문서 10-30 확인). 지금 작업 VM 부트 47GB +
옛 감시 VM(stock-monitor, 폐기 시험 중) 부트 약 47GB. 옛 VM 을 지우면 약 150GB, 안 지워도 약 100GB 를 블록 볼륨으로 붙일 수 있다.
오브젝트 스토리지는 20GB(무료 전용 계정 기준, 유료 계정이면 등급별 10GB) · 월 API 50,000회라 이 용도엔 VM 보다 좁다.

## 3. 묶음(bundle)

속도 제한(nginx 30회/분)에 걸린다 → **폴더 단위 tar 묶음**으로 내준다. parquet 는 이미 압축이라 gzip 은 빠른 단계(1)만.

## 4. VM 쪽

```
/srv/stock-data/bundles/<이름>.tar.gz     ubuntu 소유 · 644 (nginx=www-data 가 읽는다. /home/ubuntu 는 750 이라 피한다)
/srv/stock-data/bundles/manifest.json     [{name, path, bytes, sha256, files, builtAt, srcNewest}]
/srv/stock-data/incoming/                  push 가 먼저 쓰는 곳 → 검증 뒤 mv(원자적 교체, 받는 중인 세션이 반쪽 파일을 안 본다)
```

nginx(정본 `deploy/nginx-wonithink-stock.conf` 에 추가):

```nginx
location /research-data/ {               # 연구 데이터 묶음 — 키(X-Data-Key) 없으면 401, 목록 보기 없음, 읽기 전용
    limit_req zone=research_data burst=20 nodelay;
    if ($research_data_ok = 0) { return 401; }
    alias /srv/stock-data/bundles/;
    autoindex off;
    limit_except GET HEAD { deny all; }
}
```

- `$research_data_ok` 는 **VM 에만 있는 파일** `/etc/nginx/conf.d/stock-research-data-key.conf`
  (`map $http_x_data_key $research_data_ok { default 0; "<키>" 1; }`)이 정한다. 키는 저장소에 안 들어간다(절대 규칙 2).
- 속도 제한 영역 `research_data`(60회/분)는 `deploy/nginx-stock-ratelimit.conf` 에 한 줄.
- 키는 `/pins`·`/yt` 의 X-Pin-Key 와 **따로** 둔다 — 그 키는 폰 링크(`#pinkey=`)에 실려 다닌다.
- 보내는 양: 무료 송신 월 10TB. 실험 한 번에 0.1~3GB.

## 5. 스크립트 `scripts/research-data.py` (하나로)

```
python scripts/research-data.py list                 # VM manifest — 이름·크기·만든 날
python scripts/research-data.py get crypto-k1 a4     # 내려받기 → sha256 확인 → 원래 경로에 풀기
python scripts/research-data.py push [이름…]          # PC 전용: 바뀐 묶음만 다시 만들어 scp → VM incoming → 검증 → 교체
python scripts/research-data.py --selftest            # 네트워크 없이 묶기·풀기·해시·경로 탈출 방지
```

- 주소 `https://wonithink-stock.duckdns.org/research-data/`, 키는 환경변수 `RESEARCH_DATA_KEY`(PC `.env` · 클라우드 환경 설정).
- `get` 은 같은 sha256 이 이미 풀려 있으면 건너뛴다(`.research-data-stamp.json` — gitignore 대상 폴더 안이라 커밋 안 됨).
- 풀 때 경로 탈출(`../`, 절대 경로) 거부. 풀리는 곳은 묶음 표의 경로뿐.
- `push` 는 원본 폴더의 (파일 목록·크기·수정 시각)이 직전과 같으면 다시 묶지 않는다. 첫 push 11GB 는 집 업로드 속도에 따라 15~40분.
- 표준 라이브러리만(tarfile·hashlib·urllib·subprocess+scp) — 새 패키지 없음.

## 6. 쓰는 법

클라우드 세션에서 연구를 시작할 때 필요한 묶음만 받는다:

```
python scripts/research-data.py get crypto-k1 crypto-small
```

- **결과 파일에 쓴 묶음의 sha256·builtAt 을 적는다**(재현성 — 어느 시점 PC 스냅샷으로 돌렸는지).
- 클라우드에서 새로 받은 데이터는 세션이 끝나면 사라진다. VM 에 되올리기(PUT)는 **2단계로 미룬다** — 쓰기 통로는 위험이 다르다.
- preregistered-research 스킬과 CLAUDE.md '로컬 실행'에 한 줄: "데이터가 없으면 먼저 research-data.py get".

## 8. 확인할 것·위험

- **유휴 회수**: 오라클은 Always Free 전용 계정의 VM 을 7일간 CPU(95분위)·네트워크·메모리(A1) 모두 20% 미만이면 회수할 수 있다(공식 문서).
  지금 VM 은 부하가 매우 낮다(load 0.16 · 메모리 11%). 9월부터 회수가 없었지만 계정이 무료 전용인지 유료(PAYG) 전환인지 확인 필요 —
  유료 전환 계정은 회수 대상이 아니다. 회수되면 VM 데이터도 같이 사라지므로 **VM 은 백업이 아니라 사본**으로 본다(PC 원본 유지).
- 옛 감시 VM(stock-monitor) 접속이 10-30 시간 초과 — 삭제됐는지 정지인지 콘솔에서 확인하면 남은 무료 용량이 정확해진다.
- 키 유출 시: VM 키 파일만 바꾸고 reload(데이터는 공개 출처 파생이라 피해는 대역폭 정도).
