# LAB-8 — 재무와 EPS가 서로 다른 공시를 가리키는 45건

```
발행   2026-08-11 · Claude
선행   LAB-5 (완료) — 이 45건이 거기서 나왔습니다
분량   두세 시간. 조회 90건이면 끝납니다
```

## 한 줄

**같은 회사·같은 사업연도인데 재무 데이터와 EPS 데이터가 서로 다른 공시에서 왔다.
그 45건이 왜 갈렸는지, 어느 쪽이 정정본인지 확인한다.**

## 왜 중요한가

우리 체계는 과거 시점을 재현할 때 **"그날 알 수 있었던 값"** 을 씁니다. 그래서 각 데이터에
공시일이 붙어 있고, 그 날짜로 "이 시점에 이미 공시됐는가"를 판단합니다.

문제는 이렇습니다.

```
2019년 3월에 A사의 재무제표가 공시됐다        ← 재무는 이 공시를 봤다
2024년 5월에 A사가 그 보고서를 정정 공시했다   ← EPS 는 이 공시를 봤다

2020년 시점을 재현하면
  재무는 "이미 알 수 있었다"                  2019-03 < 2020
  EPS 는 "아직 알 수 없었다"                  2024-05 > 2020
  → 같은 회사의 재무와 EPS 가 서로 다른 시점에서 온다
```

이러면 그 회사의 그 연도 지표는 계산할 수 없거나, 계산해도 의미가 어긋납니다.

45건은 전체(14,578건)의 0.3%로 작습니다. **다만 이 45건이 왜 생겼는지 알아야
나머지 절반이 수집된 뒤에도 같은 일이 반복될지 판단할 수 있습니다.**

## 우리 쪽 가설 — 확인해 주세요

**이 45건이 정정공시 때문이 아니라 우리 코드의 선택 규칙 차이일 수 있습니다.**

두 수집기 모두 같은 종류의 보고서(사업보고서)를 조회하는데, 응답에 여러 공시가 들어 있을 때
고르는 방식이 다릅니다.

```
재무 수집기   응답의 첫 번째 행을 쓴다
EPS 수집기    접수번호가 가장 큰 것(= 가장 나중 공시)을 쓴다
```

정정공시가 있는 회사라면 응답에 원본과 정정본이 함께 올 수 있고, 그러면 한쪽은 원본을
다른 쪽은 정정본을 잡습니다.

**이건 가설입니다.** 코드에서 그 차이는 확인했지만, 그것이 실제로 45건을 만들었는지는
공시 자체를 봐야 압니다. **가설을 전제로 결론 내리지 마세요 — 반증도 결과입니다.**

```
            EPS 쪽이 더 나중  38건

  → 한 번에 여러 연도를 정정한 일괄 제출로 보인다
```

FY2025가 절반인 것과, 한 날짜가 4개 연도를 덮는 것 — 이 둘이 가설과 맞는지 봐 주세요.

## 할 일

각 행의 **접수번호 두 개**를 조회해서 그 공시가 무엇인지 확인합니다.

```
1  보고서 이름이 무엇인가
   특히 '[기재정정]' 같은 정정 표시가 붙어 있는가
2  둘 다 같은 사업연도의 사업보고서인가
   한쪽이 반기·분기보고서면 그건 다른 이야기다
3  둘 중 어느 쪽이 정정본인가
4  정정본이 원본을 대체하는가, 나란히 존재하는가
```

실험실에 연결된 **OpenDART 공시검색**으로 접수번호를 조회하면 됩니다.
45행 × 2 = 90건이라 부담이 적습니다.
