# LAB-2 — 연결과 별도가 섞여 비교가 깨지는가

```
발행   2026-08-11 · Claude
순서   2순위 — 내일 수집이 끝나기 전에
분량   반나절
```

> **이 과제는 원래 "diagnostics 실패 원인 분류"였는데 바꿨습니다.** 재료가 없습니다 —
> 8샤드 전부 기각 0건이라 분류할 것이 없습니다. 그 사실은 이미 확인됐으니 다시 세지 마세요.

## 한 줄

**EPS가 두 가지 회계 기준에서 왔다. 그 섞임이 어느 업종·어느 회사·어느 연도에 몰려
있는지 센다.**

## 왜 지금 이걸 하나

수집기는 EPS를 이렇게 고릅니다.

```
1순위   "(연결)주당순이익"    자회사까지 합친 실적
2순위   "주당순이익"          그 회사만의 실적       ← 연결이 없을 때만
```

실측: **연결 13,237건(90.8%) · 별도 1,341건(9.2%)**

문제는 이 지표가 **다른 회사와 비교해서** 쓰인다는 점입니다. valuation 축의 핵심 지표는
`업종 중앙값 대비 PER 배율`인데, 같은 업종 안에 연결 기준과 별도 기준이 섞이면
**그 배율이 회사 차이가 아니라 회계 기준 차이를 잽니다.**

지주회사가 대표적입니다. 지주회사의 별도 순이익은 자회사 배당 수입뿐이라 연결과 크게
다르고, 그 상태로 같은 업종의 연결 기준 회사들과 나란히 놓이면 저평가나 고평가로
잘못 보입니다.

## 배경 — 이것만 알면 됩니다

```
연결 재무제표   모회사 + 자회사를 하나로 합친 것
별도 재무제표   모회사만
```

한국 상장사는 대개 둘 다 공시하지만, **자회사가 없거나 소규모면 연결을 안 냅니다.**
그래서 별도로 내려간 9.2%는 "작은 회사이거나 자회사가 없는 회사"일 가능성이 높습니다 —
그 가설이 맞는지 확인하는 것이 이 과제의 일부입니다.

## 입력

```
data/backfill/fundamentals/_shards_a3b/shard-*.jsonl
  corp · fiscalYear · eps · epsSource
  epsSource 값은 두 가지 — "(연결)주당순이익" 또는 "주당순이익"

data/backfill/fundamentals/a3/*.jsonl.gz        업종·규모 조인용
  corp · fiscalYear · sicCode · equity · revenue · netIncome · fsDiv
```

`fsDiv`는 A3 쪽의 연결/별도 구분입니다. **A3와 A3b가 서로 다른 기준을 쓰고 있는지도
여기서 볼 수 있습니다** — 재무는 연결인데 EPS는 별도라면 그 조합으로 계산한 지표는
분자와 분모의 기준이 다릅니다.

## 재현 확인 — 먼저 이 숫자를 맞추세요

```
전체 레코드                14,578
(연결)주당순이익           13,237
주당순이익                  1,341
```

## 작업 단계

**① 업종별·연도별 분포를 낸다**

각 `sicCode` 업종에 대해 별도 비율을 계산합니다.

```
별도 비율 = 별도 건수 / (연결 + 별도)
```

**0도 1도 아닌 업종이 몇 개인지**가 핵심입니다. 0이면 전부 연결, 1이면 전부 별도라
업종 안에서는 비교가 성립합니다. 그 사이가 문제입니다.

**② 별도로 내려간 1,341건이 어떤 회사인지 본다**

```
자본(equity) 분위    작은 회사에 몰리는가
매출(revenue) 분위
업종                 금융업 · 지주회사 등에 몰리는가
```

**③ 같은 회사가 연도에 따라 기준이 바뀌는지 본다** ← **가장 중요**

한 회사의 연도별 `epsSource`를 나열해서, 중간에 바뀌는 회사를 셉니다.

```
예)  2015 별도 · 2016 별도 · 2017 연결 · 2018 연결 …   ← 2017년에 바뀌었다
```

이게 중요한 이유: 업종 안의 섞임은 업종별로 나눠 보면 완화되지만, **한 회사의 시계열
안에서 기준이 바뀌면 "EPS 성장률"이 성장이 아니라 회계 기준 변경을 잽니다.** 그 값을
쓰는 지표가 있습니다.

**⚠ 결측 연도를 '변경'으로 세지 마세요.** 조회 안 된 연도는 `_state-*.json`의 `scanned`에
`013` 또는 `EARLY_STOP`으로 남아 있습니다. `연결 → (결측) → 연결`은 변경이 아닙니다.

**④ A3의 `fsDiv`와 대조한다**

같은 `(corp, fiscalYear)`에서 A3의 `fsDiv`와 A3b의 `epsSource`가 같은 기준을 가리키는지
봅니다. 어긋나는 건수를 셉니다.
