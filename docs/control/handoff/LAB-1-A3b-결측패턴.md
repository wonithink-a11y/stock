# LAB-1 — 조기 종료가 목표 집단을 삼켰는가

```
발행    2026-08-11 · Claude
Owner   AI-Lab
우선    3순위 — 남은 수집이 끝나기 전에 알면 범위가 작아진다
형식    docs/AI협업-업무분담.md §3
```

## 목적

A3b는 연속 결측이 `stopAfterConsecutiveEmptyYears`에 닿으면 그 법인의 남은 사업연도를
**조회하지 않고 완료로 넣는다.** 설계된 동작이고, `_state-*.json`의 `scanned`에
`EARLY_STOP`으로 남는다.

문제는 **그 설계가 목표 집단을 삼켰는가**다. 조기 종료된 법인이 현재 상장 법인이면
그 법인의 EPS·배당은 **재수집 없이는 영영 안 채워진다.**

## 이미 확인된 것 — 다시 세지 않는다

```
셀 기준 분포     OK 14,578 · 013 1,460 · EARLY_STOP 3,660
법인 기준        조기 종료가 걸린 법인 471
  A3 가 재무를 못 찾은 법인   470   ← 설계대로. 정책이 "798법인은 법인당 2~3호출에서 멈춘다"
  A3 가 재무를 찾은 법인        1   00140566 · 2015~16 OK → 2017~19 013 → 2020+ 조기종료
                                    배당·EPS 공시가 끊긴 법인. 규칙대로 동작했다

연도 분포   013        2015~17 에 몰린다 (468 · 447 · 454), 2018+ 는 4~22
           EARLY_STOP 2018~2025 에 고르게 437~471
           → 2015~17 이 비어 조기 종료가 걸린 모양과 일치한다
```

**이 확인으로 "상장이 늦은 법인의 EPS가 통째로 안 잡힌다"는 성립하지 않는다** —
조기 종료가 A3 미확보 집단에 거의 정확히 갇혀 있다.

## 그래서 남은 질문은 하나다

`config/policies/fundamentals.v1.json`의 `a3b.grid.modeNote`가 이렇게 적었다.

> "798을 넣는 이유 둘: **그 안에 현재 상장 15법인이 있고 그들이 목표 집단이며** …"

**그 15법인이 조기 종료 470에 포함되는가.** 포함되면 작고 특정 가능한 손실이고,
지금이면 남은 수집에서 손댈 수 있다. 안 되면 이 축은 닫힌다.

## 현재 상태

```
A3b collect  51.1% (1,944 / 3,801법인) · commit 02f183d
```

## 입력

```
data/backfill/fundamentals/_shards_a3b/_state-*.json     8개
  필드  corpsDone · scanned { corp: { "2015": "OK"|"013"|"EARLY_STOP"|"REJECTED:사유", … } }

data/backfill/fundamentals/a3/*.jsonl.gz                 A3 재무 보유 법인 (corp)
A1a 유니버스 산출물                                        현재 상장 여부 · ticker · 상장일
config/policies/fundamentals.v1.json  a3b.grid            798법인의 정의
```

## 기대 출력

```
1  조기 종료 법인 471 중 현재 상장인 것의 목록과 수     ← 이 과제의 답
2  그 법인들의 상장일 분포
   → 상장이 2018 이후면 2015~17 이 비는 것이 정상이고, 조기 종료가 오탐이다
3  013 이 2015~17 에 몰리는 원인 확인
   상장 시점 때문인가, alotMatter 자체가 초기 연도를 안 주는가
```

## 제약

## 검증 방법

```
법인 수 합이 정합하는지 대조한다 — 조기종료 471 = (A3 있음 1) + (A3 없음 470)
현재 상장 판정은 A1a 산출물 하나만 쓴다. 두 소스를 섞지 않는다
```

## 주의사항

```
★ 51% 시점이다. 남은 1,857법인에서 조기 종료가 더 나온다. "471 중" 이 아니라
  "완료분의 조기 종료 471 중" 으로 적는다

★ '조회하지 않았다'(EARLY_STOP)와 '조회했더니 없다'(013)는 다르다(교훈75).
  둘을 합쳐 '결측'으로 세면 회수 가능한 것과 불가능한 것이 섞인다

★ 020(한도)은 이 분포에 없다. 한도를 만나면 그 법인을 통째로 버리므로
  scanned 에 남지 않는다. 실측에서도 quotaExceeded 는 8샤드 전부 none 이었다
```
