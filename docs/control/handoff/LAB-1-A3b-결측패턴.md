# LAB-1 — 조회를 멈춘 회사 중 살아있는 회사가 있나

```
발행   2026-08-11 · Claude
순서   3순위 — 남은 수집이 끝나기 전에 하면 범위가 좁아진다
분량   두세 시간
```

## 한 줄

**수집기가 "이 회사는 데이터가 없다"고 판단해 조회를 중단한 471개 회사 중, 지금
거래되고 있는 회사가 있는지 찾는다.**

## 왜 지금 이걸 하나

수집기에는 **조기 종료 규칙**이 있습니다. 어떤 회사의 사업연도를 오래된 것부터 훑다가
연속으로 몇 년 비면, 나머지 연도를 **조회하지 않고** 그 회사를 완료로 넘깁니다.
API 호출을 아끼는 장치이고, 오래전에 없어진 회사에는 맞는 동작입니다.

문제는 **최근에 상장한 회사**입니다.

```
2020년 상장 회사를 2015년부터 훑으면
  2015 없음 · 2016 없음 · 2017 없음  → 3년 연속 → 중단
  2018~2025 는 조회조차 안 한다
        ↑ 그런데 이 회사는 2020년부터 실제로 EPS 가 있다
```

이렇게 놓친 데이터는 **재수집 없이는 영영 안 채워집니다.** 완료로 기록됐기 때문에
다음 실행이 다시 시도하지 않습니다.

## 이미 확인된 것 — 다시 세지 마세요

제가 먼저 확인했고, **다행히 대부분은 정상입니다.**

```
조기 종료가 걸린 회사   471개
  재무 데이터가 없는 회사   470개   ← 설계대로. 애초에 목표가 아니었다
  재무 데이터가 있는 회사     1개   00140566
                                   2015~16 있음 → 2017~19 없음 → 2020+ 중단
                                   배당·EPS 공시가 끊긴 회사. 규칙대로 동작했다
```

**"상장이 늦은 회사의 EPS가 통째로 빠진다"는 우려는 성립하지 않습니다.** 조기 종료가
거의 정확히 "재무도 없는 회사" 집단에 갇혀 있습니다.

## 그래서 남은 질문은 하나입니다

수집 설정 파일에 이런 메모가 있습니다.

> "798개 회사를 대상에 넣는 이유 둘: **그 안에 현재 상장된 15개 회사가 있고 그들이
> 목표 집단이며** …"

**그 15개가 조기 종료된 470개에 들어 있는가.**

```
들어 있다면    작고 특정 가능한 손실이다. 회사 목록이 나오고, 남은 수집에서 손댈 수 있다
안 들어 있다면 이 축은 닫힌다. 더 볼 것이 없다
```

어느 쪽이든 **답이 짧게 나오는 질문**입니다. 그래서 우선순위가 3위이면서도 가치가 있습니다.

## 배경 — 이것만 알면 됩니다

`_state-*.json`의 `scanned`가 **회사×연도마다 무슨 일이 있었는지**를 기록합니다.

```json
"00100258": { "2015": "OK", "2016": "OK", "2017": "OK", "2018": "OK", "2019": "OK" }
"00101275": { "2015": "013", "2016": "013", "2017": "013",
              "2018": "EARLY_STOP", "2019": "EARLY_STOP", ... }
```

```
OK           조회했고 데이터가 있었다
013          조회했는데 공시에 데이터가 없었다      ← 사실이다
EARLY_STOP   조회하지 않았다 (연속 결측으로 중단)   ← 모르는 상태다
```

**`013`과 `EARLY_STOP`을 합쳐서 "결측"으로 세지 마세요.** 하나는 확인된 부재이고 하나는
미확인입니다. 대응이 다릅니다.

## 입력

```
data/backfill/fundamentals/_shards_a3b/_state-*.json     8개
  scanned : { corp: { 연도: "OK"|"013"|"EARLY_STOP" } }

data/backfill/fundamentals/a3/*.jsonl.gz                 재무 보유 회사 (corp)
A1a 유니버스 산출물                                        현재 상장 여부 · 상장일 · ticker
config/policies/fundamentals.v1.json                     a3b.grid — 798 회사의 정의
```

A1a 유니버스 파일의 정확한 경로는 저장소에서 확인하세요. 상장 여부 판정은 **이 파일
하나만** 쓰고 다른 소스와 섞지 마세요.

## 재현 확인 — 먼저 이 숫자를 맞추세요

```
회사×연도 셀 분포     OK 14,578 · 013 1,460 · EARLY_STOP 3,660
조기 종료가 걸린 회사  471
```

## 작업 단계

**① 조기 종료된 471개 회사를 뽑는다**

`scanned` 값에 `EARLY_STOP`이 하나라도 있는 회사입니다.

**② 그중 현재 상장인 회사를 찾는다** ← 이 과제의 답

A1a 유니버스와 대조합니다. 결과가 0이면 거기서 끝내도 됩니다.

**③ 나온 회사가 있으면 상장일을 본다**

```
상장일이 2018년 이후    → 2015~17 이 비는 것은 정상이고, 조기 종료가 오탐이다
상장일이 2015년 이전    → 다른 이유가 있다. 공시 자체가 없었을 수 있다
```

**④ `013`이 왜 2015~17에 몰리는지 확인한다**

관측된 패턴입니다.

```
013         2015: 468 · 2016: 447 · 2017: 454 · 2018 이후: 4~22
EARLY_STOP  2018~2025 에 고르게 437~471
```

2015~17에 몰린 이유가 **상장 시점** 때문인지, 아니면 **공시 제도가 그 시기에 달랐는지**
확인합니다. 전자면 ③과 같은 이야기이고, 후자면 조기 종료 규칙 자체를 다시 볼 근거가
됩니다(단, 규칙 변경 제안은 하지 마세요 — 사실만 알려 주시면 됩니다).

