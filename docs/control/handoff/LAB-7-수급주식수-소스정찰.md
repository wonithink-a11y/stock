# LAB-7 — 발행주식수·수급 소스 정찰

```
발행   2026-08-11 · Claude
순서   LAB-2 와 병행 가능
분량   두세 시간. 데이터셋을 만들지 않고 응답 필드만 확인합니다
```

## 한 줄

**실험실에 연결된 공공데이터 커넥터가 우리에게 없는 네 가지를 실제로 주는지, 응답 필드만
확인한다.** 수집하지 않는다.

## 왜 지금인가

우리 점수 체계에서 아직 못 채우는 지표가 넷 있고, 그중 셋이 그 커넥터 목록에 보입니다.

```
pbr                     발행주식총수가 파이프라인 어디에도 없다      +0.06
largeShareholderChange  대주주 지분율 변동                        +0.03
buybackOrRetirement     자사주 매입·소각 공시                      +0.02
```

**우리가 직접 확인하려면 DART 호출 예산을 씁니다.** 그 예산은 지금 다른 수집이 이틀간
전부 쓰고 있습니다. 실험실 커넥터로 확인하면 우리 예산이 0원이고 병렬로 돕니다.

**착수 결정이 아닙니다.** 새 소스를 넣는 것은 계약 변경이라 별도 승인 사안입니다. 이
과제는 "넣을 가치가 있는지" 판단할 재료만 만듭니다.

## 배경 — 이것만 알면 됩니다

우리가 재무 데이터를 붙일 때 쓰는 키는 셋입니다.

```
corp_code      8자리 법인코드. ★ 조인은 이걸로만 합니다
사업연도
rcept_no       공시 접수번호. 앞 8자리가 공시일이 되어
               '언제부터 알 수 있었나'를 만듭니다
```

**종목코드(6자리)로 조인하지 않습니다.** 바뀌거나 재사용되고, 비상장 법인엔 없습니다.

그리고 **`rcept_no`가 없으면 그 데이터는 우리 체계에 못 들어옵니다.** 과거 시점을 재현할
때 "그날 알 수 있었던 값"을 골라야 하는데, 공시일이 없으면 그 판단을 할 수 없습니다.
이게 아래 모든 질문에 `rcept_no` 확인이 들어가는 이유입니다.

## 확인할 것

### 1순위 — OpenDART 주식의 총수 현황

```
1  응답 필드명 전체 (발행한 주식의 총수 · 유통주식수 등)
2  연도별 조회인가, 최신 스냅샷만 주는가
3  rcept_no 가 있는가
4  법인 식별자가 corp_code 인가
```

### 2순위 — OpenDART 최대주주 변동현황

```
5  지분율 · 변동일 · 변동사유가 응답에 있는가
6  '변동 전 → 변동 후' 지분율을 둘 다 주는가, 결과값만 주는가
7  rcept_no · corp_code 유무
```

### 3순위 — OpenDART 자기주식 취득 및 처분 현황

```
8  취득 · 처분 · 소각이 구분되는가
9  결정일과 실제 취득일이 갈리는가
10 rcept_no · corp_code 유무
```

### 4순위 — 증자(감자) 현황 · 무상증자 결정

```
11 주식 수 변경의 기준일과 상장예정일이 함께 오는가
12 무상증자·액면분할·감자가 모두 포함되는가
```

### 참고 — KRX 유가증권 종목기본정보

```
13 상장주식수(또는 발행주식수) 필드가 있는가
14 과거 날짜를 지정하면 그 날의 값이 오는가
15 코스닥에 해당하는 별도 엔드포인트가 있는가
16 법인 식별자가 종목코드뿐인가, corp_code 도 있는가
```

**14번이 중요합니다.** 일별로 값이 온다면 주식 수가 바뀐 날이 데이터에 그대로 드러나,
DART 정기보고서보다 시점을 정확히 알 수 있습니다.
