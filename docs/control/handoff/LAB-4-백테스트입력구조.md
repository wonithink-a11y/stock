# LAB-4 — 전략 실험이 언제 열리는지 재고, 점수 구조가 흔들리는지 본다

```
발행   2026-08-11 · Claude
순서   5순위 — 급하지 않다. 다만 이 결과가 나머지 실험의 일정을 정한다
분량   반나절
```

## 한 줄

**과거 점수와 이후 수익률을 짝지을 수 있는 표본이 몇 건이고 언제 30건을 넘는지 재고,
그 23일 동안 종목들의 채점 구조가 안정적이었는지 본다.**

## 왜 이걸 하나

실험실이 하고 싶어 할 일 — 가중치 민감도, 팩터 비교, 국면별 성과 — 는 전부
**"과거 어느 날의 점수"와 "그 뒤 수익률"** 을 짝지어야 합니다.

지금 그 표본이 **24건**입니다. 최소 기준이 30건이고 권장이 100건입니다. 그래서 그 실험들이
전부 잠겨 있습니다.

**언제 열리는지는 아무도 안 재고 있습니다.** 이 과제가 그걸 잽니다. 자기 일정을
자기가 재는 작업입니다.

두 번째 목적은 채점 구조입니다. 종목마다 **몇 개 축으로 채점됐는지**가 다를 수 있는데,
같은 종목이 날짜에 따라 축 개수가 바뀌면 그 종목의 시계열은 **한 모델의 성과가
아닙니다.** 하루치는 확인됐지만 23일 전체는 안 봤습니다.

## 배경 — 이것만 알면 됩니다

**수익률은 저장돼 있지 않습니다.** 매일의 스냅샷에 그날 종가가 들어 있고, 수익률은
**나중 스냅샷의 종가와 비교해서 그때그때 계산**합니다.

```
2026-07-12 의 A종목 종가와
2026-07-12 + 28일 이후 첫 스냅샷의 A종목 종가를 비교 → d20 수익률
```

기간은 세 가지입니다.

```
d20   28일 뒤
d60   84일 뒤
d120  168일 뒤
```

이력이 2026-07-12부터 08-10까지 **23일치(달력 29일)** 이므로, 가장 오래된 스냅샷만
겨우 d20 짝을 찾습니다. d60·d120은 아직 하나도 없습니다.

**계산 로직을 새로 만들지 마세요.** `scripts/backtest-report.js`의 78~103행에 이미
있습니다. 다시 구현하면 실험실이 검증하는 계산이 운영이 쓰는 계산과 달라집니다.

### 축이란 무엇인가

종목은 최대 4개 축으로 채점됩니다.

```
fundamental   재무
valuation     밸류에이션
technical     기술적 지표
supplyDemand  수급
```

데이터가 없는 축은 빠지고 **남은 축으로 다시 정규화**합니다. 그래서 3축으로 채점된
종목과 4축으로 채점된 종목은 **다른 모델의 점수**입니다. 2026-08-10 하루를 세면
이랬습니다.

```
한국  4축 (재무+밸류+기술+수급)   99종목
한국  2축 (수급+기술)              1종목
미국  3축 (재무+밸류+기술)        43종목    ← 미국은 수급 데이터 소스가 없다
```

## 입력

```
docs/data/history/*.json          23개 (2026-07-12 ~ 08-10)

  파일 하나의 구조 — ★ 종목 배열의 키는 stocks 다
    {
      "date": "2026-07-12",
      "kospiClose": …,          벤치마크 수익률용
      "spxClose": …,            미국 벤치마크
      "stocks": [
        { "ticker", "name", "market", "close",
          "stockData": { fundamental · valuation · technical · supplyDemand } },
        …
      ]
    }

scripts/backtest-report.js:78~103    수익률 조인 로직 (정본)
  HORIZON_DAYS = { d20: 28, d60: 84, d120: 168 }
```

`stocks`를 `results`로 잘못 읽으면 **에러 없이 0건이 나옵니다.** 재현 확인의 2,109가
0으로 나오면 이 자리입니다(제가 검증 중에 실제로 걸렸습니다).

## 재현 확인 — 먼저 이 숫자를 맞추세요

```
스냅샷 파일        23개
스냅샷 총 건수     2,109 (종목×일)
d20 표본           24
d60 표본            0
d120 표본           0
```

**이 다섯 개를 재현하지 못하면 로직이 다른 것입니다.** 거기서 멈추세요.

### ★ 축 분포는 원본 스냅샷에서 나오지 않습니다

앞의 `한국 4축 99 · 한국 2축 1 · 미국 3축 43`은 **채점 결과**(`docs/data/latest-v2.json`의
`components`)에서 센 것입니다. 원본 스냅샷을 그대로 세면 다릅니다.

```
history/2026-08-10.json 에서 축 키의 존재 여부로 세면   한국 4축 100 · 미국 4축 43
latest-v2.json 의 components 에서 세면                한국 4축 99 · 한국 2축 1 · 미국 3축 43
```

**둘은 다른 것을 잽니다.**

```
원본 스냅샷    그 축의 원자료가 들어 있는가
채점 결과      그 축이 실제로 점수를 냈는가
```

미국 종목은 수급 원자료가 있어도 점수에 기여하지 않습니다(가중치가 0으로 선언돼
있습니다). 한국 1종목은 재무·밸류 원자료가 있는데도 점수가 안 나왔습니다 — 지표가
전부 비어 있으면 축이 죽습니다.

그러므로 ③④단계(축 분포·축 변동)는 **원본 키 존재 여부로 세면 답이 틀립니다.**
둘 중 하나를 고르세요.

```
방법 A (권장)   docs/data/latest-v2.json 로 하루치만 확인하고,
               23일 시계열은 "원자료 존재 여부" 기준으로 세되
               그것이 채점 결과가 아님을 결과에 명시한다
방법 B          채점 엔진(lib/scoringEngine.js)을 직접 돌려 23일치를 채점한다.
               정확하지만 무겁고, 환경에 Node 가 필요하다
```

**방법 A로 충분합니다.** 원자료가 사라지는 날이 있는지만 봐도 ④의 질문은 답이 됩니다 —
원자료가 있는데 점수가 안 나오는 경우는 별도 사안이고, 그건 이 과제 밖입니다.

## 작업 단계

**① d20 표본의 누적 곡선을 그린다**

날짜별로 "이 날짜까지 이력이 쌓였을 때 계산 가능한 d20 표본 수"를 냅니다.

**⚠ 단순 외삽이 어긋납니다.** 스냅샷 종목 수가 도중에 늘었습니다.

```
2026-07-12 ~   20종목/일
2026-08-07 ~  143종목/일
```

즉 08-07 이후 스냅샷이 성숙하면 표본이 **급격히** 늡니다. 그 계단을 반영해야 합니다.

**② 30건·100건 돌파 예상 시점을 낸다**

`d20`·`d60`·`d120` 각각에 대해. 추정임을 명시하세요.

**③ 날짜별 축 분포를 낸다**

23일 전체에 대해, 각 날짜의 종목들이 몇 개 축으로 채점됐는지 셉니다.

```
| 날짜 | 한국 4축 | 한국 3축 | 한국 2축 | 미국 3축 | 기타 |
```

**"기타"에 뭔가 들어오면 그것이 발견입니다** — 선언된 조합은 위 셋뿐입니다.

**④ 같은 종목의 축 개수가 날짜에 따라 바뀌는지 본다** ← **가장 중요**

종목별로 23일간의 축 조합을 나열해서 바뀌는 종목을 셉니다.

```
예)  A종목: 4축 4축 4축 3축 3축 4축 …   ← 흔들린다
```

바뀌는 종목이 있으면 **그 종목의 점수 시계열은 중간에 모델이 바뀐 것**입니다. 수급
데이터가 하루 안 들어온 날 같은 것이 원인일 수 있습니다.

**⑤ 조용히 빠지는 경로를 센다**

```
close 가 없는 스냅샷 항목
미래 스냅샷에는 있는데 과거에 없는 종목 (신규 편입)
과거에는 있는데 미래에 없는 종목 (제외 / 상장폐지)
```

마지막이 중요합니다. **사라진 종목이 수익률 계산에서 조용히 빠지면 성과가 좋아 보입니다.**
