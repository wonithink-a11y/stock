## 4. A2b — 미해결, 결정 필요

### 지금까지 확인된 것

1차 실행(calendar 수정 전) → 4건 실패. calendar 인증 수정 후 재실행 →
**"캘린더 밖 날짜"·"exitAt 비거래일" 2건은 해소**, 나머지 2건은 그대로:

```

FAIL  분석구간 내 폐지 461 >= 550 (정찰 실측 572)
```

**원인 규명 완료**: `build-price-a2b.py`가 쓰는 `stock.get_market_ohlcv_by_date(...,
adjusted=True)`는 **KRX가 아니라 Naver Finance**(`fchart.stock.naver.com/sise.nhn`)로
간다 — calendar.yml에 붙인 KRX 인증과 완전히 무관한 별도 서버다. 직접 재현해
Naver 쪽도 요청 범위와 무관하게 **정확히 3,000캔들, "오늘 기준 최근"만** 준다는
것도 확인했다(`count=999999` 요청 → 실제 반환 3,000개, 2014-05-26~2026-08-14).
정찰(2026-08-05)과 실제 수집(2026-08-16) 사이 11일 동안 이 롤링 윈도우가 전진해서
631→509·572→461로 줄어든 것으로 강하게 추정된다(LIKELY — 어느 종목이 정확히
넘어갔는지는 미확인, 원 정찰 산출물이 커밋 안 돼 있어 재정찰 없인 특정 불가).

`A2a`도 **완전히 같은 호출**을 쓰고 있어 이미 같은 문제를 안고 있다
(`frontTruncatedTickerDays: 2942`가 그 증거) — A2b만의 문제가 아니라 이 프로젝트가
"수정주가"를 얻는 방식 전체의 구조적 한계다.

### ③ 프로브 완료 — 결과: 3,000캔들 캡 없음, 그러나 분할 미조정으로 부적합

`scripts/probe-price-a2b-krx-native.py` + `probe-price-a2b-krx-native.yml`
(커밋 `3804d6a`) 실행 결과, `data/backfill/_probe-price-a2b-krx-native.json`
(커밋 `aabc808`):

```
005930·000660 둘 다  rows=3097 · first=2014-01-02 · last=2026-08-14
                     (calendar.json 전체 tradingDayCount와 정확히 일치)
```

**1·2·4 확인**: 3,000캔들 캡 **없음** — `adjStkPrc` 파라미터와 무관하게 요청한
전체 캘린더 구간(3,097거래일)을 그대로 돌려준다. Naver 우회 경로의 롤링 윈도우
문제는 이 경로에 없다.

**3·5 확인 — 부적합 판정**: `adjusted=True`(adjStkPrc=2)로 005930의 2018년
액면분할(50:1, 2018-05-04) 전후 종가를 직접 대조:

```
2018-05-03  2,650,000   (분할 전날)
2018-05-04     51,900   (분할 당일)
```

51.06배 단절 — **분할 조정이 전혀 안 되어 있다.** `adjusted=True`여도 그날짜의
KRX 정산가(액면분할 반영 전 원 단위)를 그대로 준다는 뜻이다. KRX의
`adjStkPrc=2`는 배당/유상증자 등 다른 조정을 의미할 뿐 액면분할 연속성과는
무관한 것으로 보인다(추정 — KRX 공식 정의 문서로 확인 안 됨).

**결론**: ③(KRX-native)은 3,000캔들 캡은 풀지만 분할 연속성이 없어 그대로
쓸 수 없다 — 분할 이력 종목마다 별도 재구성이 필요해지고, 이는 LAB-7이
피하려 했던 "재구성 비용"을 다시 불러온다. **다음 후보는 ④(KIS)** —
`FID_ORG_ADJ_PRC` 플래그의 분할 조정 여부와 이력 깊이·페이지네이션을 같은
방식(소수 종목 프로브)으로 확인해야 한다.

### ④ 프로브 완료 — 결과: 캡 있지만 페이지네이션 성공 + 분할 연속성 확인됨

`scripts/probe-price-a2b-kis.py`(커밋 다음 절 참고) 로컬 실행 — KIS
`inquire-daily-itemchartprice`(FHKST03010100)를 005930/000660으로 확인.
로컬 실행 산출물이라 규칙 4에 따라 `data/backfill/`에 커밋하지 않았고
실행 후 삭제했다. 수치는 이 문서에 옮겨 적는다.

**1·2 확인 — 캡 있음, 페이지네이션으로 완전히 우회됨**: 1콜당 정확히 100행
캡(`FID_INPUT_DATE_1/2` 범위와 무관, 확인된 하드 캡). `FID_INPUT_DATE_2`를
직전 응답의 최이른 날짜-1일로 갱신하는 커서 페이지네이션으로 32콜
(31×100행 + 마지막 97행) 만에 **정확히 3,097행**을 받았다 — `calendar.json`의
`tradingDayCount`와 완전히 일치, 첫날 2014-01-02·끝날 2026-08-14까지 빠짐없이.
005930·000660 둘 다 동일. **Naver·KRX-native와 달리 이 경로는 하드 3,000캔들
캡이 아니라 "콜당 100행" 캡이라 페이지네이션 비용만 감수하면 전체 이력을
받는다.**

**3·4 확인 — 분할 연속성 있음**: 005930 2018-05-04(액면분할 50:1) 전후를
`FID_ORG_ADJ_PRC=0`(수정주가)과 `=1`(원주가)로 나란히 대조:

```
             0503        0504        (원주가=1)      0503        0504
adjusted   53,000  →  51,900                     rawCloses   2,650,000  →  51,900
```

`adjusted`(=0)는 분할 전후로 **연속적**(53,000 → 51,900, 정상적인 하루
변동폭)이고 `raw`(=1)는 ③과 똑같은 51배 단절을 그대로 보인다. **KIS의
`FID_ORG_ADJ_PRC=0`은 실제로 액면분할을 조정한다** — ③의 KRX `adjStkPrc=2`와
다른 지점이다.

**결론 — ④가 인수인계 §4의 확인 항목을 전부 통과했다.** 전체기간 반환(캡은
있으나 페이지네이션으로 완전 우회) · 실제 수정주가 · 분할 연속성 유지.
A2b(및 구조적으로 같은 문제를 가진 A2a)의 대체 경로로 ④ 채택을
권고한다. **다음 결정은 사용자 GO**: `config/policies/price.v1.json`의
source를 KIS로 바꾸고 `build-price-a2b.py`를 페이지네이션 로직으로
재작성하는 것은 🔴 등급(정책·수집기 변경)이라 착수 전 승인이 필요하다.
API 호출 비용도 함께 고려한다 — 종목당 약 32콜(캘린더 확장 시 더 늘어남),
A1b 폐지 후보 1,222건 전체 수집이면 약 39,000콜(반면 Naver 경로는 종목당
1콜). 동시성·rate limit은 `probe-minute-kis.py`가 이미 재 측정한 값(8·16
동시 버스트, 거부 없음)을 재사용할 수 있으나 A2b 규모에서 다시 확인이
필요하다.
