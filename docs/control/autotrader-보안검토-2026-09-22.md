## 검토가 필요한 수정의 기준 (2026-09-22 사용자와 확정)

기준은 '어느 파일을 건드렸나'가 아니라 **'뚫리면 누가 무엇을 할 수 있게 되나'**다.

| 검토 없이 | 검토 필요 |
|---|---|
| 화면 모양(글자·색·배치·표시 항목 — 새 값은 `E(...)` 이스케이프) | 확인 **없이** 할 수 있는 일이 늘어남(새 경로·새 조작·확인 제거·약화) |
| 인증 **뒤**의 로직(전략·손익·알림 문구) | 로그인·세션·쿠키·패스키·잠금 규칙 자체 |
| 기존 확인을 **더 엄격하게**(시간 단축·허용 범위 축소) | 실계좌에 닿는 경로(실계좌 프로필 첫 연결은 필수) |
| 조건: 기존 회귀 전부 통과 | nginx·웹 유닛 격리(바깥에 무엇이 열리나) |

판단이 갈리면 검토 쪽이다. 검토를 미룰 수는 있지만 그때는 아래처럼 **미룬 범위를 여기에 적는다** — 적지 않으면 다음 검토가 그 변경을 모른 채 지나간다.
