# 종목 분석 카드 — EPS × PER 분해 모듈 설계 (2026-09-30, 초안·미구현)

계기: 사용자가 붙여넣은 외부 분석안(주가 = EPS × PER 분해). 이 문서는 그 안을 **이 저장소의 실제 데이터로 5종목에 시험한 결과**(삼성전자·SK하이닉스·NAVER·카카오·두산에너빌리티)와
거기서 나온 규칙을 정리한다. **코드·UI·데이터 변경 없음.** 계산 스크립트는 스크래치패드(임시)에만 있다 — 구현 착수 시 저장소로 옮긴다.
투자 자문이 아니라 규칙 계산값이다(절대 규칙 1: 결측은 결측으로 둔다).

## 0. 한 줄 결론

연간 EPS(A3b)로 만든 PER 은 **최대 12개월 묵은 값이라 지금 시점에서 심하게 틀린다.** 카드는 **분기 EPS 4개를 합친 TTM PER** 을 써야 하고,
그러려면 (1) DART 분기 공시 수집 (2) 액면분할 기준 보정 (3) 계속·중단영업 구분 (4) 정정 재공시 표시 — 네 가지 규칙이 필요하다.

## 1. 시험 결과 (5종목, DART 호출 241건)

| 항목 | 결과 |
|---|---|
| 귀인 항등식 `ln P = ln EPS + ln PER` | 잔차 최대 3.3e-16. 단 PER = P÷EPS 로 정의했으니 항등식은 자명하다 — **검증 대상은 입력값**이다 |
| 분기 EPS 조회 | `fnlttSinglAcntAll`(연결) + 보고서코드 11013·11012·11014·11011, 5종목 모두 가능 (별도 fallback 필요 0건) |
| 분기합 vs 연간 EPS | 삼성·하이닉스 0.1% · 카카오 0.3% · 두산 1.9%(2019) · NAVER 2021 은 92% 괴리(§3-③) |
| EPS 나이(중앙) | TTM 43~48일 ↔ 연간 157~169일 (최대 TTM 202일 ↔ 연간 410일) |
| TTM 계산 가능 거래일 | 삼성 100% · 하이닉스 99% · NAVER 95% · 카카오 70% · 두산 58% (결측은 §3-④ 정정 재공시 때문) |
| 최신가(09-29) TTM PER ↔ 연간 PER | 삼성 12.1 ↔ 41.6 · 하이닉스 7.8 ↔ 28.9 · NAVER 14.5 ↔ 15.0 · 카카오 42.9 ↔ 30.2 · 두산 284 ↔ 610 |
| 연말 기준 TTM/연간 EPS | 삼성 0.56~2.22배 · 하이닉스 0.36~3.06배 (연간 값이 최대 3배 어긋난 해가 있다) |

삼성·하이닉스는 2026 상반기 이익이 급증해 연간 PER 이 3배 넘게 높게 나온다. 카카오는 반대로 낮게 나온다.

## 2. 데이터 계약 (안)

- 소스: DART `fnlttSinglAcntAll`. 종목당 분기 1호출, 10년 ≈ 40호출. 관심종목 KR 353개 ≈ 1.4만 호출(일일 한도 2만 안), 전 종목 ≈ 10만 호출(5일 이상).
  카드가 종목 하나를 조회할 때 즉석 수집 + 캐시 방식이면 40호출.
- 분기 EPS: 1분기 = 3개월값. 2·3분기 = `thstrm_amount`(3개월). **4분기 = 사업보고서 EPS − 3분기 누적**(`thstrm_add_amount`).
- 가용일(PIT) = `rcept_no` 앞 8자리. 4분기는 사업보고서·3분기 중 늦은 쪽.
- TTM(t) = t 시점에 **공시된** 가장 최근 4개 연속 분기의 합. 4개 중 하나라도 없으면 `null`(0 으로 채우지 않는다). TTM ≤ 0 이면 PER 미표시.
- 가격은 A2a 수정주가(최신은 prices.json). 정정 이력은 API 가 최신본만 준다(§3-④).

## 3. 시험에서 나온 함정과 규칙

① **계정명이 제각각이다.** `기본주당이익(손실)` · `기본주당이익` · `기본주당순이익` · `계속영업 기본주당순이익`, 재무제표 구분도 IS/CIS 혼재.
   NAVER 2021~22 는 주당 행 이름이 `계속영업순이익` 이고(값이 작은 금액으로만 구분), 2022-1분기에는 오타 `계송영업순이익` 이 있다.
   → 규칙: '주당' 포함 & '희석' 제외 → 없으면 총합 행 우선 → 없으면 계속영업+중단영업 합 → 마지막 fallback 은 "금액이 작은 계속영업* 행 첫 쌍(기본)". fallback 사용은 화면에 표시.

② **액면분할 기준이 한 보고서 안에서도 섞인다.** 예: 카카오 2021-1분기는 5월 공시(분할 효력 4월 이후)인데 **분할 전** 기준(2,605원), 반기 보고서 누적은 분할 후 기준(1,243원).
   NAVER 2018 반기·3분기는 11월 공시인데 분할 전 기준.
   → 규칙: 분할 배수는 A3c 분기 **발행주식 수의 정수배 점프**(±3%)로 확정. 공시일이 분할 효력 분기 **안**에 있으면 같은 해 누적 항등식(`3분기누적 − 3분기 = 반기누적`)으로 기준을 이어 붙인다.
   5개 경계 공시 중 4개가 항등식으로 확정, 1개(삼성 FY2017)는 근접값 추정(값이 299,868로 분할 전임이 자명). 배수를 못 정하면 그 종목은 "분할 보정 불확실" 표시 + PER 시계열 막기.
   ★ A3d 분할 배수 261건 중 26건(카카오 포함)은 결측/1.5 미만, 5건은 다른 배수 — A3d 자체 수정은 별도 결정(§6).

③ **중단영업 일회성 이익이 총 EPS 를 왜곡한다.** NAVER 2021 은 중단영업 EPS 10만 원대가 잡혀 TTM PER 1.8배가 나온다. 계속영업 기준은 35.5배.
   NAVER 2021 은 분기 값도 일관되지 않아(분기합 212,473 vs 연간 110,854) 총 EPS 는 신뢰 불가. A3b 도 계속영업 기준(9,977)이다.
   → 규칙: **기본은 계속영업 EPS.** 중단영업이 0 이 아니면 그 사실을 표시하고 총 EPS 는 참고로만.

④ **정정 재공시가 원본을 덮어쓴다.** 카카오 FY2020~22 사업보고서는 접수일이 2024-03-20, 두산 FY2017~20 은 2024-03-27·05-16 — API 가 정정본만 준다. 원본 EPS 는 받을 수 없다.
   (분기 1~3 공시는 원본 그대로 남아 있었다.)
   → 규칙: 접수일 − 기간말 > 200일이면 "정정 재공시"로 표시하고 가용일을 그 접수일로 둔다(PIT 안전). 그 결과 4분기가 비는 구간은 TTM `null`. 카카오 TTM 결측 30%, 두산 42% 가 여기서 나온다.
   실제로는 카드에 "정정으로 원본 없음"이라고 적는 것이 정직하다.

⑤ **EPS 가 주가에 비해 너무 작으면 PER 이 무의미하다.** 두산 TTM PER 137·284배, 카카오 FY2024 335배. → 표시 규칙(임계값 EPS/주가 < 1% 는 **내가 정한 값이라 검증 필요**): 숫자 대신 "의미 낮음".

⑥ **미반영 주식 수 이벤트**: 유상증자·합병·분할합병(두산 유상증자 6건·합병 3건, 카카오 유상증자 2건·합병 7건, NAVER 합병 5건)은 EPS·가격 조정 모두 미반영. 크기 미측정 → 카드에 주의 문구.

## 4. 카드 모듈 범위 (외부 분석안 대비 제안)

- **넣는다**: Valuation 한 칸 — 최근 N년 주가 변화를 EPS 기여와 PER 기여로 분해(연말 기준, TTM). 현재 TTM PER, 그 EPS 나이(일), 위 표시 플래그.
- **이미 있음, 재사용**: 가격·ATR·52주 위치·PBR·업종·점수(카드 §11), 사업 요약(Gemini 해독 카드), 섹터(sector-strength). 중복해서 새로 만들지 않는다.
- **넣지 않는다**: 종합 신뢰도 점수(●●●○○)·등급 — 이 프로젝트는 검증된 것에만 점수를 붙인다. PER 백분위는 표시하더라도 "맥락, 신호 아님"(자기 과거 대비 PBR 밴드 시험 REJECT — findings/kr-own-pbr-band-results-2026-09.md).

## 5. 시험의 한계 (숨기지 않는다)

- 5종목·10년. 규칙이 다른 유형(별도재무만 있는 종목, 결산월이 12월이 아닌 종목, 지주사 등)은 안 봤다 — 결산월 비12월은 4분기 파생과 분기 라벨이 다르다.
- 분기 EPS 합 ≠ 연간 EPS(가중평균 주식 수 차이)라 최대 0.3% 괴리가 있다. 두산 1.9% 는 원인 미확인.
- 정정 재공시의 정확한 사유는 확인하지 않았다(사업보고서 정정으로 추정).
- 최신 가격은 prices.json(09-29), 분기 공시는 2026 반기까지.

## 6. 결정이 필요한 것 (사용자 몫)

1. 구현 착수 — 스크립트를 저장소(`research/strategy-lab/` 또는 `scripts/`)로 옮기고 카드에 붙일지. **새 외부 소스(DART 분기) 통합이라 확인 대상**(CLAUDE.md 실행 기준).

4. 임계값(⑤의 1%, 정정 200일)을 정책 파일에 둘지.
