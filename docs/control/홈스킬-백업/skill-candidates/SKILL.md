# 스킬 후보 점검

반복 업무를 스킬로 굳히면 다음 세션이 같은 함정을 안 밟는다. 하지만 스킬마다 설명문이 **매 턴 토큰**으로 들어가므로,
자동으로 만들지 않고 **제안 → 승인 → 생성** 순서로 한다.

## 1. 후보 찾기 (이 대화를 돌아본다, 새 조사 없이)

다음 중 하나면 후보다.
- 같은 절차를 이 세션에서 2번 이상 했다.
- 주·월 단위로 다시 올 일이다 (정기 점검, 월초 등록, 배포 절차).
- 하다가 함정을 알게 된 절차다 (잘못 붙으면 조용히 틀리는 것, 순서 의존, 사용자 몫과 내 몫의 경계).
- 사용자가 같은 지시를 반복했다.

후보가 아닌 것: 한 번뿐이고 반복 근거가 없는 일, 이미 CLAUDE.md·기존 스킬이 다루는 일.
기존 스킬과 겹치면 새로 만들지 말고 **그 스킬에 보강**하자고 제안한다.

## 2. 제안 (최대 2개, 한 줄씩)

`이름 — 무엇을 묶나 · 왜 지금 · 예상 빈도` + **내 권고(만들기/보강/보류)** 를 붙인다.
사용자는 전문가가 아니라 결정이 어려우니 권고가 없으면 제안이 아니다. 후보가 없으면 "없음" 한 줄로 끝낸다.

## 3. 승인되면 만들기

- `skill-creator` 로 만든다. 프로젝트 전용이면 그 프로젝트 `.claude/skills/<이름>/`, 어느 프로젝트에서나 쓰면 `~/.claude/skills/<이름>/`.
- **description 은 두 문장 이내**: 무엇을 하는지 + 언제 쓰는지. 키워드를 길게 나열하지 않는다 — 설명문이 길수록 매 턴 비용이 늘고,
  트리거 정확도는 길이보다 구체적인 상황 하나가 더 좌우한다.
- 본문은 순서·함정·사용자 몫 경계 위주로 짧게. 긴 표는 `references/` 로 뺀다 (필요할 때만 읽히게).
- 만든 스킬은 **새 세션부터** 목록에 잡힌다 (이 세션에서는 안 보일 수 있다). 첫 사용 때 맞는지 확인한다고 알린다.

## 하지 말 것

- 승인 없이 스킬 생성·저장소 커밋. 홈 폴더(`~/.claude`) 변경은 특히 확인받는다.
- 기억이나 추측으로 만든 절차. 이 세션에서 실제로 한 일에서만 뽑는다.
