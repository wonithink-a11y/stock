## 1. ★★ 선물 lead-lag — kosdaq150·usd 방향 A, REJECT 최종 확정

전임 세션(`세션인수인계-2026-09-06.md`)이 발견한 상충(§0 참고 — 공식 §16-A

```

usd       h=1  TRAIN 10.09 VALID  7.80 TEST  2.64  TRAIN -10.97 VALID -9.22 TEST -3.39
```

usd의 부호 반전도 메커니즘이 사전에 예측한 대로였다(우연이 아니라는 추가

(선물 출처일과 무관) 이 실패모드(횡단면이 "그 날 시장 자기방향"으로
퇴화)에 원리적으로 검정력이 없었다.

**판정: REJECT.** kospi200(exposure=편입비중, 이 오염 메커니즘의 대조군

## 3. 백그라운드 좀비 모니터 발견·정리 (교훈)

lead-lag 검증(§1)을 기다리려고 `until grep -q "저장:" ... ; do sleep 30;
done`식 백그라운드 모니터(Bash `run_in_background: true`)를 걸었는데,
**로그 파일 인코딩(윈도우 기본 코드페이지)과 grep 패턴(UTF-8)이 안 맞아
"끝났다" 신호를 영영 못 잡고 계속 돌고 있었다.** 실제 계산은 정상
완료됐고(결과도 이미 확보·판정 완료) 이 모니터는 순수하게 자원만
낭비하고 있었던 것 — 사용자가 "2시간째 돌고 있다"고 지적해서 발견,
`TaskStop`으로 종료(`b9ctnmmqb`).

**교훈**: 이 프로젝트(윈도우 환경)에서 Python이 쓴 로그를 bash
grep으로 감시할 때 인코딩이 안 맞으면 조건이 영원히 거짓이 되어
모니터가 안 끝난다. 다음에 비슷하게 걸 때는 실제 스크립트가 완료
직후 바로 파일(json 등) 존재 여부로 조건을 걸거나(`test -f`, 텍스트
매칭보다 안전), 완료 후 수동으로 확인해 직접 끄는 습관을 들인다.
