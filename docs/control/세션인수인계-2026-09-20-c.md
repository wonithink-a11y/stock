## 2. 다음 세션이 알아야 할 함정 여덟

### ① 서비스의 `OnFailure` 로는 유닛 파일이 깨진 실패를 못 잡는다

유닛 파일이 깨지면 **로드가 막혀 실행 자체가 없다.** 서비스는 실행이 없으니 실패하지도
않는다 — 실패하는 것은 **타이머** 쪽이다. 09-20 아침에 붙인 감시 7개는 전부 `.service`
였고, 그래서 이 사고는 무음이었다.

그날 저녁에 같은 7개의 **타이머**에도 붙였다. 붙이기 전에 **재현으로 발화를 확인했다**:

- 첫 시도는 틀렸다 — 깨진 서비스로 타이머를 `start` 하면 **start 자체가 거부**되고
  (`Job failed`) 타이머는 `inactive` 가 된다. 실제 사고와 상황이 다르다.
- 맞는 재현: 정상 서비스로 타이머를 먼저 띄워 `active (waiting)` 으로 만든 뒤 **서비스를
  깨뜨리고** `daemon-reload` → 발화 시점에 큐잉 실패 → 타이머 `failed` → sentinel 발화.

알림 스크립트에 타이머 이름을 넣어도 안전하다(로그 파일이 없으면 저널로 물러서고
`ExecMainStatus` 가 없으면 `'?'`). 실물 메시지 3번째 줄이 그대로 원인을 말한다:

```
[실패] ponytest-broken.timer
종료 ? · (시각 없음)
ponytest-broken.timer: Failed to queue unit startup job: Unit ... has a bad unit file setting.
```

**알림 이름이 `*.timer` 로 오면 그건 이 종류다.**

### ② `systemctl --failed` 는 그 순간의 스냅샷이다

첫 조회에서 `minute-oci-upload` 는 **안 보였다** — 아직 발화 시각(18:00)이 안 됐을 뿐
이미 깨져 있었다. `minute-collect.timer` 도 첫 조회 51초 뒤에 발화해서 그때 붉어졌다.

**깨진 유닛을 찾는 진짜 질의는 `--failed` 가 아니라 로드 상태다:**

```bash
grep -lE "@[A-Z_0-9]+@" /etc/systemd/system/*.service /etc/systemd/system/*.timer
for f in /etc/systemd/system/*.service; do u=$(basename "$f"); \
  s=$(systemctl show "$u" -p LoadState --value); [ "$s" != loaded ] && echo "$u -> $s"; done
```

### ③ `@ENVFILE@` 가 유닛마다 다르다 — 정상 유닛에서 베껴오면 틀린다

이 세션에서 **내가 실제로 틀렸다.** rv20 유닛에서 본 `.env` 를 분봉 계열에 그대로 넣었다.

```
rv20 · 크립토 · 무한매수    EnvironmentFile=~/collector-venv/.env          (자격증명)
분봉 계열(collect/upload)   EnvironmentFile=~/collector-venv/collector.env (MINUTE_RAW_ROOT 등)
```

증상이 조용하다 — 실행은 성공(exit 0)하고 **경로만 기본값으로 떨어진다.** 로그의
`raw`/`manifest` 줄이 평소와 다른 것으로 잡았다. 정본은 **정상 유닛이 아니라
`deploy/install-vm.sh` 의 변수 기본값**이다(`ENVFILE="$VENV/collector.env"`).

### ④ `grep $"\r"` 은 CR 을 안 센다 — `$'\r'` 이어야 한다

`$"..."` 는 **로케일 번역** 문자열이고 `$'...'` 가 ANSI-C 인용이다. `$"\r"` 은 정규식
`\r` = 리터럴 `r` 이 되어 **소문자 r 이 든 줄**을 센다. 이 세션에서 그걸로 "`.env` 에
CR 5줄" 이라는 **틀린 진단**을 냈다가 `$'\r'` 로 재서 0 임을 확인했다.

### ⑤ `set -e` + `grep -l` 은 "정상"에서 스크립트를 죽인다

"플레이스홀더가 안 남았는지" 확인하려고 `grep -l` 을 썼는데, **못 찾으면 exit 1** 이라
`set -e` 가 거기서 끊었다(뒤의 `daemon-reload` 가 안 돌았다). 검사에 `|| echo "없음"` 을
붙이거나 `set -e` 밖에 둔다.

### ⑥ 주석에 플레이스홀더 예시를 쓰지 않는다

타이머 주석에 예시로 `@REPO@` 를 적었더니 두 가지가 생겼다. (1) 설치 스크립트의 sed 가
**주석까지 치환**해 "치환 안 된 /home/ubuntu/collector" 라는 무의미한 문장이 된다
(2) 플레이스홀더 잔존 검사를 넣으면 이 주석 때문에 **영원히 붉어진다** — CLAUDE.md 가
경고한 "영원히 참인 경고" 그 자체다. 별도 커밋(`9f28964`)으로 말로 바꿨다.

★ `minute-oci-upload.timer` 의 `@RUN@` 은 **정당한 플레이스홀더다**(install-oci-upload.sh
가 치환). `minute-collect.timer` 에는 `@RUN1@`·`@RUN2@` 가 있다(16:10·17:40). 타이머를
배포할 때 "플레이스홀더 없음"을 전제하면 안 된다.

### ⑦ 유닛을 배포할 때 실효 설정 diff 를 먼저 본다

그냥 덮는 것이 이번 사고의 원인이었다. 배포 전에 주석·빈 줄을 뺀 실효 설정만 비교해
**스케줄이 바뀌지 않는지** 확인했다(6개는 `OnFailure` 만 추가, minute-collect 만
`@RUN1@/@RUN2@` 치환 필요). 이 확인이 없었으면 분봉 스케줄을 플레이스홀더로 되돌릴 뻔했다.

### ⑧ 날짜를 "거래일"이라 부르기 전에 요일을 확인한다

로컬 분봉이 09-18 까지인 것을 보고 **"09-19 금요일치가 누락됐다"고 오판**했다. 09-19 는
**토요일**이다(09-18 금 · 09-19 토 · 09-20 일 · 09-21 월). `is_expected_trading_day` 의
`weekday() < 5` 가 정확히 맞게 동작한 것이었고, 22분짜리 재수집을 할 뻔했다.

