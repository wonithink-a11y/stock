## 1. UI 시각 디자인 실제 구현

### 1.1 계기

이전 세션(§`세션인수인계-2026-08-25.md`)에서 만든 차트 트레이더 UI 4탭에
대해 사용자가 ChatGPT와 나눈 대화(공유 링크)를 보여주며 "이런 식으로
설계할 수 있나"라고 물어 브라우저로 열어 확인 — **그 대화엔 실제 이미지가
전혀 없고 ChatGPT가 ASCII 박스로 그린 와이어프레임뿐**이었다(Koyfin·
Bloomberg·TradingView 등을 텍스트로 설명). 이 사실을 먼저 정정하고, 그
IA(정보구조) 제안 자체는 화면별 가능/불가능表로 정리해 답했다.

그 다음 사용자가 **Koyfin·Chainx 실제 스크린샷 9장**을 직접 올리며 "이런
식으로 구현될까? 탭 위치만 나중에 바꿀 수 있게, 다크/라이트 전환도?"라고
질문 → 다음 3개를 확인 답변 후 실제 구현:
- 탭 순서: `ui/app.js`의 `TAB_ORDER` 배열이 이미 순서의 유일한 출처라
  재배치 비용이 원래 0이었다(기존 구조 재사용, 추가 작업 불필요)
- 다크/라이트: CSS 커스텀 프로퍼티로 이미 색상 관리 중이라 라이트 팔레트
  하나만 추가하면 됐다
- "디자인 먼저, 데이터는 나중" 설계 방식: 가능은 하나 스크린샷 속 상당수
  화면(Portfolio Value 트렌드·업종 배분 등)은 사실 데이터가 있어서 목업이
  아니라 바로 실제로 만들 수 있음을 확인 후 그렇게 진행

### 1.2 다크·라이트 테마 (완료)

- `ui/style.css`: `:root`에 `--good`·`--surface-2/3`·`--row-hover`·
  `--row-selected`·`--input-bg`·`--tooltip-bg`·`--canvas-bg-grad` 등
  흩어져 있던 하드코딩 색상 8곳을 변수로 통합, `:root[data-theme="light"]`
  라이트 팔레트 추가. `color-scheme: dark/light` 선언도 추가(브라우저
  강제 다크모드 재보정 방지 - 실측으로 발견, 아래 참고)
- `ui/app.js`: 헤더 🌙/🌞 토글, `localStorage`에 기억, `themechange`
  커스텀 이벤트 발행
- `ui/tabs/chart.js`의 캔버스 차트는 CSS 변수를 못 읽어서(Canvas2D 태생적
  한계) `cssVar()` 헬퍼로 매 프레임 실제 계산된 색을 조회하고,
  `themechange` 이벤트로 다시 그리게 연결. SVG(스파크라인)는 실제 DOM이라
  `style="stroke:var(...)"`가 테마 전환에 그냥 반응함(별도 처리 불필요)
- **실측 이슈**: 프리뷰 브라우저 툴(Claude Browser pane)이 `getComputedStyle
  ().backgroundColor`를 항상 `rgb(32,32,32)`로 강제 재보정하는 걸 발견 —
  실제 CSS 캐스케이드(`getPropertyValue('--bg')`)는 테마별로 정확히
  바뀌는 걸 확인했으므로 **코드 문제가 아니라 이 프리뷰 도구의 강제
  다크모드 렌더링 특성**이라고 판단, `color-scheme` 선언 추가 후에도
  같은 현상이라 도구 특성으로 최종 확정. 실제 사용자 브라우저에서는
  발생 안 할 가능성이 높다(추가 검증 안 함 - 프리뷰 도구 한계).

## 3. Ox Alpha(OpenCode) 협업 체계 — 이번 세션에서 확정

### 3.1 정체 확정

**"Ox Alpha"는 별도 AI 도구가 아니다.** 사용자가 확인해준 실제 정체:

```
Ox Alpha = OpenCode CLI를 다음 설정으로 실행한 것
  모델:     opencode/x-preview-f-free
  추론노력: --variant max   (사용자 표현 "노력도 맥스로 쓰라는거다")
```

- 모델명 자체는 `docs/control/opencode-model-fallback-order.md`(메모리
  파일)가 이미 2026-08-24에 최우선 순위로 정확히 기록해뒀던 것과 일치
  (재확인만 했다)
- **`--variant` 플래그는 이번 세션에 처음 확인**: `opencode run --help`로
  직접 조회해 찾음 — "model variant (provider-specific reasoning effort,
  e.g., high, max, minimal)"라고 명시돼 있다. 이전 세션들은 이 플래그를
  안 썼을 가능성이 높다(로그에서 발견 못 함) — **다음 Ox Alpha 위임부터는
  반드시 `--variant max`를 붙인다.**
- 실제 실행 커맨드(확정):
  ```bash
  opencode.cmd run "<지시문>" -m opencode/x-preview-f-free --variant max
  ```
- 이 정체·커맨드는 `AGENTS.md`에도 반영했다(아래 §4) 및
  `docs/control/opencode-model-fallback-order.md`(메모리) 갱신함

### 3.2 이 세션에서 확정한 협업 체계

CLAUDE.md의 "AI 협업 구조"(ChatGPT=설계검토, OpenCode=기계적 위임,
실험실=독립검증, 생산자·검증자 겸임 금지) 원칙을 Ox Alpha에 그대로 확장
적용하기로 했다 — 새 거버넌스를 만든 게 아니라 기존 것의 대상만 넓혔다.

```
Claude 전용(위임 금지) - 시크릿·정책판단·되돌리기 어려운 스키마
  · KIS/시크릿 관련 일체
  · Strategy Registry, Backtest 표준계약 최종 확정 (🔴 승인 등급)
  · Portfolio NAV 스냅샷 로직 (페이퍼엔진 상태 설계)

Ox Alpha 병렬 가능 - 대량 문서·기계적 분류(최종 채택은 Claude 재검증)
  · 업종 대분류 매핑 초안(160개 KRX 업종→대분류)
  · Factor Analysis JSON 추출(findings/*.md 76개 → docs/data/factors/*.json)
    ⚠ 미착수 확인함(git status에 docs/data/factors/ 없음) - 다음 세션이
    사용자에게 진행 여부 확인 필요
  · Beta/Volatility 계산기 초안(이번엔 Claude가 직접 함, 작아서 위임 오버헤드
    가 더 크다고 판단)

충돌 방지 프로토콜
  · 파일/디렉토리를 겹치지 않게 분담(Ox Alpha는 신규 파일만 생성)
  · git push는 순차적 - 이 프로젝트 기존 규칙(force push 금지, 충돌시
    rebase) 그대로 적용
  · 생산자·검증자 분리 유지 - Ox Alpha 산출 수치는 Claude가 반드시
    재검증(예: PBR Sharpe가 세션 중 2.25→0.46으로 정정된 이력이 있어,
    산문에서 기계적으로 뽑으면 옛 값을 캡처할 위험이 실제로 있음)
```

### 5.2 KOSDAQ 지수 연동 (완료, KIS 불필요로 계획 변경)

**핵심 발견**: 애초 계획(ChatGPT류 분석이 제안)은 "KIS Open API 국내업종
지수"였으나, **기존 KOSPI 데이터가 이미 KIS가 아니라 네이버 공개 차트
API(`fchart.stock.naver.com`, 무인증)에서 온다는 걸 코드로 확인** —
`symbol=KOSDAQ`만 바꾸면 그대로 되는지 curl로 직접 검증(2014-06-03부터
3,000행, 인증 없이 성공). **시크릿을 다루는 작업 자체가 사라져서** 원래
"사전 확인 대상"이었던 이유(신규 API 키 사용)가 해소됐다.

변경 파일:
- `research/strategy-lab/build_fred_extended_backfill.py`:
  `naver_kosdaq_daily()` 추가(`build_macro_layer_backfill.py`의
  `naver_kospi_daily()`와 동일 패턴 재사용), tier=1(매일 갱신)에 포함
- `research/strategy-lab/build_ui_macro.py`: `SERIES_EXT`에
  `krKosdaq: "코스닥"` 등록 — `ui/tabs/macro.js`는 `series` 딕셔너리를
  제네릭하게 순회해서 그리므로 **UI 코드 변경 0줄**

실행 완료:
1. `python build_fred_extended_backfill.py --selftest` — 6/6 통과
2. `--dry-run --tier 1` — KOSDAQ 3,000행 확인 후
3. 실제 실행 → `fred_extended_daily_kr.parquet` 갱신
4. `python build_ui_macro.py` → `ui/data/macro.json` 21개 시리즈(기존
   20+krKosdaq)로 갱신

검증: 매크로 탭에서 "코스닥" 카드가 실제 값(861.37, +3.85%, 1년 range
644.78~1,226)으로 렌더링 확인. **도중에 프리뷰 브라우저 HTTP 캐시가 이전
`fetch()` 응답을 재사용해 반영 안 된 것처럼 보인 순간이 있었다** —
`{cache:'no-store'}`로 우회해 실제로는 정상 동작함을 확정(코드 문제
아님, §1.2와 같은 종류의 프리뷰 도구 특성).

**자동 갱신 배선 완료**: 기존 Windows 작업 스케줄러(`StockUI-FRED-Tier1-
Daily`, 매일 07:30)가 이 스크립트를 그대로 재실행하므로 **추가 스케줄
등록 없이** 내일부터 KOSDAQ도 자동 갱신된다.
