**설계 결정 - Signals와 Orders를 합친 이유**: 이 엔진은 신호의 방향·확률·
기대값을 저장하지 않는다(계산 후 버림). 원장도 체결가·상태이력(FSM) 없이
최소 필드만 남긴다(KIS 체결내역이 정본이라는 설계). 둘로 나누면 Signals가
항상 빈 화면이 된다 — 실제 있는 데이터(`trades.pending[]`/`days[]`) 하나로
합쳤다. 이건 GPT가 짠 원 스펙과 다르게 간 유일한 지점이고, 사용자 승인받았다.

### Overview 계좌 전환 서브탭 — 4개 브로커 축

| 서브탭 | 데이터 출처 | 비고 |
|---|---|---|
| 모의투자 | `ui/data/positions.json` (기존) | KIS 국내주식, 가상자금 |
| KIS 실계좌 | `/accounts`의 `real.kis` | **오늘 신설** - `kis-portfolio-holdings.py`가 실시간 탭 워치리스트 용도로 쓰던 파일에 `account` 요약을 추가로 씀(새 수집 경로 아님) |
| 업비트 실계좌 | `/accounts`의 `real.upbit` | 평균매입가·평가손익 포함(거래소 응답의 `avg_buy_price` 그대로 사용) |
| 빗썸 실계좌 | `/accounts`의 `real.bithumb` | 위와 동일 구조 |
| RV20 선물 | `/accounts`의 `paper.rv20` | **오늘 신설** - `rv20_paper_order.py`가 매 실행 후 `~/.rv20-futures-holdings.json`에 씀. 필드 라벨은 추정(위 0-② 참고) |

**모두 홈 디렉터리 격리**(`~/.kis-holdings.json`·`~/.upbit-holdings.json`·
`~/.bithumb-holdings.json`·`~/.rv20-futures-holdings.json`, 전부 git 미포함) —
`kis-minute-history-api.py`(VM 상시 서버, `wonithink-stock.duckdns.org`)의
`/accounts` 엔드포인트가 유일한 공개 통로. Overview KPI(총자산 등)에는
이 4개를 안 섞는다 — 모의투자와 실제 돈을 합산 표시하지 않는다는 원칙.

### CORS 주의사항 (재발 방지)

`kis-minute-history-api.py`의 새 라우트에 `Access-Control-Allow-Origin`
헤더를 **직접 붙이지 않는다** — nginx의 `/accounts` location 블록이 이미
`add_header`로 붙인다. 둘 다 붙이면 `*, *`가 되어 브라우저가 통째로
무효 처리한다(2026-09-14 실측, `market-trend`/`minute-history`와 같은 패턴 유지).
