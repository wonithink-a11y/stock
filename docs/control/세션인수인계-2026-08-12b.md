새 세션은 이 문서 하나만 읽으면 A3c 본수집을 이어서 시작할 수 있다. 다만 이 문서는

같은 날짜에 이미 `docs/control/세션인수인계-2026-08-12.md`가 있다 — 그 문서가 끝난

쓰지 않고 `b` 접미사로 새로 만든 이유는 CLAUDE.md의 "새 날짜로 새 파일" 규칙이
같은 날 두 번째 세션까지는 정하지 않았기 때문이다 — 기존 파일을 덮어쓰면 그
세션의 서사가 사라진다.

   확인하고 `collect`를 더 돌리면 된다.
5. **다 채워지면 `mode: finalize` 1회.** 순서:
   `--finalize`(병합·검증·산출) → `verify-diagnostics.js A3c` →

   커밋. 전부 `if: success()`라 하나라도 실패하면 아무것도 커밋되지 않는다
   (workflow 자체에 이미 그렇게 짜여 있다 — 새로 만들 것 없음).
6. **finalize 성공 후** `docs/control/TASKS.md`의 A3c 행을 `DONE`으로 바꾸고

   옮긴다. **peg를 `lib/a5/resolver.js`에 연결하는 건 별도 작업이다** —
   A3c 데이터가 있어야 시작할 수 있지만, 연결 자체는 이 본수집 완료 후 새

## 알아두면 좋은 것 (운영상 함정)

- 로컬에 `DART_API_KEY` 없음 — 실제 API 호출이 필요한 모든 검증은 GitHub
  Actions(사용자가 수동 트리거)를 통했다. 로컬에서는 `--plan`(네트워크 없이
  격자만 미리보기)까지만 가능하다.
- `gh` CLI 없음 — Actions 트리거·로그 확인은 전부 사용자가 웹 UI로 하고
  결과를 붙여준다. 이 환경이 바뀌지 않는 한 다음 세션도 마찬가지다.
- **로컬 실행 후 반드시 `git checkout -- data/`**(CLAUDE.md 규칙4). 이번
  세션에서도 `--finalize` 로컬 진단 실행이 실패 경로에도 `_diagnostics.json`을
  쓴 걸 두 번 확인하고 지웠다 — 실패해도 진단 파일은 남는 게 계약이니(§
  "manifest 계약") 당황할 것 없다, 지우기만 하면 된다.
- `data/backfill/fundamentals/_shards_a3c/`는 지금 저장소에 커밋돼 있다
  — 이건 규칙4 위반이 아니다. **GitHub Actions가 커밋한 것**이라 정상이다
  (VM/로컬이 아니라 Actions가 유일한 Git writer, CLAUDE.md 「AI 협업 구조」).
- `python -c` 인라인 실행이 스크래치패드 깊은 경로에서 종종 조용히 실패한다
  (exit 49/1, 출력 없음) — 파일로 써서 `python <file>`로 실행하는 쪽이
  안정적이다. 콘솔 한글 출력이 깨지면 `PYTHONIOENCODING=utf-8`을 앞에 붙인다.
- push 전 항상 `git fetch origin` → `git log --oneline HEAD..origin/main`로
  분기 확인 → 겹치는 파일 없으면 `git rebase origin/main` → 재검증 → push.
  겹치면 중지하고 보고. force-push·`--force-with-lease` 둘 다 금지.
- `docs/control/세션인수인계-2026-08-12.md`(접미사 없는 쪽)는 **이 세션이
  아니라 그 전 세션**의 기록이다 — A5-5·A5-3 최초 보류·LAB-1~8 잠정 검증·
  Codex 편입이 거기 있다. 혼동하지 않는다.
