## 1. 실패 알림 — `.github/workflows/notify-failure.yml` (커밋 `1653c44`)

```
감시  backfill-price-a2a · Refresh strategy selections
      backfill-supply-demand-a4 · Update ui/data/positions.json (Paper Trading Engine)
발송  '성공 → 실패' 전이에만. 직전 실행이 이미 failure 면 생략
```

**설계 판단 둘.**

`if: failure()` 를 워크플로마다 붙이지 않았다 — 대상이 늘 때마다 N군데를 고쳐야
하고, 빠뜨린 하나는 여전히 조용하다. `workflow_run` 으로 한 곳에서 받는다.

★ **중복 억제가 핵심이다.** 페이퍼 엔진은 10분마다 돈다. 한 번 깨지면 하루
144통이 오고, 그러면 사용자가 채널을 끈다 — **알림이 없는 것보다 나쁜 상태**가
된다. 그래서 직전 실행의 `conclusion` 을 `gh api` 로 보고 전이일 때만 보낸다.

```
prev=$(gh api ".../workflows/<id>/runs?status=completed&per_page=3" \
       --jq "[.workflow_runs[] | select(.id != <이번 run id>)][0].conclusion")
```

이번 run 을 목록에서 빼고 그다음 것을 본다. 실제 런 이력에 태워 `success` 가
나오는 것을 확인한 뒤 커밋했다.

`workflow_dispatch` 를 남겨 둔 이유는 채널 연결을 확인할 수단이 필요해서다 —
`WF_NAME` 이 `(수동 테스트)` 로 대체된다. 시크릿이 없으면 `::warning::` 만 남기고
통과한다(no-op).

**함정 하나**: `run: |` 블록 안에 여러 줄 문자열을 그대로 쓰면 YAML 블록 스칼라
들여쓰기가 깨진다. `printf '...\n%s\n%s'` 로 한 줄에 만든다.

## 3. 폴 타이머를 장 마감에서 끊었다 (커밋 `12a2937`)

```
9..15:00/10:00          →   09..14:00/10:00
(09:00~15:50, 42회)          15:00,10,20,30:00      (09:00~15:30, 40회)
```

옛 주석은 "장마감 이후 회차는 신규 신호가 없어 같은 결과를 다시 확인하는 것뿐이라
해롭지 않다"고 했는데 **실측과 다르다** — 남아 있는 `PENDING_ENTRY` 를 회차마다
다시 제출하고 `40580000`(모의투자 장종료)으로 거부당한다. 09-09 로그 기준 30건 ×
2회차 = 하루 60건.

**엔진에는 장중 판정이 아예 없다**(`engine/` 전체 grep). 그 경계를 정하는 것은 이
타이머뿐이라 여기서 끊었다. 장마감 후 정산은 같은 날 관측하지 못하고 다음 영업일
09:00 회차가 잡는다 — `run_paper_trading_daily.py` 는 반복 실행에 안전하다.

VM 배포(`/etc/systemd/system/`) 후 `systemd-analyze calendar` 로 그날 마지막
발동이 15:30 인 것을 확인했다. **유닛 파일은 저장소 pull 로 갱신되지 않는다** —
`deploy/` 에서 `scp` → `daemon-reload` → `restart` 가 필요하다.
