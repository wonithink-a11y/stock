# 업비트 cbprem 1회 매수 금액 — 웹에서 바꾸기 설계 (2026-11-01)

> **설계만이다. 코드는 아직 없다.** 실주문 금액에 닿는 변경이라 프로젝트 규칙상 🔴 — 아래 '결정 3건'에 사용자가 GO 하면 구현한다. Claude 는 실계좌를 켜지 않는다(켜기는 지금처럼 패스키).

## 1. 요구

웹(autotrader 화면)에서 `cbprem` 프로필의 **1회 매수 금액(`params.notional_krw`)을 5,000원 이상 10,000,000원 이하**로 바꾼다. 지금은 프로필 파일 수정 + 한도 수동 조정이 필요하다.

## 2. 지금 구조 (읽고 확인한 것)

- 금액은 `params.notional_krw` 로 전략(`strategies/coinbase_premium.py`)이 읽는다. 5,000 미만이면 `ValueError`.
- 웹은 **주문을 내지 않고 요청·제어 파일만 쓴다**(`web_set_auto` → `control_path`, `web_request_run`). 한도·종목·키는 서버 프로필 파일이 정한다 — "웹이 뚫려도 손실 상한은 서버 한도"(`config.effective_auto` 주석).
- 한도 게이트 `risk.py`: 주문 금액 > `max_order_value`, 하루 합 > `max_daily_value`, 보유 > `max_position_value` 면 거부. 매도에도 걸린다.
- 웹 조작은 `OPS` 목록 + 패스키(`/passkey/action-options` → `/passkey/action`, 챌린지는 `(프로필, 조작)` 에 120초 묶임). 패스키가 있으면 인증앱 코드 경로는 막힌다.
- 매도 수량은 **진입 때 기록한 수량**(`position.qty`)이라 금액 설정을 바꿔도 보유 중 청산 수량은 변하지 않는다.

## 3. 설계

**원칙: 웹은 '희망 금액'만 쓴다. 서버 한도는 그대로 최종 상한이다.** 웹 값이 한도를 넘으면 저장하지 않는다(조용히 깎지도 않는다).

1. **저장**: `state_dir/notional_override.json` = `{"notional_krw": N, "at": ISO, "prev": M}` (임시 파일 → `os.replace`, `web_set_auto` 와 같은 방식). 이력은 `notional_history.jsonl` 에 한 줄 추가(변경 전·후·시각).
2. **적용**: 프로필 `params.web_notional: true` 인 전략(지금은 `coinbase_premium` 만)에서만 `notional_krw` 를 override 값으로 덮는다. 파일이 없거나 깨졌으면 프로필 값(= 안전한 쪽). 읽는 쪽에서도 같은 범위 검사를 다시 한다(이중).
3. **범위·형식**: 정수만, `5,000 ≤ N ≤ 10,000,000`. 업비트 최소 주문 5,000원. 쉼표·소수·문자열 거부.
4. **한도 연동 검사(저장 시)**: `1.5 × N ≤ max_order_value` ∧ `2 × N ≤ max_daily_value` ∧ `N + 개인 BTC 평가 여유 ≤ max_position_value`(평가는 스냅샷 값, 없으면 이 항목은 경고만). 하나라도 모자라면 저장 거부하고 필요한 한도를 화면에 적는다 — **웹이 한도를 올리지 못한다.**
5. **인증**: 새 조작 `set-notional` 은 패스키 전용. 챌린지에 **값 N 을 묶는다**(`pkAct = {p, op, val, until}` → `/passkey/action` 에서 값 불일치면 거부) — 지문을 받은 뒤 값이 바뀌는 것을 막는다. 확인 문구는 요구하지 않는다(주문을 켜는 것이 아님) — 단 **현재 값의 10배를 넘기면** 기존 `LIVE_PHRASE` 확인을 요구한다.
6. **의미**: '다음 매수부터' 적용. 이미 낸 매수 주문·보유 청산에는 영향 없음 → **포지션이 있어도 변경 허용**(매도는 기록된 수량).
7. **화면**: `/details?p=cbprem` 에 카드 하나 — 현재 유효 금액·출처(파일/웹)·최근 변경 5건·입력칸 + 범위 안내 + "지문으로 확인". 값은 금액 보기 재확인(`require_reauth`) 뒤에만 보인다.
8. **알림**: 변경 때 `TELEGRAM_TRADE_CHAT_ID`(매매•보안)에 "cbprem 1회 금액 M → N".
9. **되돌리기**: override 파일을 지우면 프로필 값으로 돌아간다(웹에 '파일 값으로' 버튼). 킬 스위치·auto 상태와 독립 — 금액을 바꿔도 주문이 켜지지는 않는다.

## 4-1. 구현 상태 (11-01)

구현·회귀 통과(`scripts/test-autotrader-passkey.py` 74/74 + 나머지 autotrader 회귀 전부). 설계와 달라진 점:
- 보유 한도 검사는 **하드 검사 `max_position_value ≥ N`** 만 하고, 개인 BTC 평가액은 화면 안내(스냅샷 값을 웹 저장 경로에 끌어오지 않았다).
- 변경 알림은 기존 웹 조작 알림(`🛠 웹 조작: cbprem · 1회 매수 금액 변경`)을 쓴다 — **값(M→N)은 알림에 없고** 화면 이력(`notional_history.jsonl`)에 있다.
- 프로필에 `params.web_notional: true` 를 SSH 에서 넣어야 웹 칸이 생긴다(기본은 꺼짐 = 안전한 쪽).

## 5. 구현 범위·검증 (GO 뒤)

- 수정: `autotrader/config.py`(override 읽기·쓰기·검증), `strategies/coinbase_premium.py`(유효 금액), `web.py`(조작·카드·패스키 값 묶기), 이력·알림.
- 회귀 `scripts/test-autotrader-*.py` 추가: 경계(4,999 / 5,000 / 10,000,000 / 10,000,001), 비정수·음수·빈값, 한도 연동 거부, 패스키 값 변조(옵션 때와 다른 값) 거부, override 가 `web_notional` 없는 전략에 안 먹음, 깨진 파일 → 프로필 값, 10배 확인 문구.
- 배포: PR → VM pull → **dry 상태에서 먼저**. 웹 유닛은 허용목록 격리라 state_dir 쓰기 경로(`notional_override.json`)가 막히지 않는지 확인(새 파일 규칙: BindReadOnlyPaths — 쓰는 곳은 이미 control 파일이 쓰는 state_dir).
- 실계좌 켜기 순서(README §11)는 불변: upbit-probe → dry 대조 → live.enabled → 패스키 '주문 켜기'.

## 6. 하지 않는 것

웹에서 한도(`risk`)·종목·키·`live.enabled` 변경 · 다른 전략의 금액 · 금액의 자동 조정(손익 따라 늘리기).
