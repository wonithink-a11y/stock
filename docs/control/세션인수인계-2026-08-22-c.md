## 1. A8(공매도) 본수집 — 완전히 끝남

이전 세션(`-b.md`)이 스모크를 트리거해두고 PC를 꺼서 중단된 상태에서 이어받았다.
스모크→본수집까지 가는 동안 서로 다른 세 가지 문제를 순서대로 발견·해결했다.

### 문제 1 — KRX 로그인 간헐적 실패 (JSONDecodeError)

16샤드 스모크가 2연속 실패(각각 다른 샤드가 로그인 4회 재시도 전부 실패). 처음엔
"동시 로그인 부하"로 보고 8샤드로 줄였으나(커밋 `6f0ece2`) 8샤드에서도 또 실패해
동시성이 원인이 아님을 알게 됐다. 이 과정에서 **`gh run rerun <run-id> --failed`**
가 실패한 샤드만 재시도하고 성공한 샤드 아티팩트는 그대로 재사용한다는 걸 발견·
검증했다(성공 5/8 + 실패 3개 재시도 → 성공). **이후 모든 부분 재시도에 이 방법을
쓴다.**

### 문제 2 — "종목당 1콜로 충분하다"는 정찰이 틀렸음 (더 큰 발견)

8샤드가 전부 성공했는데 finalize에서 "병합 결과 0행" — 120종목 전부 10년 구간
(2016-06-30~2026-08-14)에서 빈 응답이었다. `--rangecheck` 진단 서브커맨드를
새로 만들어 정찰종목(005930·000660, 데이터 있음 확인된 종목)으로 직접 재봤더니
**2년 구간은 성공(490행), 3년 구간은 정찰종목조차 빈 응답**이었다 — KRX가
장기간 단일 쿼리를 조용히 거부하고 pykrx가 내부 `'output'` 키 에러를 삼켜 빈
DataFrame으로 위장한다(교훈81과 동일 패턴). 최초 정찰(단일 날짜 쿼리만 테스트)의
결론이 범위를 넘겼던 것.

`date_chunks`/`fetch_range_chunked`로 종목당 collectFrom~오늘을 2년 단위(안
겹침)로 쪼개 여러 콜로 모으도록 재설계(정책 SS-1.0→**SS-1.1**, 커밋 `01b5416`).
콜 수가 종목당 1→6으로 늘어 8샤드는 샤드당 5시간+ 예상돼 16샤드로 되돌림(원래
정찰이 "1콜"을 전제로 8로 줄인 근거 자체가 무너졌으므로).

### 문제 3 — fail-fast:true가 부분 실패를 전체 실패로 증폭

16샤드+청크 스모크에서 shard 15 하나가 로그인 실패하자 fail-fast로 나머지 15개가
전부 취소됐다(이미 몇 분씩 돌고 있던 진행분 전부 폐기). `fail-fast: false`로
전환(커밋 `b5e23e7`) — 샤드는 서로 독립적으로 자기 아티팩트만 쓰고 finalize의
"샤드 전량 존재" 검사가 부분 실패의 승격을 막아주므로 안전하다.

### 결과

## 2. Ox Alpha(OpenCode) 전략랩 파일럿 — V1~V8

### 배경

사용자가 유튜브 영상 여러 개에서 매매 전략을 뽑아 ChatGPT에게 1차 정리시켰고
(MA눌림·FVG·Bollinger+RSI·Fibonacci·PIVO 수급 divergence·PIVO 동시매수·종가베팅
스캐너·거래대금+저항돌파 등 10개 후보), 이걸 **Ox Alpha**(OpenCode CLI, 모델
`opencode/x-preview-f-free`, 무료 체험)에게 research/strategy-lab 안에서만
실험시키기로 했다. 최초 접속 확인(`opencode run -m opencode/x-preview-f-free`로
정상 응답 확인)부터 이 세션에서 했다.

### 진행 방식

파일럿 원칙: 한 번에 다 안 주고 후보 하나씩, 매번 결과를 받아 **내가 직접 파일
대조로 검증**한 뒤 다음 후보를 승인하는 방식으로 진행했다. 검증은 항상: (1) 파일
실존 확인, (2) 보고된 수치가 원본 JSON과 정확히 일치하는지, (3) 핵심 코드 주장
(예: A4 스키마, PIT 계약, 5dc_v1a_p 함수명)을 실제 소스와 대조, (4) 범위 위반
없는지(커밋 없음·`research/strategy-lab/` 밖 무변경·`data/` 무변경).

**8개 후보 전부, 매번 검증 통과** — Ox Alpha가 지시된 경계를 한 번도 어기지

## 3. Ox Alpha에게 신규 데이터 수집을 시켜도 되는가 — **안 된다**

명확히 안 된다. 이유는 이 프로젝트의 기존 원칙 그대로다.

1. **쓰기 권한은 경로가 정한다**(CLAUDE.md) — `data/backfill/`의 유일한
   writer는 GitHub Actions다. Ox Alpha가 로컬/OpenCode에서 실제 수집을 돌려
   `data/backfill/`에 쓰면 두 번째 writer가 생긴다 — "정본을 쓰는 주체는
   하나다" 원칙 위반.
2. **manifest 계약** — manifest는 "인수 조건을 통과했다"를 뜻한다. Ox Alpha의
   수집은 `verify-diagnostics.js`·finalize 게이트를 거치지 않으므로, 설령
   결과가 맞아도 manifest가 보증하는 게 아니게 된다.
3. **시크릿** — KRX_ID/KRX_PW·DART_API_KEY 등을 Ox Alpha(외부 도구)에게
   전달하는 것 자체가 규칙 2("시크릿을 코드·JSON·로그에 절대 넣지 않는다")와
   OpenCode 위임 기준("credential·API key 등 민감정보는 전달하지 않는다")
   양쪽 위반.
4. **생산자·검증자 겸임 금지**와 같은 결— 실험실이 생산한 백필은 Claude가
   검증하는 구조인데, Ox Alpha가 수집까지 하면 겸임이 된다.

**Ox Alpha가 계속 해도 되는 것**: 이미 확보된 `data/backfill/`을 읽기 전용으로
열어 research/strategy-lab 안에서 파생 feature를 만들거나(V6의 매집가 VWAP
추출처럼) signal study·엔진 스모크를 돌리는 것 — 이건 이번 세션 내내 문제
없었다. **안 되는 것은 라이브 API(KRX/DART/KIS)를 호출해 새 원자료를 만드는
것**이다.

## 안전 관련 메모

- 이번 세션의 모든 워크플로 트리거(스모크·본수집·rangecheck 진단 4회·부분
  재시도)는 매번 사전 확인 받았다.
- A8 정책·워크플로 변경 4건(8샤드 축소·rangecheck 진단 추가·2년청크+16샤드
  복원·fail-fast off)은 각각 커밋 후 한 줄 보고, 커밋 자체는 🟡 등급으로 바로
  진행했다(진행 전 승인이 아니라 실행 트리거만 승인 대상).
- Ox Alpha의 모든 보고는 "일치는 승인 근거가 아니다"(교훈61) 원칙대로 파일
  직접 열어 대조했다 — 단순히 "결과가 그럴듯하다"로 넘어가지 않았다.
- 공유 엔진(`runner.py`) 수정 1건은 다른 자잘한 파일들과 다른 급으로 취급해
  diff를 직접 읽고 회귀 스위트 전체(115개)를 재실행해서 검증했다.
- `git checkout -- data/`는 이번 세션에서 로컬 실행이 없어 해당 없음(전부
  GitHub Actions 실행).
