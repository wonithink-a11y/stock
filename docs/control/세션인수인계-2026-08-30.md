## 4. 배경 — 왜 이 트랙이 시작됐나

사용자가 ChatGPT와 나눈 대화(fidetolabs "Self-Improving AI Trading Agent"
영상 분석 + 후속 대화)를 공유하며 타당성을 물었다. 그 대화의 핵심 제안은
"이미 검증한 개별 연구 결과(PER·수급·기술적 지표)를 조건부 조합으로
가져와 자동으로 새 법칙을 찾는 Rule Discovery Engine"이었다.

Claude 검토 결과: 방향은 타당하나(이 프로젝트가 이미 "조건부로 다시
보기"에서 여러 번 결정적 정보를 얻은 전례 있음 - PBR T1/T3, ROE T1/T3
등), ChatGPT가 가볍게 다룬 위험(multiple testing, 연도집중도, 상대
tercile 함정, 실제 엔진 괴리)은 이 프로젝트가 이미 여러 번 겪은 사고와
정확히 겹친다는 게 핵심 우려였다. 그래서:

- 무한 조합탐색 엔진을 바로 만들지 않고, **이미 검증된 신호를 재사용해
  조건부로 재검증**하는 점증적 접근으로 축소
- 판정 기준을 사전 고정(임계값은 실험하며 조정 가능, 단 변경 이력 남김)
- 판정 신뢰수준: "사전 고정 통계기준 통과 시 신뢰, Claude는 후보만 최종
  재현" (토큰 절약 - 사용자가 Claude 토큰 한도를 명시적으로 우려함)
- **자산군 3분할(KR/US/Crypto)** 요청 → 실측 결과 KR·Crypto는 인프라
  완비(즉시 가능), US는 프로덕션 채점기준만 있고 리서치용 개별종목
  데이터가 없어(Nasdaq100 등은 매크로 축으로만 쓰임) **US는 이번엔
  스코프에서 뺌**(별도 착수 결정 필요)
- "실험실"의 정체 확인 - 문서상 "모두의 AI 실험실"(GitHub 기반)은
  2026-08-21부터 접근 막혀 있음. 실제로 그 역할을 하는 건 **OpenCode
  CLI**(사용자가 확정) - 모델 우선순위는 Big Pickle→Nemotron 3 Ultra

2. 숫자를 소수(0.0128)로 쓰고 퍼센트(1.28)로 안 씀 - 위 frontmatter 예시

### 6-3. KR: 외국인수급5D 독립 재현 → KEEP 확정 ★가장 중요한 결과

`findings/kr-foreign-flow-5d-independent-verification-2026-08.md`.
`flow-basic-effect-2026-08.md`(다른 에이전트 산출물, 이 프로젝트 원칙상

완전히 새로 구현**해 재현 - 전체·TRAIN·VALID·TEST 전 구간 mean/NW-t/n이
**소수점까지 정확히 일치**(예: 전체 NW t=15.530, n=2590).

**부수발견(중요, 앞으로도 계속 쓸 정의)**: `foreign_net`은 A4 raw의

**`"외국인"+"기타외국인"` 합산**이 정답이다(000020/2016-01-04 실측
대조로 확인 - 외국인만 쓰면 -191,705,420원, 합산이 정답 -191,673,620원과
일치). `total_amount`는 `buyAmount["전체"]`(buy==sell 항상 동일).

이걸로 인수인계 §11-2가 최우선으로 요청했던 "외국인수급5D 독립 재현"이

### 6-5. foreign_flow5d_v1 엔진 연결 → REJECT (완료)

`findings/kr-foreign-flow5d-v1-engine-smoke-2026-08.md`. §6-3의 KEEP이
순수 통계(비용·슬롯경쟁 없는 cross-sectional 스프레드)라, `strategies/
pbr_value_v1`·`strategies/lowmom60_v1`과 같은 패턴(오프라인 selection.json
+ engine 무변경)으로 실제 포트폴리오 엔진에 연결했다. 설계 차이: PBR/
LOWMOM60은 월별 리밸런싱이지만 이 신호는 **일별** 리밸런싱 + **고정
5세션 보유**(원본 finding의 T+5 정의 그대로) - 훨씬 높은 회전율.
`foreign_net` 정의는 §6-3에서 확정한 것(외국인+기타외국인) 그대로 재사용.

**결과 1(topN=30)**: CAGR **-4.26%**, Sharpe -0.37, MDD -38.21% - 순수
통계(NW t=15.53, 전 구간 양)와 정반대. diag를 보니
`portfolioEligibleTradeCount` 60,918건 중 실제 체결 19,289건(31.7%)뿐 -
매일 top-30 신호가 나가는데 5세션 고정보유라 슬롯여유는 하루 평균
~6개뿐이라 심한 공급초과. `tieBreak=ticker_ascending`(종목코드순 -
`engine.execution.contracts.Order`가 신호강도 메타데이터를 안 나르는
기존 제약, PBR/LOWMOM60도 같은 제약이지만 월별이라 거의 안 걸림)이
매일 발동해 "그 날 상위 30개" 중 실제 편입이 알파벳순으로 정해진다고
1차 진단.

**결과 2(topN=6, 슬롯여유치에 맞춤) → 1차 진단 반증**: 슬롯 체결률이
31.7%→**99.9%**(12,978/12,990)로 사실상 완전히 해소됐는데 성과는
**더 나빠짐**(CAGR -7.32%, Sharpe -0.83, MDD -55.66%). tie-break
희석이 주원인이 아니었다는 뜻 - **수정된 해석**: 매일 top-30(유동성
필터 통과 종목의 약 상위 1.6%)에서 top-6(약 상위 0.3%)로 더 좁힐수록
나빠졌다는 건, foreign_flow_ratio 분포의 극단 꼬리가 진짜 지속적
수급압력보다 일회성 대량거래(노이즈)를 더 많이 담고 있을 가능성을
시사한다. 원본 독립재현은 **5분위(상위 20%) 평균**을 검증한 것이지
"더 극단적일수록 더 좋다"를 검증한 게 아니다 - 확정적 결론은 아니고
비선형성을 실측으로 보여준 정도.

**최종 판정: REJECT, 두 변형만 확인하고 중단.** 판정기준 없이 topN을
계속 바꿔가며 "어느 값이 좋게 나오는지" 찾는 건 이 프로젝트가 막으려는
바로 그 multiple-testing 함정이라 추가 스윕은 안 했다(사용자 지시
없이 Claude 판단으로 멈춤). 신호 자체(§6-3, 순수 통계 KEEP)는 안
바뀐다 - "일별 top-N 롱온리 포트폴리오 형태로는 REJECT"라는 뜻이다.

**코드는 로컬에만 있다** - `strategies/foreign_flow5d_v1/`·
`strategies/foreign_flow5d_v1_top6/`·`run_foreign_flow5d_v1.py`(위 §2
참고, PBR/LOWMOM60과 같은 관례).
