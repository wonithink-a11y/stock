## 3. 리밸런싱 주기 스윕 — REJECT, 월간 유지

`findings/rebalance-frequency-sweep-2026-09.md` · `sweep_rebalance_frequency.py`

findings 266건에 월간·일간만 있었고 중간(주간·격주)이 비어 있었다. 새 패널을
안 만들고 기존 월별 팩터 패널 + 일봉으로 주중 값을 **정확히** 얻는다(pbr = price/BPS,
EY = EPS/price — BPS·EPS는 재무 갱신 전까지 상수라 월 앵커에서 역산, PIT 안전).

```
기본 우주(dv20>=1억)  9칸 중 family-wise 바닥선(|t| 2.79) 통과: mom60 격주 3.02 · 주간 3.13
유동성 10배(>=10억)   통과 0건. mom60 t 3.02->1.86, 3.13->1.55, TEST 세 주기 모두 음수
```

mom60의 우위는 **하루 1~10억 거래되는 소형주 구간에만** 있었다. 슬롯당 333만원으로는
못 사는 우위다. pbr·earnings_yield는 어느 주기에서도 칸별 바닥선조차 못 넘는다.

### ★ 방법론 결함 둘을 안 고쳤으면 결론이 뒤집혔다

1. 난수 바닥선을 **부호 있는** t의 95퍼센타일로 잡고 `|t|`라고 불렀다(단측 1.645).
   `abs()`로 접으니 1.92/2.06/1.94가 됐고, 그 하나로 pbr 월간(1.51)·mom60 월간(1.86)의
   "통과"가 "미달"로 뒤집혔다.
2. 칸별 바닥선은 9칸을 훑는 순간 5% 오류율이 아니다(~37%). 격자 최고값의 귀무분포를
   부트스트랩한 family-wise 바닥선 |t| 2.79를 따로 냈다.
3. 난수 바닥선은 **총초과(비용 전)** 로 잰다. 난수는 회전율 100%라 비용 드래그가
   상수처럼 걸리고 그 |t|가 주기에 따라 부푼다(월 2.39 → 주 6.05).

부수: 유동성 문턱을 올리면 pbr은 좋아지고(+4.47→+7.44%) mom60은 나빠진다
(+20.88→+12.02%) — 수용력 질문에서 의미 있는 방향이다.

## 4. 월간 자동화 — 5개 링크

```
① A2a 수집         price-a2a.yml       매월 1~5일 19:00 KST + 중복 게이트
② selection 갱신    refresh_selections.py  8단계 오케스트레이터 + 산출물 검증

④ VM 반영          collector-pull.timer   매일 06:30 KST, 읽기 전용
⑤ 페이퍼 엔진       paper-trading-poll     10분마다 (기존)
```

### ★ A2a는 왜 월 1회인가 (실측)

A2a는 매 실행이 **전 연도 파일을 다시 쓴다** — "현재 상장분"만 담는 정의라
상장폐지분이 과거에서도 빠지고 수정주가 재산정이 소급된다(2026-09-03 커밋에서
2014년 파일까지 변경). 13개 파일 합계 **122MB가 매번 새 blob**이다.

```
일간   122MB x 250거래일 = 연 30GB   (.git 이 지금 1.6GB)
월간   연 1.5GB
```

막는 건 계산량이 아니라 **git이다.** 일간이 필요하면 A2a를 증분(과거 무변경)으로
바꾸는 계약 변경이 선행이고, manifest 바이트 동일성 보증을 건드리므로 별건이다.

게이트는 **캘린더를 안 본다** — `calendar.json`은 하루 늦게 갱신돼(선언 08:00 UTC,
실제 12:26~15:45 UTC) 매월 1일 저녁엔 그 달을 모른다. A2a 자신의 `actualDataTo`와
오늘의 연월만 비교한다.

### ★ VM pull이 규칙을 안 어긴다

"VM에 GitHub 자격증명을 넣지 않는다"는 **write** 제한이고, 저장소가 공개라 pull에는
자격증명이 필요 없다. 정본을 쓰는 주체는 여전히 Actions 하나다. `--ff-only`라
로컬이 갈라지면 덮어쓰지 않고 실패한다. 06:30을 고른 이유는 장중을 피하고(poll이
전략별 subprocess를 띄우는 사이에 pull이 끼면 한 실행 안에서 버전이 섞인다) 전날 밤
Actions 커밋 뒤여야 하기 때문이다.
