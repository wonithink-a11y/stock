## 4. 시장환경 대시보드 — KRX Open API 통합 (이번 세션 전체 흐름)

### 4-1. 배경 — ChatGPT 제안 → KOSPI200 선물 소스 탐색

사용자가 ChatGPT의 "시장환경 탭" 제안(미국증시·금리·달러·유가·BTC 등을
한 화면에)을 공유 → 기존 `docs/index.html`(실서비스 대시보드, `docs/data/*.json`
직접 fetch, `static/index.html`이 아니다 — CLAUDE.md의 그 언급은 낡은
파일명)의 "국면·포트폴리오" 탭에 매크로 지표 섹션을 신설하는 것으로 시작.

`scripts/fetch_macro.py`(FRED/Stooq/Yahoo/Naver 무료 소스)에 KOSPI·KOSDAQ·
USD-KRW·US10Y·WTI·BTC 6개 지표를 우선 추가했다가, 사용자가 "왜 3개월
비교만 하냐, 1일/30일/90일/180일/1년으로 다구간 표현 가능한가?" 질문 →
`horizon_changes()`로 전 지표 캘린더일 기준 다구간 변화(휴장일은 직전
거래일로 대체)를 계산하도록 재구성. 미국 2년물·30년물도 이때 추가.

### 4-2. KOSPI200 선물 — pykrx 실패 → KRX 공식 Open API 성공

**pykrx 경로는 대조군까지 실패.** `probe-future-krx.yml`(신규 정찰
워크플로, `.github/workflows/probe-future-krx.yml` + `scripts/probe-future-krx.py`)를
실 GitHub Actions에서 돌린 결과, 선물 OHLCV뿐 아니라 대조군(지수 현물
OHLCV)까지 실패(`KeyError`, 응답 인코딩 깨짐 정황) — pykrx 1.0.51이
KRX 쪽 변경으로 지금 전반적으로 불안정하다는 뜻. **폐기.**

대신 사용자가 KRX Open API(`openapi.krx.co.kr`) 인증키를 발급받아 제공 —
처음엔 "이용신청" 절차를 안 밟아 401(Unauthorized API Call)이 났으나,
사용자가 "API 이용신청" 버튼을 눌러 해결. 실제 엔드포인트:

```
https://data-dbg.krx.co.kr/svc/apis/drv/fut_bydd_trd?basDd=YYYYMMDD
헤더: AUTH_KEY: <키>
```

이 API는 **하루 스냅샷만 준다**(기간 조회 없음) — 그래서 다른 16개
FRED류 지표와 다른 아키텍처가 필요했다. `docs/data/kospi200fut_history.json`에
날짜별로 직접 누적(`krx_futures_backfill()`, 최근 400일 창 안의 빈 날만
채움 — 최초 실행 ~260콜/185초, 이후 매일 1~2콜). 로컬에서 실제
부트스트랩(267행, 2025-07-23~2026-08-26)까지 완료 후 커밋해 Actions
첫 실행이 대량 콜을 새로 안 쓰게 했다. 근월물 선정은 "코스피200 선물"
(미니 제외) 중 정규장 최대거래량 계약.

표시만 했고 `marketRegimeEngine.js` 로직 연결은 안 했다(범위 밖).

### 4-4. 검증 방식 (매번 반복한 패턴)

로컬 실행(실제 KRX 키로) → 로컬 정적 서버(`python -m http.server`) +
Browser 도구로 렌더링 확인(콘솔 에러 없음까지) → 커밋 → push(원격에
새 자동 커밋 있으면 stash+rebase, `_manifest_fred_extended.json` 제외하고
겹침 없음 확인) → `gh workflow run macro.yml` 수동 트리거 → 완료 대기 →
실서비스(`https://wonithink-a11y.github.io/stock/`)에서 최종 확인.
**GitHub Pages는 10분 CDN 캐시가 있다** — 방금 push한 내용이 라이브에
안 보이면 `?nocache=1`류 쿼리로 캐시버스팅 후 재확인할 것(이번 세션에
두 번 이 문제로 혼동했다가 해결).

## 6. 안전 관련 메모

- `DART_API_KEY`·`KRX_OPENAPI_KEY` 둘 다 이번 세션에도 사용자가 채팅으로
  직접 제공, 매 실행 인라인 env로만 사용, 어떤 파일에도 기록 안 함
  (커밋 전 grep으로 매번 확인) — `KRX_OPENAPI_KEY`는 GH Secrets에
  이미 등록돼 있어 다음 세션이 로컬에서 KRX API를 다시 테스트하려면
  사용자에게 재요청해야 한다
- `probe-future-krx.yml`은 진단용 워크플로로 남겨뒀다(probe-krx.yml과
  같은 패턴) — 필요하면 재사용 가능하나 pykrx 경로가 폐기됐으므로
  이제 큰 쓸모는 없다, 삭제하지는 않았다
- git push는 이번 세션 전부 완료 — 다음 세션 시작 시 추가 확인 불필요
  (단, 로컬 FRED 스케줄러가 만드는 `_manifest_fred_extended.json` 변경은
  push 전 stash 처리 필요, 위 §1 참고)
