## 1. OCI Object Storage Instance Principal — 완전 해결(4시간짜리 미스터리)

`-c.md`가 "진행 중"으로 남긴 것의 결말: **IAM은 처음부터 전부 정상이었다.** 진짜
원인은 두 번의 버킷명 표기 불일치였다:
1. 1차: `Stock-minute-manifest`(정책·Dynamic Group이 쓴 이름)로 만들려 했으나 실제
   생성된 버킷은 `Stock-mainfest`가 아니라 **`Stock-minute-mainfest`(manifest→mainfest
   오타, n·i 순서 바뀜)**.
2. 오타 수정 후 재생성했더니 이번엔 **대소문자가 달랐다**(`stock-minute-manifest`
   소문자 vs Policy의 `Stock-minute-manifest` 대문자).

`manage all-resources in tenancy`(사실상 관리자 권한)로도 여전히 실패하는 걸 확인해
권한 문제가 아님을 먼저 확정했고, 별도 임시 버킷(`stock-minute-ip-test`)에서
Dynamic Group·Policy 메커니즘 자체는 처음부터 문제없었음을 증명한 뒤에야 버킷명
표기 문제라는 게 드러났다. 대소문자까지 정확히 맞추자 PUT/HEAD 둘 다 즉시 성공.

**현재 상태**: `stock`/`stock-new` 두 VM 모두 Instance Principal로 `stock-minute-
manifest`(전부 소문자) 버킷에 OBJECT_CREATE·OBJECT_INSPECT 가능. OVERWRITE·DELETE는
의도적으로 권한 없음. `stock-new`에 OCI CLI 설치(`~/oci-cli-venv`, collector-venv와
분리). CLAUDE.md에 전체 경위 기록·커밋(`8c62052`).

**남은 것(미착수)**:
- Actions용 read-only 사용자/API Key(원래 설계 3단계) — 아직 안 만듦
- 실제 manifest 업로드·검증·commit 파이프라인 스크립트 자체 — 이제 IAM이 뚫렸으니
  이게 다음 실작업
- 진단용으로 만든 `stock-minute-ip-test` 버킷·정책은 사용자가 콘솔에서 정리하기로
  했음(제가 지울 권한 없음) — 아직 지워졌는지 미확인

## 2. 실험실(research/strategy-lab) 큐레이션

### 2-1. 가장 급했던 것 — 4.5GB 무방비 캐시 발견·차단

`.gitignore`에 전혀 안 걸려 있던 것: `.cache/`(3.1GB, 순수 재생성 가능 캐시) ·
`data/a4/`(948MB, 프로덕션 A4 사본) · `data/crypto/`(398MB, 재수집 가능 원본).
개별 파일 중 993MB짜리 parquet, 593MB 캐시, 249MB pickle까지 있었다 — 실수로
`git add -A` 한 번이면 저장소가 망가질 뻔했다. 즉시 `.gitignore`에 추가(`4888734`).

### 2-2. 전체 백업 커밋

나머지(~207MB, 681개 파일 — findings·스크립트·strategies/·tests/·reports/)를

### 2-3. 경로 버그 2건 발견·수정

- `research/strategy-lab/research/strategy-lab/...` — cwd 실수로 생긴 이중 중첩
  (내용은 `.pytest_cache`뿐이라 삭제)

  데이터라 `research/strategy-lab/reports/`로 이동(화이트리스트엔 안 넣음 — 인용
  문서 없음)
- 부수 발견: **`research/strategy-lab/reports/`는 이미 폴더별 사유 주석이 달린
  화이트리스트 큐레이션 체계가 있었다**(`research/strategy-lab/.gitignore`) —
  처음부터 무분별하게 커밋된 게 아니었다. 이 기존 규칙을 그대로 존중했다.
