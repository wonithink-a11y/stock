## 갱신 (2026-08-18) — KRX bld·종목별 수급 한정 재론

**"재론 금지"를 깬 것이 아니라, 전제(pykrx 버전)가 바뀌어 다시 잰 것이다** —
교훈52(대조군이 같은 경로인지 먼저 확인)를 그대로 적용한 결과다.

pykrx가 2026-04(PR #282)에 `KRX_ID`/`KRX_PW`(data.krx.co.kr 일반 회원 로그인 —
KRX 공식 Open API 키가 아니다) 로그인 세션을 추가했다. `pykrx==1.2.8` +
실계정으로 재실측한 결과: **종목별 수급(`get_market_trading_value_by_date`/
`_volume_by_date`)은 로그인 후 정상 응답한다** — A4 백필이 이 경로로 2,578종목·
540만9,687행(2016-01-04~2026-08-14)을 finalize까지 통과시켰다(manifest
`data/backfill/manifest/A4.json`, 세션인수인계-2026-08-18.md). 로그인 없이는
여전히 대부분 차단(무자격 재실측 확인 — 전종목 스냅샷·시가총액·PER/PBR·
공매도·지수·업종분류 전부 실패, 개별종목 일봉만 간헐적 성공).

**바뀌지 않은 것(당시)**: 전종목 스냅샷·지수·업종분류·공매도·외국인보유는
로그인 계정으로 재확인한 적이 없다 — "차단"을 아직 뒤집지 않는다. 이 프로젝트는
비공식 스크레이핑(KRX 공식 Open API 아님)을 production PRIMARY로 승격하지
않는다는 방침도 그대로다. 이 갱신은 "A4(수급)는 로그인 경로로 된다"는 사실
하나만 확정한다.

## 갱신 (2026-08-22) — 공매도 한정 재론, 차단 뒤집힘

**공매도도 로그인 세션으로 뚫린다** — 위 "바뀌지 않은 것" 목록 중 공매도만
재확인(교훈52 재적용, `.github/workflows/probe-shorting-krx.yml` 수동 실행,
run 32502926508). `short.krx.co.kr`이 결국 `data.krx.co.kr` MDC 시스템(A4가
쓰는 것과 같은 시스템)으로 리다이렉트되는 걸 먼저 확인했고, 그 로그인 세션으로
pykrx 공매도 함수를 실제 호출(정찰종목 005930·000660, A4와 동일)한 결과:

| 함수 | 결과 | 컬럼 |
|---|---|---|
| `get_shorting_balance_by_date` | OK | 공매도잔고·상장주식수·공매도금액·시가총액·비중 |
| `get_shorting_status_by_date` | OK | 거래량·잔고수량·거래대금·잔고금액 |
| `get_shorting_value_by_date` | OK | 공매도·매수·비중(금액) |
| `get_shorting_volume_by_date` | OK | 공매도·매수·비중(수량) |
| `get_shorting_balance_by_ticker`·`*_top50` | FAIL | 정찰 스크립트의 파라미터 형식 불일치(`TypeError: too many positional arguments`) — API 차단 아님, 시그니처 재확인 필요 |
| `get_shorting_investor_*`·`*_by_ticker`(value/volume) | 0행 | "market 옵션이 올바르지 않습니다" — ticker를 market 자리에 넣어서 난 정찰 스크립트 오류, API 차단 아님 |

전종목 스냅샷·지수·업종분류·외국인보유는 여전히 재확인 안 됐다 — "차단"이
아직 유효하다(이번 갱신은 공매도 하나만 다룬다). 본수집 설계(정책·manifest
계약)는 별도 🔴 승인 대상 — 세션인수인계-2026-08-22.md 이후 참고.
