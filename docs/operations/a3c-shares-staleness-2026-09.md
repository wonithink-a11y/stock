# A3c 주식수가 180일을 넘었다 — 고장이 아니라 수집 범위의 함수다

2026-09-11 실측. `docs/data/sector-strength.json` 의 `sharesStale` 이 19그룹 중
5개에서 켜졌다(2026-09-08 예고대로). 임계를 올리기 전에 **왜 켜졌는지**부터
잰 기록이다.

## 1. 무엇이 켜졌나

```
그룹 19개 중 sharesStale=True  5개   maxSharesStaleDays 182~183
                        False 14개   그 중 11개가 174~178 — 며칠 안에 같이 켜진다
STALE_WARN_DAYS = 180   (scripts/build-sector-strength.py:57)
```

★ `maxSharesStaleDays` 의 최대값은 **항상 A3C 폴백이 만든다.** KRX 스냅샷에서
온 행은 전부 7~8일이다. KRX 만 쓰는 그룹 셋(기타·항공/운수·통신/네트워크)은
maxDays 7~8 로 앞으로도 안 켜진다.

## 2. 왜 낡았나 — 정책이 그렇게 정했다

`config/policies/fundamentals.v1.json`

```
fiscalYearTo      2025
fiscalYearToRule  현재월 >= 4월이면 (현재연도 - 1), 아니면 (현재연도 - 2)
```

2026-09 기준 규칙값도 2025다 — **어긋난 데가 없다.** 즉 A3c 가 볼 수 있는
가장 새 서류는 FY2025 사업보고서이고 그건 2026-03 에 접수됐다. FY2026 분기
보고서(2026-05·08 접수)는 `bsns_year=2026` 이라 수집 범위 밖이다.

실측이 그대로 나온다:

```
종목별 최신 A3C 레코드의 접수월
  2026-03   2,378 종목   ← FY2025 사업보고서. 전체 3,197 중 74%
  2026-04~08  297 종목   ← 지연·정정 접수
  그 이전     522 종목   ← 상장폐지·거래정지 등
```

2,378종목이 2026-03 에 멈춰 있다. 오늘 기준 177일이고 **2026-09-14 경에
일제히 180일을 넘는다.** 다음 레코드는 FY2026 이 범위에 들어오는
2027-04 이후다(규칙상 2027-04 에 `fiscalYearTo` 를 2026 으로 올린다).

따라서 **`sharesStale` 은 앞으로 약 13개월 동안 A3C 폴백이 있는 모든 그룹에서
켜져 있는다.** 나이는 180 → 400일 근처까지 단조 증가한다.

## 3. 공시 간격 실측 — 180이 처음부터 틀린 값은 아니었다

```
A3C availableFrom 연속 간격 (3,197종목 · 88,225표본)
  p50  92일    p75 125일    p90 140일    p95 182일    p99 273일
```

분기 주기다. **살아 있는 수집에서는** 180일 초과가 실제로 이상 신호였다.
문제는 임계가 아니라 **수집 범위가 연 1회 리셋된다는 것**이다 — 정상 운영
중에도 한 해의 3/4 은 180일을 넘게 된다.

## 4. 그래서 무엇을 한다

- **임계(180)를 올리지 않는다.** 올려도 400일을 넘길 곳이 없어 같은 자리에
  다시 온다. 숫자를 옮기는 것은 경고를 끄는 일이지 고치는 일이 아니다.
- **`maxSharesStaleDays` 는 그대로 둔다.** 그건 사실이고, 사실은 유용하다.
- 이 문서가 "A3c 가 6개월 낡은 것은 정상"의 적을 자리다. 대시보드에서 ⚠stale
  을 보면 여기를 본다.
- 재수집으로 해결하지 않는다 — FY2026 은 정책상 아직 없는 데이터고, A3c
  전량 재수집은 DART 4만콜을 쓰는 **확인 대상** 작업이다(CLAUDE.md 실행 기준).

## 5. 결정 — KRX 출처로 좁혔다 (2026-09-11, 사용자 GO)

`sharesStale` 은 이제 **KRX 출처 행에만** 건다. A3C 폴백의 나이는 위 §2 대로
수집 범위의 함수라 경고가 아니라 사실이고, 그 숫자는 `maxSharesStaleDays` 로
계속 보인다. 새 필드 `maxKrxSharesStaleDays` 가 경고가 실제로 재는 값이다.

```
적용 후 실측 (asOf 20260910 · 352종목 · 19그룹)
  sharesStale True      0 / 19      (좁히기 전 5 / 19, 그리고 곧 전부 켜질 예정이었다)
  maxKrxSharesStaleDays 2 · 7 · 8일          ← 경고가 재는 값
  maxSharesStaleDays    7 ~ 183일            ← A3C 나이. 그대로 보인다
```

KRX 스냅샷은 매일 갱신되므로 이 값이 180을 넘으면 **그건 진짜 고장이다** —
경고가 그때 처음으로 정보를 준다.

selftest 에 tripwire 를 뒀다: 같은 나이(20200101)를 KRX 로 주면 켜지고, A3C 로
주면 안 켜지되 `maxSharesStaleDays` 는 그대로 180을 넘는다. 좁히기 전 조건으로
되돌리면 두 번째가 붉어진다(교훈61·72로 확인).
